========================================
测试目标：验证多 subagent 并发编排机制
========================================

【输入 1 - 基础并发测试】
同时创建 3 个独立任务，验证并发执行能力：

1. 写一个 Python 函数，计算斐波那契数列的第 n 项，保存到 ./test_result/fibonacci.py
2. 写一个 Python 函数，判断一个数是否为质数，保存到 ./test_result/is_prime.py
3. 写一个 Python 函数，计算两个整数的最大公约数，保存到 ./test_result/gcd.py

========================================

【输入 2 - 依赖链测试】
测试任务的依赖关系（depends_on）：

第一步：创建一个数据收集任务，从 ./data 目录读取所有 .txt 文件，统计每行的单词数，结果保存到 ./test_result/word_count.txt

第二步（依赖第一步完成）：根据统计结果，生成一个分析报告，说明哪个文件单词最多、最少，保存到 ./test_result/word_analysis.md

========================================

【输入 3 - 复杂编排场景】
测试真正的多 agent 协作：

请为 ./src/mini_agent 目录下的每个 .py 文件生成单元测试：
- agent.py  -> test_agent.py
- config.py -> test_config.py
- permissions.py -> test_permissions.py
- session.py -> test_session.py

要求：
1. 每个测试文件独立生成（可并发）
2. 所有测试生成完成后，运行测试并生成报告
3. 报告保存到 ./test_result/test_report.md

========================================

【输入 4 - 并行 + 汇总模式】
测试并行执行后汇总结果的场景：

1. 并行创建 4 个脚本，分别计算：
   - sum = a + b
   - diff = a - b
   - product = a * b
   - quotient = a / b

2. 将所有脚本保存到 ./test_result/calculator/

3. 创建一个汇总脚本，导入以上 4 个函数，实现一个完整的计算器类

4. 运行测试并生成文档

========================================

【触发多 subagent 编排的关键特征】

1. 多个独立任务同时提交（无依赖关系）-> 验证并发上限控制
2. 任务间有依赖关系（depends_on）-> 验证依赖解析和顺序执行
3. 父任务需要等待所有子任务完成才能继续 -> 验证 wait_all() 机制
4. 任务执行过程中需要查看其他任务的结果 -> 验证跨任务通信
5. 大量小任务批量提交 -> 验证 task_manager 的调度效率

========================================

【预期行为】

- 同时运行多个任务时，不超过 max_workers 限制
- 依赖任务自动等待前置任务完成
- 任务失败时，依赖它的任务应被取消
- 实时日志能够区分不同任务的输出
- 最终结果能够正确聚合
