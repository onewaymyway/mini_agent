# 看板配置管理：使用说明

对应设计文档：`next_doc/kanban_config_management_plan.md`。本文档只说明
"怎么用"，机制设计/取舍见设计文档。

## 在哪里

看板顶部 tab 栏新增 **"⚙️ 配置"**。打开后：

1. 顶部显示配置文件路径（`{project_root}/agent_config.json`）和统计信息
   （分类数 / 可见字段数 / 已偏离默认值的字段数）。
2. 每个功能域一个可折叠区块，标题带 🔶 标记的表示其中有字段被自定义过。
3. 用顶部的关键词框按字段名/说明筛选（字段较多，建议先筛选再看，比如输入
   `memory` 只看记忆相关的配置）。
4. 每个区块内是一份表单，改完点区块底部的"💾 保存"按钮——只会提交*这个
   区块里*实际改动过的字段。

## 修改后何时生效

**需要重启 agent 进程。** 看板改的是磁盘上的 `agent_config.json`
文件本身，不是正在运行的进程内存；进程启动时才会读一次配置文件，目前
没有热重载机制。保存成功后看板会提示这一点，请手动重启。

## 哪些配置不能在看板里改

- **列表/字典类的复杂字段**：MCP 服务器列表（`mcp_servers`）、隐私保护的
  密钥列表（`privacy.secrets`）、LLM 故障转移链（`llm_fallback_chain`）等
  ——这些字段本身是一组条目而不是单个值，看板暂不提供编辑，需要直接编辑
  JSON 文件。
- **敏感字段**：`http.api_token`、`web_search.api_key` 等，看板只显示
  "已配置 ✓ / 未配置"，不回显明文、不支持在看板里改，避免明文密钥出现在
  浏览器网络请求或页面里。

## CLI 参数 / 环境变量的优先级

配置生效优先级是 `CLI 参数 > agent_config.json > providers.json > 环境
变量 > 默认值`。看板里显示的"当前生效值"已经是这条链路合并后的最终结果，
但如果某个字段实际上是被 CLI 参数或环境变量覆盖的，看板改了
`agent_config.json` 也不会生效——这种情况看板不会额外提示，需要自己确认
启动方式里有没有传相关的 CLI 参数/环境变量。
