## 🤖 Agent 自主执行（核心改进）

### 1. 执行阶段状态机（ExecutionPhase）

为多轮执行的 Goal 引入**执行阶段**概念，独立于静态的 `GoalExecutionSpec`，回答"这一轮该怎么干"：

| 阶段 | 含义 | agent 行为基调 |
|------|------|----------------|
| `explore` 探索 | 尝试不同实现路径，允许试错 | 鼓励对比多方案，不必复用上一轮产物 |
| `converge` 收敛 | 从已有候选中选定一种 | 要求输出"方案对比说明"，不再引入全新方案 |
| `stable` 稳定 | 按已定方式重复执行 | 严格遵循 Spec，不做结构性变更 |
| `tidy` 整理 | 周期性维护，不产出新内容 | 只读审查 + 归档/合并/删除冗余 |
| `auto` 自动 | 系统按规则信号自动切换 | 默认模式 |

**自动判定信号（规则版，零 LLM 成本）**：
- 轮次窗口：默认前 3 轮为 explore，超过后若无剧烈变化信号则进入 converge
- Spec 变更频率：连续 2 轮未 revise 且轻量核对未命中 → 收敛信号
- 进展趋势信号：比较最近 3 轮 `progress_notes` 文本相似度（difflib），高度雷同视为"伪进展"，降级为 converge
- 健康告警：连续 6 轮卡在 explore / 窗口内反复横跳 → 触发告警
- 资源倍率：explore 期给 1.3× 超时预算，stable 期收紧至 0.85×

CLI：`/agent goals phase show/set/unlock <goal_id>`；看板展示阶段徽章、stability_score、切换下拉框。

详细设计见 `next_doc/goal_execution_phase_improvement_plan.md`（Stage A/B/C/D 已全部实现）。

### 2. 跨轮次诊断报告（CycleDiagnostics）

将散落在 7 处数据源（`goals.json` / `goal_cycle_archive.jsonl` / `execution_phase` / `cron_jobs.json` / `manifest.json` / `progress_notes` / REST `scheduling_overview`）聚合为一份 **`CycleDiagnosticsReport`**：

- 概览：轮次总数、调度周期、当前状态、阶段模式、优先级、task_template
- 健康信号：复用 `check_phase_health()` 判定逻辑，不重新发明
- 产出追踪：热数据（reaped_cycle_child_ids）+ 冷数据（归档 jsonl）拼成连续时间线
- 机制说明：基于静态模板 + 变量替换生成，**零 LLM 成本**
- 可选 LLM 摘要：`--summarize` 开关，默认关闭
- 性能边界：归档 jsonl 仅从文件尾部往前读取所需条数，不做全文件扫描

CLI：`/agent goals diagnose <goal_id>`；REST：`GET /v1/goals/{goal_id}/cycle_diagnostics`。

### 3. 交互式调优闭环（CycleTuning）

诊断报告看完之后，支持**草案 → 确认 → 应用**两步走闭环：

- **白名单参数**（安全边界，不可绕过）：`schedule` / `priority` / `execution_phase` / `task_template` / `regenerate_spec`
- **两条草案生成路径**（均零 LLM）：
  - `source="user_request"`：调用方已解析好结构化 `{param, to}` 列表
  - `source="rule_suggested"`：基于诊断规则信号自动推荐（如 cron 连续跳过 >=5 次）
- **自然语言解析层**（Stage 3，默认关闭）：`tune <goal_id> "把周期改成每天两次"` 时通过 LLM 转为结构化草案，配置开关 `cycle_tuning.tuning_llm_parse_enabled`

CLI：`/agent goals tune <goal_id> ...`；REST：`POST /v1/goals/{goal_id}/tuning_proposals`。

### 4. 调度公平性自诊断（FairnessDiagnostics）

新增 `perception/fairness_diagnostics.py`，对统一调度器的公平性进行自诊断：
- 统计各 Goal 的等待时间、执行延迟、资源分配偏差
- 输出公平性报告，帮助识别被长期饥饿的 Goal
- 看板新增公平性指标展示

### 5. 跨 Goal 经验复用（CrossGoalReference）

新增 `perception/cross_goal_reference.py`，实现相似历史 Goal 执行规范推荐：
- 当新建 Goal 时，自动检索历史相似 Goal 的执行规范作为参考
- 减少重复探索，加速新 Goal 的收敛速度
- 看板集成推荐结果展示

### 6. Goal Stuck 统计 + LLM 进展判断改进

- 新增 Stuck 统计面板，识别长期无实质性进展的 Goal
- 执行阶段进展判断引入 LLM 辅助（配置项 `execution_phase.progress_trend_llm_enabled`，默认关闭）
- 修复 `ExecutionPhaseConfig` 嵌套配置加载缺失（`progress_trend_llm_enabled` 接入 `loader.py`），补充 `tests/test_config_nested_blocks_wiring.py` 防止后续回归

### 7. Goal 执行规范自动生成 + 用户确认机制

- `goal_execution_spec.py` 支持自动从 Goal 描述生成执行规范草稿
- 新增 `spec generate` / `spec confirm` / `spec close` CLI 流程
- 补充 prompt 片段 `goal_execution_spec_builder_agent_addendum.md`、`goal_overall_completion_judge_agent_addendum.md`
- 看板集成规范生成入口

### 8. 成长顾问（Growth Advisor）自主性深化

- 新增 `growth_pursuit.json` 理想追求模板，支持自动 pursue 机制
- 新增反馈模式汇总（`test_growth_advisor_feedback_pattern_summary`）
- 新增饱和度追踪与追求可见性（`test_growth_advisor_saturation_and_pursuit_visibility`）
- 新增 spinoff 分离机制（`test_growth_advisor_pursuit_spinoff`）
- 成长顾问 × Goal/Cron 打通：`growth_advisor_goal_cron_integration` 测试通过
- 每日报告 cron（`growth_advisor_daily`，每日 22:30）+ 月度复盘 cron（`growth_monthly_retrospective`，每月）

### 9. Cron 调度器增强

- 新增 `priority` 字段：同 tick 内多个 job 同时到期时按优先级降序排队（不抢占）
- `consecutive_skip_count`：连续到点但未能成功触发时累加，便于诊断
- 决策画像归纳：`decision_profile_update`（interval:604800，默认关闭）
- Goal 结束方式优化：支持更灵活的完成信号处理
- 统一调度器与看板可见性改进：`unified_task_scheduler.py` 重构，REST 端点 `/v1/self/scheduling_overview` 增强

## 📊 FinanceData（数据验证与可靠性框架）

### 1. 三层验证中间件（L1-L3）

| 层级 | 职责 |
|------|------|
| L1 基础校验 | 类型、格式、必填字段检查 |
| L2 字段完整性 | 业务字段非空、枚举值合法性 |
| L3 逻辑一致性 | 跨字段/跨记录逻辑约束（如股价不能为负、涨跌停判断） |

- 统一数据模型规范（`specs/unified-data-model.md`）

### 5. 北向资金抓取功能
