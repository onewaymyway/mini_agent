## 一、Goal 执行引擎 — 孤儿执行记录自愈

周期性 Goal 存在一个隐患：当执行记录停留在 `running` 或 `paused_for_fairness` 状态时，后续调度无法继续，导致 Goal 永久停摆。v0.9.8 完整解决了该问题。

### 1.1 孤儿执行记录自动回收
- **新增** `ObjectiveExecutor.reconcile_orphaned_executions()` 方法，在 daemon 冷启动时自动扫描并回收孤儿执行记录
- 被回收的记录包括：`running`（进程已终止但未标记完成）和 `paused_for_fairness`（公平排队中但已超过时限）两种状态
- 回收后的记录将被重新纳入调度队列，确保 Goal 可以继续推进
- 新增完整测试套件 `test_objective_executor_orphan_reconcile.py`（121 行），覆盖各类孤儿场景

### 1.2 跳过告警改进
- cron_scheduler 的连续跳过告警机制改为**周期性重复提醒**：只在第 5/10/15/… 次跳过时发送通知，避免频繁告警噪声
- 新增 `test_cron_scheduler_repeated_skip_alert.py` 验证告警触发逻辑
- 更新 `cron-dedicated-execution-guide.md`、`goal-cycle-patrol-guide.md`、`unified-scheduler-guide.md` 三项文档

### 1.3 Goal Tidy 阶段执行通知
- Goal tidy 阶段完成后，系统会自动发送执行结果通知，包含清理统计和执行摘要
- `goal_cron_bridge.py` 和 `output_workspace.py` 新增通知逻辑（各约 100 行）

## 三、World Simulator 外部项目（核心迭代）

本版本对 world_simulator 进行了约 141 个 commit 的密集迭代，从最小起步版演进为完整的多尺度模拟器架构。

### 3.1 事件驱动决策引擎 + 反身性（第六轮架构升级）
- 引入 **Influence Field（影响场）** 概念：每个实体产生局部影响力场，影响邻近实体的决策权重
- 实现 **Event-Driven 决策点引擎**：仅当事件触发时才对相关实体进行决策计算，而非全局轮询
- **反身性（Reflexivity）**：实体的自我认知会影响其决策行为，决策结果又反过来改变自我认知
- 新增 `autopilot.py` 自主飞行模块，支持自动推进模拟
- 新增 `test_fast_forward.py` 快速推进测试

### 3.2 Reality Renderer 独立分层 + 五层输出框架
- 将 Reality Renderer 从主引擎中独立出来，形成单独的输出层
- 实现**五层输出框架**：Raw State → Normalized → Causal View → Narrative → Visualization
- 新增 **First Possible 里程碑检测**：追踪每个能力/机制首次出现的时间点，支持历史轨迹分析
- 相关测试：`test_first_occurrence_milestones.py`

### 3.3 技术/组织/制度类型协同演化
- 区分 **技术能力**、**组织能力**、**制度规范**三种类型标签
- 每种类型有不同的成熟度曲线和演化路径
- 新增 `test_capability_kind_coevolution.py` 和 `test_capability_maturity_timeline.py`
- 新增 `test_confidence_label.py`：Fact / Assumption / Hypothesis / Prediction 四级置信度标签体系

### 3.4 能力发现模块
- 新增 `capability_discovery.py`（400 行）：自动从历史状态中识别涌现的新能力模式
- 新增 `capability_discovery.yaml` workflow 定义
- 相关测试：`test_capability_discovery.py`（427 行）

### 3.5 问题分析与归因模块
- **问题分析**（`problem_discovery.py`）：自动检测状态异常、资源瓶颈、死锁等 simulated world 问题
- **归因分析**（`attribution.py`，214 行）：将状态变化归因到具体原因，支持因果链追溯

### 3.6 场账本（Field Ledger）机制
