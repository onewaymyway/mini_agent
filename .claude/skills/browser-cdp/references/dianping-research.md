# 大众点评技术特征调研报告

## 一、反爬机制概述

大众点评反爬机制属于**高难度**，核心防护包括：

| 机制类型 | 具体实现 | 难度 |
|---------|---------|------|
| _token 参数 | 核心反爬机制，综合判断风险 | ⭐⭐⭐⭐⭐ |
| WEBDFPID | 浏览器指纹参数 | ⭐⭐⭐⭐ |
| mtgsig | 请求签名参数 | ⭐⭐⭐⭐ |
| 动态字体加密 | 评论数据采用自定义字体编码 | ⭐⭐⭐⭐ |
| Cookie 管理 | 动态 Cookie，需维护登录态 | ⭐⭐⭐ |
| 行为检测 | 请求频率、行为模式检测 | ⭐⭐⭐⭐ |
| IP 限制 | 严格的 IP 频率限制 | ⭐⭐⭐ |
| 验证码 | 滑块/点选验证码 | ⭐⭐⭐ |

## 二、核心技术分析

### 2.1 _token 参数（核心防护）

_token 是大众点评最重要的反爬机制，其生成逻辑：

- **综合判断**：对 document、window、screen、element 对象进行检测
- **自动化检测**：识别自动化测试框架特征（如 webdriver、phantomjs 等）
- **请求融合**：融合请求体、查询字符串以及 URL 等数据生成 token 值
- **后端验证**：将 token 作为请求体的一部分 POST 至后端，由后端完成解密验证

**绕过策略**：
- 使用已登录的真实浏览器（browser-cdp 核心优势）
- 模拟真实浏览器环境特征
- 避免 webdriver 特征暴露

### 2.2 WEBDFPID 参数

- 浏览器指纹参数，用于识别浏览器环境
- 与 _token 联动，共同构成请求验证体系
- 需要模拟真实浏览器的指纹特征

### 2.3 mtgsig 参数

- 请求签名参数，类似其他平台的签名机制
- 需要逆向生成逻辑或依赖登录态

### 2.4 动态字体加密

- 评论数据采用自定义字体编码
- 非 OCR 方式可破解（字体映射）
- 需要动态获取字体文件并建立映射关系
- 破解方法：下载字体文件 → 解析字形映射 → 替换加密文本

## 三、browser-cdp 适配评估

| 能力项 | 现状 | 适配难度 | 建议 |
|-------|------|---------|------|
| 连接已登录浏览器 | ✅ 支持 | 低 | 可直接复用用户登录态，绕过 _token 验证 |
| 反检测模式 | ✅ stealth.py | 中 | 需配合指纹伪装，避免 webdriver 特征 |
| _token 绕过 | ❌ 不支持 | 高 | 需依赖登录态或逆向算法 |
| WEBDFPID 绕过 | ❌ 不支持 | 高 | 需模拟真实浏览器指纹 |
| 字体加密破解 | ❌ 不支持 | 高 | 需开发字体映射模块 |
| 行为模拟 | ✅ 基础支持 | 中 | 需增强人类化行为 |
| 验证码处理 | ✅ captcha_handler.py | 中 | 滑块验证码已支持 |
| 代理池 | ✅ proxy_pool.py | 低 | 可直接使用 |

## 四、适配优先级

**优先级**：⭐⭐⭐（中）

**优势**：
- browser-cdp 可连接用户已登录的真实浏览器，绕过 _token 验证
- 验证码处理已有基础支持

**劣势**：
- _token、WEBDFPID、mtgsig 三重验证，逆向成本高
- 字体加密需额外开发映射模块
- 反爬难度最高

**建议**：
1. 优先利用登录态场景（browser-cdp 核心优势）
2. 字体加密可开发通用字体映射模块
3. 纯自动化场景需投入大量资源逆向签名算法

## 五、技术路线建议

1. **登录态优先**：连接用户已登录的 Chrome 浏览器，绕过 _token 验证
2. **字体映射**：开发通用字体加密破解模块，支持动态字体映射
3. **指纹伪装**：增强 stealth.py，避免 webdriver 特征暴露
4. **行为模拟**：增强人类化行为，降低被检测风险
