# 网站技术栈差异调研报告

> 生成时间：2026-08-07
> 目标：调研电商、新闻、社交、政务四类网站的技术栈差异，为兼容性测试框架提供基础

---

## 一、四类网站技术栈对比总览

| 维度 | 电商 (ECOM) | 新闻 (NEWS) | 社交 (SOCIAL) | 政务 (GOV) |
|------|-------------|-------------|---------------|------------|
| **前端框架** | React/Vue SPA | 混合渲染 (SSR+CSR) | React/Vue SPA | 传统服务端渲染 |
| **动态加载** | 无限滚动/分页 | 懒加载 | 实时推送/无限滚动 | 静态页面为主 |
| **反爬强度** | ⭐⭐⭐⭐ 极强 | ⭐⭐ 中等 | ⭐⭐⭐⭐⭐ 极强 | ⭐ 弱 |
| **登录要求** | 高 (价格/库存需登录) | 低 | 极高 (大部分内容需登录) | 极低 |
| **验证码** | 滑块/点选/行为验证 | 无/极少 | 滑块/图形/行为验证 | 无 |
| **API 加密** | 强 (sign/token 动态加密) | 弱/无 | 极强 (WASM/字体加密) | 无 |
| **数据更新频率** | 实时 (库存/价格) | 高频 (分钟级) | 实时 (秒级) | 低频 (天/周级) |
| **典型响应时间** | 2-5s | 1-3s | 3-8s | 1-2s |

## 二、电商类网站 (ECOM)

### 2.1 技术特征

| 特征项 | 说明 |
|--------|------|
| **前端架构** | React/Vue SPA，组件化开发，状态管理复杂 |
| **路由模式** | Hash 路由或 History 路由，SPA 内路由 |
| **数据获取** | RESTful API + GraphQL，接口加密严重 |
| **动态渲染** | 服务端 SSR + 客户端 CSR 混合 |
| **反爬机制** | 设备指纹、行为分析、IP 限流、滑块验证 |
| **加密技术** | sign 参数动态生成、WASM 加密、字体加密 |
| **会话管理** | Cookie + Token 双重认证，登录态有效期短 |

### 2.2 代表性网站清单

| 序号 | 网站名称 | URL | 技术栈 | 反爬难度 | 搜索器文件 | 优先级 |
|------|---------|-----|--------|---------|-----------|--------|
| 1 | 京东 | https://www.jd.com/ | React + Node.js SSR | ⭐⭐⭐ | jd_search.py | P0 |
| 2 | 淘宝 | https://www.taobao.com/ | React + Vue 混合 | ⭐⭐⭐⭐ | taobao_search.py | P0 |
| 3 | 拼多多 | https://www.pinduoduo.com/ | React SPA | ⭐⭐⭐ | pdd_search.py | P0 |
| 4 | Amazon | https://www.amazon.com/ | React + AWS Lambda | ⭐⭐⭐ | amazon_search.py | P1 |
| 5 | 闲鱼 | https://www.xianyu.com/ | React SPA | ⭐⭐⭐ | xianyu_search.py | P1 |
| 6 | 携程 | https://www.ctrip.com/ | React SPA | ⭐⭐⭐ | ctrip_search.py | P1 |

### 2.3 抓取难点

1. **动态 sign 参数**：京东、淘宝等网站的 API 请求需要动态生成的 sign 参数
2. **设备指纹**：通过 canvas、WebGL 等生成设备唯一标识
3. **行为验证**：滑块、点选、行为轨迹分析
4. **价格/库存动态化**：不同用户看到不同价格（大数据杀熟）
5. **IP 限流**：高频请求触发 IP 封禁

## 三、新闻类网站 (NEWS)

### 3.1 技术特征

| 特征项 | 说明 |
|--------|------|
| **前端架构** | 混合渲染，部分页面 SSR，部分 CSR |
| **路由模式** | 传统多页应用 (MPA) + 部分 SPA |
| **数据获取** | RESTful API，接口相对开放 |
| **动态渲染** | 懒加载图片，部分动态内容 |
| **反爬机制** | 中等，部分网站有 IP 限流 |
| **加密技术** | 弱，少数网站有简单加密 |
| **会话管理** | 大部分内容无需登录 |

### 3.2 代表性网站清单

| 序号 | 网站名称 | URL | 技术栈 | 反爬难度 | 搜索器文件 | 优先级 |

| 1 | 新浪财经 | https://finance.sina.com.cn/ | 传统 MPA | ⭐⭐ | sina_news.py | P0 |
| 2 | 财联社 | https://www.cls.cn/ | React SPA | ⭐⭐ | thp_news.py | P0 |
| 3 | 澎湃新闻 | https://www.thepaper.cn/ | Vue SPA | ⭐ | wangyi_news.py | P0 |
| 4 | 网易新闻 | https://news.163.com/ | 传统 MPA | ⭐ | wangyi_open_search.py | P0 |
| 5 | 今日头条 | https://www.toutiao.com/ | React SPA | ⭐⭐ | toutiao_search.py | P1 |
| 6 | 虎嗅 | https://www.huxiu.com/ | Vue SPA | ⭐ | - | P2 |

### 3.3 抓取难点

1. **懒加载图片**：图片使用 lazyload，需要滚动触发加载
2. **动态内容**：部分新闻通过 JS 动态加载
3. **IP 限流**：高频请求触发验证码
4. **反爬策略**：部分网站有简单的 UA 检测

## 四、社交类网站 (SOCIAL)

### 4.1 技术特征

| 特征项 | 说明 |
|--------|------|
| **前端架构** | React/Vue SPA，复杂状态管理 |
| **路由模式** | History 路由，SPA 内路由 |

| **动态渲染** | 无限滚动、实时推送、WebSocket |
| **反爬机制** | 极强，多维度风控 |
| **加密技术** | WASM 加密、字体加密、动态 token |
| **会话管理** | 高，大部分内容需登录 |

### 4.3 抓取难点

1. **登录墙**：大部分内容需登录，登录流程复杂
2. **验证码**：滑块、点选、行为验证频繁出现
3. **设备指纹**：通过多种技术手段生成设备唯一标识
4. **WASM 加密**：小红书、抖音等使用 WebAssembly 加密接口
5. **字体加密**：部分网站使用动态字体混淆数据
6. **实时数据**：内容实时更新，需要轮询或 WebSocket
7. **IP 限流**：高频请求触发严格限流

## 五、政务类网站 (GOV)

### 5.1 技术特征

| 特征项 | 说明 |
|--------|------|
| **前端架构** | 传统服务端渲染 (SSR)，部分新网站使用 Vue/React |
| **路由模式** | 传统多页应用 (MPA) |
| **数据获取** | 传统表单提交，接口简单 |
| **动态渲染** | 静态页面为主，少量动态内容 |
| **反爬机制** | 弱，部分网站有简单 UA 检测 |
| **加密技术** | 无或极弱 |
| **会话管理** | 极低，大部分内容无需登录 |

### 5.2 代表性网站清单

### 5.3 抓取难点

1. **老旧技术栈**：部分网站使用传统技术，兼容性需测试
2. **表单提交**：部分网站使用传统表单提交，需模拟表单
3. **PDF 下载**：部分数据以 PDF 形式提供，需额外处理
4. **数据量大**：部分网站数据量巨大，需分页处理
5. **更新频率低**：数据更新频率低，需考虑缓存策略

## 七、兼容性测试框架设计建议

### 7.1 测试策略

| 网站类型 | 测试重点 | 测试频率 | 优先级 |
|----------|----------|----------|--------|
| 电商 | 搜索、价格、库存、登录态 | 每日 | P0 |
| 新闻 | 列表、详情、评论、分页 | 每日 | P0 |
| 社交 | 搜索、动态流、评论、登录 | 每日 | P0 |
| 政务 | 搜索、表单、PDF 下载 | 每周 | P1 |

### 7.2 测试用例设计

1. **基础访问测试**：验证页面能否正常加载
2. **搜索功能测试**：验证搜索查询和结果提取
3. **分页浏览测试**：验证翻页功能
4. **登录态测试**：验证登录流程和会话管理
5. **反爬绕过测试**：验证反检测能力
6. **性能测试**：验证响应时间和稳定性

### 7.3 评估指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| 页面访问成功率 | 页面正常加载的比例 | >= 95% |
| 元素定位准确率 | 元素成功定位的比例 | >= 90% |
| 抓取成功率 | 数据成功提取的比例 | >= 85% |
| 稳定性 | 连续测试通过率 | >= 90% |
| 反检测能力 | 绕过反爬机制的比例 | >= 80% |

## 八、结论

### 8.1 技术栈差异总结

1. **电商网站**：技术栈最复杂，反爬最强，需要处理动态 sign、设备指纹、行为验证
2. **新闻网站**：技术栈相对简单，反爬中等，适合快速适配
3. **社交网站**：技术栈复杂，反爬极强，需要处理登录墙、WASM 加密、字体加密
4. **政务网站**：技术栈最传统，反爬最弱，适合快速适配

### 8.2 下一步行动

1. 按优先级实现待拓展网站搜索器
2. 建立分类查询接口
3. 完善兼容性测试用例
4. 建立自动化测试框架
