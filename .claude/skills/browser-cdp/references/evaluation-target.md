# 网站操作能力评估目标说明

**版本**: 1.0.0  
**创建日期**: 2026-08-05  
**状态**: 初版  
**适用范围**: browser-cdp skill 抓取与浏览能力评估

---

## 1. 评估目标

优化 browser-cdp skill，不断拓展能抓取和浏览的网站，覆盖更多的领域，形成可靠的网站操作能力。

### 1.1 核心目标

1. **建立可量化的评估体系**：通过多维度指标体系，客观衡量 browser-cdp skill 对不同网站的抓取与浏览能力
2. **识别能力边界**：明确当前 skill 能稳定操作的网站类型和场景，以及存在困难的领域
3. **指导 skill 演进**：基于评估结果，针对性地增强薄弱环节，持续扩展覆盖范围
4. **形成能力基线**：建立各网站类型的评分基线，便于版本迭代时追踪能力变化

### 1.2 评估范围

#### 1.2.1 网站类型覆盖

| 类型 | 优先级 | 说明 | 示例网站 |
|------|--------|------|----------|
| 搜索引擎 | P0 | 基础能力验证，高频使用场景 | 百度、Bing、Google |
| 新闻资讯 | P0 | 内容提取能力验证 | 新浪新闻、网易新闻 |
| 电商平台 | P1 | 复杂交互与动态加载验证 | 淘宝、京东、拼多多 |

|------|--------|------|

## 2. 评估边界

### 2.1 能力边界

- **浏览器类型**：Chrome / Edge（基于 CDP 协议）
- **页面类型**：静态页面、动态页面、SPA 应用
- **数据规模**：单次评估不超过 100 条数据
- **执行时长**：单次评估不超过 5 分钟
- **并发限制**：串行执行，避免触发反爬

### 2.2 非评估范围

- 视频/音频下载（多媒体内容处理）
- 文件上传操作
- 支付流程操作
- 需要人工干预的复杂场景

## 3. 评估指标体系

### 3.1 核心维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 抓取成功率 | 30% | 目标数据能否被正确提取 |
| 页面加载性能 | 20% | 页面加载与渲染耗时 |
| 元素定位准确率 | 20% | 交互元素能否被准确识别 |
| 反检测能力 | 15% | 绕过反爬机制的能力 |
| 稳定性 | 10% | 多次执行结果一致性 |
| 错误恢复能力 | 5% | 异常场景下的容错与恢复 |

### 3.2 详细指标定义

详见 [website-evaluation-framework.md](./website-evaluation-framework.md)

## 4. 评估流程

### 4.1 评估准备阶段

1. 确定评估目标网站
2. 分析网站类型与特征（静态/动态/SPA/反爬强度）
3. 定义评估场景与测试用例
4. 准备评估环境与工具
5. 设定基线标准

### 4.2 评估执行阶段

1. 执行基础访问测试（页面加载、元素定位）
2. 执行数据抓取测试（提取目标数据）
3. 执行交互测试（点击、输入、滚动）
4. 执行反检测测试（触发反爬机制）
5. 执行稳定性测试（多次重复执行）
6. 收集日志与性能数据

### 4.3 评估分析阶段

1. 汇总各维度得分
2. 计算综合评分
3. 识别薄弱环节
4. 生成改进建议
5. 更新能力基线

## 8. 评估标准说明

### 8.1 评分等级

| 等级 | 分数范围 | 说明 |
|------|----------|------|
| 优秀 | 90-100 | 能力成熟，可稳定生产使用 |
| 良好 | 75-89 | 基本可用，个别场景需优化 |
| 合格 | 60-74 | 核心功能可用，需持续改进 |
| 待改进 | 40-59 | 存在明显短板，需重点优化 |
| 不可用 | < 40 | 当前能力无法支持该网站 |

### 8.2 通过标准

- **P0 级网站**：综合评分 >= 75，且抓取成功率 >= 80%
- **P1 级网站**：综合评分 >= 65，且抓取成功率 >= 70%
- **P2 级网站**：综合评分 >= 55，且抓取成功率 >= 60%
- **P3 级网站**：综合评分 >= 50，且抓取成功率 >= 50%

### 8.3 评估周期

| 类型 | 频率 | 范围 |
|------|------|------|
| 新网站评估 | 按需 | 单个新网站 |
| 定期复评 | 每月 | 已评估网站抽样 20% |
| 版本评估 | 每次发布 | 全量 P0/P1 网站 |
| 专项评估 | 按需 | 特定问题或新能力验证 |

## 9. 风险与约束

### 9.1 已知风险

1. **反爬机制升级**：目标网站可能随时更新反爬策略，导致评估结果下降
2. **页面结构变化**：网站改版可能导致选择器失效，需要重新适配
3. **网络环境差异**：不同网络环境下的表现可能不同
4. **浏览器版本差异**：不同 Chrome/Edge 版本的 CDP 行为可能有差异

### 9.2 约束条件

1. 评估过程需遵守目标网站的 robots.txt 和服务条款
2. 控制请求频率，避免对目标网站造成过大压力
3. 不使用任何破坏性操作（如提交表单、删除数据等）
4. 评估数据仅用于内部能力建设，不对外传播
