## 1. 测试目标

确保 Browser CDP 技能的各个模块功能正确、稳定可靠，支持自动化回归测试。

## 4. 测试框架与工具

### 4.1 测试框架
- **unittest**：Python 标准库，用于编写单元测试
- **pytest**：更强大的测试框架，推荐用于集成测试和端到端测试
- **mock/unittest.mock**：用于模拟外部依赖

### 4.2 测试目录结构建议
```
tests/
├── browser_cdp/
│   ├── __init__.py
│   ├── test_browser_launch.py      # browser_launch.py 单元测试
│   ├── test_browser_nav.py         # browser_nav.py 单元测试
│   ├── test_browser_extract.py     # browser_extract.py 单元测试
│   ├── test_browser_screenshot.py  # browser_screenshot.py 单元测试
│   ├── test_browser_input.py       # browser_input.py 单元测试
│   ├── test_browser_console.py     # browser_console.py 单元测试
│   ├── test_integration.py         # 集成测试
│   └── test_e2e.py                 # 端到端测试
└── conftest.py                     # pytest 配置
```

### 4.3 测试运行命令

```bash
# 运行所有单元测试
python -m unittest tests/browser_cdp/

# 运行 pytest（推荐）
pytest tests/browser_cdp/ -v

# 运行特定测试
pytest tests/browser_cdp/test_browser_launch.py::TestBrowserLaunch -v

# 生成测试覆盖率报告
pytest --cov=src --cov-report=html tests/
```

## 5. 测试数据准备

### 5.1 测试用网站
建议使用以下稳定的测试网站：
- https://example.com（官方示例网站）
- https://httpbin.org（HTTP 测试服务）
- https://quotes.toscrape.com（练习爬取的网站）

### 5.2 测试数据隔离
- 使用独立的 Chrome profile 进行测试，避免污染用户数据
- 测试完成后清理临时文件和截图

## 6. 测试用例模板

## 7. 持续集成建议

- 将测试添加到 CI/CD 流水线，每次代码变更自动运行测试
- 设置测试覆盖率目标（如 80%）
- 定期审查和更新测试用例以适应功能变化
