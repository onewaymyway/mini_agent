# 网站兼容性测试框架设计文档

> 生成时间：2026-08-07
> 目标：设计完整的网站兼容性测试框架，覆盖电商、新闻、社交、政务四类网站

---

## 一、框架设计目标

### 1.1 核心目标

1. **可量化评估**：建立统一的评估指标体系，量化各网站抓取能力
2. **可复现测试**：测试用例可重复执行，结果可对比
3. **可扩展架构**：支持快速添加新网站和新测试场景
4. **自动化执行**：支持定时任务自动执行测试

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 单一职责 | 每个测试用例只验证一个功能点 |
| 可组合性 | 测试用例可组合成测试套件 |
| 可观测性 | 测试过程可监控，结果可追溯 |
| 容错性 | 单个用例失败不影响整体测试 |

## 三、数据模型设计

### 3.1 网站配置模型

```python
@dataclass
class WebsiteConfig:
    """网站配置"""
    # 基本信息
    name: str                              # 网站名称
    url: str                               # 网站 URL
    category: str                          # 分类代码 (ECOM/NEWS/SOCIAL/GOV)
    subcategory: str                       # 子分类代码
    
    # 技术特征
    frontend_framework: str                # 前端框架 (React/Vue/SSR)
    anti_crawl_level: int                  # 反爬难度 (1-5)
    login_required: bool                   # 是否需要登录
    
    # 测试配置
    priority: str                          # 优先级 (P0/P1/P2/P3)
    timeout: int                           # 超时时间 (秒)
    retry_count: int                       # 重试次数
    
    # 评估指标
    target_success_rate: float             # 目标成功率
    target_accuracy: float                 # 目标准确率
```

### 3.2 测试用例模型

```python
@dataclass
class TestCase:
    """测试用例"""
    # 基本信息
    case_id: str                           # 用例 ID (如 BDU-01)
    name: str                              # 用例名称
    description: str                       # 用例描述
    
    # 执行配置
    steps: List[Step]                      # 操作步骤列表
    expected_results: List[ExpectedResult] # 预期结果列表
    
    # 评估配置
    evaluation_dimensions: List[str]       # 评估维度
    pass_criteria: Dict[str, float]        # 通过标准
    
    # 执行状态
    status: str                            # 状态 (pending/running/pass/fail)
    actual_results: List[ActualResult]     # 实际结果
    error_message: str                     # 错误信息
```

### 3.3 测试结果模型

```python
@dataclass
class TestResult:
    """测试结果"""
    # 基本信息
    run_id: str                            # 执行 ID
    website_name: str                      # 网站名称
    case_id: str                           # 用例 ID
    timestamp: datetime                    # 执行时间
    
    # 执行信息
    duration: float                        # 执行时长 (秒)
    status: str                            # 状态 (pass/fail)
    error_message: str                     # 错误信息
    
    # 评估指标
    metrics: Dict[str, float]              # 评估指标字典
    
    # 详细数据
    screenshots: List[str]                 # 截图路径
    logs: List[str]                        # 日志信息
```

## 五、评估指标体系

### 5.1 核心评估指标

| 指标名称 | 说明 | 计算公式 | 目标值 |
|----------|------|----------|--------|
| 页面访问成功率 | 页面正常加载的比例 | 成功访问数 / 总访问数 | >= 95% |
| 元素定位准确率 | 元素成功定位的比例 | 成功定位数 / 总定位数 | >= 90% |
| 抓取成功率 | 数据成功提取的比例 | 成功提取数 / 总提取数 | >= 85% |
| 稳定性 | 连续测试通过率 | 连续通过次数 / 总测试次数 | >= 90% |
| 反检测能力 | 绕过反爬机制的比例 | 成功绕过数 / 总触发数 | >= 80% |
| 响应时间 | 页面平均响应时间 | 总响应时间 / 请求数 | <= 5s |

### 5.2 综合评分模型

```
综合评分 = 页面访问成功率 × 0.2 + 
           元素定位准确率 × 0.2 + 
           抓取成功率 × 0.3 + 
           稳定性 × 0.2 + 
           反检测能力 × 0.1
```

### 5.3 评级标准

| 评级 | 综合评分 | 说明 |
|------|----------|------|
| A+ | >= 95% | 优秀，完全支持 |
| A | 90-95% | 良好，基本支持 |
| B | 80-90% | 中等，部分支持 |
| C | 70-80% | 较差，需优化 |
| D | < 70% | 不支持，需重构 |

## 六、测试执行流程

### 6.1 执行流程图

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  初始化配置  │────▶│  启动浏览器  │────▶│  执行测试用例 │────▶│  收集结果   │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
       │                   │                   │                   │
       ▼                   ▼                   ▼                   ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  加载网站配置 │     │  创建浏览器实例 │     │  执行单个用例   │     │  生成测试报告 │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
```

### 6.2 执行步骤

1. **初始化阶段**
   - 加载网站配置
   - 初始化浏览器实例
   - 准备测试环境

2. **执行阶段**
   - 按优先级顺序执行测试用例
   - 记录执行过程和结果
   - 处理异常情况

3. **评估阶段**
   - 计算评估指标
   - 生成综合评分
   - 输出测试报告

4. **清理阶段**
   - 关闭浏览器实例
   - 清理临时文件
   - 归档测试结果
