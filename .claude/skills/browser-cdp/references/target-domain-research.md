# 目标领域技术调研报告

本文档调研小红书、携程、大众点评三个目标领域的技术特征，为 browser-cdp skill 适配优先级提供决策依据。

---

## 一、小红书（内容电商平台）

### 1.1 反爬机制概述

小红书 2025 年反爬机制全面升级，属于**高难度**目标：

| 机制类型 | 具体实现 | 难度 |
|---------|---------|------|
| 动态签名 | x-s、x-s-common、x-t 三个核心参数，季度更新算法 | ⭐⭐⭐⭐⭐ |
| 设备指纹 | Canvas + WebGL + 字体 + 设备指纹多维校验 | ⭐⭐⭐⭐ |
| Cookie 时效 | 动态 Cookie 每 10 分钟过期 | ⭐⭐⭐ |
| 行为检测 | 请求频率、UA 顺序、点击间隔、页面停留时间 | ⭐⭐⭐⭐ |
| IP 限制 | 请求频率限制，秒封 IP/账号 | ⭐⭐⭐ |

### 1.2 技术特征分析

**x-s 签名机制**：
- 核心函数 `mnsv2`，使用自定义 Base64 字母表编码
- 依赖浏览器环境（window、document、navigator 等）
- 需要 JSVMP（JavaScript 虚拟机）环境补全
- 算法每季度更新，逆向成本高

**x-s-common 设备指纹**：
- 编码设备信息（IMEI、MAC、Android ID 等）
- 使用自定义字母表 Base64 编码
- 与 x-s 签名算法同源

**登录态要求**：
- 部分接口需要登录态（Cookie）
- 未登录可访问公开内容，但有限流
- 登录态 Cookie 有效期约 10 分钟

### 1.3 browser-cdp 适配评估

| 能力项 | 现状 | 适配难度 | 建议 |
|-------|------|---------|------|
| 连接已登录浏览器 | ✅ 支持 | 低 | 可直接复用用户登录态 |
| 反检测模式 | ✅ stealth.py | 中 | 需配合指纹伪装 |
| 动态签名绕过 | ❌ 不支持 | 高 | 需逆向 x-s 算法或依赖登录态 |
| 行为模拟 | ✅ 基础支持 | 中 | 需增强人类化行为 |
| 代理池 | ✅ proxy_pool.py | 低 | 可直接使用 |

**适配优先级**：⭐⭐⭐（中）
- 优势：browser-cdp 可连接用户已登录的真实浏览器，绕过签名验证
- 劣势：纯自动化场景需逆向签名算法，成本高
- 建议：优先利用登录态场景，纯爬虫场景需额外开发签名模块

## 二、携程（旅游服务平台）

### 2.1 反爬机制概述

携程反爬机制属于**中高难度**：

| 机制类型 | 具体实现 | 难度 |
|---------|---------|------|
| 动态签名 | sign 参数，时效性极强（几秒到几分钟） | ⭐⭐⭐⭐ |
| Cookie 管理 | 动态 Cookie，需维护登录态 | ⭐⭐⭐ |
| 行为检测 | 点击间隔、页面停留时间检测 | ⭐⭐⭐ |
| IP 限制 | 请求频率限制 | ⭐⭐⭐ |
| 验证码 | 滑块验证码（极验） | ⭐⭐⭐ |

### 2.2 技术特征分析

**sign 签名机制**：
- 动态生成，时效性极强
- 直接抓包复用会瞬间被封
- 需要破解生成逻辑或依赖登录态

**Cookie 管理**：
- 需要动态获取并维护有效 Cookie
- 登录态 Cookie 有效期较短
- 可通过模拟登录或从页面请求中动态获取

**行为特征检测**：
- 检测点击间隔、页面停留时间
- 需要模拟人类行为模式

### 2.3 browser-cdp 适配评估

| 能力项 | 现状 | 适配难度 | 建议 |
|-------|------|---------|------|
| 连接已登录浏览器 | ✅ 支持 | 低 | 可直接复用用户登录态 |
| 反检测模式 | ✅ stealth.py | 中 | 需配合行为模拟 |
| 动态签名绕过 | ❌ 不支持 | 高 | 需逆向 sign 算法或依赖登录态 |
| 行为模拟 | ✅ 基础支持 | 中 | 需增强人类化行为 |
| 验证码处理 | ✅ captcha_handler.py | 中 | 滑块验证码已支持 |
| 代理池 | ✅ proxy_pool.py | 低 | 可直接使用 |

**适配优先级**：⭐⭐⭐⭐（中高）
- 优势：browser-cdp 可连接用户已登录的真实浏览器，绕过签名验证
- 劣势：纯自动化场景需逆向 sign 算法
- 建议：优先利用登录态场景，验证码处理已有基础支持

## 三、大众点评（本地生活服务平台）

### 3.1 反爬机制概述

大众点评反爬机制属于**高难度**：

| 机制类型 | 具体实现 | 难度 |
|---------|---------|------|
| _token 参数 | 核心反爬机制，综合判断风险 | ⭐⭐⭐⭐⭐ |
| 动态字体加密 | 评论数据采用字体加密 | ⭐⭐⭐⭐ |
| Cookie 管理 | 动态 Cookie，需维护登录态 | ⭐⭐⭐ |
| 行为检测 | 请求频率、行为模式检测 | ⭐⭐⭐⭐ |
| IP 限制 | 严格的 IP 频率限制 | ⭐⭐⭐ |
| 验证码 | 滑块/点选验证码 | ⭐⭐⭐ |

### 3.2 技术特征分析

**_token 参数**：
- 核心反爬机制，对请求风险进行判别
- 综合判断 document、window、screen、element 对象
- 检测自动化测试框架特征
- 融合请求行为特征生成

**动态字体加密**：
- 评论数据采用自定义字体编码
- 非 OCR 方式可破解（字体映射）
- 需要动态获取字体文件并建立映射

**登录态要求**：
- 部分接口需要登录态
- 未登录访问受限更严格
- 登录态 Cookie 有效期较短

### 3.3 browser-cdp 适配评估

| 能力项 | 现状 | 适配难度 | 建议 |
|-------|------|---------|------|
| 连接已登录浏览器 | ✅ 支持 | 低 | 可直接复用用户登录态 |
| 反检测模式 | ✅ stealth.py | 中 | 需配合指纹伪装 |
| _token 绕过 | ❌ 不支持 | 高 | 需逆向算法或依赖登录态 |
| 字体加密破解 | ❌ 不支持 | 高 | 需开发字体映射模块 |
| 行为模拟 | ✅ 基础支持 | 中 | 需增强人类化行为 |
| 验证码处理 | ✅ captcha_handler.py | 中 | 滑块验证码已支持 |
| 代理池 | ✅ proxy_pool.py | 低 | 可直接使用 |

**适配优先级**：⭐⭐⭐（中）
- 优势：browser-cdp 可连接用户已登录的真实浏览器
- 劣势：_token 和字体加密逆向成本高
- 建议：优先利用登录态场景，字体加密需额外开发

## 四、综合对比与适配优先级

### 4.1 三平台对比

| 维度 | 小红书 | 携程 | 大众点评 |
|-----|-------|------|---------|
| 反爬难度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| 签名机制 | x-s/x-s-common | sign | _token |
| 特殊加密 | 设备指纹 | 无 | 字体加密 |
| 登录态依赖 | 中 | 高 | 高 |
| browser-cdp 适配难度 | 中 | 中低 | 高 |
| 建议优先级 | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |

### 4.2 适配优先级建议

**第一优先级：携程**
- 反爬难度相对较低
- browser-cdp 可连接已登录浏览器，绕过签名验证
- 验证码处理已有基础支持
- 旅游数据需求旺盛

**第二优先级：小红书**
- 反爬难度高，但登录态场景可行
- 设备指纹需额外处理
- 内容电商数据价值高

**第三优先级：大众点评**
- 反爬难度最高
- _token 和字体加密逆向成本高
- 本地生活数据需求稳定

### 4.3 技术路线建议

1. **登录态优先**：browser-cdp 核心优势是连接用户已登录的真实浏览器，应优先利用此能力
2. **签名逆向**：对于纯自动化场景，需投入资源逆向各平台签名算法
3. **行为模拟**：增强人类化行为模拟，降低被检测风险
4. **字体加密**：针对大众点评，需开发字体映射模块

---

## 五、结论

browser-cdp skill 在连接已登录浏览器方面具有独特优势，可有效绕过部分反爬机制。建议优先适配携程（中高优先级），其次小红书和大众点评（中等优先级）。对于高难度反爬场景，需结合签名逆向和行为模拟技术，或依赖用户登录态。
