## 2. 评估周期配置

### 2.1 网站优先级与评估频率

| 优先级 | 定义 | 全量评估 | 快速检查 | 最小验证次数 |
|--------|------|----------|----------|-------------|
| P0 | 核心网站（百度、Google） | 每周 | 每日 | 3次 |
| P1 | 重要网站（Bing、知乎） | 每两周 | 每周 | 2次 |
| P2 | 扩展网站（新闻、电商） | 每月 | 每两周 | 2次 |
| P3 | 探索网站（新领域） | 每季度 | 每月 | 1次 |

### 2.2 评估类型说明

#### 全量评估 (Full Evaluation)
- **内容**: 执行全部测试用例（45个）
- **输出**: 完整评估报告 + 一致性验证
- **时长**: 约5-10分钟
- **触发**: 周期到期 或 手动触发

#### 快速检查 (Quick Check)
- **内容**: 执行核心用例子集（15个）
- **输出**: 关键指标摘要
- **时长**: 约2-3分钟
- **触发**: 周期到期 或 异常告警

#### 专项评估 (Special Evaluation)
- **内容**: 针对特定问题深度评估
- **输出**: 问题分析报告 + 改进建议
- **时长**: 按需
- **触发**: 问题识别 或 手动触发

## 3. 评估维度迭代机制

### 3.1 维度审查周期

| 维度 | 审查周期 | 触发条件 | 审查内容 |
|------|----------|----------|----------|
| 页面访问成功率 | 每月 | 通过率下降 > 10% | 网络策略、超时配置 |
| 元素定位成功率 | 双周 | CV > 15% | 选择器策略、等待机制 |
| 数据提取准确率 | 每月 | 准确率下降 > 5% | 提取逻辑、字段映射 |
| 反爬绕过率 | 每周 | CV > 30% | UA策略、指纹伪装 |
| 稳定性 | 每周 | 一致性下降 > 10% | 错误恢复、连接管理 |

### 3.2 维度迭代流程

```
1. 监控维度指标
   ↓
2. 检测触发条件
   ↓
3. 生成审查任务
   ↓
4. 分析根本原因
   ↓
5. 制定改进方案
   ↓
6. 实施优化
   ↓
7. 验证改进效果
   ↓
8. 更新评估标准
```

### 3.3 维度调整规则

#### 新增维度
- **条件**: 现有维度无法覆盖新场景
- **流程**: 提案 → 评审 → 试点 → 全量
- **示例**: 新增"AI内容识别率"维度

#### 废弃维度
- **条件**: 维度长期无变化或失去意义
- **流程**: 标记废弃 → 过渡期 → 移除
- **示例**: 废弃"静态页面检测"（已无意义）

#### 权重调整
- **条件**: 业务重点变化或指标相关性变化
- **流程**: 数据分析 → 权重计算 → 评审 → 更新
- **示例**: 提升"反爬绕过率"权重从15%到20%

## 4. 测试用例迭代机制

### 4.1 用例分类与处理

| 用例类型 | 判定条件 | 处理策略 | 周期 |
|----------|----------|----------|------|
| 总是通过 | 通过率 = 100% (≥3次) | 标记为"过于简单"，考虑移除或增加难度 | 季度 |
| 总是失败 | 通过率 = 0% (≥3次) | 标记为"环境问题"，检查测试配置 | 月度 |
| 高波动 | CV > 20% | 标记为"不稳定"，分析原因并优化 | 双周 |
| 新场景 | 覆盖新网站模式 | 新增用例，纳入评估体系 | 月度 |

### 4.2 用例迭代流程

```
┌─────────────────┐
│   用例发现      │ ← 评估执行 / 问题反馈 / 新场景识别
└────────┬────────┘
         ↓
┌─────────────────┐
│   用例分析      │ ← 通过率统计 / 波动分析 / 场景覆盖检查
└────────┬────────┘
         ↓
┌─────────────────┐
│   用例决策      │ ← 新增 / 优化 / 废弃 / 保持
└────────┬────────┘
         ↓
┌─────────────────┐
│   用例实施      │ ← 编写用例 / 更新规格 / 删除用例
└────────┬────────┘
         ↓
┌─────────────────┐
│   用例验证      │ ← 回归测试 / 一致性验证
└────────┬────────┘
         ↓
┌─────────────────┐
│   用例归档      │ ← 更新用例库 / 记录变更历史
└─────────────────┘
```

### 4.3 用例库管理

#### 用例库结构
```
references/test-cases/
├── core/              # 核心用例（所有网站必须通过）
│   ├── page_access/   # 页面访问
│   ├── element_locate/# 元素定位
│   ├── data_extract/  # 数据提取
│   └── interaction/   # 交互功能
├── advanced/          # 高级用例（P0/P1网站）
│   ├── anti_detection/# 反检测
│   └── stability/     # 稳定性
└── optional/          # 可选用例（P2/P3网站）
    └── special/       # 特殊场景
```

#### 用例版本控制
- 每个用例包含版本信息
- 变更记录到 `CHANGELOG.md`
- 废弃用例保留3个月过渡期

## 5. 持续改进工具

### 5.1 评估调度器

**脚本**: `scripts/evaluation_scheduler.py`

**功能**:
- 自动检查评估周期
- 生成待评估网站队列
- 识别需要审查的维度
- 生成用例迭代建议

**使用示例**:
```bash
# 查看待评估状态
python scripts/evaluation_scheduler.py --action status

# 生成改进报告
python scripts/evaluation_scheduler.py --action report

# 运行指定网站评估
python scripts/evaluation_scheduler.py --action run --website baidu --priority P0

# 查看审查队列
python scripts/evaluation_scheduler.py --action review
```

### 5.2 一致性验证器

**脚本**: `scripts/validate_evaluation.py`

**功能**:
- 加载多份评估报告
- 计算一致性指标（CV）
- 生成验证报告
- 识别异常波动

**使用示例**:
```bash
# 验证百度评估一致性
python scripts/validate_evaluation.py -w baidu -c 3

# 验证所有网站
for site in baidu bing zhihu; do
    python scripts/validate_evaluation.py -w $site
done
```

### 5.3 维度分析器

**脚本**: `scripts/dimension_analyzer.py`（待实现）

**功能**:
- 分析各维度得分趋势
- 识别维度间相关性
- 建议维度权重调整

## 6. 改进效果验证

### 6.1 验证指标

| 指标 | 目标 | 计算方法 |
|------|------|----------|
| 评分提升率 | ≥ 5%/季度 | (当前评分 - 基线评分) / 基线评分 |
| 一致性改善 | CV下降 ≥ 20% | 前后CV对比 |
| 用例有效率 | ≥ 90% | (通过用例数 / 总用例数) |
| 问题闭环率 | ≥ 80% | (已解决问题 / 发现问题) |

### 6.2 验证周期

| 验证类型 | 周期 | 内容 |
|----------|------|------|
| 即时验证 | 改进后 | 单次评估对比 |
| 短期验证 | 1周 | 3次评估趋势 |
| 中期验证 | 1月 | 4次评估趋势 + 一致性分析 |
| 长期验证 | 1季度 | 综合改进效果评估 |

### 6.3 验证报告模板

```
## 改进效果验证报告

### 改进项
- 改进内容: [描述]
- 改进时间: [日期]
- 负责人员: [姓名]

### 验证结果
| 指标 | 改进前 | 改进后 | 变化 |
|------|--------|--------|------|
| 综合评分 | X | Y | +Z% |
| 通过率 | X% | Y% | +Z% |
| 维度CV | X% | Y% | Z% |

### 结论
- ✅ 改进有效 / ❌ 改进无效 / ⚠️ 部分有效

### 后续行动
- [ ] 行动1
- [ ] 行动2
```
