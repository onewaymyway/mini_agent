# 阶段0-1：小说→剧本转换 + 剧本校验

**依赖**：无外部 API，纯 Agent 推理 + 文件读写。
**校验脚本**：`scripts/check_script.py`。
**产物**：`<output_dir>/script.md`（剧本）+ `<output_dir>/script_review.yaml`
（阶段1 Agent 语义核查结论）。

这是本 skill 新增的第一个阶段，在阶段2（角色/地点抽取）之前执行。目的
是把小说原文一次性转换成结构清晰的"自然语言剧本"，**从此之后阶段2
（角色/地点抽取）、阶段4（大场景切分）、阶段5（详细规划）读的都是
这份剧本，不再直接碰小说原文**——原文里"叙事视角混杂对话、
引号嵌套动作描写"的非结构化特性，是过去大场景/小场景切分反复出问题的
根本原因（详见 `next_doc/novel_video_studio_fix_plan_v5.md`），剧本化
就是为了在下游所有需要"区分旁白/对话/说话人"的环节之前，把这件事一次
性做对。

## Step 1：通读全文，转换为剧本

按"场"为单位（剧情/时间/地点的自然分段，通常一场对应原文里一到几个
自然段）逐段转换，每一场固定这个结构：

```
### 场次 1｜林远家客厅/门口·夜（内景）
旁白：2038年冬天，雪下得很大，林远四年没见过这么大的雪了。他裹着毛毯坐在沙发上，手里攥着一张泛黄的照片。
旁白：门铃响了。林远起身，透过猫眼看到一个穿白色大衣的女人站在雪地里，面容模糊。他打开门。
苏晴：林远，你还记得我吗？
旁白：那个女人抬起头，雪片落在她的睫毛上，她的眼睛是苏晴的眼睛。林远的血液在这一刻凝固了。
林远：晴？
苏晴：是我。
```

规则：
- **场次标题**固定格式 `### 场次 N｜地点·时间（内景/外景）`，地点/时间
  从原文交代的信息里提取，交代不清楚时用"未知"占位而不是编造；
- **旁白行**以 `旁白：` 开头，装叙事者视角的内容——环境描写、人物动作/
  神态、心理活动、间接转述（"她告诉他……"这类没有直接引语的转述也算
  旁白，不能标成对话）。旁白**允许适度转述改写**，让句子更适合口播
  （比如把书面语的长句拆短、去掉纯文学修辞），但**不能改变剧情事实、
  不能新增原文没有的情节或细节**；
- **对话行**固定格式 `角色名：台词`，一行一句（同一角色连续说了好几句
  中间没有被别人打断或被叙事插入语打断的，也可以合并成一行，但如果
  中间夹了动作描写，要拆成"对话行→旁白行→对话行"）。角色名要用后续
  阶段2会用到的正式称呼（通常是原文里的名字），同一角色全篇统一用同
  一个名字，不要一会儿"林远"一会儿"他";
- **对话台词要求贴近原文原意**：不要求逐字保留原文标点/语气词，但
  实质内容、说话人身份、语气强弱不能被曲解或代写；原文里夹在对话中间
  的"XX说""XX一边擦桌子一边说"这类描述说话动作的部分，转换时直接
  拆出去变成独立的旁白行，不要保留在对话行里；
- 场次划分**先不用考虑后续时长约束**（那是阶段4的工作），本阶段只
  按剧情/时间/地点的自然转折点分场，能大能小，转换完之后可能有几十
  个场次，阶段4会再做归并/细分。

## Step 2：落盘为 `script.md`

```markdown
# 《永生协议》剧本

### 场次 1｜林远家客厅/门口·夜（内景）
旁白：...
苏晴：...
...

### 场次 2｜...
...
```

## Step 3：剧本校验（阶段1）

对每个场次，Agent 逐条核对以下四项，写入结构化的核查报告
`script_review.yaml`：

```yaml
checked_at: "2026-09-15T10:00:00"
source_text_file: "test_cases/inputs/novel_video_sample_novel_ai.txt"
script_file: "script.md"
entries:
  - scene_no: 1
    status: pass    # pass | fail
    checks:
      plot_coverage: pass       # 该场次对应的原文关键情节点是否都体现了，无遗漏/无新增
      dialogue_coverage: pass   # 原文该场次内的直接引语是否都能在剧本对话行找到对应
      speaker_attribution: pass # 每句台词的说话人是否符合原文语境
      no_fabrication: pass      # 是否存在原文没有依据的情节/台词
    notes: "对照原文第1-3段，情节和对话均对应，无遗漏无新增"
```

四项核查维度：
1. **plot_coverage（剧情覆盖）**：原文本场次对应范围内的关键情节点
   （事件、转折）是否都在剧本里体现，没有遗漏或新增；
2. **dialogue_coverage（对话覆盖）**：原文里用引号直接引用的话语，是否
   都能在剧本对应场次的对话行里找到内容一致的对应（允许语气词/标点
   差异，不允许实质内容被改变或遗漏）；
3. **speaker_attribution（说话人归属）**：每一句对话行标注的角色名是否
   符合原文语境判断；
4. **no_fabrication（无臆造）**：剧本里不能出现原文没有依据的情节、
   对话或细节。

任意一项不是 `pass`，该场次 `status` 记 `fail`，`notes` 写清楚具体问题，
**必须回 Step 1 修正对应场次的剧本内容后重新核查**，不能带着 `fail`
条目进入下一步。

## Step 4：跑校验脚本

```bash
python .claude/skills/novel-video-studio/scripts/check_script.py \
  <output_dir> --novel-text-file <小说原文路径>
```

`check_script.py` **只做机械把关，不做语义判断**（语义判断已经在 Step 3
由 Agent 完成，脚本没有能力替代）：
- 检查 `script_review.yaml` 里的 `entries` 是否覆盖了 `script.md` 里
  全部场次编号（一个不漏）；
- 检查所有 `entries` 的 `status` 是否全部为 `pass`；
- 检查 `script.md` 的内容 hash 和 `script_review.yaml` 里记录的
  `script_content_hash` 是否一致（防止核查通过之后剧本又被改动但报告
  没更新的"过期"情况——`script_review.yaml` 顶层需要多写一个字段
  `script_content_hash`，对整份 `script.md` 内容算 `sha1` 前12位，加
  `sha1:` 前缀）；
- 传 `--novel-text-file` 时，额外做一次粗粒度字数覆盖率检查（剧本总
  字数与原文总字数的比例是否在合理范围，默认 ±30%——剧本允许旁白转述
  改写，比例容忍度比阶段4的原文覆盖率检查更宽松）。

**errors 非空 → 不允许进入阶段2**，回 Step 1-3 修正。

## 下一步

`script.md` + 校验通过的 `script_review.yaml` 就绪后，进入阶段2
（角色/地点抽取），阶段2的输入源从小说原文改为 `script.md`。

## 已知限制

- 剧情覆盖/对话覆盖/说话人归属/无臆造这四项核查完全依赖 Agent 的语义
  判断，脚本只能做机械的"报告覆盖完整性+全pass+未过期"把关，不能替代
  Agent 去逐字核对——如果 Agent 核查时敷衍了事（比如所有场次都简单标
  `pass` 而不真的逐条对照原文），脚本无法识别这种情况；
- 覆盖率检查是粗粒度字数比例检查，容忍度比阶段4更宽松（剧本允许旁白
  转述改写导致字数和原文有一定偏差），不能替代人工抽查；
- 旁白"适度转述改写"和"新增情节"之间的边界依赖 Agent 判断，没有绝对
  客观的量化标准，建议转换时保守一些——拿不准算不算改变了剧情事实的
  地方，优先贴近原文表述。
