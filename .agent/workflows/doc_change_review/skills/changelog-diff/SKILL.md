# changelog-diff Skill

将两份文档之间的差异，整理成结构化、可审查的变更清单，而不是原始的逐行 diff。

## 输出格式

```
## 变更清单

### 新增
- [章节/段落] 简要描述新增内容

### 删除
- [章节/段落] 简要描述被删除的内容

### 修改
- [章节/段落] 修改前 → 修改后（一句话概括核心变化，不是整段复制）

### 未变化但需要关注
- 因为上下文变化而可能需要联动更新、但本身没被改动的部分（如有）
```

## 使用步骤

1. 读取旧版本路径（`{old_path}`）和新版本路径（`{new_path}`）对应的文档内容。
   如果调用方已经在 prompt 里给出了前一步提取的摘要，优先复用摘要，避免
   重复读取整份原文。
2. 按段落/章节粒度比较，而不是逐字符 diff——目标是让审查者一眼看出
   "变了什么、为什么重要"，不是完整还原 diff 算法的输出。
3. 修改类条目必须包含"修改前 → 修改后"的一句话对比，不要只写"某处有改动"。
4. 如果两份文档差异很大以至于无法逐条罗列，先给出整体结论（如"结构性重写，
   建议全文重新审阅"），再列出仍能识别出的关键变更点。

## 注意事项

- 不判断变更的好坏、不给审查意见——那是下一步 `reviewer` agent 的职责，
  这个 skill 只负责把差异整理清楚。
- 找不到指定路径的文件时，明确说明"文件不存在"，不要编造内容。
