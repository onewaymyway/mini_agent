## 它解决什么

P5a–P5d 让因果边/树分支声明能入队、到期提醒、被 LLM 交代，但界面只有一份文字清单。看不出：哪些边**多次被
AI 自报兑现**、哪些**多次被抵消**、哪些**还没有任何证据**；也看不出下一个到期的是谁。本阶段在详情页「🔗 因果引擎」
面板顶部加一个"查看方式"单选：

| 视图 | 内容 |
|---|---|
| 📋 兑现统计（默认） | 原有面板，不变 |
| 🕸️ 着色关系图 | Graphviz 图：节点=因果线/技术节点（树分支起点画椭圆 `线/分支`），边按状态着色，边标签 `状态 · 兑现率（兑现/有结论）`；图下方有各状态计数和逐条清单 |
| ⏰ 到期时间线 | ① 未结案项：已到期的在前（到期后被忽略次数多的更靠前），其余按"还差多少"升序；② 最近 20 条处置记录（新的在前，含自动结案） |

## 边状态——先读懂它**是什么、不是什么**

状态完全由**兑现统计**推出，而兑现统计是 **LLM 自报**的（引擎无法验证 `realized` 是否真写进了状态，见
`causal_engine_guide.md`）。所以"已观察/已证伪"= **AI 自己多次这么说**，不是世界里被验证/被证伪。

| 状态 | 颜色/线型 | 规则（默认阈值） |
|---|---|---|
| 假设 | 灰 虚线 | 没有任何有结论的处置（含从未触发、只入队未到期、只有推迟/自动结案） |
| 已观察 | 绿 粗实线 | `realized ≥ 1` 且兑现率 ≥ 50% |
| 已证伪 | 红 实线 | `realized == 0` 且 `countered ≥ 2` |
| 未定 | 橙 实线 | 有结论，但不满足上面两条（如 1 兑现 + 2 抵消、仅 1 次抵消、仅部分兑现） |
| 已停用 | 浅灰 点线 | 边声明里 `enabled: false`（优先于其它状态） |

**相对计划原文（三态）的细化**：新增"未定"。只有一条自报抵消就判"已证伪"证据太薄；混合结果硬塞进三态任何一个都会
误导；**只有部分兑现（dampened）不算证伪**——效果发生了，只是比声明的弱。

阈值是通用占位值，不是领域事实。可用 `settings.causal_view_params` 覆盖（非法值忽略）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `observed_min_realized` | 1 | 判"已观察"至少要几次自报兑现（正整数） |
| `observed_min_rate` | 0.5 | 判"已观察"的最低兑现率（0–1） |
| `refuted_min_countered` | 2 | 判"已证伪"至少要几次自报抵消（正整数） |
| `recent_limit` | 20 | 时间线里"最近处置记录"的条数（正整数） |

## 哪些边会出现在图里

- `declared_causal_graph` 里的边（含停用的），按声明顺序；
- P5d 的树边（`tree:线/分支->目标`）：当前声明的，**以及历史里出现过兑现记录但声明已被删掉的**
  （仍画出来，免得兑现记录凭空消失）。

不包含 `causal_links` 的事后自述聚合——那是「🔗 跨线影响关系」区块（`causal_graph.py`），两者并存、口径不同
（那边是"AI 说哪条线影响了哪条线"，这边是"声明的因果结构兑现得怎样"）。

## 到期时间线的"还差多少"

- 边/树声明了 `delay_days` 且区间内每步都有 `elapsed_days`：显示"还差约 N 天"（天精度）；
- 否则退化为按步计数："还差 N 步（按步计，精度较低）"（与 `causal_engine._is_due` 同口径，`delay_steps` 优先）；
- 排序里**天精度排在步精度前面**——"2 步"和"20 天"量纲不同，不直接比大小；
- 已到期的写"已到期，下一步会提醒"，并显示推迟次数、到期后未交代的步数、源头再次有进展的次数。

## 已知边界（如实）

- 状态与兑现率都是 **LLM 自报统计**的函数；样本很小时（默认 1–2 次）波动大，所以边标签始终带"（兑现/有结论）"次数。
- `elapsed_days` 是 LLM 的估计值，"还差约 N 天"只用于量级判断。
- 图是**示意图**，用 Graphviz 默认布局；边多（几十条以上）时会挤，可先看「逐条清单」。图是否好读没有自动化测试能替代，
  需要用真实数据人工看一眼。
- `app.py` 的新增渲染只做了：纯函数单测 + 用记录型 `st` 桩调用渲染函数 + `streamlit.testing.AppTest` 对面板三个视图的冒烟；
  **没有浏览器级验证**（看不到真实配色与布局），设置页保存流程同样没实跑。
- 没有在真实 LLM 下验证过——真实世界里 AI 的自报分布（是否几乎全部 `realized`）未知，若如此，"已观察"会很泛滥。
- 静态 HTML 导出已在 P10 接入着色关系图与到期时间线（见 `html_export_mechanisms_guide.md`）；本阶段交付时只做了看板界面，导出里原有的「跨线影响」图仍并存、口径不同。
