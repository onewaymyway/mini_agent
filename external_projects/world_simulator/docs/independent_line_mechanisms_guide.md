# 独立推进路径上的新机制（第二十二轮 P8）

> 适用对象：开了 `settings.independent_line_advance`（界面里的"独立推进因果线"入口，调用 `engine.advance_lines()`）的实例。
> **P8 之前**，这条路径完全绕过第二十二轮的全部新机制；**P8 起**，技术模型、外生事件采样、因果引擎（含树影响）、树接地、一致性守卫
> 在这条路径上也按**与 `advance()` 相同的顺序、相同的开关**运行。这些机制本身的规则没有改，见各自的指南。

## 先说结论：什么时候和你有关

- 你**没有**开 `tech_model_enabled` / `event_sampling_enabled` / `causal_engine_enabled` / `tree_grounding_enabled`：
  提示词里只多一个空的占位符，线的调用次数、`vars` 和叙事与 P8 之前一致。**唯一的默认变化**：一致性守卫（`consistency_guard_enabled`，
  默认开启，只记录、不阻断、不改数值）现在也会在这条路径上给每步写 `consistency_warnings`。不想要就把它设为 `false`。
- 你开了其中任一项：每条到点的线的提示词会多出对应的机制说明，并可以多输出几个**可选**字段（见下表）。

## 和主路径的根本差别，以及由此做的四个决定

主路径一步只有**一次** LLM 调用，LLM 一次性看到全部机制提示、一次性输出全部字段。独立推进路径一步对**每条到点的线**各调一次，
而技术状态、待兑现因果、外生事件又都是**全局**的。所以需要回答四个问题：

| 问题 | 决定 | 理由 |
|---|---|---|
| 这一步在世界里过了多久（`elapsed_days`）？ | 每条到点的线申报**自己这一次推进**的跨度，取**最大值**作为全局步长 | 没有"全局那一次调用"可以问；到点线里最慢的那条决定世界走了多远。**这是 LLM 的估计值** |
| 外生事件抽样几次、投给谁？ | 每步**只抽一次**（调用任何线之前，种子与主路径同一套）；`affects` 为空 → 投给所有到点线；否则投给 `affects` 与**线 id 或该线 `owned_vars`** 有交集的到点线 | 事件是全局的，不该因为有几条线就被抽几遍 |
| 多条线都改技术怎么办？ | 提议按线的声明顺序拼接，**同一项技术只采纳先到的那条**，其余记 `T10`（info） | 技术状态是全局的，不能让两条线各自写一份 |
| 目标线本步没到点的待兑现因果？ | **挂起**：不参与处置，不记"到期未交代"，也不会因此被自动结案 | 否则慢节奏线的待兑现项会在它轮到之前就被判"没人交代"而结案 |

## 线的新增输出字段（全部可选，只在对应机制开启时才会被要求）

| 字段 | 触发条件 | 含义 |
|---|---|---|
| `elapsed_days` | 技术模型 / 事件采样 / 因果引擎有按天延迟的边 / 关系有按天延迟 任一开启 | 这条线这一次推进跨越的天数。合法正数才算；非法值（负数/0/非数字/布尔/NaN）忽略 |
| `tech_updates` | 技术模型开启 | 与这条线直接相关的技术变化，协议同主路径 |
| `effect_dispositions` | 因果引擎开启且有到期待兑现项投给了这条线 | 对到期项的处置，协议同主路径 |

每条线申报的有效跨度会记进该步 `line_updates[<线 id>]["elapsed_days"]`；全局步长在 `SimState.elapsed_days`。
所有线都没给有效值时，`elapsed_days` 为空，技术模型按 `fallback_days_per_step` 退化（审计里 `elapsed_source = "fallback"`），事件概率与因果延迟随之降为按步精度——与主路径一致。

## 提示词怎么分发

- **事件**：每条线只看到投给自己的事件；没有投给它的，看到"没有与这条线相关的已抽中外部事件，写平静推进即可"。
- **技术**：每条到点的线都看到完整的全局技术状态，并被告知"只提议与这条线直接相关的变化"。
- **待兑现因果**：目标线是可独立推进的线 → 只有目标线看到并负责交代；目标线不是可独立推进的线（比如没声明 `owned_vars`）→ 所有到点线都能交代。
- **时间跨度**：一句统一的话，要"这条线这一次推进"的跨度，不再重复主路径那句"这一步跨越天数"。

## 审计与可见性（不静默）

- 每个已抽中的事件带 `delivered_to`（投给了哪些线）。**空列表**表示事件已发生、已计入冷却，但本步没有任何到点线能写它
  （`affects` 指向没到点的线，或指向没有被任何线拥有的字段）。
- 多线同技术提议的冲突记在 `tech_violations`（`T10`，`detail.lines` 里是被采纳的线和被忽略的线）。
- 其余违规码（T1–T9、E*、G*）与主路径含义相同。

## 步骤顺序（与 `advance()` 一致）

技术种子锚定 → 事件抽样（调用线之前）→ 逐线调用 → 合并输出 → 事件落状态 → `elapsed_days` → 技术裁决（+可选修复调用）→
树接地 → 因果处置 → 因果入队 → 树影响入队 → 分支快照 → 一致性守卫。共用实现在 `world_simulator/engine/mechanisms.py`。

**没有任何线到点的空推进里世界没有前进**：不抽样、不裁决、不调用 LLM，与 P8 之前一致。

## 已知边界（如实记录）

- **这条路径上的线不产出 `tree_updates`、`causal_links`，也不处理 `triggered_relationships`。** 因此：树分支的状态迁移只来自
  树接地的结构化 `trigger_condition`（需 `tree_grounding_auto_transition`），不会有"LLM 自己宣布分支被印证/排除"；
  树接地的提示词（`tree_grounding_hint`/`tree_effects_hint`）没有喂给线；树影响（P5d）只有在分支被自动迁移为 active 时才会入队；
  关系的待兑现效果（`relationship_pending_effects`）在这条路径上不入队。
- **`elapsed_days` 是各线自报值的最大值**：线越多、越慢的线越主导；没有任何校验能证明这个估计合理。
- **挂起不等于兑现**：目标线长期不到点的待兑现项会一直留在队列里占用 `max_pending` 的名额。
- 事件 `affects` 只做字符串交集（线 id 或 `owned_vars` 名），不做语义匹配；投给没到点线的事件**不会补投**。
- 一致性守卫在这条路径上默认开启（见开头），可能在没有人看过的实例上突然出现 `consistency_warnings`。
- **没有在真实 LLM 下运行过**：线是否会遵守"只提议与自己相关的技术变化"、是否会给出合理的 `elapsed_days`、额外的提示词 token 成本都是未知数；
  没有浏览器级目视验证（P8 没有改界面）。
- 静态 HTML 导出已在 P10 接入这些机制（见 `html_export_mechanisms_guide.md`）。
