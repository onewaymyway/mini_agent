# life-sim-template

## 背景与边界

本 skill 是 `world_simulator` 的第一个"场景模板"（对应方案 2.4 节），
服务两类场景：

1. **决策推演分析**：用户给出当前处境 + 候选选择，模拟未来走向，
   辅助对比。
2. **持续性人生模拟**：从一个起点持续推进，形成一条可以回看的时间线。

被 `generate_scenario` workflow 挂载时，你只做"生成初始状态"这一件事；
被 `advance_step` workflow 挂载时，你只做"推进一步"这一件事——两者的
`result_file` 契约不同，见下方两节，不要混淆。

## 通用判断原则

1. **不要越界替用户做决定**：除非上游明确给出"代理决策"的画像/原则
   （`advance_step` prompt 里的 `decision_context` 非空），否则你只负责
   给出候选选项和对应后果，不擅自替用户选。
2. **变量要具体、可追踪**：`vars` 里的字段应该是"这个人生模拟里真实
   存在、会随时间变化"的量（年龄、存款、健康、职业阶段、人际关系状态
   等），不要塞入大段自由文本描述当变量值。
3. **叙事克制、有代入感，但不夸张**：`narrative` 是几句话的情节推进
   文本，不是小说章节，服务"看得懂发生了什么"，不是文学创作比赛。
4. **候选选项要有真实的取舍**：每个 `options` 条目应该代表一个方向
   明显不同的选择，不要给"实质等价"的假选项凑数量。

## 作为 `generate_scenario` 挂载时（result_file: scenario.json）

输入：`{intent}`（用户一句话意图）。

输出（合法 JSON，顶层字段）：

- `title`：字符串，这次模拟的简短标题。
- `summary`：字符串，初始状态一句话摘要。
- `vars`：对象，初始状态的结构化变量（字段自定，需具体可追踪，见上）。
  建议至少包含：`age`（年龄，整数或字符串区间）、`stage`（当前人生
  阶段/身份，字符串）、`resources`（资源状况，字符串或子对象）、
  `key_relationships`（关键人际关系，字符串数组）。
- `options`：数组，2-4 个初始候选方向，每项含 `id`（短英文/拼音
  标识）、`label`（几个字的选项名）、`description`（一两句话说明这个
  方向意味着什么）。若用户意图里已经明确给出了几个候选选择，直接
  对应展开成这几项；若没有，你需要合理生成。

## 作为 `advance_step` 挂载时（result_file: next_state.json）

输入：当前标题、当前状态摘要、当前 `vars`（JSON）、当前时间步、当前
状态的候选分支选项（JSON 数组，可能为空）、本次选择的选项（可能为空
对象 `{}`）、可选的 `decision_context`（"代理决策者画像"，非空时表示
这一步是自动挡场景，你需要自己从候选分支选项里选一个，见下方规则）。

**选择逻辑（按优先级）：**

1. 如果"本次选择的选项"非空：直接按这个选项推进，`chosen_option_id`/
   `chosen_reason` 字段可以省略（调用方已经知道选的是什么）。
2. 如果"本次选择的选项"为空对象，但 `decision_context` 非空（自动挡
   代选）：从"候选分支选项"里挑一个最符合 `decision_context` 给定
   原则/风险偏好的选项，在输出里加上 `chosen_option_id`（选中选项的
   id，必须是候选列表里真实存在的 id，不要编造）和 `chosen_reason`
   （一两句话，说明为什么这么选，要具体到"符合了画像里的哪条原则"，
   不要写"综合考虑后选择了这个方向"这种空话）。若候选分支选项为空
   数组（无可选项），按第 3 条处理，不需要这两个字段。
3. 如果"本次选择的选项"为空对象且 `decision_context` 也为空（普通
   手动挡，未指定选择）：依据当前状态给出最合理的默认走向，不要等待
   用户输入，也不需要 `chosen_option_id`/`chosen_reason`。

输出（合法 JSON，顶层字段）：

- `next_summary`：字符串，推进后新状态的一句话摘要。
- `narrative`：字符串，本步发生了什么的叙事文本（几句话，不要写成
  大段小说）。
- `next_vars`：对象，推进后的完整 `vars`（不是增量，是完整新值——
  引擎不做字段合并，直接整体替换）。数值型字段变化要符合常理的幅度
  （比如年龄通常 +1 对应"过了一年"，除非情节明确是"跳跃了 N 年"）。
- `options`：数组，供*下一步*选择的候选分支（结构同上），情节明显
  没有分支时可以给空数组（引擎会据此判定"直接给默认走向即可，不需要
  用户选择"）。
- `major_decision`：布尔值（可选，默认 false），当这一步的选择/走向
  明显是人生的重大转折点时设为 true——自动挡的 `review_mode:
  pause_on_major_decision` 用它判断是否需要暂停等用户确认，见
  `world_simulator/autopilot.py`；手动挡场景可以照常产出这个字段，
  引擎不会因为它是 true 而改变手动挡的任何行为。
