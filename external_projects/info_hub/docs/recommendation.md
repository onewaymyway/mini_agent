# 推荐信息流

推荐页把抓取结果整理成“少量精选 + 分区”，目标是尽快看完当天最值得看的内容。完整设计、各阶段的取舍与验证记录见 `../../../next_doc/info_hub_recommendation_feed_design.md`。本页是使用与参数的说明。

## 流水线

1. **候选池**：取时间窗内的条目（合并各源的快照）。过滤掉：不再显示的信息源、屏蔽词命中的条目、已 👍 / 👎 / 打开的条目（除非开启“显示已处理”）、换一批排除的条目。“稍后看”的条目单独进入稍后看队列。候选超过 `candidate_limit` 时只取最近出现的一部分。
2. **聚合去重**：标题的字符二元组 Jaccard 相似度超过 `cluster_threshold`（0.45）的条目合并为一个“事件”。宁可漏聚，不误并。URL 完全相同直接合并。
3. **多信号打分**：每个事件计算六个分量（0–1），再按权重相加：
   - `interest`：与兴趣画像的匹配度（分位数归一化；画像为空时整体乘以 `cold_start_factor`）
   - `source_affinity`：来源的历史正向反馈比率（带先验平滑）
   - `freshness`：距首次出现的时间，指数衰减，半衰期按信息源类型
   - `importance`：多源报道数、最高排名、排名上升
   - `persistence_penalty`：一直挂在榜上且从未新增的条目降权
   - `fatigue_penalty`：展示很多次却从未点击的条目降权（弱负向）
4. **重排**：精选采用贪心挑选，同一信息源最多 `diversity.source_cap` 条，同一主题重复时逐条扣分。探索从“没有命中关注主题、也不属于多源热点”的事件中选取。
5. **分区**：按顺序分配（精选 → 探索 → 多源热点 → 关注主题 → 其余），每个事件只归入一个分区。

## 分区

| 分区 | 内容 | 数量参数 |
|---|---|---|
| 今日精选 | 综合得分最高的事件，带理由 | `featured_size` |
| 探索 | 画像之外、但重要性与新鲜度较高的事件 | `explore_size` |
| 多源热点 | 被至少 `hot_min_sources` 个不同信息源报道的事件 | `hot_size` |
| 关注主题 | 按兴趣主题分组，每组需要至少 `topic_min_group` 个事件 | `topic_groups`、`topic_group_size` |
| 稍后看 | ⏰ 标记的条目，按加入时间倒序 | `later_size` |
| 其余 | 其他事件，默认折叠 | `others_limit` |

数量参数均可在看板“⚙ 显示数量设置”中调整，见 [配置](configuration.md#看板可调的展示数量)。

## 反馈如何影响推荐
- 👍 / 👎 / ⏰：记录在事件的每一条报道上，同一事件处理后不会以另一来源再次出现。
- 打开：计为正向，并隐藏该条目（通过看板打开时由服务端记录；通过“打开”链接直接跳转时服务端无法感知，因此不记录）。
- 来源反馈：影响 `source_affinity`；关键词学习影响 `interest`（画像中的关键词权重按 30 天半衰期衰减）。
- 🚫 不再显示：隐藏整个信息源，可在页面底部恢复。
- 屏蔽主题：把主题词加入手写屏蔽词，可在画像面板撤销。

## 快照与刷新
推荐数据在会话内保存为快照。以下操作会重建快照：首次进入页面、切换筛选条件、点击“🔄 刷新推荐”、点击“🔀 换一批”、保存显示数量。其余交互只改变卡片上的标记，列表不变。

## 可选增强（默认关闭）
- **学习权重**：用展示记录与反馈训练线性权重，只有样本不少于 `learning.min_samples`（200）、在留出集上比手工权重高出至少 `learning.min_gain`，并在页面开启后才生效。
- **LLM 增强**：页面开启后点击“运行”才调用模型，为前列卡片生成主题与摘要，并判断近似报道是否为同一事件（只写入缓存，聚合时只读缓存）。每日调用上限 `llm.daily_limit`。标题会发送给所配置的模型，开启前请确认。

## 评估
- **离线回放**：用历史展示与之后的 👍 / 打开 / 👎 作为标签，比较推荐顺序与时间倒序的前 10 条（正例率、👎 率、NDCG@10）。样本不足时只给数字并标注“仅供参考”。存在位置偏差。
- **推荐效果评估**（设置与管理）：曝光、打开、反馈的统计。

## 数据
- `data/feed/shown.jsonl`：每次展示的位置、分区与分量，用于疲劳与回放。
- `data/feed/prefs.json`：偏好。
- `data/feed/learned_weights.json`、`llm_cache.json`、`llm_usage.json`：学习权重、LLM 结论缓存与每日计数。
