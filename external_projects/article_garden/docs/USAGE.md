# article_garden 使用说明（截至 P6）

本文说明当前版本能做什么、怎么做。命令行与看板的每个操作都可互换。

## 1. 新建文章库
看板 →「➕ 新建文章库」，选择模板（人工智能模板已预置 10 个方向与术语别名）。
或命令行：`python entrypoints/create_domain.py ai 人工智能 ai`

## 2. 导入文章
看板 →「文章库」→「➕ 导入文章」：
1. 选择文件（`.md` / `.txt` / `.zip`，可多选），或填写本机路径（文件、目录或 zip，多个用 `;` 分隔）。
2. 点击 **预览导入**：每篇会标注 新增 / 重复 / 跳过 及原因。
3. 确认无误后点击 **确认导入**。

命令行：
```
python entrypoints/import_library.py ai D:/articles            # 仅预览
python entrypoints/import_library.py ai D:/articles --apply    # 确认导入
```

要点：
- **源文件不会被修改**。导入的是副本，保存在 `data/domains/<id>/library/imported/`。
- 内容相同（忽略空白差异）的文章只保留一份。
- 正文不足 200 字的跳过。
- 手动把 Markdown 放进 `library/imported/` 也可以，刷新页面即可识别（编号自动分配）。

## 3. 摘要
看板 →「文章库」→ **开始摘要**（增量：只处理新增或内容已变更、或上次失败的文章）。
任务在后台运行，进度与错误见「▶ 运行日志」。

单篇：在「查看文章」中选中一篇，点击 **重新摘要这篇**。

命令行：
```
python entrypoints/digest.py ai                       # 增量
python entrypoints/digest.py ai --article-id a-0003   # 单篇
python entrypoints/digest.py ai --force               # 全部重做
```

摘要使用 mini_agent 的文本模型，请先在 mini_agent 中配置好模型。若模型未就绪，任务会在运行日志中给出原因。

**怎样读摘要结果**：
- 「论点、类型、层级、概念」是模型给出的归纳。
- 「断言」表中，**原文摘录**一列是程序校验过的：它一定逐字出现在原文中。
- 显示 **失败** 的文章：展开「最后一次模型输出」可以看到未通过的原因。可以先手动修改文章或稍后重新摘要。

## 4. 章程草稿
摘要完成后，在「章程草稿（由摘要反推）」中点击 **由已摘要文章生成章程草稿**。
草稿包括范围、读者、文风、术语与别名等。**草稿不会自动生效**：请检查后点击 **采用为正式章程**（旧章程会备份为 `charter.yaml.bak`）。

也可以在「⚙ 设置 → 章程」中直接手动编辑章程。

## 5. 概念与关系（P2）
看板 →「🕸 概念图」→ **构建概念与关系**（后台运行）。完成后可以：
- 在列表中选择概念，查看**定义**（每条定义都依据若干断言）。
- 「断言与出处」页签：该概念相关的断言及其原文摘录。
- 「关系」页签：与其它概念的关系；每条都带原文依据摘录，没有依据的关系不会出现。
- 「冲突」页签：同一概念在不同文章中互相矛盾的说法，双方出处并列。冲突只做展示，需要你自己判断。

命令行：`python entrypoints/build_wiki.py ai`（`--force` 重写全部定义）。

注意：
- 同一概念的不同写法（如「RAG」与「检索增强生成」）会合并。章程「术语」中的别名优先作为规范词，请在章程中维护。
- 「无依据」的概念表示它在文章中只被提到，没有可追溯的断言，不会生成定义。
- 想手动改某个概念的定义：直接编辑 `wiki/concepts/<编号>.md`，并把 front matter 中的 `human_edited` 改为 `true`，之后自动构建不会覆盖它。

## 6. 知识树与覆盖度（P3）
看板 →「🌳 知识树」：
1. 点击 **生成挂载提案**（后台）。只有尚未挂载的概念会被送去挂载，已挂载的不会动。没有变化时不会生成提案，也不调用模型。
2. 在「挂载提案」区查看操作清单，确认无误后点击 **应用提案**。树版本若在此期间变化，提案会被拒绝，请重新生成。不想要就点 **放弃提案**。
3. 在树视图中查看各节点的覆盖度（🔴 空洞 / 🟡 偏浅 / 🟢 充足）。展开方向查看主题与概念。
4. 在「节点操作」中可以改名、锁定（锁定的主题不再接收自动挂载）、移动主题、合并节点、在方向下新建主题。这些操作立即生效，旧树会备份为 `wiki/tree.prev.yaml`。

命令行：`python entrypoints/build_tree.py ai`（生成提案）、`--apply`（确认应用）、`--discard`（放弃）、`--coverage`（只重算覆盖度）。

覆盖度的阈值按库规模分档：文章少于 50 篇时，一个节点需要至少 2 篇文章且平均 1500 字以上才算“充足”。

## 7. 选题（P4）
看板 →「💡 选题」：
1. 点击 **检测缺口并生成选题**（后台）。缺口检测只看规则，不调用模型。
2. 先看「缺口」展开栏，了解库里哪里缺什么。
3. 在「待审」列中，每张卡片都写明了**理由**（为什么值得写）、类型与层级、必须覆盖的概念，以及**分数明细**（可展开）。
   - 可以先修改标题，然后点 **放行** 进入「已放行」列。
   - 或选择原因后点 **拒绝**。原因必填，并且同一个缺口之后不会再次被提议。
4. 「已拒绝或放弃」列记录了历史决定。

注意：
- 「未判重（需模型）」的选题，表示它与已有文章的概念有一定重叠，但没有模型做判断。放行前请自己确认是否重复。
- 每轮最多新增的选题数由设置 `budget.max_topics_per_cycle` 控制（默认 5）。
- 自动放行只在挡位 G2/G3 且打开「自动放行」时生效；默认 G0，全部需要人工放行。

命令行：`python entrypoints/plan_topics.py ai`（检测）、`--approve t-0001`、`--reject t-0001 --reason "重复已有内容"`。

## 8. 资料收集（P5）
看板 →「🔎 调研」：
1. 在列表中选择已放行的选题，点击 **开始调研（后台）**。系统会生成查询、搜索、抓取网页，并生成来源卡与证据包。调研需要网络。
2. 查看「证据包」：要点覆盖情况、充分与否的原因、库内已有的可互链文章。
3. 查看「来源卡」：每张卡有可信度（A–D）、网址、摘录。不满意的可以删除。
4. 资料不够时，可以在「手动补充资料」中粘贴正文（指定可信度），或粘贴网址由系统后台抓取。
5. 证据充分的选题会变为「已调研」；不充分的会变为「已放弃」，原因写在证据包里。

注意：
- 网站的 robots.txt 不允许抓取时，系统会跳过该页面，并在日志中记录。
- 搜索或网页在一段时间内会被缓存（30 天），重复调研不会重复请求。
- 搜索不可用时，系统仍会使用你手动提供的资料。

命令行：`python entrypoints/research.py ai t-0001`、`--add-url <网址>`、`--remove-source src-0002`。

## 9. 成文与审阅（P6）
看板 →「✍ 审阅」：
1. 选择「已调研」（或「成文失败」）的选题，点击 **开始成文（后台）**。系统依次生成选题简报、大纲、逐节初稿，做代码校验并修复，再由独立评审检查一遍，最后入库为草稿。需要模型，进度见「▶ 运行日志」。
2. 成功后选题变为「待审阅」，页面左侧是成稿，右侧是证据与来源。成文中的每段都带有 `[^src-NNNN]` 脚注，可对照右侧来源。
3. 审阅：
   - **通过审阅**：选题变为「已审阅」；
   - **退回重写并附意见**：把你的意见写进输入框后点击，系统会按意见重写（复用同一篇文章编号，旧版保存在 `drafts/<选题>/revisions/`）；
   - **确认发布**：只在「已审阅」时出现，需要明确点击，发布后文章状态为「已发布」；
   - **放弃此选题**：必须填写原因，文章归档。
4. 「成文失败」时页面会显示未通过的原因（例如：段落缺少证据标记、禁用说法、评审指出无证据支持的句子）。中间产物都保留着，你可以退回重写并附意见，或放弃。

注意：生成文章的默认状态是「草稿」，不会自动发布。它不会成为某个概念定义的唯一依据；入库后要运行 `build_wiki` 与 `build_tree`，概念与知识树才会吸收它。

命令行：`python entrypoints/write_article.py ai t-0001`；`--feedback "意见"`；`--approve`；`--publish`；`--abandon "原因"`。

## 10. 常见问题
- **为什么有的文章显示“失败”？** 模型输出多次未能通过校验（如引文与原文不符），达到每篇修复上限后停止。重新摘要通常可以解决；若反复失败，检查该篇文章是否格式异常。
- **能否撤销导入？** 目前没有批量撤销。删除某篇需手动删除 `library/imported/<id>.md` 并在 `library/index.json` 中去掉对应条目（或整库删除/重建）。这一功能会在后续版本提供。
- **摘要会花多少调用？** 每篇一次（长文约为分块数加一次）。整库首次摘要按篇数计算；之后只处理变化的部分。
