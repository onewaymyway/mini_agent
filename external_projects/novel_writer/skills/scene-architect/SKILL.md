# 场景设计技能（Scene Architect）

## 职责

chapter-writer 知道"这章要写几个场景"，但每个场景内部怎么构建需要专门设计。本技能处理单个场景的完整结构——从进入到离开，确保每个场景都有自己的内在张力和戏剧完整性。

---

## 好场景的三个标准

```
① 有戏剧性问题（dramatic question）
   场景开始时存在一个疑问，场景结束时给出答案（或更大的问题）

② 有状态变化
   场景结束时，至少有一样东西发生了变化：
   人物关系 / 信息状态 / 角色内心 / 外部处境

③ 有自己的小弧线
   起点 → 发展 → 转折 → 结果（场景层面的起承转合）
```

缺少戏剧性问题的场景是描述性段落，不是真正的"场景"。

## 场景设计七步

### 第一步：明确场景目标

```
情节目标：这个场景结束后，故事推进了什么？
情感目标：这个场景结束后，读者的情感状态是什么？
```

两个目标必须都能回答，缺一则场景设计不完整。

### 第二步：设定戏剧性问题

```
好的戏剧性问题特征：
  - 读者真的关心答案
  - 答案开始时不确定
  - 答案在本场景内给出（或转化为更大的问题）

示例：
  "李凌云能通过考核吗？"
  "王道长会不会说出真相？"
  "这次相遇会变成对抗还是合作？"
```

### 第三步：选择进入点

判断方法：去掉第一段，场景还能运行 → 进入点太早，删掉第一段。

| 场景类型 | 推荐进入点 |
|---------|-----------|
| 战斗/冲突 | 从冲突已经开始时 |
| 重要对话 | 从对话已经开始后几句 |
| 揭秘/发现 | 从角色正在接近真相时 |
| 情感场景 | 从情绪已经在空气中时 |

### 第四步：设计场景内部小弧线（5节拍结构）

```
节拍1 建立（establishing）
  设置场景空间和初始基调；戏剧性问题在这里提出

节拍2 发展（development）
  双方开始博弈，信息/情绪逐步升温

节拍3 转折（turn）← 最高点
  某件意外的事改变了场景走向
  可以是：意外信息、情绪突破、外部干扰、意外决定

节拍4 结果（outcome）
  转折后的直接结果；戏剧性问题在这里得到答案

节拍5 出口设置（exit setup）
  为离开这个场景做准备，同时设置下一个场景的入口
```

### 第五步：管理信息密度

```
每个场景最多提供 2-3 条核心新信息
过多 → 读者信息过载，分散到多个场景
过少 → 场景缺乏增量，考虑与相邻场景合并
```

### 第六步：设计场景出口

| 出口类型 | 效果 | 适用 |
|---------|------|------|
| 自然结束 | 读者满足，准备进入下一事件 | 喘息场景、确认性场景 |
| 悬而未决 | 读者被强迫翻到下一场景 | 冲突场景、悬念章节 |
| 情感过渡 | 下一场景首句承接情感余波 | 情感高峰后 |
| 硬切 | 陌生感冲击，时间/空间跳接 | 蒙太奇式叙事 |

### 第七步：确认状态变化

```
场景结束前，至少一项发生了变化：
□ 人物关系状态
□ 信息状态（主角知道/误解/失去了什么）
□ 角色内心状态（信念/情绪/决定）
□ 外部处境
□ 读者与角色的关系
```

## 推进性场景 vs 展示性场景

```
推进性：改变故事状态——大多数场景应该是这种
展示性：展示角色特质或世界细节，不直接推进情节

判断：删掉这个场景，后续章节需要修改 → 推进性
     删掉这个场景，后续不需要改变 → 展示性（检查是否必要）

一章内展示性场景最多一个，且放在喘息位置
```

---

## 场景检查清单

```
□ 戏剧性问题在这个场景里得到了答案（或转化）？
□ 至少有一项状态变化？
□ 场景内有转折点？
□ 进入点是否太早（删去第一段场景还能运行）？
□ 出口为下一场景做好了准备？
□ 核心新信息数量（理想1-3条）？
```
