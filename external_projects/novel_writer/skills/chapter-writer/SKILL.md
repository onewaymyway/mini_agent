# 章节写作技能（Chapter Writer）

## 读取约定（第二至五阶段）

蓝图读取 `大纲规划/蓝图/_index.md` 与本章的 `第NNN章.md`；人物只读本章出场角色的角色文件（不要读取整本人物档案）；伏笔读取 `大纲规划/线索设定/伏笔/_index.md`。

## 职责

系统的唯一内容生产者——把结构化规划转化为有温度的文字。依赖 memory-manager 组装的上下文包，写完后触发六模块同步链。写对话时可调用 dialogue-crafter 协作。

---

## 写作前置清单

写任何章节之前，**必须按以下顺序完成所有加载步骤**。顺序不可颠倒，因为后面的步骤依赖前面加载的信息。

### 第一步：确认工作目录

```
[ ] workspace-manager  确认工作目录路径 {WORKSPACE} 已设置
                       如未设置，立即停止并要求用户指定工作目录
```

### 第二步：加载本章大纲规划（从工作目录读取）

```
[ ] 读取 {WORKSPACE}/大纲规划/蓝图/_index.md
    → 提取本章（第n章）的完整规划数据：
      - chapter_type（章节类型）
      - word_budget（字数目标）
      - key_scenes（关键场景列表）
      - plot_points（情节任务列表）
      - foreshadowing（本章伏笔操作）
      - ends_with（章末预期状态）
      - hook_type（钩子类型）
      - pov（叙事视角）
      - tension_level（预期张力）
      - designer_note（写作备注，含灵感整合标记）
    → 这是本章写作的最高优先级指导，必须优先遵守
```

### 第三步：加载所有已完成章节的总结（防止剧情矛盾）

```
[ ] 读取 {WORKSPACE}/章节总结/全书章节索引.md
    → 获取所有已完成章节的一句话总结，快速了解故事全貌

[ ] 读取 {WORKSPACE}/章节总结/ 目录下的所有 *_总结.md 文件
    → 重点读取最近3-5章的详细总结（避免近期剧情矛盾）
    → 有历史引用需求时读取相关章节的总结

    加载目的：
      ✓ 确认上章结尾状态（主角位置/情绪/正在发生的事）
      ✓ 确认本章与前章的时间/逻辑衔接是否自然
      ✓ 避免重复已发生的事件
      ✓ 确认伏笔的当前状态（哪些已经提过，哪些读者已知）
```

### 第四步：加载人物、世界、线索设定

```
[ ] {WORKSPACE}/大纲规划/人物设定/角色/（每角色一个 {id}.md）
    → 提取本章出场角色的 current_state 和 behavior_guide
    → 重点：wont_do 列表（写作时必须遵守的硬性边界）

[ ] {WORKSPACE}/大纲规划/世界观设定/world_bible.json
    → 提取本章涉及地点的设定 + 相关规则
    → 旅行时间/距离、力量体系边界

[ ] {WORKSPACE}/大纲规划/线索设定/伏笔/_index.md
    → 读取本章的情节任务清单（chapter前提醒）
    → 本章待兑现伏笔列表 + 依赖链确认
    → 本章应推进的故事线
```

### 第五步：加载风格和字数配额

```
[ ] {WORKSPACE}/大纲规划/其他设定/style_profile.json
    → 获取本章的风格提示（当前幕次基调、避免高频词）

[ ] {WORKSPACE}/大纲规划/其他设定/word_count.json
    → 获取本章字数配额、场景分配建议
    → 确认上章偏差是否需要本章消化
```

### 第六步：memory-manager 组装上下文

```
[ ] memory-manager 读取以上所有已加载内容
    → 按 chapter_type 动态分配 token 预算
    → 组装本章写作上下文包（含历史章节摘要的结构化索引）
    → 上下文包优先级：
        大纲规划 > 章节总结(近3章) > 角色状态 > 世界设定 > 伏笔任务 > 风格提示
```

**写作前加载确认**：以上所有步骤完成后，输出加载摘要：

```
📋 第n章写作前加载完成

章节规划：[chapter_type] | 字数目标：[X]字 | 张力目标：[X]
情节任务：[X]项 | 待兑现伏笔：[X]条 | 待埋伏笔：[X]条
已加载章节总结：[X]章（第1-[n-1]章）
本章出场角色：[角色列表]
上章结尾状态：[一句话描述]

→ 所有加载完成，可以开始写作
```

## 冷启动：如何开始第一句

**① 定锚点**：上一章用什么钩子结束？本章必须正面回应或侧面延伸。

**② 选开场类型**（根据 chapter_type）：

| 开场类型 | 适用场景 |
|---------|---------|
| 行动切入 | 冲突章/高潮章——直接写正在发生的动作，无铺垫 |
| 感官定位 | 过渡章/新地点——一个最有辨识度的感官细节 |
| 对话切入 | 人物关系章——有分量的台词开场，不写说话者身份 |
| 内心独白 | 心理揭示章——疑问句或判断句，主角内心声音 |
| 时间跳接 | 过渡章——"三天后……"直接跳过空白期 |

**第一段原则**：必须有一个强记忆点（意象/动作/台词三选一），前500字内不做世界观说明。

## 按 chapter_type 分化的写作模板

### opening（开篇定调章）3000-5000字

```
段落1-3    感官开场，定位世界氛围（≤300字）
段落4-8    主角登场，通过行为/处境展示性格（不要自我介绍）
段落9-15   抛出核心冲突的第一个信号
最后1段    章末最小悬念

要点：主角核心欲望或困境在本章内必须可感知
```

### setup（铺垫章）2000-4000字

```
场景A   人物互动（对话为主，推进关系）
场景B   世界/背景信息通过行动自然渗透
场景C   次要情节推进一步
章末    轻伏笔或轻悬念

要点：每个场景必须有信息增量，用人物细节填充而非事件堆砌
```

### conflict（冲突推进章）4000-6000字

```
开场     从上章悬念直接切入
发展     矛盾逐步升级（不一步到位）
转折     引入意外变量
章末     矛盾不解决——危机钩子或悬念钩子

要点：对手要有自己的逻辑；短句为主保持紧张感
```

### climax（高潮决战章）8000-12000字

```
前1/4   最后准备/最后对话，情绪蓄积
中1/2   核心对决/事件爆发（多波次）
后1/4   结果揭晓 + 情感余震（不能省略）
章末    情感钩子

要点：胜负必须在角色弧线上有意义；关键时刻用细节慢镜头；
      字数超出需向 word-count-controller 申报
```

### transition（过渡喘息章）2000-3500字

```
场景A   高潮后情绪处理
场景B   日常性互动（有意放慢节奏）
场景C   悄悄埋下下一段伏笔
章末    轻悬念，给读者充分满足感
```

### reveal（揭秘/逆转章）4000-7000字

```
铺垫（≤1/4）  营造"即将揭开"的紧张感
揭示          真相呈现——清晰完整不含糊
冲击          角色的即时情绪反应（不能跳过）
重构          真相如何改变接下来的局面

要点：兑现内容必须与 plot-tracker 的 reveal_content 一致
```

### closing（收束余韵章）2500-4500字

```
处理尾声   解决未收束的支线（简短）
主角状态   外在处境 + 内在变化
主题显现   不点破，让读者自己感受
最后一笔   全书余音——花最多时间打磨

要点：结尾是"回响"不是"总结"
```

## 场景内部四元素编排

```
A 动作  B 对话  C 心理  D 环境

快节奏：A → B → A → B（C/D穿插，占比小）
慢节奏：D → C → B → A → C
揭秘：  B → C → A
```

**对话**：每句台词同时完成两项任务；各角色说话方式来自 character-manager 的 speech_pattern；重要对话调用 dialogue-crafter 协作。

**心理**：行动化优先；禁用"他感到…/非常…/心中涌起…"；长段内心独白限200字。

**环境**：每个重要场景最多一处集中描写（100-250字）；氛围与人物情绪呼应。

---

## 节奏控制

```
快节奏：短段落1-3句 · 短句 · 动词密集
慢节奏：长段落5-8句 · 感官细节 · 留白
```

## 输出格式

正文文件由两部分组成，顺序固定，**只写一次**：

```
# 第[n]章 [章名]

[正文内容]

---

## 写作备注

- 实际字数：[整数，只写数字]
- chapter_type：[类型]
- 完成情节任务：
  - [x] [任务描述]
  - [ ] [任务描述]（未完成原因：[说明]）
- 本章场景覆盖：
  - [x] [场景描述]
- 埋设伏笔：[id（埋设方式），多个用；分隔；无则写 无]
- 兑现伏笔：[id（兑现方式）；无则写 无]
- 角色状态变化：[角色：变化；无则写 无]
- 章末钩子类型：[类型：实际钩子文本]
```

格式规则（不得自行变动）：
- 备注块标题只能是「## 写作备注」，前面紧跟一行 `---`，位于正文最末尾。
- 字段名与顺序必须与上面完全一致；每个字段都要出现，没有内容写「无」。
- 不要使用【写作备注】、加粗、「约」字、「第N轮写入」等变体；字数只写整数。
- 备注只写这一次，不要在正文中间或开头另写备注、元信息或字数统计。

## 写作完成后：强制触发 chapter-review

写作完成后，**必须且只需要**调用一个模块：

```
chapter-writer 写作完成
    ↓
chapter-review（完章核查技能）自动接管
    完成以下全部工作：
    ① 核查内容是否符合大纲规划（与 novel-planner 对照）
    ② 发现硬错误时驱动本技能修改，循环至通过
    ③ 生成章节概述，归档到 project/summaries/ch_n_概述.md
    ④ 更新项目全局状态（剧情线索/角色快照/伏笔总览/整体进度）
    ⑤ 触发所有下游模块状态同步
```

**chapter-writer 不直接调用任何其他模块**。所有写作后的同步工作统一由 chapter-review 协调。这样确保：
- 核查通过前不会归档错误内容
- 修改循环在 chapter-review 内部管理，不污染其他模块
- 所有状态更新在同一个事务中完成，不会出现部分更新的不一致状态

---

## 写作备注（提交给 chapter-review）

写作备注就是上文「输出格式」中的备注块，chapter-review 按同一格式核查，不需要另写一份。
核查时重点对照：「完成情节任务」对应 novel-planner 的每个 plot_point，「本章场景覆盖」对应每个 key_scene，
「埋设伏笔 / 兑现伏笔」的 id 必须与伏笔登记一致。

## 输出路径（最高优先级）

- 指令中给出的【输出路径】是唯一准则，必须逐字使用，不得改名、不得添加章节标题或其它字样。
- 正文文件的「第NN章 标题.md」命名规则，只适用于正式正文（章节正文），**不适用于候选稿、草稿等辅助文件**。
- 候选稿（精品档择优的第二稿）固定命名为 `第NN章_候选B.md`，写在 `正文/_drafts/` 下。
