# 剧情推演模拟技能（Plot Simulator）

## 职责

在实际写作之前充当"剧情沙盘"——模拟不同叙事决策的后果，帮助作者在数百种可能性中找到最有张力、最合逻辑、最符合人物性格的那一条路。

本技能是整个小说系统中唯一具有**前瞻性**的模块：其他模块处理已经发生的事，而本技能专门探索"还没发生但可能发生"的事。

---

## 核心能力

### 能力一：情境注入模拟

给定一个情境，模拟所有在场角色的反应链：

```
输入：
  情境描述：李凌云发现师傅王道长私下与魔道中人接触
  当前章节：第12章
  在场角色：李凌云（char_001）、王道长（char_002）

模拟过程：
  1. 读取每个角色的当前心理状态和决策逻辑
  2. 推演每个角色在此情境下最可能的第一反应
  3. 模拟反应链（A的反应→触发B的反应→…）
  4. 评估每种反应对后续章节的影响

输出：多条可能的反应路径 + 各路径的后续影响评估
```

### 能力二：叙事分支树

在关键决策点展开所有可能的叙事分支，评估每条分支的优劣：

```
输入：
  决策节点：第15章末尾——李凌云是否向宗主揭发师傅

输出：
  分支A：揭发
    - 短期后果（1-3章内）
    - 中期后果（4-10章内）  
    - 对主线的影响
    - 对人物关系的影响
    - 叙事风险评估
    - 读者情感预测
  
  分支B：隐瞒
    ...
  
  分支C：对质师傅本人
    ...
  
  推荐分支：[分析后的最优选择] + 理由
```

### 能力三：剧情压力测试

对已规划的情节施加"压力"，找出逻辑薄弱点：

```
输入：
  待测情节：第20章的大逆转——原来宗主才是幕后黑手

压力测试维度：
  □ 伏笔充分性：之前有没有足够的铺垫支撑这个逆转？
  □ 动机合理性：宗主这样做符合其人物逻辑吗？
  □ 信息自洽性：逆转揭示后，之前的所有情节还成立吗？
  □ 读者期待管理：这个逆转是意外中有意料，还是完全无迹可寻？
  □ 情节连锁反应：这个揭示后，其他角色会怎么反应？世界格局怎么变？
```

### 能力四：人物决策模拟器

给定一个情境，严格按照角色档案模拟该角色会做什么：

```
输入：
  角色：李凌云（char_001）
  情境：被人诬陷偷窃门派资源，宗主要当众惩罚他
  已知信息（角色视角）：他知道是师兄陷害，但没有证据

模拟输出：
  第一反应（0-5秒内）：[基于性格标签和当前情绪状态]
  行动选择：[基于决策逻辑]
  说出的话：[基于语言习惯和当前处境]
  内心独白：[基于核心欲望/恐惧]
  
  反事实检验：
    - 如果是性格更冲动的角色，会怎么处理？（对比）
    - 这个选择3章后会带来什么后果？
```

### 能力五：读者情感曲线预测

模拟目标读者在阅读特定情节序列时的情感走向：

```
输入：
  情节序列：[第10-15章的规划摘要]
  
输出：
  章节情感曲线图（文字版）：
    第10章：期待↑（悬念积累）
    第11章：紧张↑↑（危机来临）
    第12章：紧张→焦虑（峰值）
    第13章：疑惑（信息量大）
    第14章：满足（揭示伏笔）+ 新期待↑
    第15章：情感爆发（高潮）
  
  风险提示：
    - 第13章信息量过大，读者可能感到困惑，建议分散到12/13章
    - 第12章峰值过后如无缓冲，读者会疲劳
  
  建议调整：[具体节奏优化方案]
```

## 推演深度等级

| 等级 | 适用场景 | 推演范围 | 耗时 |
|------|---------|---------|------|
| **浅层** | 日常章节决策 | 1-3章影响 | 快速 |
| **中层** | 幕次转折点 | 4-10章影响 | 中等 |
| **深层** | 核心逆转/高潮 | 全局影响 | 详尽 |

## 特殊推演模式

### 模式一：蝴蝶效应追踪

追踪一个微小改动对整部小说的潜在影响：

```
输入：如果在第3章让李凌云"救了"那个路人（原计划他没有伸出援手）

追踪：
  - 这个路人身份会在哪章揭示？
  - 如果他后来成为盟友，哪些章节需要改写？
  - 这个改动是否与已有伏笔冲突？
  - 主角形象变化：从"孤冷"到"内心善良"，是否符合人设？
```

### 模式二：反派视角推演

从反派/对立角色视角独立推演，检查其行为是否有完整逻辑：

```
目标：确保反派不是"为坏而坏"，而是有完整的内在逻辑

输入：反派角色档案 + 其已知目标

推演：
  - 如果我是反派，我的最优行动策略是什么？
  - 当前情节中反派是否在做最优解？
  - 如果反派更聪明，主角会不会更快失败？（用来发现主角的胜利是否太过容易）
```

### 模式三：读者认知模拟

模拟一个只读到第N章的读者，其认知状态和期待：

```
输入：模拟读到第10章的读者认知状态

输出：
  已知信息（读者视角）：
    - 确认知道的：[列表]
    - 猜测到的：[列表]
    - 完全不知道的：[列表]（这是伏笔空间）
  
  当前期待：
    - 强烈期待：[最想看到的后续]
    - 担忧：[最不想发生的事]
    - 疑问：[心里还有的问题]
  
  风险：
    - 如果第11章没有回应"读者最强期待"，流失风险：[高/中/低]
```

### 模式四：快进模拟

快速推演从当前章节到小说结局的"骨架路线"，验证整体可行性：

```
输入：当前进度（第15章/共40章），当前所有活跃状态

输出：
  剩余25章的骨架推演（每幕一段话）：
    第三幕（16-25章）：……核心可能走向……
    第四幕（26-35章）：……高潮路线……
    结局（36-40章）：……收束方式……
  
  可行性评估：
    □ 当前埋设的伏笔能否在结局前全部兑现？
    □ 人物成长轨迹是否能在结局达到令人信服的高度？
    □ 主题是否能在结局得到充分表达？
  
  风险点：[哪些地方最容易写崩]
```

## 与其他模块的交互协议

### 推演前（读取）
- **character-manager**：获取所有相关角色的当前状态和心理档案
- **world-builder**：获取相关规则体系（制约推演的边界条件）
- **plot-tracker**：获取当前活跃伏笔和故事线状态
- **novel-planner**：获取全局规划，评估推演结果与蓝图的兼容性

### 推演后（写入）
- **plot-tracker**：注册推演中发现的新伏笔机会
- **novel-planner**：如果推演结果建议修改蓝图，生成变更请求
- **chapter-writer**：将推荐路径转化为具体的章节写作指令

### 触发建议
在以下节点**强烈建议**运行推演：
1. 每个幕次开始前（中层推演）
2. 重大逆转/高潮章节写作前（深层推演）
3. 引入新的重要角色前（情境注入模拟）
4. 感觉"情节走不下去"时（分支树 + 快进模拟）
5. 写完第一幕后（读者认知模拟）
