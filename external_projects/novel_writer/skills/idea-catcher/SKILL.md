# 灵感捕捉与整合技能（Idea Catcher）

## 职责

写作的线性流程（规划→写作→校验）无法处理非线性的创意输入。突发的好灵感如果没有捕捉机制，要么被遗忘，要么不假思索地插入当前写作破坏蓝图结构。本技能是两者之间的缓冲层。

---

## 灵感类型分类

| 类型 | 示例 | 默认路由 |
|------|------|---------|
| 场景灵感 | "我想写一个主角在雨中独自训练的场景" | 评估是否匹配某章规划 |
| 台词灵感 | "突然想到一句台词：'你要的不是变强，你要的是不再害怕。'" | 暂存，在合适场景使用 |
| 伏笔灵感 | "如果那把剑后来被打碎，能不能变成一个伏笔？" | 评估后送到 plot-tracker |
| 情节灵感 | "如果第15章主角失败而不是成功，后面会更有意思？" | 送到 plot-simulator 推演 |
| 人物灵感 | "王道长年轻时可能有过一段令他遗憾的关系" | 送到 character-designer 评估 |
| 结构灵感 | "整个第三幕从不同视角叙述同一段时间？" | 送到 novel-planner 评估 |
| 主题灵感 | "这个故事其实是在说'接受不完整的自己'？" | 送到 theme-architect |

---

## 灵感捕捉格式

```
灵感记录：
ID: idea_XXX（自动生成）
捕捉时间: 写作第n章时
类型: [类型]
内容: [灵感的完整描述，尽量具体]
来源: [是什么触发了这个想法]
初步感觉: [直觉评估：很好/一般/不确定]
状态: 待评估
```

## 灵感评估三步法

### 第一步：相关性评估

```
这个灵感与哪里相关？
  □ 当前正在写的章节（立即使用）
  □ 已规划的某个章节（标注目标章节，未来使用）
  □ 某个角色的人设（送到 character-designer/manager）
  □ 全书的主题（送到 theme-architect）
  □ 全书结构（送到 novel-planner）
  □ 与当前内容无关（暂存，等待合适时机）
```

### 第二步：兼容性评估

```
兼容（可整合）：
  - 不改变任何已规划的章节结构
  - 可在现有场景/对话中自然加入
  - 强化而不是替代现有情节

部分兼容（需要调整）：
  - 需要修改某章的 key_scenes
  - 需要调整某条伏笔的埋设位置
  - 需要通知相关模块更新

不兼容（需重新评估）：
  - 与已有设定冲突
  - 需要改变角色的核心弧线
  - 需要大幅调整蓝图结构
  → 发给 plot-simulator 推演后果，再决定是否采纳
```

### 第三步：优先级评估

```
高优先级（立即处理）：
  - 这个灵感让当前章节显著提升
  - 这个灵感解决了一个已知的叙事问题

中优先级（近期处理）：
  - 在未来某章会有用，但现在用不到
  - 有潜力但需要更多打磨

低优先级（暂存）：
  - "感觉不错"但不知道放在哪里
  - 与当前故事关联不强
```

## 灵感整合操作

### 立即整合（当前章节）

通知 chapter-writer 在指定位置整合灵感内容。如果是伏笔类灵感，同时通知 plot-tracker 注册。

### 未来章节整合

在 novel-planner 对应章节的 designer_note 中标注：
`「灵感 idea_XXX 待整合：[内容摘要]」`

### 暂存待定

保存在 idea_bank.json 的 pending_review 列表，每幕结束时统一复查。

---

## 定期复查（每幕结束触发）

```
灵感库复查报告（第一幕结束，5条待处理）

idea_003 台词："有些东西，强大也无法弥补。"
  评估：高度契合全书主题，建议整合进第22章关键对话
  处理：移至"已安排"，通知 novel-planner 标注在 ch_022

idea_005 结构灵感：双视角叙述第25章
  评估：有趣但风险较高（需大量改动）
  处理：发给 plot-simulator 推演，再决定

idea_007 场景灵感：某路人的细节
  评估：与当前故事方向渐行渐远
  处理：丢弃（保留原始文字存档）

idea_008 伏笔灵感：角色A的旧物
  评估：兼容，可在第18章自然埋入
  处理：送到 plot-tracker 注册，目标章节 ch_018

idea_009 人物灵感：王道长的年轻往事
  评估：能丰富人物层次，但目前蓝图中没有合适位置
  处理：送到 character-manager 补充背景档案，暂不写入正文
```

## 特殊情况：大型灵感的处理

当一个灵感的影响范围超过3章时，需要更谨慎的评估：

```
大型灵感评估流程：
1. 记录到 idea_bank.json，标记为"大型灵感-待评估"
2. 发给 plot-simulator 做完整的影响推演
3. 推演结果提交给作者决策
4. 如果采纳：
   a. novel-planner 更新蓝图（升级版本号）
   b. 所有受影响模块同步
   c. 可能需要 revision-editor 评估已写章节的连锁修改
5. 如果不采纳：记录在丢弃列表，说明原因

原则：大型灵感不应该在捕捉后立即写入，必须经过完整评估
```

## 灵感质量快速判断

以下信号说明一个灵感值得认真评估（不要立刻丢弃）：

```
✅ 高价值信号：
  - 这个灵感解决了一个之前感觉"不对"但说不清楚的问题
  - 这个灵感让某个角色变得更立体
  - 这个灵感让某个情节变得更"必然"（减少了巧合感）
  - 这个灵感与全书主题高度共鸣

⚠️ 低价值信号（谨慎对待）：
  - 这个灵感只是"感觉很酷"，但不知道为什么
  - 这个灵感需要大量修改现有内容才能使用
  - 这个灵感是从别的作品里受到的启发（注意影响过大）
  - 每次重读这个灵感，激动感在下降（冷却效应，真正好的灵感不会冷却）
```

## 与其他模块交接

- 调用时机：任何时候有突发灵感
- 评估后路由：
  - 台词/场景灵感 → chapter-writer 或 novel-planner（标注目标章节）
  - 伏笔灵感 → plot-tracker
  - 情节分支灵感 → plot-simulator
  - 人物灵感 → character-designer / character-manager
  - 结构灵感 → novel-planner
  - 主题灵感 → theme-architect
- 文件：idea_bank.json（持久化所有灵感记录，含丢弃的）
