# 节奏编排技能（Pacing Architect）

## 职责

节奏的管理目前分散在多个 skill 里——plot-tracker 管张力曲线、word-count-controller 管字数、chapter-writer 管单章节奏。本技能专门处理**跨章节的节奏编排**，这个维度原本处于无人管理状态。

节奏不等于快慢，而是**高强度和低强度的交替方式**。

---

## 节奏的本质

```
读者疲劳的原因不是"内容太多"，而是"太长时间没有变化"

两种疲劳：
  强度疲劳：连续多章高张力，读者情绪系统透支
  → 读者说"太累了，要缓一缓"

  平淡疲劳：连续多章低张力，读者注意力耗尽
  → 读者说"太无聊了，没动力继续"
```

---

## 三章节奏单元

最基础的节奏编排单元是"三章一循环"：

```
标准三章单元：
  第一章  建立/铺垫  → 情绪积累，埋下本单元核心张力
  第二章  爆发/高峰  → 核心冲突或情感高峰
  第三章  余波/重建  → 处理高峰后的状态，为下一单元蓄力

示例（中等张力单元）：
  第n章   setup（4分）：新威胁开始显现
  第n+1章 conflict（7分）：直接冲突爆发
  第n+2章 transition（3分）：处理后果，角色调整
```

### 三章单元的四种变体

连续相同结构会让读者"预判节奏"，必须有意变化：

```
变体一：延迟高峰（四章单元）
  setup → setup（加深张力）→ conflict（高峰）→ transition
  效果：高峰更有力量，因为等待时间更长

变体二：双高峰（五章单元）
  setup → conflict（小高峰）→ 短平息 → conflict（大高峰）→ transition
  效果：第二个高峰因有对比而更强

变体三：颠倒结构
  从高点开始 → 交代原因 → 余波处理
  效果：打破读者的节奏期待，增加新鲜感

变体四：纯喘息（跳过高峰）
  setup → transition → setup（完全跳过高峰）
  效果：用"什么都没有发生"制造静谧感（适合幕次收尾或重大高峰后）
```

## 幕次级节奏规划

### 各幕次的张力曲线形状

```
第一幕（建立期）：
  形状：缓慢上升，1-2个小高峰
  目标：建立读者的投入和好奇
  必须有：一个中等高峰作为幕末，留下明确主线悬念

第二幕（发展期）：
  形状：震荡上升，高峰逐渐提高，中间有明确低谷
  目标：让读者对主角命运有真正的担忧
  必须有：最大挫败/低谷（整部小说最低点，约在55%-65%进度处）
  幕末：以一个高峰结束，指向最终高潮

第三幕（高潮期）：
  形状：快速攀升 → 顶峰 → 骤降
  目标：兑现所有积累，给读者最大情感冲击
  原则：高潮后立即开始收束，不拖延

尾声/第四幕（收束期）：
  形状：平稳下降
  目标：给读者情感着陆的空间
  节奏：比任何其他幕次都慢
```

### 幕次节奏硬性规则

```
每个完整幕次必须包含：
  □ 至少一个高张力章（7分以上）
  □ 至少一个低张力章（3分以下）——喘息空间
  □ 不允许连续5章都在5分以上
  □ 不允许连续3章都在3分以下

整部小说必须有：
  □ 最大高峰（9-10分）：通常在85%-92%进度处
  □ 最大低谷（1-2分）：通常在55%-65%进度处（主角最大挫败）
  □ 开篇前10%章节不超过5分（铺垫期）
  □ 结局章回落到4分以下（余韵期）
```

## 节奏错误诊断

### 诊断一："高原现象"

```
症状：张力一直维持在6-8分，从没到过顶，也从没真正低过
影响：读者情绪"免疫"——8分场景开始感觉只有5分

修复：
  1. 找到一章可以真正放松到3分以下（配角日常/角色内心/轻松时刻）
  2. 轻松章之后，下一章的冲突才能有更强的冲击感
```

### 诊断二："过山车"综合征

```
症状：章章都有冲突，高低起伏太频繁，读者感到混乱
影响：每个高峰意义被稀释，读者失去对"什么是真正重要的"的判断

修复：
  1. 将相邻的两个小冲突合并为一个中等冲突
  2. 在重要高峰后安排2-3章的平息期
```

### 诊断三：结构性低谷缺失

```
症状：主角一直在进步，没有真正意义上的失败
影响：读者对主角没有真正的担忧，高潮的胜利缺乏分量

修复：
  在55%-65%进度处安排一个真正的低谷——
  不是小挫折，而是主角失去了重要的东西，
  且这个损失短期内无法挽回
```

### 诊断四：尾声节奏失控

```
症状：高潮后仍维持高张力，结局仓促
影响：读者没有情感着陆的空间，合上书感到空洞

修复：
  高潮结束后，立即降至3分以下并维持2-3章
  只处理"之后"，不引入新的冲突
```

## 节奏编排输出格式

```
节奏规划：第二幕（第11-30章，共20章）

整体形状：震荡上升，在第18-19章触底后反击

三章单元规划：
  单元1（11-13章）：建立→冲突→余波    张力：4→7→3  [标准]
  单元2（14-16章）：建立→建立→冲突    张力：4→6→8  [延迟高峰变体]
  单元3（17-19章）：高峰→崩溃→低谷   张力：9→5→2  [双高峰+最大挫败]
  单元4（20-22章）：重建→重建→推进   张力：3→4→6  [从低谷爬起]
  单元5（23-26章）：推进→推进→高峰→余波  张力：5→7→9→4  [四章单元]
  单元6（27-30章）：收束+悬念        张力：5→4→6  [指向第三幕]

幕次检查：
  ✅ 最高点（9分）：第18章
  ✅ 最低点（2分）：第19章
  ✅ 无连续5章5分以上
  ✅ 无连续3章3分以下
  ✅ 三章单元使用了4种变体
```

## 节奏数据同步

将规划的章节张力值推送给 plot-tracker 的 tension_curve：

```
同步格式：
  章节n → tension: X（来自节奏编排规划）
  章节n+1 → tension: Y
  ...
```

## 与其他模块交接

- 调用时机：novel-planner 规划各幕时；幕次开始前；revision-editor 主动巡检发现节奏问题时
- 依赖：plot-tracker（张力曲线现有数据）· novel-planner（幕次章节范围）
- 输出：幕次级节奏规划 + 三章单元分配 + 节奏问题诊断报告
- 数据推送：将规划的章节张力值同步给 plot-tracker 的 tension_curve
