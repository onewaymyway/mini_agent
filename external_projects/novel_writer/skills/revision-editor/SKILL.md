# 修订编辑技能（Revision Editor）

## 职责

所有 skill 都假设在"向前写"，但实际写作中大量时间花在修改上。本技能处理两种场景：
1. **响应式修订**：用户或其他模块指出了具体问题，给出修复方案
2. **主动巡检**（新增）：给定任意章节文本，不依赖外部指令就能输出诊断报告

---

## 修订分级体系

| 等级 | 问题类型 | 修改范围 | 连锁风险 |
|------|---------|---------|---------|
| L1 表层润色 | 措辞、句式、禁用词 | 段落内 | 无 |
| L2 场景重构 | 节奏、情绪落点、场景结构 | 场景级 | 低 |
| L3 情节调整 | 事件逻辑、人物决策合理性 | 整章 | 中 |
| L4 架构重写 | 人物弧线偏移、主题背离 | 多章 | 高 |

## 模块一：主动巡检（新增）

不需要用户指出具体问题。给定章节文本，输出系统性诊断报告。

### 巡检触发时机

```
1. 每5章主动触发一次
2. 幕末深度审稿时
3. reader-simulator 报告满意度持续低于预期时
4. 用户感觉"哪里不对但说不清楚"时
```

### 巡检维度（8个）

**维度一：情感强度分布**

```
检查：全书至今有没有出现过"10分"的情感高峰？
      近5章最高情感强度是多少？
      
风险信号：
  - 连续8章情感强度都在6-7分（从没到过顶）→ 读者开始"免疫"
  - 高潮章之后没有情感余波（直接切到下一事件）→ 读者没有消化时间
```

**维度二：人物出场频率**

```
检查：所有有未完结故事线的配角，最近10%进度内有没有出现过？

风险信号：
  - 配角消失超过15%进度但其故事线仍活跃 → 读者会忘记此人
  - 建议：安排一次"存在感确认"场景（不一定要推进故事线，但要让读者记起此人还在）
```

**维度三：文风漂移检测**

```
检查：近5章和前5章相比，
      平均句长是否显著变化？
      禁用词是否开始出现？
      叙事距离是否偏移？
      
风险信号：
  - 平均句长增加30%以上 → 节奏变慢，可能与当前幕次基调不符
  - 禁用词出现频率上升 → 向 style-guardian 报告
```

**维度四：隐性节奏平板**

```
检查：连续5章，每章的情感曲线是否都是"平稳开始→中间高峰→平稳结束"？

风险信号：
  - 章节结构过于相似（读者开始"预判章节结构"）→ 需要结构变化
  - 建议：尝试从高点开始、从低点结束，或在意想不到的地方出现高峰
```

**维度五：对话质量趋势**

```
检查：近5章的对话密度和类型是否单调？

风险信号：
  - 连续5章都是"两人平和交谈"，没有冲突或情绪化对话 → 缺乏戏剧张力
  - 对话归因"说"字比例是否上升（style-guardian 数据）→ 向 dialogue-crafter 报告
```

**维度六：伏笔激活状态**

```
检查（结合 plot-tracker 数据）：
  当前活跃伏笔数是否在5-8条范围内？
  最近10%进度内有没有任何伏笔被兑现或推进？
  
风险信号：
  - 活跃伏笔超过8条 → 读者信息过载，建议近期兑现2-3条
  - 超过15%进度没有任何伏笔推进 → 悬念密度不足，读者失去期待感
```

**维度七：主角弧线推进**

```
检查（结合 character-manager 数据）：
  主角的 arc_stage 在最近20%进度内有没有推进？
  主角的信念（belief）是否有任何细微动摇的描写？

风险信号：
  - 主角弧线长期停滞（超过30%进度没有任何推进）→ 人物成长感缺失
  - 弧线推进过快（不到20%进度就从"扭曲信念"→"觉醒"）→ 成长不可信
```

**维度八：世界设定激活**

```
检查（结合 world-builder 数据）：
  有没有重要世界设定距上次出现超过20%进度？
  
风险信号：
  - 建立的规则体系近期很少出现 → 世界感在消退
  - 建议：将设定与情节绑定，让规则成为推进情节的工具
```

### 巡检报告格式

```
主动巡检报告：第n章（进度X%）

发现隐性问题：3项

🟡 问题一：情感高峰缺失
   现象：近8章最高情感强度为7分，从未到达高峰
   影响：读者开始对中等强度免疫，当真正高潮来临时打动力会减弱
   建议：在第n+2章或n+3章安排一个充分蓄积的情感高峰（9-10分）

🟡 问题二：王师兄消失过久
   现象：王师兄（配角，有活跃故事线）最后出现于第5章，当前第14章（进度差22%）
   影响：读者开始忘记此角色和其故事线
   建议：第n+1章安排一次存在感确认，无需推进故事线，一句提及或远景出现即可

🔵 问题三：伏笔密度偏低
   现象：当前活跃伏笔仅3条，最近15%进度内没有任何新伏笔埋设
   影响：读者期待感下降，阅读驱动力减弱
   建议：在接下来两章各埋1条伏笔（一主线、一副线）

综合评估：整体质量稳定，无需修改现有章节，在后续写作中针对性改善
```

## 模块二：响应式修订

### 症状→根因快速诊断

| 症状 | 最可能的根因 |
|------|------------|
| 读起来无聊，什么都没发生 | 场景缺少信息增量；每段缺少情绪温度 |
| 对话感觉假/生硬 | 台词服务作者而非角色逻辑；语言差异化不足 |
| 节奏奇怪 | 场景密度与 chapter_type 不匹配 |
| 某角色的反应不可信 | 违反 character-manager 的 behavior_guide |
| 情感高峰没有打动人 | 情绪蓄积不足；余波处理太短 |
| 结尾没有钩子感 | 钩子类型与 chapter_type 不匹配；力度不足 |
| 主角感觉不像自己 | 弧线阶段描写与 arc_stage 不匹配 |

### L1：表层润色

```
禁用词替换：
  "不禁" → 具体行为（停住了脚步）
  "突然感觉到" → 描述感觉本身（胸口一紧）
  "非常" → 删去或换具体程度词

句式优化：
  拆长句为短句（高张力场景）
  合并破碎句子（情感场景）

重复检测：
  同一个词在5句内出现3次以上→ 至少替换2次
```

连锁影响：无，无需通知其他模块。

### L2：场景重构

```
问题：情感高峰太短，没有余波
修复：在高潮段落后增加1-2段余波处理
      （角色即时身体反应 → 沉默 → 第一个行动）

问题：对话密度太均匀
修复：在关键台词前插入动作/停顿，让那句话更有分量

问题：场景开场太慢
修复：将切入点前移到"已经在发生"的地方

问题：场景结束太干净，没有悬念
修复：加入一个小细节或未回应的问题
```

连锁影响：低，通知 style-guardian 检查修改后风格一致性。

### L3：情节调整

**人物决策修订**

```
1. 从 character-manager 读取 decision_logic 和 wont_do
2. 找到"不可信点"：前提不充分，还是违反了 wont_do？
3. 选择修复路径：
   路径A：修改行为本身，符合角色逻辑
   路径B：补充前置铺垫，让角色产生此行为有了合理动机
   路径C：将此行为定性为角色的"失误"，后续给出代价
```

**事件逻辑修订**

```
1. 明确"逻辑漏洞"：前提缺失/因果断裂/世界规则冲突
2. 从 world-builder 和 plot-tracker 确认相关规则和伏笔状态
3. 最小化修改原则：优先在本章内修复
4. 如必须修改前章，评估对 memory-manager 摘要的影响
```

连锁影响：中，完成后通知 character-manager · plot-tracker · memory-manager · consistency-checker。

### L4：架构重写

**触发信号**

```
□ consistency-checker 幕末审稿：该幕整体情感弧线未实现
□ 多章连续出现 arc_stage 与实际描写不匹配
□ reader-simulator 诊断出"看不下去"
□ 主动巡检发现弧线长期停滞（超过30%进度）
```

**处理流程**

```
1. 向 novel-planner 发起蓝图诊断请求
2. 与 plot-simulator 运行"当前状态快进模拟"，确认问题根源
3. 确定最小修改范围（避免大规模重写）
4. 输出修订计划
5. 依次触发：novel-planner 更新蓝图 → 各模块同步 → 按新蓝图重写
```

连锁影响：高，通知所有模块。

## 修订报告格式

```
修订报告：第n章《章名》

问题等级：L2 场景重构
诊断：
  症状：王道长的反应不像这个人物
  根因：台词服务情节推进，而非王道长的迂回性格
  位置：第4段，王道长直接说出"我认识你父亲"

修复方案A（推荐）：改为行动暗示
  王道长在"好孩子"三字上停顿了一下，然后转身离开，没有再说话。

修复方案B（备选）：保留直说但加前置动机
  在台词前补充：王道长被什么触动，才会在这时说出这句话？

修改影响：仅本章第4段，无连锁
需通知：style-guardian（风格一致性检查）
```

## 常用工具

**钩子强度检测**：遮住最后一段，"如果这是今晚最后能读的，会不会熬夜再翻一章？"

**节奏检测**：把每段的句子数列出来（如 1,1,2,1,2,8,7,8,6,1,1,2），找到连续长段落区（节奏平板区）。

## 与其他模块交接

- 接收：用户请求 · consistency-checker 修改意见 · reader-simulator 诊断 · 主动巡检触发
- 依赖（诊断时）：character-manager · world-builder · novel-planner · plot-tracker · memory-manager
- 修改完成后通知（按等级）：consistency-checker（重新校验）+ 其他受影响模块
