# 长篇小说宏观规划技能（Novel Planner）

## 产出约定（第五阶段）

整本蓝图仍由本技能一次性产出，但写到草稿 `大纲规划/蓝图/_draft.json`（整本一个 JSON 对象）。系统的 `blueprint_split` 步骤会自动拆分为 `_meta.md`（顶层字段）与每章一个 `第NNN章.md`，并生成 `_index.md`。不要直接写入 `_index.md` 或章节文件。

## 职责

将用户的创作意图转化为可执行的结构化叙事蓝图。本技能是整个系统的**起点与协调者**——不只输出蓝图，还负责触发各下游模块的初始化，并在写作过程中响应蓝图变更请求。

---

## 第一步：输入收集

优先从对话中提取已有信息，缺失时一次性提问，**不多轮追问**。

### 基础要素

| 要素 | 说明 | 默认值 |
|------|------|--------|
| 题材类型 | 玄幻/都市/历史/科幻/言情/悬疑等 | 用户指定 |
| 核心主题 | 想传达的中心思想或情感 | 从题材推断 |
| 预计篇幅 | 短篇(<5万)/中篇(5-30万)/长篇(>30万) | 长篇 |
| 发布平台/读者 | 网文平台/出版/自用——影响节奏期待与章节密度 | 网文平台 |
| 特殊限制 | 时代背景、必须出现的元素、禁区 | 无 |

### 主角与核心冲突（最影响结构质量）

这两项是幕级骨架的地基，没有就无法生成有意义的结构：

```
主角是谁（一句话）：[性别/年龄/身份/最显著的特质]
主角的核心欲望：[他/她最想要的是什么]
主角的核心障碍：[什么在阻止他/她]
故事的核心冲突：[人 vs 人 / 人 vs 社会 / 人 vs 自我 / 人 vs 命运]
期望的结局走向：[HE/BE/开放/留白]
```

### 已有创意碎片（避免规划与用户想象割裂）

用户通常脑子里已有一些具体片段，先收集再规划：

```
已确定的场景或桥段：[有哪些场景是必须要写的]
已确定的角色：[已经想好的人物]
已确定的结局/高潮：[如果有的话]
参考风格/作品：[想要什么感觉]
```

## 第二步：结构模型选择

按决策矩阵选择，而非笼统推荐，并向用户说明选择理由：

| 情况 | 推荐结构 | 理由 |
|------|---------|------|
| 单主线 + 篇幅 < 30 万字 | **三幕式** | 简洁有力，节奏易控 |
| 单主线 + 篇幅 > 30 万字 | **四幕式** | 中段拆为两幕，防止中间塌陷 |
| 多主线交织（2-3条） | **五幕式** | 各幕有空间交错推进 |
| 主副线并重 | **双线结构** | 明确标注每章属于哪条线 |
| 仿古/章回风格 | **章回体** | 每章有独立标题和小钩子 |
| 网文爽文类 | **升级弧结构** | 每 5-8 章一个小高潮，持续正反馈 |

### 网文与严肃文学的节奏差异

```
网文节奏：前3章必须有钩子 · 每章结尾有悬念 · 每5章一小高潮 · 主角成长曲线快速上升
严肃文学：允许慢热铺垫 · 结尾可开放 · 允许平弧或悲剧弧 · 重内心甚于外部成就
```

## 第四步：蓝图自检（输出前必做）

生成蓝图后、展示给用户前，自动执行全部核查，发现问题先修正再展示：

```
字数核查
  □ 所有章节 word_budget 之和 == meta.target_length？（允许 ±2%）
  □ 各幕 word_budget 之和 == total_target？

伏笔核查
  □ 每条伏笔的 planned_reveal_chapter <= 总章节数？
  □ 主线伏笔数量 <= 3 条？
  □ foreshadowing_index 的 id 与各章节内 foreshadowing[].id 一一对应？
  □ 每条伏笔都有非空的 reveal_content？

结构核查
  □ 各幕 chapter_range 连续且不重叠？
  □ 高潮幕（最后一个高密度幕）tension_range 上限 >= 8？
  □ 所有章节都有 hook_type 字段？
  □ 所有章节都有 pov 字段？

主角弧核查
  □ 最大挫败转折点在全书 50%–70% 位置？
  □ 最终价值观转变在全书 85%–95% 位置？
  □ arc_type 与 ending_type 是否相符（悲剧弧不应对应 HE）？
```

在摘要末尾标注"已自动修正 N 处"或"自检全部通过"。

## 第五步：执行顺序

```
1. 收集意图        提取对话信息 + 补充提问（重点：主角/创意碎片/平台）
2. 选择结构模型    按决策矩阵，说明推荐理由
3. 设计幕级骨架    确定幕次、情感弧、张力范围、主角状态首尾
4. 分解章节列表    逐章填写全部字段（含 pov/chapter_type/tension_level/foreshadowing）
5. 建立伏笔索引    汇总 foreshadowing_index，每条含完整 reveal 信息
6. 蓝图自检        执行第四步所有核查项，修正后进入下一步
7. 保存蓝图        novel_blueprint.json（v1）
8. 分发各模块      按下方协议触发初始化（含新增的三个模块）
9. 展示摘要        向用户呈现，等待确认或修改
```

## 第六步：与各模块的交接协议

### → character-designer（新增）

蓝图完成后，统计在 `characters_present` 中出现 **≥ 3 章** 的角色，判定为主要角色，逐一触发人设设计：

```
触发信息：
  角色名：[姓名]
  在故事中的定位：[主角/配角/反派]
  首次登场章节：[n]
  已知上下文：[从 plot_points / key_events 中提取与该角色相关的线索]
  设计深度：完整人设卡
```

character-designer 完成后将核心字段同步给 character-manager 建档。

### → word-count-controller（新增）

同步全书字数配额作为管控基准：

```
同步字段：
  meta.target_length          → 全书总目标
  structure.acts[*].word_budget   → 各幕配额
  chapters[*].{id, word_budget}   → 各章配额
```

### → plot-simulator（新增，建议）

蓝图确认后，建议运行"快进模拟"验证整体可行性：

```
模式：快进模拟
输入：幕级骨架 + protagonist_arc + foreshadowing_index
期望输出：
  □ 伏笔能否在结局前全部兑现？
  □ 主角成长节点分布是否合理？
  □ 最危险的叙事断裂点在哪里？
```

### → world-builder

```
输入：meta（题材/基调/平台）+ acts[*].key_events
任务：初始化世界圣经（地点/力量体系/社会结构）
```

### → plot-tracker

```
输入：foreshadowing_index（完整列表）+ protagonist_arc.key_turning_points
      + chapters[*].tension_level（建立张力曲线基准）
任务：注册所有伏笔，建立张力曲线
```

### → chapter-writer（按章提供）

每章写作前读取：
```
chapters[n].{function, chapter_type, key_scenes, characters_present,
             plot_points, foreshadowing, ends_with, hook_type,
             pov, tension_level, word_budget, designer_note}
```

## 第七步：蓝图变更机制

写作中途调整规划是常态，遵循以下流程：

### 变更分级

| 变更内容 | 级别 | 需通知模块 |
|---------|------|----------|
| 修改某章 key_scenes / designer_note | 轻微 | chapter-writer |
| 调整章节字数 | 轻微 | word-count-controller |
| 新增/删除/修改角色 | 中等 | character-designer, character-manager |
| 增删/修改伏笔 | 中等 | plot-tracker |
| 章节合并/拆分/顺序调整 | 重大 | 全部模块 |
| 修改幕次结构或主角弧线 | 重大 | 全部模块 |

### 变更前影响评估模板

```
变更内容：[描述]
影响评估：
  □ 涉及哪些章节的 characters_present / plot_points？
  □ 有哪些伏笔需要转移或删除？
  □ 字数总量是否变化？需通知 word-count-controller？
  □ memory-manager 的章节摘要是否需要重建？
```

### 版本记录格式

每次变更后在 `blueprint_version_log` 追加条目并升级版本号：

```json
{
  "version": "v2",
  "timestamp": "第8章完成后",
  "changes": "第15章拆分为15a/15b，总章节40→41，第二幕字数160000→165000",
  "affected_modules": ["word-count-controller", "plot-tracker", "memory-manager"],
  "notified": true
}
```

## 规划原则参考

### 节奏百分比
```
前 5%     开篇钩子——必须快，第1章末有悬念
5–15%     世界建立——可慢，铺设规则与关系
15–55%    冲突升级——变节奏，每10%一个小高潮
55–70%    最大危机——急转直下，节奏骤快
70–90%    反击与揭秘——高速推进，伏笔密集兑现
90–100%   收束余韵——放慢，情感落地
```

### 字数参考
```
过渡喘息章：2,000–3,500 字
标准推进章：3,500–5,500 字
重要事件章：5,500–8,000 字
高潮决战章：8,000–12,000 字
```

### 伏笔健康原则
- 主线伏笔：≤ 3 条，埋设到兑现间隔 15–25 章
- 支线伏笔：每幕活跃 ≤ 5 条，间隔 5–15 章
- 兑现率规划目标：≥ 90%
