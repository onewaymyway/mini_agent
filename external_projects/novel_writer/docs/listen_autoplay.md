# 听书自动连播：章节结束后停下的问题

## 现象
自动连播读完一章后停下，位置回到该章开头，不再继续播放下一章。

## 机制
- 播放器（`ui/listen_component/index.html`）在每章的第一段开始朗读时（`onstart`），向 Python 回传位置（章节号、段号）。
- Python 端（`ui/listen.py`）发现章节号变化后，记下待显示章节并 `st.rerun()`，由下一次运行把选择框同步到该章节（程序性写入）。
- 选择框的 `on_change` 回调只应处理用户的改选。改选会保存新位置、递增 `listen_nonce`，使播放器以新 key 重新挂载；挂载后从保存的位置（章首）启动，但 `init` 不会自动开始朗读，所以表现为「停在章首」。

## 原因与修复
程序性同步选择框之后，前端可能把这次变化当作用户操作回传，触发 `on_change`。原实现对任何回调都会重新挂载播放器，于是切章后的回调把播放器重置到章首并停止。

修复（`ui/listen.py::_on_pick`）：回调的值等于我们最后一次程序性同步的值（`_EXPECT`）时直接忽略，只有真正的用户改选才重新挂载。

回归测试：`tests/test_listen_persistence.py::test_program_sync_echo_is_not_a_user_pick`，并保留原有的选择框持久化测试。

## 未能覆盖的情况
- 本修复基于代码分析与 Streamlit AppTest 的行为确认，未在真实浏览器中复现。如仍出现，请记录：停止位置（章节号与段号）、浏览器控制台报错、是否伴随「朗读出错」提示。
- 若前端回传的是同步之前的旧值（而不是同步后的值），守卫不会拦截，需要另行处理。

## 仅本地音色开关

听书面板的「仅本地音色（不经网络，不受代理影响）」开关，保存在 `_studio/reading_state.json` 的 `listen_local_only`（默认关闭）。

- 开启后，音色下拉只列出浏览器的本地中文音色（`localService` 为真，例如 Windows 自带的 Huihui、Yaoyao），不再列出需要联网的在线音色；
- 当前所选音色不是本地音色时拒绝朗读，并提示更换，因此不会由浏览器静默改用在线音色；
- 本地音色列表为空时同样不朗读，提示安装中文语音包；
- 切换开关即时生效，朗读中会按新音色列表重排队，播放器不重新挂载。

注意：这一开关只约束语音合成的音色选择。它不能控制浏览器对页面本身的网络访问，也不改变浏览器的代理设置。
