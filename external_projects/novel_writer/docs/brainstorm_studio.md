# 灵感构思工作室

> 设计：`next_doc/novel_brainstorm_studio_design.md`
> 当前进度：**B0–B5 全部完成**。B0：工作目录、卡片校验读写、定版快照、回退、列表；B1：题材卡、灵感池、发散与采纳，独立页面「💡 灵感构思」；B2：对话区与提议区；B3：世界观与角色编辑、质检；B4：剧情骨架、备选方案、收敛模式；B5：交接到新小说。

## 独立项目

构思项目与小说项目并列，默认放在 `data/brainstorms/<名称>_<时间戳>/`。它不参与小说的步骤流水线。

```
<root>/
  _studio/brainstorm.json   元信息；有这个文件才算构思项目（kind = brainstorm）
  working/                  当前草稿（ideas.json brief.json premise.md world.json cast.json plot.json open_questions.json）
  versions/v<n>/            定版快照，只增不删，含 version.json（n、时间、备注、内容哈希）
  options/                  备选分支（B4）
```

书架索引没有改动：构思项目通过 `_studio/brainstorm.json` 的 `kind` 字段识别，不需要迁移旧数据。

## 卡片

| 模块 | 文件 | 结构 |
|---|---|---|
| ideas | ideas.json | 列表；每条 id、text、tags、source（author/ai）、status（keep/park/drop/used） |
| brief | brief.json | 与新建向导字段一一对应（`intake.INTAKE_KEYS`），只接受这些字段 |
| premise | premise.md | 文字 |
| world | world.json | rules / locations / factions / timeline / taboos；规则类条目需要 text，可选 cost |
| cast | cast.json | 以角色 id 为键；必须有 name；可选 role/want/need/flaw/lie/arc/relations |
| plot | plot.json | acts（每幕 title + beats）、twists、endings |
| open_questions | open_questions.json | 列表；每条 id、text、closed |

所有写入都经过 `cards.put_module`：先校验，再原子写入。不合法的数据会被拒绝，文件保持原样。

## 版本

- `snapshot(ws, note)`：把草稿定版为 v<n>。版本目录已存在时拒绝覆盖。
- `restore(ws, n)`：把草稿恢复为 v<n>，并记为一个新版本（备注「回退到 v<n>」）。历史不删除。
- 版本里不存在的模块文件，回退后会被删除，保证草稿与该版本一致。
- `content_hash(ws)`：按模块文件内容计算哈希，用于之后交接时溯源。

## B1：题材卡、灵感池、发散

入口：侧栏「💡 灵感构思」。页面分三个标签：

- **题材卡**：与新建向导的字段一一对应，保存时经过校验。
- **灵感池**：手动添加灵感（可加标签）；每条可设为保留 / 搁置 / 已采用 / 丢弃。丢弃只改状态，不删除记录。
- **发散**：输入一个方向（可空），让 AI 给出 3–10 条候选。候选保存在 `_studio/spark/<id>.json`，**不会直接进入灵感池**；勾选后点「采纳所选」才会写入灵感池，来源记为 AI。已采纳的候选不能重复采纳。

### 发散的实现

- 提示词包含：题材卡中已填的字段、已有灵感（排除已丢弃的，最多 40 条，避免重复）、方向、数量。要求模型只输出 JSON 数组。
- 解析容忍代码块与前后文字；取不到有效候选时报错，不写任何文件。
- 生成器默认走 mini_agent 的受限 Agent（无工具、单轮，复用 `runner._build_restricted_agent`）。测试中替换为桩，不调用真实模型。
- **未经真实模型验证**：默认生成器的调用路径已接通，但我没有在有 API key 的环境里跑过，第一次使用时请留意输出是否正常。

### 对外接口

`novel_writer/brainstorm/api.py`，统一返回 `{ok, data}` 或 `{ok: false, error, error_type}`：
`list_projects`、`create_project`、`get_project`、`save_brief`、`list_ideas`、`add_idea`、`update_idea`、`spark`、`spark_history`、`adopt_candidates`。

- 卡片的编辑只支持题材卡和灵感池；世界观、角色、剧情骨架的界面在 B3 加入，现阶段只能通过代码写入。
- 备选方案分支目录已预留，没有创建与对比逻辑（B4）。

## B2：对话与提议

页面第一个标签是「对话」。模式目前有「追问」（默认）和「自由」。

### 对话如何工作

- 每轮提示词包含：模式说明、当前卡片摘要（题材、命题、保留的灵感、世界观条目数、角色、剧情幕、未解决的问题）、最近 4 轮对话，以及作者的新话。
- 会话续接：通过 mini_agent 的 Agent，`load_session` 续接上一轮的会话 id（保存在 `_studio/agent_session.json`），因此模型保留完整历史。
- 为稳健起见，最近几轮对话总是附在提示词里。即使会话续接失败，模型也能接上上下文。
- 「新开对话」会丢弃会话 id，之后的第一轮不再记得之前的内容。对话记录（`_studio/session.jsonl`）保留。

### 提议：确认之前不落卡

- AI 的修改建议以 ```proposals 代码块附在回复末尾，格式为 `[{module, op, target?, value, reason}]`。解析时，正文与提议分开保存。
- 无效的提议（缺字段、模块或操作不被支持）会被计数并丢弃，不会生效。
- 提议保存在 `_studio/proposals.json`，状态为待确认、已采纳或已拒绝。
- 只有点击「采纳」才会写入卡片；采纳前会重新校验，失败则保持待确认，并记录错误原因。
- 「拒绝」只改状态，卡片不变。已处理的提议不能再次处理。

### 允许的提议

| 模块 | 操作 | 说明 |
|---|---|---|
| premise | set | 替换核心命题 |
| brief | set | 更新部分题材字段 |
| ideas | add / set | 新增灵感（来源记为 AI），或按 id 修改文字、标签、状态 |
| open_questions | add / set | 新增问题，或按 id 修改文字、关闭状态 |
| world | add | 向 rules / locations / factions / timeline / taboos 之一追加条目 |
| cast | add / set | 新增角色（需要 name），或按 id 更新字段 |
| plot | set | 替换 acts / twists / endings 中给出的键 |

### 接口

`chat_send`、`chat_history`、`chat_new`、`list_proposals`、`accept_proposal`（可带修改后的值）、`reject_proposal`，均在 `novel_writer/brainstorm/api.py`。

## 已知限制（B2）

- 没有快捷回复按钮，AI 的提问只能通过自由输入回答。
- 「修改后采纳」目前只有接口，界面上只有直接采纳和拒绝。

## B3：世界观、角色、质检

### 世界观与角色（直接编辑）

- 页面「世界观」标签：按分类（规则、地点、势力、时间线、禁忌）增删条目。规则可以填写代价。
- 页面「角色」标签：新增角色（名字、定位、想要、需要、缺陷），展开后可编辑全部字段，或删除角色。
- 这些编辑是作者本人的操作，立即生效；与 AI 的提议不同，不需要再确认。
- 关系写作「角色id:说明」每行一条，例如 `char_abc123:弟弟`。质检会检查 id 是否存在。

### 质检（只报告，不改卡片）

- **结构检查**（确定性，不调用模型）：命题为空；角色没有定位；关系指向不存在的角色；角色重名；规则没有代价；幕没有转折点；仍有未关闭的开放问题。
- **AI 审阅**（可选，调用一次模型）：检查设定之间的矛盾、动机是否站得住、说教风险、含糊之处。每次最多 8 条。
- 结果保存在 `_studio/checks/<id>.json`，记录内容哈希。质检前后卡片内容完全一致（测试中有专门的断言）。
- 发现项只是建议。若要修改，请在世界观或角色标签中手动调整，或通过对话提议。

### 接口

`world_add`、`world_remove`、`cast_add`、`cast_update`、`cast_remove`、`run_check`（参数 `use_llm`）、`check_history`，均在 `novel_writer/brainstorm/api.py`。

## 已知限制（B3）

- AI 审阅的默认生成器未经真实模型验证（与 B1、B2 相同）。
- 结构检查只做了几项明确的规则，没有检查剧情与世界观之间的语义矛盾，那部分要靠 AI 审阅。
- 剧情骨架的编辑界面在 B4 加入。

## B4：剧情骨架、备选方案、收敛

### 剧情骨架（直接编辑）

- 页面「剧情」标签：增删幕（标题）、增删每幕的转折点；反转与结局候选各自增删。立即生效。

### 备选方案

备选是同一模块（剧情骨架或核心命题）的另一种走向，存放在 `options/<oid>/`：

- `option.json`：名称、对应模块、优缺点、状态（open 待定 / merged 已合并 / discarded 已放弃）。
- `content.json`：备选的内容。
- `replaced.json`：合并时被替换下来的主线，用于撤销。

操作：

- **新建**：以当前主线为起点复制，或填入完整内容。创建**不会改变主线**。
- **对比**：显示备选与当前主线的统一差异格式（diff）。
- **合并为主线**：主线被替换，原主线保存到 `replaced.json`；备选保留，状态改为 merged。
- **撤销合并**：用 `replaced.json` 恢复主线，备选回到待定。
- **放弃**：状态改为 discarded，不能再合并。

备选提议（AI）：`options` 模块的提议只能新建备选，不能直接合并。采纳后备选出现在列表中，主线不变。

### 收敛模式

对话的模式新增「收敛」：AI 把已有想法收束成 2–3 个备选方向，逐项说明优缺点，给出推荐但不替作者决定。需要时可以用 options 提议把某个方向登记为备选。

### 接口

`plot_add_act`、`plot_remove_act`、`plot_add_beat`、`plot_remove_beat`、`plot_add_item`、`plot_remove_item`、`option_create`、`option_list`、`option_diff`、`option_merge`、`option_discard`、`option_undo_merge`，均在 `novel_writer/brainstorm/api.py`。

## 已知限制（B4）

- 备选只支持剧情骨架和核心命题。世界观、角色、题材卡的备选暂不支持。
- 备选之间没有合并（把两个备选的部分内容拼在一起），只能整体替换主线。
- 收敛模式的推荐质量取决于默认运行器，未经真实模型验证。

## B5：交接到新小说

页面最后一个标签是「交接」。

### 流程

1. 只能交接**定版**的版本（至少定版一次）。默认交接最新版本，也可以选择更早的版本。草稿中未定版的改动不会被交接。
2. 调用 `tool_api.create_novel` 创建小说工作目录（默认位置 `data/novels/`，与新建小说相同）。
3. 题材卡通过 `tool_api.save_intake` 写入小说的新建向导意图。字段一一对应，题材卡没填的字段保持为空。
4. 整个版本快照复制到小说的 `_studio/seed/brainstorm/v<n>/`，并写入 `source.json`，记录构思项目路径、版本号、内容哈希与交接时间。
5. 生成构思种子摘要 `_studio/seed/brainstorm_seed.md`：核心命题、世界规则（含代价）、地点、势力、禁忌、主要角色、剧情幕与转折点、反转、结局候选、尚未决定的问题。摘要超过 3000 字时截断，并指向完整文件。
6. 构思项目的元信息记录 `linked_novels`。同一构思可以交接多次，每次生成一本新小说。

### 种子如何进入写作

- 运行器构造每一步的提示词时，把「向导意图」与「构思种子」一起放进「作者意图」段落。种子标明「仅供参考，与蓝图冲突时以蓝图为准」。
- 种子单独存放在 `brainstorm_seed.md`，重新保存向导意图不会删除种子。
- 种子与小说之后不自动同步。

### 接口

`handoff_to_novel(root, version?, title?, novels_dir?, index_file?)`、`linked_novels(root)`、`snapshot_version(root, note)`。

## 已知限制（B5）

- 只支持整包交接。部分导入（例如只导入角色）暂不支持。
- 没有「从构思包重新导入」。交接后的小说与构思各自独立，需要的话只能手动复制。
- 种子通过提示词注入，不是作为每个步骤的输入文件。这意味着步骤可以读到种子的摘要，但不会自动读取完整的卡片文件；完整文件在 `_studio/seed/brainstorm/v<n>/` 中，需要时可以让 agent 读取。
- 交接会创建新的小说目录，不会合并到已有的小说中。

## 对话过程日志

对话区会显示 agent 在回复之前的全部过程输出，而不只是最后的回答。

### 显示什么

- 工具调用（工具名与参数）、工具结果（完整内容，不截断）、工具错误；
- 提示、警告、错误；
- 技能加载、重试提示、统计等框架输出。

### 实时与保留

- 作者发出一句话后，回复在后台线程中运行。对话区会每秒刷新一次「本轮过程」，实时显示进展。
- 结束后，过程日志保存在 `_studio/chat_runs/<轮次>.jsonl`；每条助手回复下方都有「本轮全部过程（N 条）」，可以展开查看。
- 作者的话在 agent 开始运行前就记录下来，中途刷新页面也不会丢失。

### 实现

- `novel_writer/brainstorm/runlog.py::Capture` 临时包装框架 `mini_agent.ui.renderer.R` 上的 `print_*` 方法：记录后仍调用原函数，终端输出不变，退出上下文时恢复原状。
- 对话轮次由 `chat.start_turn` 启动，`chat.run_state` 读取状态与日志；接口为 `chat_start` 与 `chat_run`。

### 限制

- 模型的推理过程（reasoning 流式输出）**不显示**，只显示框架通过 `print_*` 输出的过程信息。
- 捕获是进程级的，同一时间只能有一轮对话在捕获；如果同一进程中还有别的 agent 在输出，这些输出也会被记录到当前轮次。
- 包装期间，框架的 `print_*` 调用会经过一层转发；如果框架以后新增了输出函数，需要把它加入 `runlog.CAPTURED`。

## 整理对话：把讨论变成产出

对话区底部的「📝 整理对话」是手动功能，只有点击「▶ 整理」才会运行。

### 范围与模块

- 范围：「上次整理之后的全部对话」，或「最近 N 轮」（一轮 = 作者一句 + 助手一句）。
- 模块：可以只选几个，例如只整理角色。超出所选模块的条目会被丢弃，并在结果中列出原因。
- 检查点：整理成功后，`_studio/distill/state.json` 记下已整理到的位置。下次默认从这里开始。失败时检查点不推进，对话不会被跳过。

### 结果

- **待确认的修改**：每条是一个提议，带批次号和来源轮次（对话记录的编号）。它们出现在「待确认的提议」列表里，采纳前不会写入卡片。
- **Markdown 纪要**：保存在 `output/纪要/纪要_<时间>_<批次>.md`，包含讨论要点、已形成的决定、被否定的方向、仍待定的问题，每条都标注对话编号。纪要在对话区底部可以直接查看。
- **重复去重**：新增的灵感或开放问题如果与已有文字完全相同，会跳过。

### 冲突处理（通过对话）

整理出的内容与现有卡片不同时，会标记为冲突（⚠），显示现有内容与差异。冲突**不会自动覆盖**。

点击「与 AI 在对话里处理这个冲突」，系统会把双方内容整理成一条消息发到对话里，由 AI 权衡取舍。AI 的结论以新提议的形式出现，作者确认后才生效。这样冲突处理本身也有完整的对话记录。

### 接口

`distill_run(root, modules, scope, recent_rounds)`、`distill_conflict_prompt(root, pid)`、`distill_minutes`、`distill_read_minutes`、`distill_pending_range`。

## 已知限制（整理对话）

- 整理依赖模型的提取质量，还没有用真实模型验证。建议先用较短的对话试跑。
- 一次整理使用的对话范围较大时，模型的输入会很长；超长对话建议分段整理。
- 纪要是模型生成的，只保证结构，内容需要作者核对。
- 冲突只能通过对话处理，没有单独的「保留现有 / 采用新内容」按钮。

## 整理过程的实时日志

点击「▶ 整理」后，整理在后台运行，过程逐步显示在整理面板中（每秒刷新）：

- 模块与对话范围（第几条至第几条，有效条数）；
- 提示词大小，以及开始调用模型；
- 模型返回的大小，解析出的候选数；
- 每条候选的处理结果：待确认、与现有内容冲突（附说明）、与已有内容相同而跳过、模块不在范围内而跳过、格式无效；
- 纪要写入的位置，检查点推进到的位置；
- 结束时的汇总：待确认条数、冲突条数、跳过条数。

模型调用期间，agent 自己的过程输出（如工具调用）也会被记录到同一份日志中。

整理完成后，日志保存在 `_studio/distill_runs/<运行编号>.jsonl`，面板中可以展开「上一次整理的过程」查看。失败时日志以错误结尾，检查点不推进。

实现：`distill.run(..., log=...)` 逐步回报过程；`distill.start_run` 在后台线程中运行并写入日志文件；`distill.run_state` 读取状态与日志。接口为 `distill_start` 与 `distill_state`。


## 生成设定文档（对话 → 世界观与设定）

在构思页「整理对话」下方的「📖 生成设定文档」，把对话整理成一份完整的小说世界观与设定 Markdown，之后可以直接当灵感素材创作。

- **只有点击才运行**，默认不会自动生成。
- **素材只用对话**，不并入卡片；范围：全部对话 / 最近几轮。
- **直接调用 LLMHelper**（单轮、无工具），输出 Markdown 正文，不要求 JSON。
- **文档结构**：一句话概述、题材与基调、世界观（规则 / 地点 / 势力 / 时间线 / 禁忌）、角色设定、剧情骨架、核心悬念与伏笔、未定与待讨论、创作灵感钩子；每条设定标注对话编号。仅被提到、未被认可的想法进「未定与待讨论」，被否定的方向不写入设定。
- **产出**：`output/设定/设定_<时间>.md`，每次生成一份新文件，不覆盖旧的；界面可预览与下载。
- **不影响其它功能**：不改卡片、不进待确认列表、不推进「整理对话」的检查点。
- **失败时**：过程日志完整显示模型原始输出，并存档到 `_studio/distill/raw_<时间>.txt`。

整理对话的相关改动（直调 LLMHelper、json_repair 修复、格式规整、全部范围）见 `brainstorm/distill.py` 的模块说明。

## B6-1：历史对话列表与切换（2026-10-20）

一个构思项目可以有多段对话。对话区顶部是「历史对话（仅本项目）」选择框，可切换到之前的任一段继续聊，也可点「新对话」开始一段新的。

- **只含当前构思项目的对话**：索引与记录都在项目目录内，不会跨项目出现。
- **存储**：`_studio/conversations.json`（索引：`active` 当前对话 id，`items` 每段的元信息与文件路径）；每段的记录在 `_studio/conversations/<id>/session.jsonl`，框架会话 id 在同目录的 `agent_session.json`。
- **旧数据兼容**：旧版单段对话（`_studio/session.jsonl`）第一次访问时自动登记为一段（标题取其第一句话），文件原地不动。索引缺失或损坏时会从磁盘重建，不丢对话。
- **新对话**：切换到空白对话并续接它自己的框架会话，不会带入其它段的上下文。若当前对话还没有任何内容，直接沿用，不堆积空对话。
- **后台轮次绑定开始时的对话**：发出一句话后即使切换了对话，回复仍写回原来那一段。运行中（有轮次进行时）禁止切换，避免界面与记录错位。
- **列表排序**：最近更新的在前；显示标题（首句前 18 个字）、条数与更新时间。
- **与其它功能的关系**：「整理对话」与「生成设定文档」读取的是**当前对话**的记录。

接口：`api.chat_list(root)`、`api.chat_switch(root, cid)`、`api.chat_new(root)`；底层 `chat.list_conversations / switch_chat / new_chat / current_conversation`。

行为变化：原先「新开对话」会丢弃框架会话但保留同一份记录；现在会真正开一段新对话，旧的记录保留在列表里。

测试：`tests/test_brainstorm_b6a.py`（迁移、索引重建、新开/切换/续接隔离、跨项目隔离、后台轮次绑定、接口与页面）；`tests/test_brainstorm_b2.py::test_new_chat_starts_fresh_session_and_keeps_old_conversation` 随之更新。
