# 大纲先行模式（outline_first）

> 设计与分期：`next_doc/novel_writer_outline_first_plan.md`（仓库根目录 next_doc/）。
> 当前进度：**O0–O5 全部完成**（大纲先行已对外开放）。

## 已确定的规则（设计）

- 每章简述：300–600 字的场景段落式，另附结构化的关键内容（必须事件、人物状态变化、伏笔动作、章末钩子）。
- 关键内容锁定，写作不得偏离；非关键内容可发挥，但须回写简述并记录原因。
- 写作模式每本书单独选择，默认直写。
- 简述修改后已写章节的处理：`brief_change_policy` = `ask`（默认，由作者决定）或 `auto_rewrite`（自动重写，复用修订流程执行器）。

## 使用流程（大纲先行）

1. 新建小说时选「大纲先行」，并选定简述变更策略。
2. 流水线先补全蓝图 → 逐幕生成简述 → 停在「章节简述确认」。
3. 在「📚 章节简述」页逐章编辑 / 反馈改写 / 整幕重排，校验全部通过后点「确认全部简述」。
4. 逐章写作；每章写后自动做关键内容核对（未实现的关键内容会被定向修正，两次仍不过则交给你），非关键偏离自动记入偏离记录。
5. 之后若再改简述：先到「章节简述」页处理受影响章节（重写 / 保留 / 忽略），再重新确认并继续。

**成本提示**：大纲先行比直写多一轮完整简述生成，以及每章一次关键内容核对（LLM 调用明显增加）。

**整体限制**：界面部分未做浏览器验证（沙箱无 streamlit）；全部大纲先行机制未在真实 LLM 下端到端验证；关键内容核对靠 LLM 判断，可能误判（误判时最多修正两次后交给作者，不会静默放行）。

## O4 已实现

| 项目 | 位置 | 说明 |
|---|---|---|
| 写作依据记录 | `brief_sync.record_written`，`章节简述/_sync.json` | 关键内容核对通过时记下该章所依据的简述（含完整内容与哈希）；确认简述时为尚无记录的章节补记 baseline（只填不覆盖，作回退基准） |
| 受影响判定 | `brief_sync.affected` | 章节已有正文 + 有基准（written 优先）+ 当前简述哈希 ≠ 基准 + 作者未对当前哈希做过处理 → 「简述已变更」，并给出逐项差异（叙述、事件、人物状态、伏笔、钩子、章名）。偏离记录不在简述 JSON 内，不触发 |
| 逐章处理 | `brief_sync.keep / ignore / rewrite` | 保留：以当前简述重记为写作依据；忽略此次变更：只对这一版不再提示，再改一次会重新提示；重写：提交一条「作者反馈修订循环」请求（意见 = 简述差异），由 worker 逐章执行 |
| 步骤状态 | `rebaseline_stale` | 简述一改，写作步骤与核对步骤会变「需重跑」。保留/忽略：两者重新基线；重写：仅写作步骤重新基线（避免整章重写），核对步骤保持「需重跑」，重写后由流水线验证新简述 |
| 策略 | `settings.brief_change_policy`，`brief_sync.apply_policy` | `ask`（默认）：只提示、不自动执行任何操作；`auto_rewrite`：**确认简述时**对全部受影响章节提交重写（单章失败不影响其它章，失败原因返回），界面另有「现在按策略提交重写」按钮 |
| 旧书 | `brief_sync.adopt_current_as_written` | O4 之前写的章节没有记录；确认当前简述与已写正文一致后，可调用它补记（否则这些章节在 baseline 缺失时不会被标记） |
| 接口与界面 | `tool_api.brief_changed_chapters / resolve_brief_change`，`ui/briefs.py` | 「章节简述」页顶部列出受影响章节（折叠显示差异）与三个按钮 |

**偏离原计划**：原计划写复用 `revision_flow` 执行器，但它要求全书终审后的完稿基线，写作进行中不可用，故改用「作者反馈修订循环」请求（同样逐章、可停止、可续跑）。

**已知限制**：①界面部分只做了静态检查，沙箱无 streamlit，未做 AppTest/浏览器验证；②真实 LLM 下的重写效果与核对未验证；③重写请求提交后，worker 要处于运行中才会执行；④O3 时期的旧书若没有记录，需先调用 `adopt_current_as_written`。

## O3 已实现

| 项目 | 位置 | 说明 |
|---|---|---|
| 写作输入 | `steps.chapter_steps(outline=True)` | `write_chapter` 的输入加入本章简述 JSON；指令明确“简述为结构依据，关键内容不得偏离，非关键内容可以发挥” |
| 核对步骤 | `ch{nn}.brief_check`，`brief_check.py` | 写作后、乱码守卫前运行。把关键内容拆成编号条目（e1…、s1…、f1…、h1），LLM 逐条判断正文是否实现，并列出非关键偏离（只读，不改正文） |
| 定向修正 | `brief_check._rewrite` | 有关键条目未实现时，带着缺失条目修正本章（revision-editor 式定向改写，其它段落不动；字数明显失控则不写入），最多两次 |
| 交给作者 | `NeedsUser` → waiting_user | 两次修正后仍未实现，步骤挂起，把缺失条目与核对依据交给作者决定 |
| 偏离记录 | `大纲规划/章节简述/偏离/第NNN章.json`，并渲染进 `.md` 的「偏离记录」小节 | 非关键偏离自动追加（位置、简述原文、正文实际写法、原因；原因缺失记为「未说明」）。偏离存放在简述 JSON 之外，因此不改变简述哈希，不会让确认失效，也不会让写作步骤过期 |
| 计划顺序 | `steps.chapter_steps`、`pipeline` | 大纲先行每章：写作 → 关键内容核对 → 乱码守卫 → 机器校验 → …；直写模式下步骤集合不变（测试守住） |

**注意**：修改已确认的简述会让已写章节的写作步骤变为过期（它的输入包含简述文件）。O4 起请先在「章节简述」页处理受影响章节（见下），再运行流水线，否则流水线会整章重写。

## O2 已实现

| 项目 | 位置 | 说明 |
|---|---|---|
| 版本历史 | `brief_review.py`、`大纲规划/章节简述/_history/第NNN章.vNNN.json` | 每次改动（编辑、回退、单章改写、整幕重排）前保存旧版本，附原因与时间；可回退，回退本身也记为新版本 |
| 直接编辑 | `brief_review.save_edit`、界面「章节简述」页 | 先按生成时的同一套规则校验，失败则不写盘并列出全部错误 |
| 单章反馈改写 | `brief_review.rewrite_chapter` | 作者意见 + 当前简述 + 前后章章末钩子交给 LLM 改写本章；LLM 同时给出可能受影响的章节，过滤越界与自身后展示给作者，由作者决定是否检查 |
| 整幕重排 | `brief_review.regenerate_act`、`brief.generate_act(feedback=...)` | 整幕带着作者意见重新生成；改动前每章旧版本入历史 |
| 确认检查点 | `brief_review.confirm` | 仅当 `brief_review` 处于 waiting_review 时可确认；确认前每章必须通过校验；记录每章哈希到 `_confirmed.json`，批准检查点 |
| 确认失效 | 检查点输入包含 `第*章.json` | 任何简述改动都会让检查点变为 stale（需重新运行到确认点再确认）；编辑保存和改写也会主动使已确认状态失效 |
| 冻结检测 | `brief_review.confirmation_status` | 绕过界面直接改文件时，按哈希报告哪些章节在确认后被改动 |
| 界面 | `ui/briefs.py`，导航「📚 章节简述」 | 确认状态与按钮、章节表（校验与版本数）、编辑表单、版本历史与回退、单章反馈改写、整幕重排（后台执行，实时日志，最新在下）、操作日志 |

## O1 已实现

| 项目 | 位置 | 说明 |
|---|---|---|
| 简述数据 | `大纲规划/章节简述/第NNN章.json` | 唯一事实来源：叙述简述、关键内容（must_events / must_states / must_foreshadow / must_hook）、偏离记录（O3 使用） |
| 阅读版本 | `第NNN章.md` | 由 JSON 渲染，供阅读；`_index.md` 列出全部章节 |
| 按幕生成 | 步骤 `brief_draft:<幕号>` | 每幕一个步骤，LLM 一次写出该幕全部章节；输出经确定性校验后才落盘，失败的幕带错误重试一次，仍失败则步骤失败且不写半成品 |
| 确定性校验 | `brief.validate_brief` | 章号与蓝图一致、叙述 300–600 字（非空白字符）、must_events 非空、must_states 非空且人物须在人物档案中、must_foreshadow 为 F+数字且须在伏笔账本中、must_hook 非空、新简述不含偏离记录 |
| 计划顺序 | `pipeline.build_plan` | 大纲先行时：先补全所有缺失幕的蓝图条目（plan_act / blueprint_extend）→ 结局设计 → 逐幕简述 → 确认检查点 → 章节写作。所有简述在任何章节写作之前完成 |
| 上下文衔接 | 提示词 | 每幕提示带上前一幕最后一章的章末钩子，保持衔接 |

输出的规范 JSON 结构见 `brief.py` 文件头。

## 现阶段的行为

- 直写：与之前完全一致（测试守住计划不变）。
- 大纲先行：简述生成、确认、写作接入与核对、简述变更处理均已可用，向导已开放（O5）。

## 配置存放位置

与 `pause_after_ideation` 等每本书的开关一致，存放在工作目录的 `studio_settings`（即 `ws.settings()`），而不是 `项目状态/workspace_config.json`。计划文档已同步。
