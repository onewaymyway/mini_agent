# 构思修订：按一个新思路整体调整（concept revision）

在规划页顶部的「🧭 构思修订」里，写下一个新的思路，选择要调整的范围，系统会按这个思路重写所选产物，并把依赖它们的步骤标为需重跑。

## 可调整的范围

| 范围 | 产物 | 说明 |
|---|---|---|
| 蓝图 | 蓝图草稿与可读大纲 | 全书级改动，运行时需要在总控台确认 |
| 主题 | 主题设计文档 | 复用「主题设计」步骤（theme-architect） |
| 节奏 | 节奏规划 | 复用「节奏设计」步骤（pacing-architect） |
| 世界观 | 世界圣经 | 复用「建立世界观设定」步骤（world-builder） |
| 角色 | 主要角色的人设卡与角色档案 | 复用人设设计与建档步骤，之后刷新角色索引 |
| 开篇 | 前三章开篇设计 | 复用「前三章开篇设计」步骤（hook-designer） |

## 流程

1. 提交请求：生成一条 `concept` 请求（`_studio/requests/concept_<id>.json`），步骤 id 为 `cpt.<id>`。
2. 运行：在规划页点「▶ 运行」，或在总控台运行该手动步骤。
3. 备份：运行前，所选范围的现有产物复制到 `_studio/concept_backups/<id>/`，并记录清单（包括修订前不存在的文件）。
4. 修订：每个范围的步骤指令前加上新思路（「这是本次修订的核心方向，优先级高于原有设定」），其它要求不变。
5. 记录：修订写入的文件记为**作者修改**（writer = author）。因为计划中的修订步骤排在最后，若记为执行器写入，下游不会被标记。
6. 标记：调用 `mark_stale`，依赖这些产物的已通过步骤标为需重跑。结果里列出实际改动的范围与需重跑的步骤数。

## 蓝图的特殊规则

- 修改蓝图前需要确认（与 L4 修订一致）。未确认时不备份、不调用执行器。
- 在总控台选择「确认，改写蓝图」并点「提交答复并重跑此步」后，步骤会**立即重跑**（答复提交与运行是一起完成的）。
  蓝图范围实际调用的是 `plan_blueprint`，产出草稿（校验规则与首次生成一致）。
- 蓝图改写后，依赖蓝图的其它范围（节奏、世界观、角色、开篇等）**不会在同一次请求中运行**，因为它们应基于新的蓝图拆分结果。结果里会列出这些「待后续」的范围，请在「蓝图拆分」完成后重新提交。
- 角色修订需要已有蓝图（用于确定主要角色）。

## 撤销

修订完成后，点「撤销，恢复修订前」，备份会被恢复，修订前不存在的文件会被删除，下游步骤标为需重跑。撤销本身也会记为作者修改。

## 接口

- `tool_api.create_concept_revision(workspace, direction, scopes)`
- `tool_api.list_concept_revisions(workspace)`
- `tool_api.restore_concept_revision(workspace, rid)`

实现：`novel_writer/concept_revision.py`；请求类型与步骤展开：`novel_writer/ondemand.py`；界面：`ui/planning.py`。
测试：`tests/test_concept_revision.py`（9 项）。

## 修复记录

- 后台任务面板：构思修订请求缺少标签，导致 `KeyError: 'concept'`，已补全标签表，并让任务标题显示修订思路。
- 总控台「提交答复并重跑此步」：以前只写答复、不运行，现在提交后立即以单步模式运行。
- 蓝图范围：修订分派中缺少 `blueprint` 分支，确认后报 `未知范围`，已补上。

## 构思审核（开关）

新建小说时可以勾选「构思完成后暂停，等我审核」（之后可在规划页「🧭 构思修订」里开关）。开启后：

1. 构思步骤（主题、节奏、角色、世界观、开篇设计）完成后，流水线停在「构思审核」检查点（`ideation_review`），不会直接进入章节写作。闸门强制为审核，不受挡位影响；只有显式「跳过」可以绕过。
2. 运行该步骤会生成 `大纲规划/构思审核清单.md`：蓝图概要、主题、节奏、世界观、角色外形（缺失项标注为待补充）、开篇设计。
3. 作者在总控台批准后，流水线继续进入章节写作。
4. 不满意时，用「构思修订」提出新的思路，点「▶ 运行」即可。修订完成后，系统会**自动续跑**：
   依赖变化的构思步骤（如节奏设计）自动重跑，不再逐步弹出「需重跑确认」，直到停在构思审核；清单此时已是最新内容，作者再次审核即可。撤销修订同样会自动续跑到构思审核。
   续跑只覆盖构思范围（审核之前的步骤）；托管挡位下构思审核仍需作者批准，不会被自动通过。续跑结束后标记自动清除。

这样就形成「审核 → 修订 → 重新审核 → 批准」的循环。开关关闭时计划与之前完全一致。

实现：`novel_writer/ideation_review.py`（清单与刷新）、`steps.ideation_review_step`、`pipeline.build_plan`（开关开启时插入）、`gates.resolve_gate`（强制审核）、`concept_revision`（修订与撤销后刷新审核）。测试：`tests/test_ideation_review.py`（10 项）。

## 修改意见自动重跑（托管挡 G5）

托管挡对「需重跑」的处理分两类：

- **派生或报告类步骤**（幕末审稿、风格、节奏、主题、世界观检查等）：自动重跑，只覆盖自身产物。
- **会改写正文或全书设定的步骤**（节奏设计、人设、世界观等）：默认停下来等作者确认（`stale_confirm`）。

只有**根据修改意见**产生的改动，才会让第二类步骤也自动重跑。涉及的修改入口：构思修订、撤销修订、章节修订（L1–L4）、修改循环、作者确认的蓝图级修订。这些入口完成并产生改动后，会置位 `revision_autorun` 控制标记；运行器据此自动重跑需重跑的步骤。

- 没有需重跑的步骤时，标记清除；每次运行结束也会清除，因此之后无关的上游变化仍然需要确认。
- 构思审核依旧需要作者批准，托管挡不会自动通过。

测试：`tests/test_revision_autorun.py`（4 项）。

## 日志与运行记录

- 构思修订本身（`cpt.<id>`）不调用 agent，agent 在它的子步骤 `cpt.<id>.<范围>`（如 `cpt.<id>.theme`、`cpt.<id>.characters.<角色>`）里运行，运行目录为 `_studio/steps/cpt.<id>.<范围>/run_N/`。
- 子步骤每次运行使用新的 `run_N`（`concept_revision._next_run_no`），不再固定 `run_1`：重跑不会覆盖上次的 `prompt_1.md`，`agent.log` 也不会把多次运行混在一起。
- 「指标 → 步骤详情」选择 `cpt.<id>` 时，会列出各子步骤（回执、prompt、agent 输出末尾 200 行；完整内容见对应 `agent.log`）。普通步骤的详情同样带 agent 输出末尾。接口：`tool_api.step_detail`（新增 `agent_log_tail`、`substeps` 字段）。
- 实时过程看总控台「📜 运行输出」：skill 调用一律走子进程并镜像进 run.log（见 `step_timeout.md`「日志可见性」），不受是否设了步骤时限影响。

测试：`tests/test_log_visibility.py`。

## 构思审核遇到损坏的角色文件

构思审核清单要读取全部角色文件。某个角色文件格式损坏（典型：字符串里夹了英文双引号，如 `psychology` 字段不是合法 JSON）时：

1. 先做确定性修复（`character_store.repair_dir`：BOM、缺 `---`、整份 JSON、多行值等），run.log 记「🔧 构思审核：已确定性修复…」。
2. 仍不合格则抛**可修复错误**（`RepairableDataError`，校验器 `characters`，点名出问题的文件），worker 把问题与文件交给 `data-repair` skill 修复后重跑（`settings.auto_repair`，默认开，最多 `repair_max_attempts` 次，见 `repair.py`）。
3. 修复次数用尽后停下等人处理，不再无限重试。

以前这里直接抛不可修复的 `CharacterStoreError`，自动重跑和「不停机」重置只会反复报同一个错（日志里 ideation_review 连续失败十几次）。测试：`tests/test_ideation_review.py` 最后两例。
