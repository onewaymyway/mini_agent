# article_to_video — 项目说明

> 把一篇 Markdown 文章改编成讲解视频（配音 + 字幕 + 动态画面 + 署名与水印）。

## P0 已确定的规则

- **作者名**：界面或命令行输入优先；留空时依次尝试 front matter（`author:` / `作者:`）、文首“作者：”行；都没有则留空并警告。**不让模型猜作者。**
- **水印**：文字水印，最多 60 字。水印文字为空时自动关闭。位置与模式不合法时取默认值并给出警告。
- **署名与水印可随时修改**：「📚 项目」页保存时只改 `project.json`，源文章与块数据保持不变，后续阶段据此判断是否需要重跑。
- **块 ID**：`s{章号:02d}.p{序号:02d}`，章号按一级标题递增，一级标题之前为 `s00`。
- **时长估算**：按 4.2 汉字/秒。参考文章 7,022 汉字，全文朗读约 27.9 分钟。

## P1 已确定的规则

- **两种生成方式**：`rules`（离线，确定性，不调用模型）与 `miniagent`（LLM）。规则版章标题取一级标题，论点取该章第一节的首个完整论点句，不做改写，质量有限，适合作为兜底与人工起点。
- **分节摘要**：按一级标题累加成组，每组不超过约 4000 字符；超长节在块边界切开。
- **忠实度**：摘要中的 `quotable` 与 `key_numbers` 必须是原文逐字片段（去空白与 Markdown 标记后比较），否则带问题清单重试一次；仍不合格则**不写任何结果**，原始输出存入 `plan/raw_*.txt`。
- **V1 覆盖**：每个小节必须且只能出现在一个章或取舍报告中；金句必须来自摘要登记的原话；章数超出 5～7 只给警告。
- **断点续跑**：LLM 摘要记录输入哈希（含提示词版本与原文），输入未变时复用，不重复调用。
- **C0 确认**：任何编辑都会取消确认；已确认的大纲默认不能被覆盖，需显式勾选。

## P2 已确定的规则

- **口播稿按章生成**：每章一个 `parts/<章ID>/script.json`；段落 ID 为 `P01.b01`；句子带 `quote`（金句）与 `emphasis`；`tts` 由词典自动生成，字幕仍显示原写法。
- **V2 忠实度**：句中的数字、年份、英文词必须出现在本章原文中；标记为金句的句子必须是原文逐字片段；引用的小节必须属于本章。
- **V3 可读性**：不得含 Markdown 符号与裸公式；单句超过 60 字报错，超过 40 字警告。
- **节奏**：condensed 模式下，章的字数应在预算 ±15% 内。节奏问题与硬错误分开处理：硬错误必须修正，节奏问题重试后仍存在则接受并记为警告（设计文档：超限留给人工）。
- **重试**：每章最多 3 次；硬错误或节奏问题都会把问题清单带入下一次提示词。仍有硬错误则不写结果，原始输出存为 `raw_last.txt`。
- **断点续跑**：输入（章节原文、大纲、术语、词典、上一章结尾、人设）未变则复用。
- **C1 确认**：编辑后本章变为未确认；确认前必须通过所有硬校验。
- **后台写稿**：界面中写稿在线程里运行，可随时「请求停止」；模型请求每 0.2 秒检查一次停止信号，停止后不写入未完成的结果。

## P3 已确定的规则

- **逐句合成**：每句一个 WAV（`parts/<章>/audio/<句ID>.wav`）；句子 ID 形如 `P01.b01.s01`。音频统一为 24kHz 单声道 16bit。
- **缓存**：键 = 音色 + 语速 + 朗读文本 + 引擎链。编辑口播只重配改动的句子；换引擎链会全部重配。每句完成即写入 `manifest.json`，停止或失败后可续跑。
- **双声线**：主讲用 `narration_voice`，`quote: true` 的金句用 `quote_voice`；每章引文音色最多 2 句（可设），超出的改用主讲音色并给出警告。
- **语速**：beat 的 pace 映射到 -10% / 0 / +10%；开场（hook）默认 +5%。
- **停顿**：句内停顿 `sentence_gap_sec`（0.15 秒）；段末停顿用 beat 的 `pause_after_ms`；章首章尾各 0.5 秒。
- **时间轴不变量**（测试覆盖）：`end = start + duration`；下一句 `start = end + gap`；`total = 末句 end + 末 gap + tail`。
- **不静默降级**：引擎链全部失败时报错并列出每个引擎的原因；只有 `--stub` 或界面勾选"仅流程验证"才生成静音，且时间轴带 stub 警告。
- **前置条件**：大纲已确认（C0），且该章口播稿已确认（C1）。
- **试听**：写入 `preview/`，不改变项目的音频与时间轴。

## P4 已确定的规则

- **分镜两种引擎**：`rules`（规则版，离线，确定）：画面类型由原文结构决定：代码块链式流程/回路 → `diagram`；表格 → `table`；公式 → `formula`；列表 → `list`（年份开头 → `timeline`）；金句 → `quote`；其余 → `keypoint`。`llm`（模型版）：模型为每段选择画面类型、写出短条目与插图主题，但结构内容（流程节点与回路、表格、公式、列表、金句原文）一律取自原文，不由模型生成。模型输出中的数字与英文词必须在本段口播中出现，否则带问题清单重试，最多 3 次（插图镜头可以只有画面、不带条目；keypoint 必须有条目）；仍不合格抛错且不写结果，不会静默回退为规则版。分镜文件 `parts/<章>/storyboard.json`，场景 ID 即段落 ID，记录所用引擎。
- **文字密度**：单条文字 ≤ 60 字，超出自动按子句拆分；每张卡条目数上限：卡片/插图 4、列表与时间线 5、流程 6 节点、表格 6 行 × 4 列、公式 3 条解释。
- **逐步出现**：每个状态对应一句（`at_sentence`）；状态多于句子时，同一句内均分时长。表格的条目由行派生，不接受单独编辑。
- **V4 节奏**：相邻三段不得同一类型（生成时自动修正，编辑后不通过则报错）；原文结构未被画面表达时给出提示。
- **一图多用（自动分配）**：插图镜头按顺序轮转分组，组数 = ⌈镜头数 ÷ 每图镜头数⌉，每组第一个镜头为主图，只有主图生图，其余镜头复用主图文件、各自取景。同组镜头相隔约组数段，避免相邻两段看起来像同一张图。取景按组内人数分布（2 个镜头：左 0.2、右 0.8；3 个：0.12 / 0.5 / 0.88），奇数组反向，让相邻组的运镜方向不同。「每图镜头数」默认 2，范围 1–3；设为 1 即关闭复用。点击「🔁 重新分配一图多用」只重算组与取景，不改动文字与类型。
- **取景余量**：插图底图先放大 1.35 倍再取景。正方形图按画幅铺满时宽度恰好相等，没有水平移动余量，不放大则不同取景完全相同。
- **V5 插图**：额度按**需生成的图片数（组数）**计算 = 章时长 × 每分钟上限（默认 2.5，上限 6）。组内镜头数不超过每图上限，每组恰好一个主图；主图的画面主题必须带固定风格锚（含禁文字约束），主题中不得出现写字类词语。
- **插图缓存**：`parts/<章>/images/index.json` 记录提示词哈希；哈希不变则复用，不调用生图。重新生成写入新版本 `_vNNN.png`，旧版本保留。同章第一张生成的图作为后续图的风格参考。渲染时先统一解析每组主图，再逐场景取景；主图主题变化时，组内所有镜头的场景指纹同时变化、全部重绘。
- **降级**：未配置生图 key、已关闭生图或生图失败时，插图按卡片绘制，并在清单与界面中写明原因。渲染不因此中断。
- **过期**：口播稿或视觉设置变化后，分镜标记为过期；过期分镜不能确认或渲染，重新生成会覆盖界面中的编辑。
- **封面不淡入（R21）**：淡入淡出转场下，片头卡、每章封面（时间轴 `lead_in_sec`）、片尾卡从第一帧直接显示，只保留它们结尾的淡出。之前每段都从黑场淡入，所以成片开头和每章封面都是黑屏。`compose/post.py` 的 `join` 接受 `holds`，`compose/export.py` 按段传入。切换与叠化模式不受影响。
- **渲染所有章的画面（R20）**：分镜页「全部章节」区域新增「🖼️ 渲染所有章的画面」。只渲染就绪的章（分镜已确认、未过期、无错误、有时间轴）；未就绪的章跳过并写明原因（如「分镜未确认」）。逐章后台执行，单章失败不影响其它章，全部完成后若有失败则任务以失败结束并列出失败章节；停止请求在下一章开始前生效。已生成的图片复用，不重复生图。
- **时间设置只重建时间轴（R19）**：章封面停留、章首静音、句间停顿、章尾停顿只影响时间轴。配音页提供「按当前时间设置重建本章时间轴」与「重建全部已确认章的时间轴」：按已缓存的句长重算时间轴，不重新配音、不重写分镜、不重新生图；之后在分镜页重新渲染画面（复用图片）再合成。缺句配音时拒绝执行。
- **清空产出并重新生成（R18）**：每个阶段页（大纲、口播、配音、分镜、导出）底部有「清空产出并重新生成」面板，驾驶舱也有同样的面板（仅清空）。范围：本章 / 全部章节（大纲与导出为全部）；起点：默认为本页阶段，可选其它阶段；生图缓存默认保留，可勾选同时清空；必须确认。起点等于本页阶段时清空后直接在后台重新生成（配音会忽略句子缓存）；起点不同则只清空。后端：`pipeline/reset.py` 的 `reset_project`（`reset_part` 保持不变）。
- **时间参数的设置界面（R17 补充）**：设置页「讲解与配音」新增四项：章封面停留（3～10 秒）、章首静音（0～3 秒）、句间停顿（0～2 秒）、章尾停顿（0～3 秒）。界面范围与配置归一化一致；保存后「受影响的阶段」提示需依次重新配音、渲染画面、合成。片头卡、片尾卡与下三分之一条的时长仍是代码常量（`compose/branding.py`），尚未放入设置。
- **章封面停留（R17）**：章封面停留由 `audio.chapter_card_sec` 决定，默认 3.5 秒，下限 3 秒（低于 3 秒会被提高到 3 秒，上限 10 秒）。时间轴中旁白从封面结束后开始，`lead_in_sec` 为实际的章首时长。合成前检查：时间轴的章首时长不足 3 秒，或画面与时间轴不一致时，合成会报错并提示重新配音 / 重新渲染（旧项目需要各重跑一次）。
- **成片封面（R16）**：`compose/cover.py`。画面：本项目第一张真实生成的插图（取自分镜清单 `background_src`，铺满并压暗）；没有插图时用浅色渐变底（不再是黑底）。文字：标题（最多 3 行）、强调线、作者、副标题（全片论点 `thesis`，缺省取第一章一句话）、AI 声明（启用时）。水印与成片相同（文字 / 图片，位置或斜向平铺）。不额外调用生图接口，不增加费用。
- **分镜预览修正（R15 补充）**：一个状态（单帧）的场景不再创建滑块（Streamlit 不接受 min == max，渲染成功后会报错）；状态滑块按场景区分 key，切换场景时不再沿用其它场景的状态序号。
- **模型版分镜的两处修正（R15 补充）**：①公式条目（`formula_explanation`）可以使用原文公式中的符号与变量名，不再因此被判为编造；②模型选了本段不可用的画面类型（原文无对应结构）时，不再整段重试，改为卡片（keypoint），条目缺失时取本段第一句原文；日志会写明「模型选择的 X 在本段不可用，已改为卡片」，分镜记录中保存 `fallback_from`。
- **分镜引擎默认值与指标（R15 补充）**：分镜页的引擎默认选「模型版」（可切换为规则版）。尚未生成分镜时，「需生成图片」与「引擎」显示「—」，不再把图片额度当作已计划数量，也不再误显示「规则版」；额度在提示中给出。
- **分镜过程日志（R15 第二阶段）**：模型版分镜的日志包括：输入规模（段/句/字、图片额度）、每段可选画面与原文结构；每次调用的提示词字数、返回字数与用时；校验失败时列出全部错误（每条一行）与将重试的原因；缓存决策（复用 / 输入已变化 / 强制重新生成 / 尚无分镜）；最终结果与画面类型统计。
- **逐章与全部章节（R15）**：分镜始终按章生成（每章一个 `storyboard.json`）。分镜页除单章「生成分镜」外，提供「⚡ 生成全部章节分镜」：按章节顺序逐章处理，只处理口播稿已确认的章；缺失或已过期的章生成，已是最新的章跳过（保留手工编辑）；勾选「覆盖已有分镜」后全部重新生成（丢失编辑，界面有提示）。单章失败只记录原因，不影响其它章，全部处理完后若有失败，任务以失败结束并列出失败章节；停止请求在下一章开始前生效。Python 入口：`article_to_video.visual.storyboard.plan_all_storyboards(pdir, force=False, engine="rules"|"llm", llm=None)`。
- **渲染清单** `parts/<章>/visuals/manifest.json`：P5 合成的唯一输入。每个场景记录时间段、底图与各状态图层及出现时刻（来自时间轴）。场景缓存键 = 场景内容 + 主题 + 风格锚 + 画幅 + 渲染版本。
- **画幅**：横屏 1920×1080（1080P）/ 1280×720（720P），竖屏 1080×1920 / 720×1280。字号按短边比例缩放。
- **字体**：中文字体优先读取环境变量 `ARTICLE_TO_VIDEO_FONT`，其次系统字体候选；找不到时报错，绝不画成方框。

## P7 已确定的规则

- **挡位**（设计 14.3）：`G0`（默认）四个检查点（C0 大纲、C1 口播、C2 分镜、终审）都需人工；`G1` 只有 C0 与终审人工，C1、C2 通过校验后自动确认；`G2` 全自动，**必须**设置预算上限（生图次数或总耗时至少一项），未设置则拒绝启动。
- **流水线**（`run_pipeline`，`--until` 指定停止阶段）：outline → script → voice → storyboard → render → compose → export。每一步先看已有产物：已确认则跳过，过期则按各自指纹重算；可重复运行。遇到需人工的检查点时 `state=waiting` 并记录原因；人工确认后再次运行即可继续。状态写入 `pipeline.json`。
- **大纲默认用规则版**（离线、确定）；选择模型版时需要文本模型。写稿、分镜（规则或模型版）、配音、渲染、合成、导出各自沿用对应模块的校验与缓存。
- **终审**：`export` 阶段在 G0/G1 需要 `--approve`（界面勾选「确认终审」），否则停在导出之前。
- **预算账本**（`budget.json`，跨次累计）：生图次数只统计真正调用 provider 的次数（缓存复用不计）；超限在调用前抛出，`state=budget_exceeded`。总耗时在阶段之间检查。
- **停止**：沿用 cancel 机制，`state=stopped`；已完成的产物保留，可重新运行继续。
- **多期拆分**（设计第 10 节）：只在章边界拆分；每期总时长不超过 `episode_max_minutes`（默认 15）；超长的单章独占一期。期首「上期回顾」、期末「下期预告」直接取相邻章的一句话（`one_line`），不由模型生成。只有一期时不加期号。
- **多期导出**：每期独立成片，文件名带「_第N期」，中间文件放在 `exports/.work/<后缀>/`，各期互不覆盖；`--merge-all` 额外导出「_全集」。
- **整章重置**（`reset_part`）：必须 `confirm=True`，从指定阶段起删除该章产物并级联；图片缓存（`images/`）保留，重新生图代价高且按指纹复用。
- **驾驶舱**（界面「🧭 驾驶舱」，R7 起为主入口）：顶部流程总览（各步骤状态与下一步）；步骤区的「🧭 总控」选择挡位、预算、运行到哪一步、离线冒烟，显示上次运行、预算使用、分期与各章状态，提供整章重置；其余步骤（大纲、口播稿、配音、分镜、合成导出）在同一区域内切换，不再是侧边栏的独立页面。

## R3 已确定的规则（大纲默认模型）

## R2 已确定的规则（全页面实时日志）

- **日志来源**：服务内部通过线程绑定的 `joblog.bound_log` 写入，未绑定时不写（命令行与测试不受影响）。界面的后台任务线程在 `jobs.start` 中绑定 scope，因此任意深度的模型调用、逐句配音、ffmpeg 编码都会进入对应页面的日志。
- **scope 约定**：大纲 `outline`、口播稿 `script`、配音 `voice`、分镜 `storyboard`、渲染 `render`、合成导出 `export`、导入 `import`、流水线与整章重置 `pipeline`。每个页面底部的面板只显示本页的 scope；项目页显示全部。
- **后台化范围**：页内会运行的操作都在后台线程中执行，可请求停止；编辑、保存、确认类的即时写入不进入后台。页面顶部的状态条与底部面板共同显示运行状态；同一项目同时只允许一个后台任务，运行中相关按钮禁用。
- **页面结构**：业务代码在 `_xxx_body(pdir)` 中，外层 `try/finally` 渲染日志面板，保证页面提前返回时面板仍然显示。
- **时间表边界**：只有流水线（驾驶舱）生成运行级时间表；其它页面的后台任务沿用「后台任务开始/完成/失败」日志，不生成时间表（R1 测试依赖该文案）。

## R1 已确定的规则（实时日志与步骤时间表）

- **日志文件**：`<项目>/logs/job.jsonl`，一行一条 JSON：`{ts, scope, level, message, …}`。scope 区分来源（流水线为 `pipeline`；后台任务默认 `job`，R2 起各页面用自己的 scope）。多线程写入加锁；读取时容忍半行；只读文件尾部（最多 2 MB），界面刷新不会扫描整个文件。
- **结构化事件**：`run_start/run_end` 包住一次运行；`step_start/step_end` 记录步骤，`item` 不为空表示某阶段下的子步骤（如某一章）。步骤记录开始/结束时间、用时、状态（完成/等待确认/失败/已停止）、失败原因与完整堆栈。
- **等待人工确认不是失败**：检查点停下记为 `waiting`（⏸），不进入错误日志。用户停止记为 `stopped`，不当作错误。
- **心跳**：子步骤耗时久时，每 30 秒写一条「仍在进行（已 N 秒）」，卡住时能看出卡在哪一章、等了多久。
- **步骤时间表**（`timeline.build_timeline`）：从日志的结构化事件汇总，增量读取；没有结束事件且当前没有在运行的步骤记为「中断」（多为进程被终止）。
- **流水线埋点**：每个阶段、每一章（大纲、口播、配音、分镜、画面渲染、章合成、导出）前后写事件；已有产物被跳过时写一条「已存在/已是最新，跳过」。`pipeline.json` 在开始时和每个阶段结束后都会保存，不再只在结束时写一次。
- **界面**：驾驶舱的「流水线运行监控」每 2 秒局部刷新，显示运行状态、步骤时间表、后台日志（固定高度、自动滚到最新一行）；运行中可「请求停止」；任务刚结束时整页刷新一次。命令行启动的流水线也会写同一份日志，界面据日志活跃度判断「运行中（由命令行或其它进程启动）」，此时只能查看，不能从界面停止。
- **后台任务**（`ui/jobs.py`）：线程绑定项目日志，任务开始/结束/失败（含堆栈）自动写入；先写日志、再改任务状态，界面看到「已结束」时日志一定完整。

### R1 已知限制

- 日志只覆盖流水线（驾驶舱）；其它页面的日志面板与服务内部日志点已在 R2 完成。
- 流水线在模型/生图/ffmpeg 的单次调用内部还没有更细的日志（只到「某一章的某一阶段」粒度，靠心跳显示仍在进行）。

- 界面的实时刷新与自动滚动只用 Streamlit 自动化测试验证了渲染，没有在真实浏览器里目视确认。

- 流水线在 `storyboard` 过期时，G0/G1 停在人工检查点，不会静默覆盖编辑；G2 会自动重新生成分镜（覆盖未确认编辑）。

## P6 已确定的规则

- **署名来源**：作者、来源链接、各项署名开关与水印设置均在 `project.json` 的 `branding` 中。界面与命令行的更新是**合并**写入（只改提交的字段，其余保持原值）。作者留空则不署名，不猜测。
- **片头标题卡**（默认开）：标题 + 「作者：xxx」，4 秒，程序绘制，背景为主题底色。
- **片尾卡**（默认开）：标题、作者、来源链接（可选）、AI 生成声明（可选），5 秒。
- **下三分之一条**（默认开）：「原文｜标题 · 作者」，片头结束后 5 秒出现，持续 4 秒，左下方半透明条带。只有在它结束时早于片尾卡开始时才加入，短片不会压住片尾卡。原文标题超过 22 字时截断为「…」形式。
- **角标**（默认关）：「原文作者：xxx」，左上角，全程显示，需要填写作者。
- **文字水印**：程序绘制，字号随画面宽度缩放；透明度为 0–1。**图片水印**：项目内相对路径的 PNG（保留透明通道），目标宽度按 `scale` 缩放。
- **水印位置**：`top_left / top_right / bottom_left / bottom_right / center`，或 `diagonal_tile`（斜向平铺，整幅画面，防裁剪）。位置与模式分开：`diagonal_tile` 是位置，模式只有 `static`（固定）与 `drift`（缓慢在安全区内正弦往复，不随镜头晃动）。
- **安全区**：水印框必须完整位于画面内（V6 检查）。斜铺水印的框即整个画布。
- **分步与缓存**：导出分四步，各步有指纹：① 序列拼接 → `exports/.work/joined.mp4`；② 主版本（下三分之一条、角标、BGM）→ `master.mp4`；③ `*_clean.mp4`（主版本，无水印，附元数据）；④ 最后一步水印叠加 → `<标题>.mp4`。**改水印、署名文字不影响前两步**：章视频与主版本不重编码，只重做最后一步（测试断言 `part.mp4`、`joined.mp4` 的修改时间不变）。
- **BGM（可选，默认关）**：只使用用户放在项目内（如 `assets/bgm.wav`）的本地音频；不下载、不生成音乐。混音时以配音为侧链，配音出现时自动压低 BGM，末尾 2 秒淡出。路径必须是项目内相对路径，绝对路径与 `..` 会被拒绝。
- **AI 生成声明**（默认开）：写入片尾卡，并作为元数据 `description`。关闭后两处都不出现。
- **元数据**：`title`（标题）、`artist`（作者，留空则不写）、`description`（AI 声明）、`comment`（来源链接）。`_clean.mp4` 同样附带元数据。
- **V6 水印检查**：水印框完整位于画面内；超出则报错，阻止导出。

## 已知限制（P6）

- 水印图片、BGM 需要用户自己提供；本环境用生成的测试图片与正弦波验证了流程，未用真实 logo 或音乐。
- 片头/片尾的背景只用主题底色，没有 AI 底图（设计方案允许，但未做）。
- 下三分之一条的时间固定（片头后 5 秒、持续 4 秒）；短于约 14 秒的片子不显示它。
- 三种以上的水印字体样式未做，文字水印使用中文字体的单一样式。
- 漂移水印的周期固定（横向 40 秒、纵向 53 秒），未提供调整。
- 叠化、淡入淡出与水印都会重新编码，完整成片导出比 P5 更慢（约多一次整片编码）。

## P5 已确定的规则

- **章音轨**：按时间轴把每句 WAV 放到准确时刻，中间留静音（纯 Python 实现）。要求 24kHz 单声道 16bit，格式不符直接报错。
- **分段合成**：切点取自场景起止、画面状态时刻、句子起止与章标题卡结束。每段只合成一张图（底图 + 当前画面状态 + 字幕 + 进度条 + 章标签），段内画面不变。
- **字幕**：每句一条，底部居中半透明底框，关键词用强调色。`auto` 时，若卡片（非插图）的条目已完整包含这句话，则隐藏字幕；`always` 始终显示；`off` 关闭。字幕设置只影响合成，不需要重新渲染画面。
- **进度条与章标签**：底部细进度条表示本章进度；左上角显示章号与章名（可关闭）。
- **编码**：ffmpeg concat 时长列表 + libx264（veryfast，crf 20）+ AAC，帧率固定 25，输出 `parts/<章>/video/part.mp4`，并写入 `info.json`（时长、字幕时间窗）。
- **前置条件**：画面已渲染且与当前分镜一致（否则拒绝合成，提示重新渲染）；时间轴存在。
- **停止**：ffmpeg 以 0.2 秒为周期轮询停止信号，收到停止即结束子进程，不写入未完成的结果。
- **转场**：`cut` 直接拼接（流复制）；`fade` 每章首尾黑场淡入淡出后拼接；`dissolve` 相邻章叠化（xfade + acrossfade），后一章提前 `transition_sec` 开始。转场时长 0.2–2 秒，章短于两倍转场时长时拒绝叠化。
- **成片输出**（`exports/`）：`<标题>.mp4`（写入标题与作者元数据）、`<标题>.srt`（字幕时间已按章起点与叠化重叠平移）、`<标题>_cover.png`（封面，见 R16）、`<标题>_report.json`（校验报告）。
- **V6 成片校验**：分辨率、平均帧率（误差 0.05）、音轨存在、时长与预期相差不超过 0.25 秒、字幕结束不超过成片时长。校验失败则报错。
- **前 30 秒预览**：快速编码，不改变章视频。

## 已知限制（P5）

- 只提供章视频的前 30 秒预览，没有单 beat 预览。
