# article_to_video — 项目说明

> 把一篇 Markdown 文章改编成讲解视频（配音 + 字幕 + 动态画面 + 署名与水印）。

       --watermark-text "作者名 · 频道" --watermark-position top_right

## P0 已确定的规则

- **作者名**：界面或命令行输入优先；留空时依次尝试 front matter（`author:` / `作者:`）、文首“作者：”行；都没有则留空并警告。**不让模型猜作者。**
- **水印**：文字水印，最多 60 字。水印文字为空时自动关闭。位置与模式不合法时取默认值并给出警告。
- **署名与水印可随时修改**：「📚 项目」页保存时只改 `project.json`，源文章与块数据保持不变，后续阶段据此判断是否需要重跑。
- **块 ID**：`s{章号:02d}.p{序号:02d}`，章号按一级标题递增，一级标题之前为 `s00`。
- **时长估算**：按 4.2 汉字/秒。参考文章 7,022 汉字，全文朗读约 27.9 分钟。

## P1 已确定的规则

- **两种生成方式**：`rules`（离线，确定性，不调用模型）与 `miniagent`（LLM）。规则版章标题取一级标题，论点取该章第一节的首个完整论点句，不做改写，质量有限，适合作为兜底与人工起点。
- **分节摘要**：按一级标题累加成组，每组不超过约 4000 字符；超长节在块边界切开。
- **忠实度**：摘要中的 `quotable` 与 `key_numbers` 必须是原文逐字片段（去空白与 Markdown 标记后比较），否则带问题清单重试一次；仍不合格则**不写任何结果**，原始输出存入 `plan/raw_*.txt`。
- **V1 覆盖**：每个小节必须且只能出现在一个章或取舍报告中；金句必须来自摘要登记的原话；章数超出 5～7 只给警告。
- **断点续跑**：LLM 摘要记录输入哈希（含提示词版本与原文），输入未变时复用，不重复调用。
- **C0 确认**：任何编辑都会取消确认；已确认的大纲默认不能被覆盖，需显式勾选。

## P2 已确定的规则

- **口播稿按章生成**：每章一个 `parts/<章ID>/script.json`；段落 ID 为 `P01.b01`；句子带 `quote`（金句）与 `emphasis`；`tts` 由词典自动生成，字幕仍显示原写法。
- **V2 忠实度**：句中的数字、年份、英文词必须出现在本章原文中；标记为金句的句子必须是原文逐字片段；引用的小节必须属于本章。
- **V3 可读性**：不得含 Markdown 符号与裸公式；单句超过 60 字报错，超过 40 字警告。
- **节奏**：condensed 模式下，章的字数应在预算 ±15% 内。节奏问题与硬错误分开处理：硬错误必须修正，节奏问题重试后仍存在则接受并记为警告（设计文档：超限留给人工）。
- **重试**：每章最多 3 次；硬错误或节奏问题都会把问题清单带入下一次提示词。仍有硬错误则不写结果，原始输出存为 `raw_last.txt`。
- **断点续跑**：输入（章节原文、大纲、术语、词典、上一章结尾、人设）未变则复用。
- **C1 确认**：编辑后本章变为未确认；确认前必须通过所有硬校验。
- **后台写稿**：界面中写稿在线程里运行，可随时「请求停止」；模型请求每 0.2 秒检查一次停止信号，停止后不写入未完成的结果。

## P3 已确定的规则

- **逐句合成**：每句一个 WAV（`parts/<章>/audio/<句ID>.wav`）；句子 ID 形如 `P01.b01.s01`。音频统一为 24kHz 单声道 16bit。
- **缓存**：键 = 音色 + 语速 + 朗读文本 + 引擎链。编辑口播只重配改动的句子；换引擎链会全部重配。每句完成即写入 `manifest.json`，停止或失败后可续跑。
- **双声线**：主讲用 `narration_voice`，`quote: true` 的金句用 `quote_voice`；每章引文音色最多 2 句（可设），超出的改用主讲音色并给出警告。
- **语速**：beat 的 pace 映射到 -10% / 0 / +10%；开场（hook）默认 +5%。
- **停顿**：句内停顿 `sentence_gap_sec`（0.15 秒）；段末停顿用 beat 的 `pause_after_ms`；章首章尾各 0.5 秒。
- **时间轴不变量**（测试覆盖）：`end = start + duration`；下一句 `start = end + gap`；`total = 末句 end + 末 gap + tail`。
- **不静默降级**：引擎链全部失败时报错并列出每个引擎的原因；只有 `--stub` 或界面勾选"仅流程验证"才生成静音，且时间轴带 stub 警告。
- **前置条件**：大纲已确认（C0），且该章口播稿已确认（C1）。
- **试听**：写入 `preview/`，不改变项目的音频与时间轴。

## P4 已确定的规则

- **分镜两种引擎**：`rules`（规则版，离线，确定）：画面类型由原文结构决定：代码块链式流程/回路 → `diagram`；表格 → `table`；公式 → `formula`；列表 → `list`（年份开头 → `timeline`）；金句 → `quote`；其余 → `keypoint`。`llm`（模型版）：模型为每段选择画面类型、写出短条目与插图主题，但结构内容（流程节点与回路、表格、公式、列表、金句原文）一律取自原文，不由模型生成。模型输出中的数字与英文词必须在本段口播中出现，否则带问题清单重试，最多 3 次；仍不合格抛错且不写结果，不会静默回退为规则版。分镜文件 `parts/<章>/storyboard.json`，场景 ID 即段落 ID，记录所用引擎。
- **文字密度**：单条文字 ≤ 60 字，超出自动按子句拆分；每张卡条目数上限：卡片/插图 4、列表与时间线 5、流程 6 节点、表格 6 行 × 4 列、公式 3 条解释。
- **逐步出现**：每个状态对应一句（`at_sentence`）；状态多于句子时，同一句内均分时长。表格的条目由行派生，不接受单独编辑。
- **V4 节奏**：相邻三段不得同一类型（生成时自动修正，编辑后不通过则报错）；原文结构未被画面表达时给出提示。
- **一图多用（自动分配）**：插图镜头按顺序轮转分组，组数 = ⌈镜头数 ÷ 每图镜头数⌉，每组第一个镜头为主图，只有主图生图，其余镜头复用主图文件、各自取景。同组镜头相隔约组数段，避免相邻两段看起来像同一张图。取景按组内人数分布（2 个镜头：左 0.2、右 0.8；3 个：0.12 / 0.5 / 0.88），奇数组反向，让相邻组的运镜方向不同。「每图镜头数」默认 2，范围 1–3；设为 1 即关闭复用。点击「🔁 重新分配一图多用」只重算组与取景，不改动文字与类型。
- **取景余量**：插图底图先放大 1.35 倍再取景。正方形图按画幅铺满时宽度恰好相等，没有水平移动余量，不放大则不同取景完全相同。
- **V5 插图**：额度按**需生成的图片数（组数）**计算 = 章时长 × 每分钟上限（默认 2.5，上限 6）。组内镜头数不超过每图上限，每组恰好一个主图；主图的画面主题必须带固定风格锚（含禁文字约束），主题中不得出现写字类词语。
- **插图缓存**：`parts/<章>/images/index.json` 记录提示词哈希；哈希不变则复用，不调用生图。重新生成写入新版本 `_vNNN.png`，旧版本保留。同章第一张生成的图作为后续图的风格参考。渲染时先统一解析每组主图，再逐场景取景；主图主题变化时，组内所有镜头的场景指纹同时变化、全部重绘。
- **降级**：未配置生图 key、已关闭生图或生图失败时，插图按卡片绘制，并在清单与界面中写明原因。渲染不因此中断。
- **过期**：口播稿或视觉设置变化后，分镜标记为过期；过期分镜不能确认或渲染，重新生成会覆盖界面中的编辑。
- **渲染清单** `parts/<章>/visuals/manifest.json`：P5 合成的唯一输入。每个场景记录时间段、底图与各状态图层及出现时刻（来自时间轴）。场景缓存键 = 场景内容 + 主题 + 风格锚 + 画幅 + 渲染版本。
- **画幅**：横屏 1920×1080（1080P）/ 1280×720（720P），竖屏 1080×1920 / 720×1280。字号按短边比例缩放。
- **字体**：中文字体优先读取环境变量 `ARTICLE_TO_VIDEO_FONT`，其次系统字体候选；找不到时报错，绝不画成方框。

## P5 已确定的规则

- **章音轨**：按时间轴把每句 WAV 放到准确时刻，中间留静音（纯 Python 实现）。要求 24kHz 单声道 16bit，格式不符直接报错。
- **分段合成**：切点取自场景起止、画面状态时刻、句子起止与章标题卡结束。每段只合成一张图（底图 + 当前画面状态 + 字幕 + 进度条 + 章标签），段内画面不变。
- **字幕**：每句一条，底部居中半透明底框，关键词用强调色。`auto` 时，若卡片（非插图）的条目已完整包含这句话，则隐藏字幕；`always` 始终显示；`off` 关闭。字幕设置只影响合成，不需要重新渲染画面。
- **进度条与章标签**：底部细进度条表示本章进度；左上角显示章号与章名（可关闭）。
- **编码**：ffmpeg concat 时长列表 + libx264（veryfast，crf 20）+ AAC，帧率固定 25，输出 `parts/<章>/video/part.mp4`，并写入 `info.json`（时长、字幕时间窗）。
- **前置条件**：画面已渲染且与当前分镜一致（否则拒绝合成，提示重新渲染）；时间轴存在。
- **停止**：ffmpeg 以 0.2 秒为周期轮询停止信号，收到停止即结束子进程，不写入未完成的结果。
- **转场**：`cut` 直接拼接（流复制）；`fade` 每章首尾黑场淡入淡出后拼接；`dissolve` 相邻章叠化（xfade + acrossfade），后一章提前 `transition_sec` 开始。转场时长 0.2–2 秒，章短于两倍转场时长时拒绝叠化。
- **成片输出**（`exports/`）：`<标题>.mp4`（写入标题与作者元数据）、`<标题>.srt`（字幕时间已按章起点与叠化重叠平移）、`<标题>_cover.png`（程序绘制的封面）、`<标题>_report.json`（校验报告）。
- **V6 成片校验**：分辨率、平均帧率（误差 0.05）、音轨存在、时长与预期相差不超过 0.25 秒、字幕结束不超过成片时长。校验失败则报错。
- **前 30 秒预览**：快速编码，不改变章视频。

## 已知限制（P5）

- 本环境只做了离线全流程（假配音、假生图）。真实 edge-tts 与生图的画质与时长未验证。
- 叠化与淡入淡出需要重新编码：6 章约 11 分钟的成片，导出约 3 分钟（720P）。1080P 未做完整计时。
- 只提供章视频的前 30 秒预览，没有单 beat 预览。
- 封面只有标题与作者，没有图片。
- 输出文件（报告 json）权限为 600，仅影响本机直接访问，界面下载不受影响。
- 片头、片尾、下三分之一条、水印与 AI 声明属于 P6，本期未加入。

## 已知限制（P4）

- 模型版分镜的画面选择质量依赖模型；本环境只用假模型验证了流程（JSON 解析、来源校验、重试、缺段检测）。首次使用请检查分镜页的警告。
- 插图提示词由「画面主题 + 风格锚」拼接；模型版分镜会给出主题，但没有单独改写提示词的步骤。
- 一图多用的取景是按组内位置固定分布的；若要更精细的取景，可在分镜页手动调整水平取景位置（保存后变为未确认）。
- 真实生图接口（Agnes）未在本环境调用过，测试全部使用离线占位图。
- 渲染测试只做结构检查（状态数、透明底、覆盖面递增、画幅、换行不越界）和人工目视检查，没有像素级快照。
- 分镜页的表格只读；表头与行不能在界面中修改。

## 已知限制（P3）

- **真实 edge-tts 没有在本环境验证**：沙箱无法解析 `speech.platform.bing.com`。冒烟测试已写好（`A2V_REAL_TTS=1` 时运行），失败时会给出"网络不通"的说明。请在本机运行一次。
- CosyVoice 路径只实现了接口，未在本环境测试（需要本地模型与 torch）。
- 真实 edge-tts 需要 ffmpeg 转码（mp3 → wav）。
- 句内强调词（emphasis）不影响配音，只在 P4 视觉中使用。
- 试听的语速固定为 +0%，音色为主讲音色。

## 已知限制（P2）

- 写稿只支持模型（miniagent），没有离线规则版：口播改写需要语言能力。
- 真实模型的写稿质量未验证，本环境只用假模型验证了流程；首次使用请留意校验与节奏警告。
- 发音词典使用 `lexicon.json` 而非设计文档中的 `lexicon.yaml`，内容相同，为免新增依赖。
- 单章原文超过 12000 字时拒绝写稿，需要在大纲页拆分。
- 节奏检查只对 condensed 模式生效；faithful 与 highlights 模式不检查字数。
- 在 C1 页编辑时，句内强调词（emphasis）会被清空，需要在 P4 视觉阶段重新标注。
- 停止机制目前覆盖模型调用与配音请求；ffmpeg 子进程的停止在 P5 处理。

## 已知限制（P1）

- LLM 路径在本环境只用假模型验证了流程（重试、失败不落盘、断点续跑），**未对真实模型做质量验证**，首次使用请留意。
- 大纲页的界面只做了 AppTest 冒烟，真实浏览器中的编辑体验需本机确认。
- 规则版的论点句偶尔是残句或长句（原文本身结构复杂时），属预期内的局限。
- 章划分尚未按时长权重做二次校正；`weight` 目前按字符数。
- P1 的模型调用已改为可停止（P2 实现），不再有此限制。

## 已知限制（P0）

- 界面的文件上传与表单提交只做了 Streamlit AppTest 冒烟（空表单报错路径）；带真实文件的提交靠 CLI 与导入函数测试覆盖，**真实浏览器中的体验需本机确认**。
- 尚未调用任何模型，`health` 中的 ffmpeg 与 pillow 仅提示，P4/P5 再强制。
