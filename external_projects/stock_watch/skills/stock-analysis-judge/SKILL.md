# stock-analysis-judge

## 背景与边界

`stock_watch/analysis.py::collect()` 只负责"把材料收集、结构化好"，刻意
不做"AI 综合研判"——见该模块 docstring。本 skill 就是补上的那一步：读取
已经抓取好的结构化材料（公告、股吧热帖、相关新闻），给出**有理有据、
克制、如实标注不确定性**的研判结论，不是自由发挥的荐股文案。

## 输入

上游会在 prompt 里给你：
- `code` / `name`：标的代码和名称
- 一段 JSON 文本（`material_json`），对应 `StockAnalysis` 的字段：
  `announcements` / `guba_posts` / `news` / `errors`（`errors` 非空说明
  部分材料抓取失败，你必须在报告里如实标注，不能假装材料齐全）

## 判断原则（务必遵守）

1. **材料不足以支撑判断时，明确说"材料不足以判断"**，不要为了给出结论
   而过度推断。`errors` 里列出的每一类缺失材料都要在报告里点名。
2. **区分"事实摘要"与"你的推断"**：公告/新闻的内容陈述属于事实摘要，
   "这可能意味着…"这类属于你的推断，两者在报告里要能被读者分清楚。
3. **不做确定性的买卖指令**（如"建议现在买入"），只给"信号强度 +
   需要关注的风险点 + 建议的下一步动作"（如"值得纳入观察池，需等待
   XX 公告落地后再评估""与行业整体波动一致，暂无独立信号，建议观察"）。
   这是分析材料，不是投资建议，报告末尾必须带免责声明。
4. **股吧帖子情绪是滞后/易被操纵的弱信号**，权重明显低于公告和新闻，
   不要仅凭股吧热度给出正面结论。

## 输出（result_file，合法 JSON，顶层字段）

- `verdict`：字符串，三选一：`"positive_lean"` / `"neutral"` /
  `"caution"`（分别对应"偏积极但仍需验证" / "中性，无明显独立信号" /
  "需要谨慎，存在需要关注的风险点"）——刻意不用"买/卖/持有"这类操作
  指令式的取值。
- `summary`：不超过 200 字的一句话摘要。
- `key_signals`：字符串数组，支撑 `verdict` 的关键事实依据（每条注明
  来自公告/新闻/股吧中的哪一条）。
- `risk_points`：字符串数组，需要关注的风险/不确定性（含材料缺失导致
  的"未知"风险）。
- `action_suggestion`：字符串，非指令式的下一步建议（如"建议持续观察，
  等待下一份定期报告"）。
- `report_markdown`：字符串，**完整的最终分析报告 Markdown 正文**，
  结构与 `stock_watch/report.py::render_analysis_report()` 的既有材料
  报告保持一致（标题 `# {name}({code}) 综合分析材料`、公告/股吧/新闻
  三个小节各自摘要要点，而不是整段照抄原文），并把上面的
  `## 综合研判` 小节替换成你的实际研判内容（含 `verdict` 对应的中文
  说法、`summary`、`key_signals`、`risk_points`、`action_suggestion`
  的完整展开），报告末尾追加一行：
  `> 本报告由 AI 基于公开材料自动生成，不构成投资建议，据此操作风险自负。`
