## 脚本协议（必须严格遵守）
1. 脚本必须定义一个函数 `run(ctx)`，这是唯一入口。
2. `ctx` 提供以下能力：
   - `ctx.input_json("task_input")` —— 获取本次任务的输入数据（已解析为 dict/list，即上面的输入样例结构）。
   - `ctx.params` —— dict，内容与输入数据相同，供你按习惯任选一种方式读取。
   - `ctx.llm.ask(prompt, system="")` —— 如果任务里有一部分确实需要语言理解能力（比如摘要、分类、抽取），可以调用它做单轮问答，返回字符串。不要为了"用上 LLM"而滥用，能用确定性代码写清楚的逻辑就直接写代码。
   - `ctx.llm.ask_json(prompt, system="", schema_hint="")` —— 同上，但返回值是已解析好的 dict。
   - `ctx.write_output(filename, data)` —— 需要落盘中间产物时使用，非必需。
3. `run(ctx)` 的返回值必须是：一个字符串，或者一个可以被 `json.dumps` 序列化的 dict/list。这个返回值就是本次执行的最终输出。
4. 脚本必须能独立运行，不能假设有额外的全局变量或 import 之外的上下文。
5. 出现无法处理的输入时，请显式 `raise` 一个描述清楚的异常（比如 `ValueError("原因")`），不要吞掉错误或返回模糊的默认值——报错会触发自动修复流程，静默返回错误结果不会。
