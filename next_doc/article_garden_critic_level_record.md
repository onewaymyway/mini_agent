# article_garden 评审严格度记录

- **问题**：成文总是失败。日志中独立评审连续 4 轮都在挑「摘录里没有逐字出现」的表述（如“信号处理”“正则化或记忆回放”“关键阶段”“对模型权重的直接干预”），其中还包括对“摘录中没有提供数据”这种如实说明的挑剔；修复轮数用尽后整篇判失败。
- **完成日期**：2026-11-24

## 1. 原因

来源摘录只是节选，评审又要求每句话都能在摘录里找到依据，轻微的概括、领域常识、过渡句都被当成“无证据支持”，修复循环很难收敛。

## 2. 设计

1. **评审提示词收紧**：明确不要报领域常识与过渡句、对“摘录里没有某信息”的如实说明、措辞上的轻微概括、不含具体事实的论述；每条问题要标 `severity`：
   - **严重**：具体事实（数字、名称、因果结论、明确断言）没有依据或与来源相反；
   - **轻微**：表述稍有拔高或不够严谨，但不改变事实。
2. **新设置项** `thresholds.critic_level`（设置页「校验阈值」，可全局或按文章库覆盖），默认「标准」：
   - **严格**：评审提出的所有问题都要修，修不好则成文失败（即原来的行为）；
   - **标准**（默认）：只修「严重」问题，轻微问题仅记录；
   - **宽松**：评审意见只记录，不阻止成稿。
3. 被放过的评审意见写入运行日志（警告）和 `drafts/<tid>/checks.json` 的 `critic_notes`，成稿后审阅时可以参考。
4. 评审没标 `severity` 的问题一律按「严重」处理（保守）。
5. 已成稿仍需人工审阅；严重问题在修复轮数用尽后仍然失败，不会被放过（宽松除外）。

## 4. 验证

- 全套 **278 项通过**（1 项按环境跳过），pyflakes 无告警。
- 没有在真实模型下重跑 t-0015，实际效果取决于模型是否遵守新提示词的 severity 标注。

## 5. 注意

- **默认行为变了**：原来等同于「严格」，现在默认「标准」。想恢复原样，在设置页把「评审严格度」改为「严格」。
- 若「标准」下仍常因严重问题失败，可再加大每篇最多修复轮数，或改用「宽松」后依靠人工审阅把关。
