# article_to_video 模型版分镜：信息丰富度与卡片扩展方案（待确认）

> 状态：**方案草案（2026-11-20），未实施**。范围：只针对模型版分镜（`visual/director_llm.py`）与其渲染；规则版不在本轮范围内。
> 前提（已确认）：公式本体始终可见；不做高亮；表格、流程图等结构化画面整体一次显示。
> 请先确认第 6 节的待定问题，再按期实施。

## 1. 目标

1. 每张卡片承载文章中的**关键信息**，而不只是一两个关键词。
2. 同一章的画面覆盖该章的**主要论点、数据、结构与公式**，不能漏掉关键要点。
3. 在不增加生图预算的前提下，让画面类型更丰富。

## 2. 现状：为什么卡片信息少（已读代码）

| 限制 | 位置 | 后果 |
|---|---|---|
| 卡片文字中的每个数字与英文词，必须在本段口播或原文结构中出现 | `director_llm.py::_item_errors`、`_tokens_missing` | 卡片只能复述原句，无法写标题、说明、结论，只能是原文关键词的拼接 |
| keypoint / illustration：最多 3 条，每条 ≤ 60 字 | `MAX_SHOT_ITEMS`、`TEXT_LIMIT`（`director.py`） | 一张卡至多 3 行，没有“标题 + 要点”的层次 |
| 「图表」实际是表格（表头固定为“项目 / 数值”，最多 3 项） | `KIND_TO_TYPE["chart"] = "table"`、`CHART_HEADER` | 没有真正的数据图（柱状图等）；数据只能以文字列表呈现 |
| 表格、流程、列表的内容完全由原文决定，只能选句子范围 | 窗口提示词第 6 条 | 无法为结构补充一句结论或分组 |
| 公式只能配最多 3 条解释，解释必须是原句 | `formula_explanation` | 符号与含义之间没有对应关系 |
| 金句卡只能是原文金句 | `quote` 类型 | 金句前后的上下文不出现在画面中 |
| 规划阶段产出的每段“要点”（`points`）只用于写分镜提示，**没有检查是否被画面覆盖** | `build_window_prompt` 中的“要点：” | 关键要点可能整段漏掉，而校验不会发现 |
| 渲染器只有 8 种固定版式，没有对比、定义、数据图 | `render/renderers.py::_DRAWERS` | 新信息形态无处放 |

**根本原因**：当前规则是“画面文字 = 原句词的子集”，它防止了编造，但也把画面压成了关键词。要丰富画面，需要区分两类文字，分别设规则。

## 3. 设计思路：区分“锚点”与“表述”

- **锚点（anchor）**：数字、单位、专名、公式、原文表格与流程的节点、金句。必须逐字来自原文（沿用现有的 token 检查）。
- **表述（wording）**：标题、说明、结论、符号含义、对比维度等由模型组织的文字。允许使用模型自己的措辞，但要满足两条约束：
  1. 表述中出现的数字与专名，必须能在本段口播、原文结构中找到（复用 token 检查，只针对锚点部分放宽其它词）；
  2. 表述必须能归属到具体句子（每条表述附带 `sentences` 引用，便于审阅与后续校验）。

这样，文字可以更完整，同时数字与事实仍然可以追溯。

## 4. 方案：信息丰富度的四个改进

### 4.1 覆盖关键要点（先做，收益最大）

- 把规划阶段的 `points`（每段 1–4 条）作为**覆盖目标**。
- 窗口输出后，检查每条要点是否至少有一张卡承载它（判断依据：要点中的关键词与卡片的标题、条目、锚点的匹配；匹配不上时由模型做一次判定，结果写入分镜）。
- 未覆盖的要点：按设定触发整窗重做（见待定问题 Q4）。
- 结果写入 `storyboard.json` 的 `coverage` 字段，编辑界面可见。

### 4.2 卡片的层次：标题 + 要点（扩展 keypoint）

- 新增可选字段 `headline`（一句话结论，≤ 24 字，可由模型组织，数字必须可追溯）。
- keypoint 的 `items` 仍是要点（最多 3 条，每条 ≤ 60 字）。
- 版式：标题居上，要点逐条出现（沿用现有的逐条节奏，这是与语音对齐的主要方式）。
- 旧版 keypoint 不带 `headline` 时照常渲染，保持兼容。

### 4.3 新卡型（扩展现有类型，不改动已有的 8 种版式的含义）

| 新卡型 | 用途 | 内容构成 | 锚点来源 |
|---|---|---|---|
| **数据卡**（`stat`） | 句中有一个关键数字 | 大号数字 + 单位 + 指标名 + 一句说明 | 数字、单位取自原句 |
| **柱图卡**（`bars`，替代现在的 `chart`） | 2–5 个可比较的数值 | 柱状图，标签与数值取自原句/原表 | 标签与数值逐字来自原文 |
| **对比卡**（`compare`） | “A 相比 B”“而 / 但 / 不同” | 左右两栏，各有标题与 2–3 条要点，中间可有一行结论 | 两侧的名称取自原句 |
| **定义卡**（`definition`） | “X 是指…”“X 即…” | 术语（大字）+ 定义（原句，可略作删减）+ 1 条补充说明 | 术语与定义取自原句 |
| **符号卡**（`symbols`，公式的扩展） | 公式有符号解释 | 公式本体始终在上方可见；下方逐行“符号 — 含义” | 符号取自原公式，含义取自原句或模型表述（受 3 的规则约束） |
| **流程卡增强**（`diagram` 加注释） | 原文流程 | 每个节点下附一行说明（取该节点所在句，原句截取） | 节点名与说明取自原文 |
| **表格精选**（`table` 加选择） | 原文表格行数多 | 模型从原表中选出 3–4 行，并可加一句表头结论 | 行与单元格逐字来自原表 |
| **章节回顾卡**（`recap`） | 每个章节或较长段落的结尾 | 本段 2–4 条要点（取自已生成卡片的 `headline` 或要点），无新事实 | 全部取自前文已有卡片 |

说明：
- 柱图卡替换当前的“图表=表格”。现有 `chart` 类型保留以兼容旧分镜，新分镜不再生成。
- 所有新卡型都**不占生图预算**。
- 公式本体始终可见（已确认）；结构化卡（流程、表格、列表、年代线）一次整体显示，不做分步出现（已确认）。

### 4.4 信息量与可读性的控制

- 每张卡的文字总量设上限（建议 ≤ 120 字，见 Q5）。超出则拆成两张卡。
- 每张卡的要素数量有上限（标题 1、要点 ≤ 3、数据 ≤ 5 项、对比两侧各 ≤ 3 条）。
- 渲染前检查文字是否溢出版面；溢出则在校验中报错，触发该镜头的重做。

## 5. 分期

| 期 | 内容 | 验收 |
|---|---|---|
| 一期 | 4.1 覆盖关键要点（检查 + 写入 `coverage`）；4.2 `headline` 字段（keypoint 扩展，渲染标题） | 人工构造漏要点的分镜能被发现；正常分镜覆盖率达标；旧分镜仍可渲染 |
| 二期 | 4.3 中的数据卡与柱图卡（新渲染器）；符号卡 | 含数字的句子能生成数据卡，数字全部可追溯；柱图数值来自原文；公式本体始终可见 |
| 三期 | 对比卡、定义卡、流程卡增强、表格精选 | 对比句生成对比卡；定义句生成定义卡；流程节点带说明 |
| 四期 | 章节回顾卡、文字溢出检查、信息量上限 | 长段落结尾有回顾；无溢出；每卡不超过上限 |

每期都需要：更新 `PROJECT.md`、外部总规划相应节、本方案的实施记录；全量测试通过；打包 diff zip。

## 6. 待定问题（请确认）

- **Q1（关键）**：是否放宽“画面文字只能用原文词”的规则？建议放宽为：**锚点（数字、专名、公式、表格与流程节点、金句）仍须逐字来自原文；标题、说明、结论等表述允许模型组织**，但表述中的数字与专名必须能追溯。这是丰富度提升的主要来源，也带来一定的表述偏差风险（模型可能曲解原意），需要你接受这个取舍。
- **Q2**：数据图是否新增真正的柱图渲染（替换现在“图表 = 表格”）？建议新增，一期之后做。
- **Q3**：keypoint 的要点是否保持逐条出现（与语音节奏对应）？建议保持，标题始终可见。
- **Q4**：覆盖检查未通过时，是否重做整窗（会增加模型调用与耗时）？还是只警告？建议：第一次重做，仍未覆盖则警告，由人判断。
- **Q5**：每张卡文字上限是否为 120 字？数据卡与对比卡的要素上限是否合适？
- **Q6**：修改后模型版分镜版本号会变化，已有的模型版分镜会被判为过期，需要重新生成。是否接受？（这会消耗模型调用。）
- **Q7**：章节回顾卡是否需要？它不增加新事实，但会增加画面数量。

## 7. 风险

- **模型表述偏差**：放宽后，模型可能把原句的意思说歪。缓解：表述必须引用句子；数字专名校验；覆盖检查时由模型比对表述与原句（一期可先不做这一步，只做数字专名的机器检查）。
- **输出变长、重试增加**：每窗的 JSON 更复杂，失败率可能上升。缓解：保持每期只加一类字段；沿用现有的 `MAX_ATTEMPTS` 与整窗重做机制。
- **旧分镜不兼容**：通过版本号使其过期，界面提示重新生成。
- **不改动**：大纲、口播、配音、导出、预算账本、规则版分镜。
