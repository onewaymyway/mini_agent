# info_hub 反馈闭环改进计划

> 状态：计划已确认；P1–P4 均已实施并通过测试（后续事项见第 9 节）
> 范围：info_hub 外部项目（`external_projects/info_hub/`）
> 关联文档：`next_doc/info_hub_external_project_plan.md`、`next_doc/info_hub_implementation_record.md`

## 1. 背景与目标

当前 info_hub 只能"抓取 → 展示 → 朗读"，用户看完一条信息没有任何方式告诉系统自己的偏好，系统也无法据此调整抓取和排序。本计划目标是建立闭环：

```
信息采集 → 阅读呈现 → 用户反馈 → 偏好学习(画像) → 发现与排序 → 信息采集
```

本轮只落地第一阶段的基础设施（阅读呈现 + 反馈收集 + 打开模式切换），后续阶段在本文档中一并规划，便于逐步确认。

## 2. 已确认的决策

| 决策点 | 结论 |
|---|---|
| 页面打开方式 | 三种模式并存（阅读模式 / 内嵌 iframe / 新标签页），在看板上可切换，先试用，之后再确定默认值 |
| 反馈 | 三个动作：感兴趣 / 不感兴趣 / 稍后看；原因标签可选，默认可以不填 |
| 新信息源 | 系统自动发现的信息源必须用户确认后才加入抓取，不自动启用 |
| LLM | 允许用于画像学习（关键词归纳、偏好总结）；抓取和整理流程仍不依赖 LLM，LLM 不可用时退回规则统计 |

## 3. 分阶段规划

### 第一阶段（P1）：呈现与反馈基础设施【本轮实施】

1. **三种打开模式**
   - 阅读模式：服务端用信息源配置的抓取方式（需要登录的站点走共享浏览器 profile）获取页面，抽取标题、段落、图片地址，在看板渲染，附原链接。
   - 内嵌模式：`st.components.v1.iframe`，失败时（多数站点禁止嵌入）给出提示并引导使用其他模式。
   - 新标签页：`st.link_button`，始终可用。
   - 默认模式写入 `config/settings.yaml` 的 `view.default_open_mode`；看板上的临时切换和"设为默认"写入 `data/state/runtime_config.json`，覆盖默认值。
2. **反馈收集**
   - 每条条目可标记：感兴趣 / 不感兴趣 / 稍后看；可选原因标签（话题不符、内容太浅、已经看过、来源不喜欢）和备注，默认不强制填写。
   - 存储：`data/feedback/events.jsonl`，append-only，写入使用文件锁。
   - 每条事件包含：事件 id、时间、信息源 id、条目 key（URL 规范化后的哈希）、条目标题与 URL、动作、原因标签、备注、打开方式。
3. **反馈查看**：看板展示当前条目的历史反馈与按动作的计数，便于人工检查。

验收：三种模式可切换且能记住默认值；反馈写入文件、重启后仍在；原因标签可不填；单元测试覆盖存储、校验与正文抽取。

### 第二阶段（P2）：画像与排序【已实施，见第 7 节】

- 离线任务读取反馈事件，按关键词、来源、分类计算兴趣权重，带时间衰减，不同动作权重不同（喜欢 > 稍后看 > 无反馈 > 不感兴趣）。
- 画像分为两部分：显式偏好（用户手写的关注主题，优先级最高）与学习得到的偏好（带证据数量，用户可查看、修正、删除）。
- LLM 可选参与：归纳关键词、生成画像摘要；不可用时使用统计结果。
- 排序应用到信息流和报告。

### 第三阶段（P3）：基于画像的发现与候选收件箱【已实施，见第 8 节】

- 根据高权重兴趣生成搜索类信息源草案（站内搜索页模板、`{query}` 占位）以及基于已喜欢条目的相关推荐。
- 候选进入"候选收件箱"，展示来源、理由、预计可用性；**用户确认后才加入信息源**。
- 每日发现数量上限，防止信息源无限扩张。

### 第四阶段（P4）：评估与优化【已实施，见第 9 节】

- 每一版排序的点击率、喜欢率、不感兴趣率对比。
- 发现的采纳率与质量统计，反向调整候选生成策略。

## 4. 数据与隐私

- 所有反馈与画像仅保存在项目目录内，不上传。
- 画像与反馈支持查看、导出、删除。
- 反馈事件不可修改，画像由事件重算得出，因此删除画像不会丢失原始证据（需要时可通过删除事件文件彻底清除）。

## 5. 已知风险

- 阅读模式对视频、强动态页面效果有限，遇到时提示用户切换为新标签页。
- 需要登录的站点阅读模式依赖浏览器 profile，同一时间只能被一个浏览器进程占用，阅读请求与抓取会串行。
- 停留时长在 Streamlit 中难以精确获取，因此不作为主要信号。
- LLM 参与画像学习时存在成本和可用性问题，需要在配置中可关闭。

## 6. 第一阶段实施记录

- 新增 `core/feedback.py`：反馈事件校验、URL 规范化与条目 key、append-only 存储（`data/feedback/events.jsonl`，文件锁）、按动作计数。
- 新增 `core/reader.py`：正文抽取（去除导航/页脚/脚本，保留标题、段落、图片地址）、打开方式默认值与运行时覆盖。
- `server/api.py` 新增 `read_article` / `record_feedback` / `item_feedback` / `view_prefs` / `set_default_open_mode`；阅读模式复用信息源的抓取方式，需要登录的站点走共享浏览器 profile，登录失效与风控拦截分别返回 409。
- `app.py` 结果页新增「阅读与反馈」面板：三种打开方式切换、「设为默认」、反馈按钮（感兴趣 / 不感兴趣 / 稍后看）、可选原因标签与备注、该条目的反馈历史。
- `config/settings.yaml` 新增 `view.default_open_mode`（默认 reader）。
- 测试：`tests/test_feedback_reader.py`（存储、校验、正文抽取、偏好、API 约束）与 `tests/test_feedback_dashboard.py`（AppTest 验证面板渲染、反馈写入、默认值持久化）。
- 未实施（属于后续阶段）：离线画像学习、排序、LLM 画像、候选信息源收件箱。

## 7. 第二阶段实施记录

- 新增 `core/profile.py`：
  - 画像结构分三块：`explicit`（用户手写的关注主题与屏蔽词，重算时保留）、`learned`（反馈离线统计的关键词与来源权重）、`llm`（可选的归纳结果）。存储于 `data/profile/profile.json`。
  - 学习：动作权重为 感兴趣 +1、稍后看 +0.5、不感兴趣 −1；半衰期 30 天；“话题不符”放大关键词负向权重，“不喜欢这个来源”额外降低来源权重；|权重| 低于 0.3 的噪声剪枝，最多保留 80 项。
  - 分词：不依赖分词库，中文取 2~4 字子串，英文按单词。
  - 自动刷新：读取画像时若反馈事件数量变化，先重算 learned（即按需的离线学习）；也提供手动重算与清空。
  - LLM 归纳：复用主项目模型（`build_llm`），输入最近 80 条反馈，输出 JSON（兴趣关键词、避开关键词、一句话摘要）；解析失败或模型不可用时画像退回统计结果。受 `config/settings.yaml` 的 `profile.llm_enabled` 控制，默认开启，需手动点击触发。
  - 排序：按关键词权重 + 显式主题（+1.5）+ LLM 关键词（+0.8）+ 来源权重（×0.5）打分，屏蔽词 −3；最近一次反馈为“不感兴趣”的条目沉底。返回列表不修改原始数据。
- `server/api.py` 新增 `get_profile` / `save_explicit_profile` / `rebuild_profile` / `clear_learned_profile` / `summarize_profile_with_llm` / `rank_snapshot`。LLM 关闭返回 403，未配置模型返回 503，LLM 输出错误返回 502。
- `app.py`：结果页顶部新增「🎯 我的兴趣画像」面板（显式偏好编辑、学到的正负向关键词、LLM 摘要、重算/归纳/清空按钮）；结果表格新增「按我的兴趣排序」开关，开启后显示推荐分、匹配词与反馈图标。
- 测试：`tests/test_profile.py`（26 个用例：分词、学习与衰减、排序、显式偏好、LLM 解析与失败路径、API 约束）；`tests/test_feedback_dashboard.py` 追加画像面板与排序开关的渲染验证。全量 263 个用例，仅剩基线中已存在的 2 个 entrypoints 账本用例失败。

### 本阶段未覆盖（转入后续）

- 排序尚未应用到报告（`core/digest.py` 未改动），目前只作用于看板结果表格。
- 画像学习目前只用标题文本，未利用摘要、来源分类与阅读时长。
- LLM 归纳是手动触发，未纳入定时任务。
- 关键词的中文分词质量依赖 n-gram 统计，对同义词、语义相近词的合并尚无处理。

## 8. 第三阶段实施记录

- 搜索来源：只使用用户在 `config/discovery.yaml` 中配置的站内搜索模板（URL 必须且只能包含一次 `{query}`），不调用 mini_agent 的 web_search。模板结构与普通信息源的 source.yaml 相同，由用户按目标站点填写选择器。
- 新增 `core/discovery.py`：
  - 查询词选择：显式关注主题优先，其次是权重 ≥ 1.0 且至少 2 次反馈支持的学习关键词；排除屏蔽词与 LLM 避开词。
  - 实例化：查询词做 URL 编码，候选 id 形如 `disc_<模板>_<哈希>`，默认 `enabled: false`。
  - 生成上限：每日新生成数量（`limits.daily`，默认 3）与同时待确认数量（`limits.pending`，默认 10）。
  - 去重：同一（模板, 查询词）组合只生成一次；被忽略或已加入的候选不会再次生成。
  - 状态：`data/discovery/state.json`，状态为 pending / accepted / rejected。
- 确认机制：候选只有在用户点击“加入信息源”后，才经 `validate_candidate` 校验并通过 `write_source` 写入 `sources/`，并启用。候选在确认前不会被抓取。
- `server/api.py` 新增 `list_candidates_api` / `generate_candidates` / `accept_candidate` / `reject_candidate`；id 经过格式校验，重复确认返回 409，模板配置错误返回 400。
- `app.py`：结果页新增「📥 候选信息源」面板，展示模板、查询词、生成原因和 URL，提供“根据我的兴趣生成候选”、“加入信息源”、“忽略”。
- 测试：`tests/test_discovery.py`（20 个用例：模板校验、查询词选择、上限与去重、确认/忽略、API 约束、看板确认流程）。全量 283 个用例，仍只有原有的 2 个 entrypoints 账本用例失败。

### 本阶段的限制与未做的部分

- 默认 `templates: []`，需要你自己按目标站点的搜索页写入模板并校验选择器，否则不会生成候选。我没有在沙箱里访问真实站点，因此没有提供经过验证的站点模板。
- 候选确认前没有“试抓预览”，要确认是否可用需要加入后在“信息源”页签手动抓取。后续可以把预览接入候选卡片。
- 只支持站内搜索模板，没有接入 web_search（这是第三阶段开始前的决策）。
- 报告（`core/digest.py`）仍未应用画像排序，这一项仍在未完成清单中。

## 9. 第四阶段实施记录

- 新增数据：
  - 曝光（`data/feedback/exposures.jsonl`，kind=impression）：每次在看板展示列表时，记录展示的条目 key、排序视图（ranked / plain）与快照。同一会话、同一快照、同一视图只记一次。
  - 打开（同文件，kind=open）：加载正文或展开内嵌页面时记录，作为“点击”。新标签页无法在 Streamlit 中可靠捕获，因此不计入。
  - 反馈事件新增 `view` 字段，记录反馈发生时所在的排序视图。旧事件没有该字段，不计入视图对比。
- 新增 `core/evaluation.py`：
  - 视图指标（近 30 天）：曝光条目数、点击率（打开过的已曝光条目 ÷ 已曝光条目）、感兴趣 / 不感兴趣 / 稍后看 比例。
  - 排序对比：按兴趣排序相对原始顺序的点击率差与不感兴趣比例差。
  - 候选采纳率：按模板、按查询词来源（显式主题 / 学到的偏好）统计加入与忽略。
  - 自动暂停：某模板已做决定的候选达到 `adoption.min_decisions`（默认 5）且采纳率低于 `adoption.min_rate`（默认 20%）时，`generate` 跳过该模板，并在 skipped 中计数。阈值与暂停原因可在评估面板看到；`min_rate` 设为 0 即关闭。
  - 建议文案：样本不足（反馈少于 10 条）时不做排序结论；否则按差值给出建议（例如不感兴趣比例上升时提示检查画像）。建议只展示，不自动改动排序配置。
- `server/api.py` 新增 `record_impression_api` / `record_open_api` / `evaluation_report`，并让候选生成读取暂停列表。
- `app.py`：结果页新增「📊 推荐效果评估」面板；列表与阅读面板接入曝光、打开记录，反馈带上视图信息。
- 测试：`tests/test_evaluation.py`（13 个用例）。全量 296 个用例，仍只有原有的 2 个 entrypoints 账本用例失败。

### 本阶段的限制

- 点击只统计“看板内加载正文或内嵌展开”，不统计用户在新标签页中的打开行为。
- 样本量小时指标波动大，面板只做参考，不应据此直接下结论。
- 自动暂停只针对模板，不会按查询词自动降权；查询词来源的采纳率目前只展示，不参与决策。
- 报告（`core/digest.py`）仍未应用画像排序，这一项从第二阶段开始就一直未完成。

### 计划的全部阶段已完成后的遗留事项

1. 报告生成应用画像排序。
2. 画像学习纳入摘要、来源分类与阅读时长。
3. 候选卡片增加试抓预览。
4. 站点搜索模板需要用户根据实际站点编写并验证。

## 10. 未完成事项的补充实施记录

- 报告按画像排序：`core/digest.py` 在单源截断前按画像排序，由 `profile.rank_reports` 控制。
- 停留时长：插件统计可见时长并经 `/v1/dwell` 上报；画像学习将满 30 秒的停留作为弱正向信号（`DWELL_WEIGHT` = 0.5，需高于剪枝阈值 0.3）。
- 抓取附着专用浏览器（CDP）：`core/browser_session.py` 的 `cdp` 模式；`dedicated_browser.scrape_mode` 与看板切换；专用浏览器带调试端口启动（仅本机）。
- 仍未完成：候选卡片的试抓预览；插件域名范围的界面配置；真实浏览器中的端到端验证。
