## 3. 关键实现与决定
| 事项 | 做法 | 理由 |
|---|---|---|
| 归一打分 | 相同（去空白标点）→1.0；章程别名→1.0；相似度≥0.92 直接合并；[0.6,0.92) 或包含关系 交 LLM | 方案 §5.2：高分合并、中间分确认、低分不合并；无 embedding |
| LLM 确认 | 批量（每批 30 对），必须对每个 id 给出 true/false，拿不准答 false | 漏答或格式错误走修复循环 |
| 概念 id | 按写法重叠匹配旧 id，新簇才分配新 id | 重跑后 id 稳定，概念页不乱 |
| 定义 | 只依据已提供的断言；定义必须点名概念；`based_on` 只能引用提供的 id | 定义可追溯，编造 id 会被打回修复 |
| 无依据概念 | 标记 `status: no_source`，不生成定义 | 不编造；这类概念在看板中可见 |
| 关系 | 每篇文章内的概念对一次批量提问；每条边独立校验，不合规的丢弃，**不修复** | 方案“无依据的边丢弃”；修复会让模型“补”出依据 |
| 冲突 | 同一概念、至少两篇文章时才检查；模型只能引用已给出的 id；同文章的对被拒 | 方案 §5.2 冲突定义 |
| 增量 | 定义：依据哈希（名称+依据 id+版本）；关系：文章内容哈希+概念对；冲突：断言文本 | 没变则零调用，见测试 |
| 人工保护 | `human_edited: true` 的页面不被覆盖；删除概念时同样跳过 | 方案 §19.4 流程 D |
| 失败隔离 | 单个概念定义失败只标该概念 failed；冲突检查失败记日志并跳过 | 与 P1 的单篇隔离一致 |

## 4. 验证
- `pytest`：**108 项全部通过**（P1 的 94 项 + P2 新增 14 项）。
- `pyflakes` 无告警。
- 测试期间发现并修复的问题：
  1. 样例文章低于 200 字被导入器正确跳过，导致只有一篇进入流程——属于测试数据问题，已加长样例。
  2. 假模型生成的定义 59 字，被长度校验正确拦截——属于假模型问题，已修正。
  3. 定义阶段最初没有步骤日志，已补上（运行日志中可见“定义”步骤）。
  4. 关系方向以模型给出的 src/dst 为准（测试原先的期望写反，已改）。
  5. 重跑时关系与冲突会重新调用模型，违背增量原则，已加缓存并增加测试。

## 5. 与方案的偏差 / 未做
- **定义字数**：方案写 100–300 字；首版放宽为 60–400 字，以免短概念因字数不足而反复修复。可在 `content.py` 中调整。
- **归一未使用共现信号**：方案 §5.2 提到“名称归一/别名表/编辑距离/共现”，首版只用字符串相似度与包含关系，共现分未参与打分。
- **超长文章不做关系**：正文超过 12000 字跳过关系步骤（需要整篇原文做摘录校验）。这是已知缺口，P3 之后再评估分段校验。
- **看板不能操作冲突与合并**：冲突只读展示；“采纳 A / 采纳 B / 并存”、“概念合并建议”、“手动加删边”（方案 §19.3）未实现，留给后续迭代。
- **人工编辑只能直接改文件**：没有看板内的编辑表单，需设置 `human_edited: true`。
- **归一两两比较为 O(n²)**：几百种写法以内可接受；规模更大需要分桶预筛。
- 概念页的 `status: failed` 页面在看板中以错误样式显示，但没有“一键重试该概念”按钮（可用 `--force` 整体重跑）。
