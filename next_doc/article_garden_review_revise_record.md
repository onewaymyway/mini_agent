# article_garden 审阅页「按意见修改」记录

- **需求**：审阅功能应该增加根据用户意见对文章进行修改的功能。
- **完成日期**：2026-11-24
- **阶段**：单阶段需求，一次完成。

## 1. 与已有「退回重写」的区别

| | 按意见修改（新增） | 退回重写（已有） |
|---|---|---|
| 做法 | 保留原文，逐节让模型判断意见是否涉及该节，只改相关小节 | 按意见整篇重新生成 |
| 适合 | 补一个例子、调整语气、删一段、改某一节 | 方向性大改 |
| 未涉及的小节 | 原样不动 | 全部重写 |

## 2. 设计

- **位置**：审阅页右侧，已成稿 / 已审阅的选题可见「按意见修改（后台）」输入框；命令行 `write_article.py <domain> <topic_id> --revise "意见"`。
- **流程**：拆出正文小节（`## 小节标题`，不含「延伸阅读」）→ 逐节调用模型判断并修改（`changed: true/false`，`text` 为修改后的完整小节）→ 重新组装全文（参考来源脚注自动按引用重建）→ 全文检查 → 独立评审。
- **校验**：修改后的小节与成文一样经过代码校验（证据标记、只用已有来源、不照抄摘录、禁用说法、范围外内容等），不通过时把具体问题回喂模型，共用每篇修复预算。
- **评审只修本次改动的小节**：评审严格度沿用设置项（严格/标准/宽松）；其他小节的既有问题只记录到 `critic_notes`，不会因此让修改失败。
- **失败不破坏原文**：修改失败（校验或评审修不好、修复预算用尽）或被中断时，文章和选题状态保持修改前的样子，原因写入运行日志。
- **意见与任何小节都无关**：文章不改动，日志提示“可把意见写得更具体，或改用退回重写”。
- **成功后**：文章回到「待审阅」（已审阅的需要重新通过审阅）；修改前的版本存入 `drafts/<tid>/revisions/`；`checks.json` 新增 `last_revision`（意见、改动小节、时间），审阅页显示上次修改；摘要重新生成。
- 只用于已成稿 / 已审阅的选题，不会自动审阅或发布。

## 5. 注意

- 每次修改要对每个正文小节各调用一次模型（判断是否涉及），小节多时调用次数比单节修改多；调用受每日上限与停止信号约束。
- 修改的是文章本身，不改选题、大纲和证据；若意见需要新增证据中没有的内容，应先补充调研。
