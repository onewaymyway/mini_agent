## 1. 现状（已有能力，不重复建设）

| 能力 | 代码位置 | 说明 |
|---|---|---|
| 画像：显式 + 统计 + LLM | `core/profile.py` | explicit 手写主题/屏蔽词；learned 由反馈离线统计（半衰期 30 天，停留作弱信号）；llm 可选归纳 |
| 画像页面 | `app.py::_profile_tab`（阶段 Pa 完成，“我的画像”页签） | 指标、关键词表、来源权重、维护按钮 |
| 推荐排序与探索位 | `core/feed.py` | 多信号打分；`explore_size` 条画像之外的内容 |
| 信息源发现 | `core/discovery.py`、`config/discovery.yaml` | 按画像生成站内搜索模板的候选源，**默认停用**，需在候选收件箱确认 |
| 数据保留 | `core/retention.py` | 过程数据定期清理，反馈与画像永久保留 |

结论：**“主动抓取可能感兴趣的信息”已有雏形**（探索位 + 发现候选），缺的是“画像如何更新与可审阅”、“发现来源是否可以更多样”、以及“画像的可解释与纠错”。

## 2. 问题

1. **画像只会被动学习**：只从反馈中学，用户不点就不更新；冷启动期几乎为空。
2. **画像难以审阅**：用户看不到“为什么系统认为我喜欢这个”，也无法说“这条不准”。
3. **兴趣会漂移**：半衰期是全局固定的，不区分“长期兴趣”与“一时好奇”。
4. **发现只依赖站内搜索模板**：候选来源单一，需要用户手工写模板，覆盖面有限。
5. **探索位只防窄化，不提供新来源**：画像之外的内容仍只来自已配置的信息源。

## 3. 目标与非目标

### 3.1 目标
- 画像可解释：每个关键词能追溯到哪些反馈，并能被用户纠正。
- 画像有“长期兴趣”与“近期兴趣”之分，衰减速度不同。
- 主动发现的来源多样化，但**每个新来源都必须经用户确认后才启用**。
- 所有新增仍保持纯文本、可人工阅读、默认不调用 LLM。

### 3.2 非目标
- 不把用户画像或反馈发送给任何外部服务（LLM 归纳是既有的可选行为，不在此扩大）。
- 不自动启用新发现的信息源，不自动抓取未确认的候选。
- 不引入向量数据库或嵌入模型；文本匹配保持现有的分词方式。
- 不要求用户配置站点或域名：站点由系统自动探索获取（见 4.2 节）。用户只确认最终是否启用某个源。
- 不做“猜测用户性格、政治立场、健康状况”等敏感推断（与 mini_agent 的隐私规则一致，见下第 7 节）。

## 4. 方案

### 4.1 画像深化（P10–P11）

**a. 画像变化日志**（P10）
- 每次重算 learned 时，与上一版比较，把“新增偏好词 / 消失偏好词 / 权重明显变化”追加到 `data/profile/changes.jsonl`。
- 画像页增加“最近变化”区块，列出最近 20 条变化，并标注触发它的反馈条数。
- 目的：让用户看到画像在如何变化，而不是只看到结果。

**b. 关键词可追溯与纠错**（P10）
- 画像表中每个关键词增加“证据”展开：列出贡献该词的最近 3 条反馈标题。
- 每个关键词提供两个按钮：“这是我的兴趣”（写入 explicit.topics）、“不是我的兴趣”（写入 explicit.exclude）。
- 显式操作优先于统计，且可撤销。

**c. 长短期兴趣分层**（P11）
- learned 拆为 `short`（半衰期约 7 天）与 `long`（半衰期约 90 天）两张表，打分时分别加权。
- 长期表只在某关键词跨越多个自然周时才进入，避免一次性点击变成长期偏好。
- 默认参数写入 `config/settings.yaml` 的 `profile` 段，可在看板调整（沿用 P9 的“看板优先于 settings.yaml”模式）。

**d. 隐式信号扩展**（P11）
- 现有信号：👍 / 👎 / ⏰ / 打开 / 停留。
- 新增候选信号（需逐项确认）：快速跳过（在快速分诊模式中按“跳过”）、同一来源被连续忽略、同一关键词在多个来源重复出现。
- 只作为弱信号进入 learned，不改变显式偏好的优先级。

### 4.2 主动发现（P12–P13）

**原则：站点由系统自动探索，用户不配置站点或域名。** 用户只决定“是否启用某个已探索出的源”。

现有 `discovery` 依赖用户手写的站内搜索模板，这一步改为自动化。新的发现流程：

1. **种子**：从画像的高权重关键词出发，种子站点来自两处。
   - 已启用信息源的页面本身（热榜、资讯页、订阅页）：读取其中的外链与分类入口，作为相关站点的线索。
   - 项目内置的公开站点目录（`config/seed_sites.yaml`，由项目维护，用户不编辑）：只列公开、无需登录的站点首页，覆盖常见的热榜、资讯、社区、视频、技术博客。
2. **探索**：对每个候选站点，复用 `core/explore.py` 生成页面结构摘要，只访问公开页面，不登录，不携带共享 profile。
3. **生成**：复用 `core/source_generator.py`，按 rss > json_api > html_list > script 的优先级生成源草稿，并自动运行一次预览。
4. **评估**：候选按预览质量打分（条目数、字段完整度、与画像的相关性、与已有源的重复度）。低于阈值的直接丢弃。
5. **收件箱**：通过评估的候选进入候选收件箱，默认停用。用户只需“启用”或“忽略”。被忽略的站点记录下来，不再探索。

**自动探索的护栏**（替代原来的域名允许列表）
- 只读取公开页面；遇到登录页、验证页、付费墙时立即放弃并记录原因，不尝试绕过。
- 遵守站点的 `robots.txt`；无法获取时保守地不访问该站点。
- 每站点有最小访问间隔，全局有每日探索次数上限（默认值写入 `config/settings.yaml`，用户可以收紧，但不需要为每个站点设置）。
- 探索的全部结果（访问的域名、时间、结论）写入 `data/discovery/explore_log.jsonl`，可在看板查看。
- 列表之外的外链只能作为线索，仍需经过同样的探索与评估。
- 用户可以在看板“屏蔽站点”，但不需要添加站点。

**统一约束**
- 所有候选默认停用；启用前不抓取。
- 每日新生成候选数量受 `limits.daily` 约束。
- 被忽略的候选按指纹记录，不再重复探索。

**探索位的升级**（P13）
- 当前探索位从已有源中挑选画像之外的条目。
- 升级为：探索位可优先展示“新发现来源”的前几条内容（仅在用户确认启用后，且只在对应来源有抓取结果时）。
- 保持 `explore_size` 上限与“探索不抢占热点资格”的规则不变。

### 4.3 成本与频率
- 发现与画像重算都不调用 LLM（默认）。
- LLM 归纳保持每日上限与手动触发，不进入定时任务。
- 关键词订阅类候选的抓取频率不高于对应模板的 `schedule`，并受站点级最小间隔约束（沿用 P9 健康机制）。

## 6. 分阶段执行（每阶段完成后更新文档，单独确认后再进入下一阶段）

| 阶段 | 内容 | 验收 | 预计 |
|---|---|---|---|
| P10 | 画像变化日志、关键词证据展开、“是/不是我的兴趣”纠错 | 改一次反馈后，画像页能显示变化与证据；纠错可撤销 | 1 天 |
| P11 | 长短期兴趣分层、隐式信号扩展 | 短期词在一周后权重明显回落；长期词需跨周出现 | 1–1.5 天 |
| P12 | 自动站点探索：种子目录 + 外链线索 → 结构探索 → 生成草稿 → 质量评估 → 候选收件箱；护栏（robots、只读、公开页、审计日志） | 无需用户配置站点即可产生候选；登录/验证页被放弃；未确认前不抓取 | 2 天 |
| P13 | 探索位升级为展示新发现来源内容 | 新来源确认后，其内容能进入探索位，且不挤占热点资格 | 1 天 |

## 7. 隐私与安全
- 画像与反馈只存在 `data/` 内，不随任何请求外发（LLM 归纳沿用既有行为：仅发送最近反馈标题，且需手动开启）。
- 画像不推断敏感属性（健康、宗教、性取向、政治立场、财务状况等）；只记录用户明确关注的主题与对条目的反馈。
- “这是/不是我的兴趣”的纠错结果会写入 explicit，用户可在画像页撤销。
- 新发现的信息源默认停用；自动探索只访问公开页面，遵守 robots.txt，遇到登录或验证即放弃，并沿用既有的“不静默失败”规则。

## 8. 风险
- **窄化与回声室**：探索位与“相关来源”生成器用于对冲，但效果需要真实使用数据验证。
- **误判的长期兴趣**：长期表的门槛（跨周出现）可能让真正的新兴趣响应变慢；可在看板调整参数。
- **外部站点变化**：自动探索生成的源仍可能因改版失效，沿用既有的健康机制（降频、暂停、告警）。
- **自动探索的合规边界**：自动访问公开站点需遵守 robots.txt 与站点条款。系统只做低频、只读、公开页面的访问；若某站点明确禁止，应从种子目录移除，而不是绕过。

## 9. 已确认的决定

| 事项 | 决定 |
|---|---|
| P10 纠错入口 | 采纳：关键词旁提供“这是我的兴趣 / 不是我的兴趣 / 撤销手动标记”，三者互斥，可撤销 |
| 长短期半衰期 | 短期 7 天、长期 90 天（P11 实施时写入 `config/settings.yaml`） |
| 种子站点目录 | 采纳项目维护的目录，初始草案见附录 A，P12 实施前需逐个核对 robots.txt 与站点条款 |
| 自动探索频率 | 每天最多 20 个站点，每站点最小间隔 1 小时 |
| “快速跳过” | 只统计，不参与打分（避免把“没时间看”误判为不喜欢） |

确认后的实施顺序：P10（已完成）→ P11 → P12 → P13，每阶段完成后更新文档并单独确认。
