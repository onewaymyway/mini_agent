# article_to_video 分镜改进方案：以测试文章《Harness：让 AI 从“灵魂”成为“生命”》为样本（待确认）

## 1. 测试样本的特征（实测）

用项目自带的解析器（`source/md_parse.py`）对文章做了统计：

| 项目 | 数量 | 说明 |
|---|---|---|
| 章节（一至二十二） | 22 | 每节以 `---` 分隔 |
| 块总数 | 400 | 段落 213，引语/强调 83，标题 32，代码块 42，列表 6，表格 1，分隔线 23 |
| 流程链（chain） | 11 | 含 `↓ → ↑` 三种箭头 |
| 文本代码块（text） | 30 | 169 行：标签列表、公式式表达、对比、分层、阶段 |
| 架构图（ascii_art） | 1 | 第 28 节的 “循环” 架构图，约 1775 字符 |
| 公式块（math） | 0 | 文章的 4 个关键公式都写在代码块里，没有 `$` 标记 |
| 表格 | 1 | 16 行数据，“人类系统 / AI 系统”对照 |
| 列表 | 6 | 9、10、6、11、6、10 项 |
| 概念标题 | 约 6 | `# Identity Infrastructure`、`# Experience Loop`、`# Life Data`、`# AgentOS`、`# Artificial Life`、`# Intelligence Infrastructure` |

文章的论证方式很典型：**抽象概念 + 类比 + 因果循环 + 反复的对比与递进**。这正是讲解视频最难的内容，因此适合作为样本。

## 2. 现状问题（逐条对照代码）

### P1 截断导致关键结论丢失（已量化）

`director.py` 的上限是：流程 6 个节点、列表 5 项、表格 6 行。文章中超限的结构：

| 位置 | 原文 | 被丢弃的内容 | 影响 |
|---|---|---|---|
| s24 | Prompt → … → Model（9 个节点） | **Identity、Goals、Model** | 丢掉了这一节的结论“先进化生命形态，再进化神经网络”中的落点 **Model** |
| s17 | Model → … → Evolution（10 个节点） | Memory、Learning、Identity、Evolution | 核心循环的后半段消失 |
| s06 | World → … → World（8 个节点） | Action、World | 闭环的回到 World 看不见 |
| s03 | 感知 → … → 再次行动（7 个节点） | 再次行动 | 循环的返回点消失 |
| s10 | Model → … → New Experience → …… （7 个节点） | New Experience | “经历循环”的回路消失 |
| s21 | 人类系统 ↔ AI 系统（16 行） | 10 行 | 对照表只剩 6 行，映射关系不完整 |
| s19 | 11 项列表 | 6 项 | 半数内容不见 |

**根因**：截断是“静默”的，且按前面截取，丢的恰好是句子的结尾（结论、落点、回路）。

### P2 向上箭头被当作向下箭头（方向反转）

`source/ascii_graph.py` 的箭头分割把 `↑`、`↓`、`→` 同等处理，节点按书写顺序排列。文章第 25 节写的是：

```
Application Layer
        ↑
AgentOS / Harness Layer
        ↑
Model Layer
        ↑
Compute Layer
```

`↑` 的含义是“堆叠在上面”，`Compute` 才是底座。当前解析得到的节点顺序是 `Application → AgentOS → Model → Compute`，若渲染为流程箭头，画面会表达 **Application 驱动 Compute**，与原文相反。这是**语义错误**，不是样式问题，比截断更严重。

### P3 文本代码块整体被忽略（169 行）

分镜只读取 `chain`、`table`、`list` 三类结构块（`_build_beat` 与 `beat_context`）。`shape=text` 的代码块（30 个）和 `ascii_art`（1 个）**完全不参与分镜**，只能退化为口播句子的卡片。它们恰恰是文章中最密集的信息：

- 标签列表：`Identity / Memory / Environment / Experience / Learning / Adaptation / Relationship / Goal / Continuity`（s22，9 项）
- 公式式表达：`Identity ≈ Model + Memory + Experience + Continuity`（s07）、`AI = Potential × Embodiment × Experience × Continuity`（s29）
- 分层递进：`早期 Harness → 中期 Harness → 高级 Harness`（s15），每层带一组标签
- 对比：`Model = Same`、`A ≠ B`（s07、s12）
- 数据列表：`完成 18,000 个任务 / 犯过 3,000 次错误 …`（s14，7 项带数字）

### P4 公式检测不到（0 个公式块）

公式识别依赖 `math` 块（`$...$`）。文章的 4 个核心公式都是普通代码块，因此 `formula` 类型从不会出现。这意味着“公式本体始终可见”的要求，对这篇文章完全没有生效。

### P5 架构图未解析（s28）

约 45 行的框线图（“循环”架构：Foundation Model → Harness → Experience → Memory → Learning → Identity → Evolution，回到 Experience）被标记为 `ascii_art`，`nodes` 为空，分镜不读取。文章中最重要的一张图完全没有进入视频。

### P6 “循环”语义丢失

文章反复使用“循环”（第 4、7、10、16 节等），但回路只在**节点完全重复**时才标记（`loop = 节点有重复`）。本文的回路靠“回到开头”“再次行动”“……”表达，都没有被识别，所以 `loop` 全为假。

### P7 概念标题没有画面

6 个概念标题（`Identity Infrastructure`、`Experience Loop` 等）是全文的术语锚点，分镜规则不读取标题块（32 个标题块均未参与分镜）。观众第一次听到这些术语时，画面上没有定义。

### P8 抽象概念无法做插图主体

插图主体规则禁止抽象词作主体（`ABSTRACT_WORDS`，如“效率”“趋势”）。本文几乎全是抽象概念（Harness、Identity、Experience），因此插图要么被拒，要么落到泛泛的“人脑”“大楼”。但文章本身给出了**具象类比**：人（第 1 节）、大脑、神经系统、电网、交通系统（第 18 节）、人体器官对照（第 21 节）。这些是现成的、可在原文中找到依据的插图主体，目前没有被利用。

### P9 递进叙述被拆散

第 1 节与第 25 节出现 “过去…：> Compute / 然后：> Model / 接下来：> Application”这类**递进**叙述，三个标签被拆成三个独立的引语块，画面上是三张互不相关的卡。

### P10 对比与问答没有对应卡型

第 30 节的 “常见观点 vs 本文判断”（“模型越强，Harness 越厚” / “Harness 会被模型逐渐吃掉” vs “只要 AI 仍然需要存在于一个世界中，Harness 就不可能消失”）是典型的对比结构，但目前只能是两张引语卡。

### P11 回顾段落超出卡片密度

第 30 节结尾的六行总结（`模型赋予…` … `而时间，最终决定它会成为谁。`）是一个引语块，整体塞进一张卡，超出“每卡要素 ≤ 3”的目标（见 richness 方案）。

## 3. 改进方案

按“结构正确性 → 卡片承载 → 覆盖与回归”三层推进。

### 层一：结构正确性（source 与分镜读取）

**A1 超限分页，不静默截断。** 流程、列表、表格超出上限时拆成续镜，每镜保持原文顺序；续镜保留上一镜的最后一项作为衔接（例：`…Model | Identity | …`）。16 行对照表拆为 6 + 6 + 4 行，三镜依次显示，每镜内整体显示（与 sync 方案的“整体显示”一致，不要求一次显示 16 行）。超限必须产生分镜警告，不得静默丢弃。

**A2 箭头语义。** 解析器区分三种箭头：
- `→`、`↓`：流程（时间或因果先后）；
- `↑`：堆叠（层级），节点按**从下到上**排列，渲染为层级图（或降级为列表），禁止渲染为流程箭头；
- 末尾 `……` 或 `再次`、`回到`、`循环`：回路标记（见 A5）。

**A3 文本代码块分类。** 对 `shape=text` 的代码块做规则分类（纯规则，不调用模型）：
- `formula`：含 ≈ = × + 且至少两个操作数，符号为英文或拉丁词 → 公式（见 B3）；
- `kv`：每行形如 `X = Y` 或 `X ≠ Y` → 对比；
- `stages`：首行为“早期 / 中期 / 高级 X”形式，后续为标签 → 递进（见 B2）；
- `labels`：多行短词、无标点 → 列表或分组列表；
- `numbered_facts`：每行“数字 + 单位 + 名词” → 数据列表（可作为数据卡的候选）；
- 其余保持 `text`，只作为口播句子的补充。

**A4 架构图解析。** `ascii_art` 按框线解析：框内文字为节点，连线与箭头为边，框外的 `↑`/`↓` 提示回路。第 28 节可解析为 7 个节点加一条回到 Experience 的回路。解析失败时保留原样并记为 `ascii_art`，分镜给出警告而不是忽略。

**A5 回路识别升级。** 识别以下信号：节点重复、末尾 `……`、相邻句含“再次”“回到”“循环”“反复”。命中则 `loop=true`，渲染回路箭头（文章中的 s03、s06、s10、s16 都属于这一类）。

**A6 概念标题入库。** 概念型标题（非章节标题，如 `Experience Loop`）及其后第一句定义，作为“概念条目”写入 `blocks.json`，供定义卡使用（见 B5）。

### 层二：卡片承载（分镜选择）

**B1 结构块必须被承载。** 每个结构块（流程、列表、表格、公式、架构图、阶段）必须至少被一个镜头承载，否则分镜校验报错。这与覆盖检查（richness 方案 4.1）合并实现，覆盖对象从“规划要点”扩展到“结构块”。

**B2 递进卡。** 对 `stages` 与“先…再…”“首先…然后…”“过去…然后…接下来…”类递进，生成递进卡：每个阶段一个方框（标题 + 1–3 个标签），阶段之间用方向箭头，按原文顺序显示。第 25 节的 Compute → Model → Application 可以作为一张向上堆叠的递进卡（A2 的层级图），而不是三张引语卡（P9）。

**B3 公式卡（公式本体始终可见）。** 公式本体固定在上方；解释的映射取自紧随其后的句子，例如第 7 节：`Identity ≈ Model + Memory + Experience + Continuity`，紧随的原文是“模型提供潜能。经历塑造个体。连续性创造‘我’。”，可得到符号卡：`Model — 潜能`、`Experience — 经历`、`Continuity — 连续性`（符号取自公式，含义取自原句，不编造）。这一项直接解决 P4。

**B4 插图主体：用文章中的具象类比。** 抽象概念（Harness、Identity）不做插图主体，改用定义卡或符号卡；插图只用文章中已出现的具象对象（人、大脑、神经系统、电网、交通系统），主体词必须在原文中出现（沿用 token 检查）。这样既不违反“抽象词不作主体”，也让插图与原文类比对应。

**B5 定义卡（概念标题）。** 概念标题首次出现时生成定义卡：大字术语 + 原文定义句（可截取）。例：`Experience Loop` + “感知 → 思考 → 行动 → 获得结果 → 形成记忆 → 改变自己”的原文截取（P7）。

**B6 对比卡。** 对 `kv` 块与“常见观点 vs 本文判断”结构生成对比卡：左栏为“常见观点”，右栏为“本文判断”，两侧文字均取自原句。第 30 节可以生成一张对比卡（P10）。

**B7 回顾卡分组。** 结尾的六行总结拆为两张回顾卡，每张三条（P11），与 richness 方案的“每卡要素 ≤ 3”一致。

### 层三：覆盖与回归

**C1 以文章为回归样本。** 将本文放入 `tests/fixtures/`，编写断言：
- 流程与列表不再静默截断（所有节点或条目都出现在某个镜头中）；
- s25 的层级不被画成流程箭头（方向校验）；
- s07 的公式被识别，符号卡的映射存在；
- s21 的 16 行表格分为三镜，每行都被承载；
- s28 的架构图被解析出节点与回路；
- s30 的六条回顾分为两张卡；
- 插图主体均在原文中出现过。

**C2 覆盖报告。** 分镜完成后输出一份覆盖报告：每个结构块、概念条目、规划要点对应的镜头编号；未覆盖的列出来，写入分镜的 `coverage` 字段（与 richness 方案 4.1 共用同一结构）。

## 5. 风险与取舍

- **误判风险（A3）**：规则分类可能把普通标签列表误判为公式或递进。缓解：每条规则配测试样本（本文中的每个 text 块都作为正例或反例）；误判由分镜编辑界面修正，不阻断。
- **分页增加镜头数**：16 行表格变成三镜，会拉长时长。需要与时长预算联动（分镜的预算校验已存在，应在超出时提示而不是静默压缩）。
- **“↑ 为堆叠”的前提**：本文第 25 节的用法是清楚的，但不是所有 `↑` 都表示堆叠（如第 11 节的 “↑ 用户…”）。缓解：只在上下相邻的行都是名词短语、且没有动词时判定为堆叠，否则保持流程。
- **插图类比（B4）**：用类比作主体会偏离“只表达原文内容”，但类比本身就是原文内容。缓解：主体词必须在原文中出现，且不得包含原文没有的具体对象。
- **不改动**：大纲、口播稿生成、配音、导出、预算账本。

## 8. 已确认的决策与第一期实施记录（2026-11-20）

### 8.1 已确认的决策（对应第 6 节）

- **Q1 拆分**：超限结构拆成续镜，每镜保持原文顺序，不静默截断。
- **Q2 堆叠层图**：新增 `stack` 版式。原文只用 `↑` 书写的链按堆叠处理，自上而下书写、底层在最后，箭头自下而上，不画成流程。
- **Q3 自动分类**：允许新增文本块的自动分类规则（分类规则本身在二期实施）。
- **Q4 具象类比作主体**：允许以文章中的具象类比作插图主体（三期实施）。
- **Q5 概念定义卡**：只对首次出现的概念生成（三期实施）。
- **Q6 回归样本**：本文作为 `tests/fixtures/harness_article.md` 放入仓库（按默认采纳，如需撤回可删除）。

### 8.2 第一期改动（结构正确性）

- `source/ascii_graph.py`：`↑` 单独使用时 `direction=up`，节点按书写顺序；回路判定增加“再次/回到/循环/反复”与末尾省略号（节点不少于 3 个）。
- `visual/states.py`：结构化类型（流程、堆叠、表格、列表、年代线）整体一次显示，只有一个状态；公式与逐条要点不变。新增 `stack`，`ALL_AT_ONCE_TYPES` 导出。
- `visual/shots.py`、`visual/director_llm.py`：镜头类型新增 `stack`；`flow` 对堆叠层级不可用（回退为卡片，并记录 `fallback_from`）。

## 11. 第四期实施记录（对比卡、回顾分组、回归样本、覆盖报告展示）

### 11.1 改动

- **B6 对比卡（新画面类型 `contrast`，镜头类型 `contrast`）**：
  - 识别（`visual/structures.py::contrast_of`）：段落以「不是：」或「也不是：」结尾并紧跟引语，记为左栏；随后的「而是：」加引语，记为右栏。左右各至少一条，每条为单行引语且不超过 40 字。第 30 节得到左 2 条、右 1 条；第 26 节「这层解决的不是：> … 而是：> …」同样成立。
  - 来源二：文本代码块（kv）中的「X ≠ Y」逐行写法或「X / ≠ / Y」三行写法，左栏为 X、右栏为 Y，无栏标题。测试文章中没有这种写法，因此只有单元测试覆盖。`=` 不被当作对照（第 7 节的 `Model = Claude` 等不会误判）。

### 11.2 与计划的偏差（需要你知道）

- **对比卡的栏标题**：计划写的是「常见观点」「本文判断」。实际实现改为原文的对照词「不是」「而是」。原因：第 26 节的对照是「这层解决的不是：…而是：…」，左侧并不是“常见观点”，用该标题会给原文加上不存在的立场。直接取原文的词则对两节都准确，且不添加任何结论。如需改回计划的标题，只需修改 `CONTRAST_LEFT_TITLE` / `CONTRAST_RIGHT_TITLE`。
- **回顾卡的画面类型**：计划没有规定名称。实现为独立类型 `recap`（而不是复用 `list`），因为它是一张整体显示的卡片，且编辑界面可以区分。分页机制与列表完全相同。
- **覆盖报告只读**：报告是生成时的快照，界面不提供修改。若需要在界面上手动补齐，留待后续。
- **kv 中的 `≠` 对照**：只有单元测试，没有在测试文章中出现的实例（文章中唯一的 `A ≠ B` 只有一行，不构成 kv 块）。
