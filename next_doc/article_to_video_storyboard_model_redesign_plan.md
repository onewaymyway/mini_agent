# article_to_video 分镜改造计划（模型版优先）

> 状态：第一期已完成（2026-11-19，见第 11 节）；第二期（口播稿改造）待样例确认后开始。本文档覆盖 R21 之后的分镜与口播改造。
> 规则版（离线）保留，本计划不改动规则版。
> 每期完成后更新本文档对应章节，并打包提供下载（保持目录结构）。

## 0. 已确认的决定

| 项目 | 决定 |
|---|---|
| 画面与口播的关系 | 关键论点、表格、图表、流程图等必须上画面；画面与口播可以重复；不再因"画面上有字，口播就不说"而省略 |
| 听众体验 | 很多用户只听不看，口播与字幕必须连续完整，不看画面也能理解全部内容 |
| 字幕 | 始终开启，逐句原文，不做摘要，不因画面有字而隐藏 |
| 金句 | 保留整句字卡，同时显示该句字幕 |
| 插图数量 | 不设固定比例，允许增加或减少，只受图片额度约束 |
| 主要使用的版本 | 模型版（需要优先做好） |
| 模型调用方式 | 接受分窗调用（每章拆成多个窗口，逐窗调用） |
| 口播稿 | 需要改造：含图形内容的段落，口播要把关键数字与关系讲清楚；但不是机械地"口述图形"，而是用自然的口语方式表达 |
| 第一期范围 | 只做模型版的结构改造；规则版暂不动 |

## 1. 背景与问题

现状（基于 `visual/director_llm.py` 与口播稿生成）：

1. 每章一次模型调用，输出约 3000 字；任一校验错误即整章重试，重试 3 次仍失败则整章失败。日志中多次出现"只差一处问题，却整章重来"。
2. 提示词要求画面文字必须逐字来自本段口播，模型只会复述句子，不会把关系、结构画成图。
3. 输出是"每段一个场景"，没有句子范围与镜头切分，无法表达"这一镜讲的是 A 到 B 的流程"。
4. 口播稿阶段不知道后面的画面需要什么；含表格、流程、数据对比的段落，口播往往泛泛带过，画面要表达的信息在声音里找不到，听众会断线。

## 2. 目标

- 模型版生成的分镜：画面形式适合内容（论点、数据、结构、流程以图形呈现；比喻与场景用插图；金句用字卡）。
- 镜头与句子精确对齐，字幕连续完整。
- 单章失败的影响局部化：只重做出错的窗口。
- 口播对含结构的内容有清楚的口语表达，听众不看画面也能理解关键数字与关系。

非目标（本计划不做）：规则版改造；视频生成；画面风格的美术重做；字幕样式的重新设计。

## 3. 设计原则

1. **画面是内容的可视形式**，与口播可以重复；画面不得引入口播没有的新信息（保证听众能懂）。
2. **口播是完整的主信息通道**：凡是画面上出现的关键数字、名称、关系，口播在同一镜头的时间段内都要以口语方式说到。
3. **口语化而非口述图形**：口播用讲解的方式把结构说清楚（例如"先是……，接着……，最后……"），不写"如图所示"、"见下方流程图"之类依赖画面的表述。
4. **字幕连续**：字幕逐句对应口播，始终开启，不因画面而隐藏。金句字卡例外只在于画面形式，字幕照常显示。
5. **镜头依据视觉变化切分**，并与句子范围精确对齐。
6. **防编造保留**：图表与表格中的数字、名称必须能在原文或口播中找到；关系与结构允许归纳，但归纳出的节点必须在该镜头的口播中被提及。

## 4. 第一期：模型版结构改造（本期范围）

### 4.1 分两步调用

**第一步：章级策划（1 次调用）**

- 输入：整章口播（已确认的口播稿，含句号与段落结构）、原文结构块列表（表格、流程、公式、列表、代码块）、图片额度。
- 输出（精简，主要是判断）：
  - 每段的视觉角色：`argument`（关键论点）、`data`（数据与对比）、`structure`（结构与流程）、`formula`（公式）、`quote`（金句）、`narrative`（叙述过渡）、`image`（比喻与场景）、`hold`（保持上一镜）；
  - 每段的要点列表（每段 1–4 个需要被看见的内容，每条不超过 20 字）；
  - 窗口划分建议（由模型根据内容边界给出）。
- 不输出镜头细节，不输出提示词。

**第二步：分窗落镜（每窗 1 次调用，窗口长度 3–5 段）**

- 输入：本窗的口播句子（带句号）、本窗段落的视觉角色与要点、上一窗最后一镜的摘要（类型、主体、句子范围）、图片额度余量。
- 输出：本窗的镜头列表，每个镜头包含：句子范围、画面类型、图形内容、揭示时机、插图的视觉主体与场景（如适用）。
- 窗口之间必须衔接：第一镜的句子范围紧接上一窗最后一镜。

窗口边界尽量落在段落边界上，避免把一个论点切在两窗之间。

### 4.2 镜头数据结构（新）

每个镜头：

```json
{
  "id": "P04.shot03",
  "sentences": ["P04.b05.s01", "P04.b05.s03"],
  "kind": "chart | table | flow | quote | illustration | keypoint | hold | formula",
  "content": { "...按 kind 不同..." },
  "reveal": [{"step": 0, "at": "P04.b05.s01", "element": "..."}],
  "image": { "subject": "...", "scene": "...", "composition": "..." }
}
```

- `sentences`：句子范围（起止，连续）。
- `content`：
  - `chart`：数据点（标签、数值，数值必须可溯源）、图表类型（柱、线、对比）；
  - `table`：表头与行（每个单元格的值可溯源）；
  - `flow`：节点列表（名称 ≤ 8 字）与有向边；
  - `quote`：整句金句文字（与字幕同句）；
  - `keypoint`：要点列表（每条 ≤ 20 字，最多 4 条）；
  - `formula`：公式原文与逐步解释的要点；
  - `illustration`：插图镜头的内容由 `image` 字段描述，`content` 可为空；
  - `hold`：不产生新画面，沿用上一镜。
- `reveal`：每个元素在口播中首次被提及的句子，画面元素按口播时机出现。
- `image`：视觉主体（具体物体或场景，不得是抽象词）、场景、构图；不包含文字请求。

### 4.3 切镜规则

- 切镜依据视觉变化：同一图形讲完之前不切；新论点、新对象出现时切。
- 单镜时长参考 4–10 秒（由句子时长估算），超过时在口播自然停顿处切。
- 同一段内可以有多个镜头；不同段落的镜头不得跨段（除 `hold`）。
- 单镜画面元素不超过 3 个（超出时拆分镜头，而不是压缩内容）。

### 4.4 局部修复与缓存

- 校验按镜头定位错误。出错时只重做出错的窗口，已通过的窗口保留。
- 修复提示只包含：出错的镜头原文、具体错误、允许修改的范围。例如"镜头 P04.shot03 的流程节点『AgentOS』在口播 P04.b05.s01–s03 中没有出现，请补充口播句子或删除该节点"。
- 缓存：章级策划以"口播稿指纹 + 结构块指纹 + 额度"为键；窗口落镜以"窗口句子指纹 + 窗口视觉角色 + 前一窗摘要指纹"为键。口播未变的窗口不重新调用模型。
- 每次调用的日志沿用 R15 第二阶段的格式（输入规模、耗时、全部错误、保留与重做的窗口）。

### 4.5 校验（第一期需要的最小集合）

| 规则 | 级别 |
|---|---|
| 镜头句子范围连续、不重叠、覆盖全部句子 | 错误 |
| 图表与表格中的数字、名称能在原文或口播中找到 | 错误 |
| 流程节点、图表标签在该镜头口播中被提及 | 错误 |
| 插图提示词包含文字、标题、标志请求 | 错误 |
| 单镜元素超过 3 个 | 错误（要求拆分镜头） |
| 同一类型镜头连续超过 3 个 | 警告 |
| 金句镜头的字幕未显示 | 错误（金句必须同时显示字幕） |

画面与字幕的重复不作为检查项。

### 4.6 与现有产物的关系

- 第一期只改动 `director_llm.py` 的模型版路径与分镜数据结构；规则版 `director.py` 不改。
- 分镜数据结构变化（镜头列表替代"每段一个场景"）会影响渲染（`render/compose_part.py`）与合成（`compose/segments.py`）。第一期需要让渲染读取新结构；如果渲染改动较大，拆出为第一期的子任务，先保证新结构能被渲染。
- 旧分镜（旧结构）在新版本下标记为过期，需要重新生成。

## 5. 第二期：口播稿改造（含图形内容的段落）

- 口播稿生成的提示词增加一条要求：含表格、流程、数据对比、公式的段落，口播要用口语把关键数字、关系与顺序讲清楚。
- 表达方式：用讲解的方式描述结构，例如"第一步……，接着……，最后……"、"A 是 B 的两倍，主要因为……"。禁止"如图所示"、"见下图"、"上面的流程图"等依赖画面的表述。
- 口播的数字与关系必须来自原文，不得新增原文没有的事实。
- 只对含结构的段落重写（指纹变化的段落），其它段落保持不变。
- 评估：抽取含结构的段落，检查口播是否能不看画面讲清楚。

## 6. 第三期：插图与提示词

- 插图由内容决定：比喻、场景、抽象概念的具体化适合插图；数据、流程、定义适合图形或字卡。
- 插图数量不设固定比例，只受图片额度约束。
- 插图提示词由视觉主体、场景、构图、风格锚组成，明确不含文字、标题、标志。
- 视觉主体必须是具体的物体或场景（如"齿轮与蒸汽"），不得是抽象词（如"效率"）。

## 7. 第四期：评估

用参考文章 P01–P05 评估：

1. 只听字幕：口播与字幕能否讲清楚主要论点与结构（人工抽样）；
2. 只看画面：图形能否看出结构与关系（人工抽样）；
3. 错位率：画面元素在对应镜头口播中出现的比例（自动统计，目标 100%）；
4. 字幕连续性：句子范围覆盖率（自动统计，目标 100%）；
5. 耗时：单章总耗时与每窗耗时，对比改造前。

每期结束提供前后对比（同一段落的旧分镜与新分镜）。

## 8. 分期与确认

| 期 | 内容 | 确认点 |
|---|---|---|
| 第一期 | 模型版结构改造：章级策划 + 分窗落镜 + 镜头数据结构 + 局部修复 + 缓存 + 最小校验集 | 结构与耗时确认后进入第二期 |
| 第二期 | 口播稿改造（含图形内容段落的口语表达，需要重新生成相关口播） | 口播样例确认后进入第三期 |

| 第四期 | 评估与参数调整 | 评估结果确认后结束 |

## 9. 风险

- 分窗调用增加调用次数，单章总耗时可能持平或略增；每窗更快，失败影响更小。
- 口播稿重写会改变已确认的口播，需要用户重新确认相关段落。
- 镜头结构变化要求渲染与合成同步改造，第一期的范围可能需要拆分。
- 模型输出稳定性：分窗后每窗输出更短，理论上更稳定，但需要在第一期用参考文章验证。

## 10. 第一期开始前需要确认的细节

1. 窗口长度是否固定为 3–5 段，还是按字数（建议按字数，约 1500–2500 字一窗）？
2. 章级策划的输出是否需要用户可见并可编辑（建议第一期先不做编辑界面，只在日志中展示视觉角色）？
3. 旧分镜过期后，是否允许保留旧结构作为只读参考？

## 11. 第一期实施记录（2026-11-19）

**完成内容**

- 两步调用：章级策划 1 次（每段视觉角色与要点，只做判断）；分窗落镜每窗 1 次（`visual/director_llm.py`）。
- 窗口：按段落边界切分，累计约 2500 字以内；单段超限自成一窗（`visual/shots.py: plan_windows`）。
- 镜头结构：镜头 = 同一段内连续句子，`sentences = [首句编号, 末句编号]`，带 `kind`；场景形状与渲染格式不变，`reveal.at_sentence` 仍为段内句序号。
- 类型映射：keypoint、illustration、quote、formula、flow（渲染为 diagram）、chart（渲染为 table，表头「项目 / 数值」）、table、list；hold 并入同段上一镜，段首 hold 改为卡片（记录 `fallback_from`）。
- 局部修复：校验失败只重做出错的窗口，最多 3 次；已通过的窗口保留并缓存。
- 缓存：`parts/<章>/director_cache/`，策划与窗口各自按输入指纹缓存；`force` 忽略缓存；重置分镜阶段时一并清除。
- 最小校验集：镜头在每段内连续覆盖全部句子；流程节点与图表标签必须出现在镜头自己的句子中；数字与英文词须来自本段口播或原文结构；插图额度按窗口累计检查；单镜条目不超过 3 个（流程、表格、原文列表由原文决定，不受此限）；同类型连续超过 3 个为警告。
- 联动修改：渲染按镜头句子范围取时间段（`RENDER_VERSION` 升为 p4-render-v3）；字幕按句查找所属镜头，默认模式改为 `always`；分镜编辑页与规范化保留句子范围与类型；批量分镜的 `force` 不再被写死为 True。
- 版本：`LLM_PROMPT_VERSION = s4-llm-v2`，旧的模型版分镜自动标记为过期。

**有意的偏差**

- 窗口按字数切分，不由模型决定（采用第 10 节的推荐值）。
- 图表暂以表格绘制，没有柱状图渲染器。
- 第一期没有策划的编辑界面，策划结果仅保存在分镜文件的 `plan` 字段与日志中。
- 单镜元素上限取 3（计划 4.5），与 `director.py` 中关键词卡最多 4 条的规则并存：模型版按 3 执行，规则版与手工编辑仍按 4。
- 金句镜头的字幕"必须显示"规则依赖字幕模式为 `always`；若用户把字幕设为 `auto` 或 `off`，此规则不会被强制检查。

**验证**

- 新增 `tests/test_s1_shot_structure.py`（23 项）：分窗边界、整章覆盖、局部修复只重做出错窗口、缓存复用与强制、hold 合并与段首回退、流程节点与图表标签的句子校验、金句与插图额度、策划剔除无依据要点、渲染时间段、字幕按句映射、编辑规范化、校验器的覆盖规则。
- 改写旧测试：模型版分镜的测试（`test_p4_sharing_llm.py`、`test_r15_stage2_storyboard_logs.py`）改为两步协议；`test_p4_pure.py` 的连续同类型规则改为警告；`test_p5_pure.py` 与 `test_r4d_legacy_compat.py` 的字幕默认值相应更新。
- 全量：525 项通过、3 项跳过（基线 502 + 新增 23）。

**未验证**

- 没有调用真实文本模型。策划与分窗的输出质量、以及每章的实际耗时，需要在本机用真实模型运行一章后确认。
- 字幕默认值改为 `always` 只影响新项目与未显式保存过该字段的项目。

**下一步**

第二期（口播稿改造）：对含表格、流程、数据对比与公式的段落，口播改为口语方式讲清关键数字与关系。需要先确认第一期的分镜结构与耗时。
