## 问题1（P0）：小场景画面按"规划预估时长"缩放，不是按"真实配音时长"缩放，导致画面/字幕逐场景相对配音漂移

### 现象
用户反馈：合成后的大场景视频里，经常是某句配音已经开始播放了，对应的
画面和字幕却还停在上一个小场景，隔了一小段才切过来——越往视频后面这种
错位越明显。

### 根因
`compose_macro_scene.py` 的合成流程分两层对齐：

1. **小场景内部**：Step 2 把每个小场景的 clip 缩放到
   `s["duration_sec"]`——这是**规划阶段**（`novel-video-planner` /
   `check_scene_detail.py`）按粗估语速预估、并量化到视频生成接口
   4~12 秒硬上限/下限区间的一个**预估值**，不是这个小场景配音合成
   完成后的**真实时长**。
2. **整个大场景**：Step 3 拼接完所有小场景画面后，只在**总时长**层面
   把 `joined_dur`（画面总时长）和 `audio_dur`（配音总时长）做一次
   比较，如果对不上就整体 `setpts` 拉伸一次（`align_scale`）强制对齐。

问题就出在这两层之间的空隙：**每个小场景内部**，画面时长（预估值）和
这个小场景自己的真实配音时长完全没有单独对齐过。规划阶段的预估语速
（`common.ROUGH_CHARS_PER_SEC`，约 4.5 字/秒）本来就是个粗略经验值，
加上还要被量化到 4~12 秒区间，几乎不可能和 TTS 引擎真实合成出来的时长
精确相等。于是场景 1 的画面比它的真实配音长一点点，场景 2 又比它的真实
配音短一点点……这种场景级的时长误差会逐场景累积，而最后那次"整体拉伸"
只能保证**总长度**兑平，完全没法修正**每个小场景内部**的画面/字幕和
它自己配音之间的错位——这正是用户看到的"配音先出来，画面慢一拍才跟上"，
且越往后累积误差越大、越明显。

对应代码位置（改动前）：

```python
# Step 2：用规划阶段的预估时长缩放画面
target_dur = max(s["duration_sec"], 0.1)
scale = target_dur / clip_dur
...
# Step 3：只在总时长层面做一次整体强制对齐，无法修正场景内部错位
if abs(joined_dur - audio_dur) > ALIGN_EPS:
    align_scale = audio_dur / joined_dur
    ...  # 整体 setpts 拉伸

# Step 4：字幕时长也用的是同一个预估值
dur = round(s["duration_sec"] * align_scale, 6)
```

### 修复方案（已实施）
把"每个小场景画面缩放到多长""每个小场景字幕显示多久"的依据，从
"规划阶段的预估 `duration_sec`"改成"这个小场景自己真实的配音时长"
（Step 1 拼接 `per_scene_audio` 之后就能拿到，`get_dur(per_scene_audio[id])`）：

1. 在 Step 1 拼完每个小场景的 `per_scene_audio` 后，立即算出
   `scene_audio_dur = {场景id: 真实配音时长}`；
2. Step 2 的 `target_dur` 改用 `scene_audio_dur[s["id"]]`，画面直接
   对齐自己场景的真实配音；
3. Step 4 渲染字幕的 `dur` 同样改用 `scene_audio_dur[s["id"]]`（仍然
   乘以 `align_scale` 保留一层兜底，见下条）；
4. Step 3 末尾原来的"整体强制对齐"逻辑**保留但降级为兜底**：逐场景
   已经各自对齐了真实配音时长后，`joined_dur` 和 `audio_dur` 理论上
   应该已经非常接近（只剩编码/帧率量化的极小误差），这一步只用来
   兜住这类极小误差；如果这里的差值仍然明显偏大，就该回头去查某个
   具体小场景的缩放是不是出了别的问题，而不是心安理得地指望这一步
   兜得住。

修复后每个小场景的画面/字幕边界和它自己的真实配音边界精确重合，
不再有"预估时长"和"真实时长"之间的缝隙可以累积漂移。

### 影响范围确认
- 只影响 `compose_macro_scene.py` 一个文件的 Step 1/2/3/4，不涉及
  `generate_scene_videos_v2.py`（clip 生成时长仍然按规划阶段的预估值
  向视频生成接口请求，这个不用改——生成时长本来就没法做到和 TTS 完全
  精确一致，缩放到真实配音时长这一步本来就是为了兜住这个天然误差）；
- 不影响 `check_scene_detail.py`/`check_assets_and_audio_v2.py` 的粗估
  校验逻辑（那两处是规划/复核阶段的"提前预警"，目的是尽早拦下明显
  超限的文本量，不追求和真实配音时长完全一致，本次不改）；
- `scene["duration_sec"]` 字段仍然会被 `load_micro_scenes()` 读入，
  只是不再用于 Step 2/4 的缩放计算，保留字段本身不影响其它逻辑。
