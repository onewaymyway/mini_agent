# novel_writer 完稿后修改机制方案（设计，待确认后实施）

> 状态：设计已确认的部分：①设定变更支持两种时间语义，由作者逐次指定；②修改产生新版本，原稿永不改写；
> ③本机制是独立流程，不改动现有写作流水线。以下分期为待确认的实施计划。

## 1. 边界与不变量

- 启用条件：全书终审（final_review）已通过，才可进入完稿修改流程。
- **原稿只读**：完稿快照 v1 写入后不再改动，附 manifest（每文件 sha256）用于校验。
- **新版本**：每次确认执行的修改，先整体复制当前版本到 `_versions/vNNN/`，所有改动只落在新版本里。
- **不侵入现有流水线**：不新增 steps.py 步骤，不写 pipeline_state.json，不被 worker / G 挡位 / G5 托管 / 自动重跑调用。
  独立模块 `novel_writer/revision_flow/`，独立状态 `_versions/` 与 `_revision/` 目录，独立入口与独立 UI 页。
- 不改动：chapter_ops、ondemand、concept_revision、patrol 的现有行为。

## 2. 设定变更的时间语义（每次变更由作者选择）

| 模式 | 含义 | 影响范围 | 额外检查 |
|---|---|---|---|
| retcon 追溯式 | 全书仿佛一直如此 | 所有出现该设定的章节 | 无 |
| from_chapter 从第 N 章起 | 故事内发生的变化 | 第 N 章及之后涉及该设定的章节；N 之前不动 | N 之前章节若引用了新设定，报警告，作者决定是否放弃或前移 |

确认页必须展示：模式、生效章节、受影响章节清单及每章理由，作者确认后才执行。

## 3. Change 数据模型

```
Change {
  id, created_at, source: "direct" | "chapter_feedback",
  target: {kind: character|world_rule|plot_thread|timeline_fact|chapter_outline, id},
  before, after, reason,
  mode: "retcon" | "from_chapter", effective_from: int | null,
  base_version, result_version (执行后填写), status
}
```
存于 `_revision/changes/<id>.json`，修订日志由它派生。

## 4. 分期实施

**P0 完稿版本基线（不调用 LLM）**
- `revision_flow/versions.py`：完稿快照 v1、manifest、只读校验、列出版本、以版本为单位的复制。
- 完稿门禁：final_review 通过才允许创建修订。
- 测试：快照内容与 manifest 一致；修改 v2 不影响 v1；未完稿时拒绝。

**P1 变更模型与影响预览（确定性，不调用 LLM）**
- Change 模型与校验；两种时间语义的受影响章节计算。
- 章节实体索引：出场角色字段 + 角色名与别名文本匹配 + 伏笔引用，生成 `_revision/index/`。
- 预览接口：返回受影响章节、理由、from_chapter 模式下的前文引用警告。作者确认后才能进入 P2。
- 测试：两种模式的章节集合；前文引用警告；未确认不执行。

**P2 语义判定与按章改写（调用 LLM）**
- 对候选章节做 LLM 语义判定（过滤误报、识别"他父亲"类指代），结果写入预览，作者可逐章取消或加入。
- 按章序滚动改写：每章读取当前版本的前一章已改写结果，在 `_versions/vNNN` 内生成新章节文件。
- 复用现有章节写作与校验的提示词约束，但通过 `revision_flow` 自己的执行器调用，不经 chapter_ops 的步骤队列。
- 每章产出 diff，失败章节保留原文并标记，不推进后续依赖它的章节。
- 成本上限：章数、LLM 调用数，超限暂停等确认。
- 测试：滚动顺序；失败隔离；from_chapter 不改前文。

**P3 章节反馈分诊**
- 作者在某章留下反馈（可选中段落或只写一句）。LLM 分诊为：局部措辞 / 章内情节 / 设定变更（转为 Change，再走 P1–P2）。
- 分诊结果先展示，作者确认后执行。局部修改同样产生新版本。
- 测试：分诊结果到 Change 的转换；未确认不执行。

**P4 派生物、版本对比与导出**
- 新版本内对改动章节重跑一致性检查；人物索引、伏笔账本、全书终审报告标为待重跑（由作者决定，不自动跑）。
- 版本对比（章节级 diff）、修订日志、导出时选择版本。
- 测试：导出选版本；v1 导出内容不变。

**P5 管理与界面**
- 版本删除（仅非 v1）、撤销某次修改（回到上一版本，实质是丢弃未采用的版本）。
- 独立的"完稿修订"页，挂在驾驶室之外的入口，不放进现有流水线表格。

## 5. 风险

- 滚动改写累积漂移：通过逐章 diff 与一致性检查兜底，无法完全避免，需作者抽查。
- 名称匹配误报与漏报：靠 LLM 判定补充，成本随候选章节数增长。
- 成本：整本级修改会产生大量 LLM 调用，依赖 P2 的上限与预览。
