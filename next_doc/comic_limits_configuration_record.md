# world_forge 漫画上限可配置 · 实施记录

> 背景：P3 质检已取消（用户决定）。原先的两个上限（图像调用 80 次/操作、候选 3 张）写死在代码与环境变量中，本次改为可配置。
> 测试：`python -m pytest -q tests` 全部通过（195 项，其中新增 10 项）。

## 1. 做了什么

- **图像调用上限**：每个世界可单独设置，范围 1–500，默认 80。
  优先级：世界设置 > 环境变量 `WORLD_FORGE_IMAGE_BUDGET` > 默认 80。
  作用范围：漫画渲染、角色表、场景图（每次操作各自计数）。
- **每格候选数上限**：每个世界可单独设置，范围 1–5，默认 3。每次渲染的候选数不超过该上限；看板的候选数选择框只显示不超过上限的选项。
- **保存**：写入世界元数据 `comic_limits`；超出范围报错且不保存；未修改的项保持原值。
- **入口**：看板故事页「上限设置」（数字输入与保存按钮）；CLI `limits --world <wid> [--budget N] [--candidate-max M]`，不带参数时只显示当前值。

## 2. 改动文件

路径均相对于 `external_projects/world_forge/`：

| 文件 | 说明 |
|---|---|
| `world_forge/comic_layout.py` | 上限的默认值与范围常量 |
| `world_forge/engine.py` | `comic_limits`、`set_comic_limits`；渲染、角色表、场景图改用世界上限 |
| `app.py` | 上限设置面板；候选数选项随上限变化 |
| `entrypoints/cli.py` | 新增 `limits` 命令 |
| `tests/test_comic_limits.py` | 新增 10 项测试：默认值、环境变量回退、保存与保留、范围校验、候选上限生效、调用上限生效 |
| `docs/README.md`、`PROJECT.md` | 使用说明与状态 |

## 3. 说明

- 候选数上限降低后，已经生成的候选不会被删除，只是之后的渲染不再超过新上限。
- 调用上限是单次操作的上限，不是累计预算。
- P3 质检不做，因此没有对应的重试上限。
