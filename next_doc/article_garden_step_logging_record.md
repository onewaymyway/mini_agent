# article_garden 步骤日志改进记录

- **触发**：归一步骤运行 390 秒，日志只有“仍在进行（已 390 秒）”，看不出处理到哪一批、有多少内容、是否在推进。
- **完成日期**：2026-11-23

## 1. 改进内容

| 内容 | 之前 | 之后 |
|---|---|---|
| 心跳 | 只显示已用秒数 | 显示当前进度，例如“仍在进行（已 390 秒）；当前：第 3/12 批，40 对候选” |
| 模型调用 | 看不到 | 每次调用记录：归属的步骤、发送字数、用时、回复字数；失败时记录原因 |
| 归一 | 只有开始与结束 | 每批开始（第 k/n 批、候选对数）与判定结果（同义 x/y 对） |
| 定义 | 只有结束 | 每个概念一行：已生成 / 无依据断言 / 失败，并注明依据断言数 |
| 关系 | 只有结束 | 每篇文章一行：概念对数、采纳与丢弃条数；注明跳过原因（不足 2 个概念、正文过长、生成文章、沿用缓存） |
| 冲突 | 只有结束 | 每个概念一行：断言数与涉及的文章数 |
| 成文 | 只有结束 | 简报（来源与概念数）、大纲（节名）、每节开始与完成（字数）、每轮评审结果、全文检查问题 |
| 调研 | 只记录入库结果 | 查询数与候选网址数；每个网址的抓取进度（k/上限）与结果（已入库 / 无关 / 无法抓取原因） |

## 2. 修改

| 文件 | 修改 |
|---|---|
| `joblog.py` | 步骤记录当前所在步骤（线程内）；心跳附带 `info["progress"]`；新增 `current_stage()`；步骤结束后恢复上一层归属。 |
| `budget.py` | 每次模型调用记录归属步骤、字数、用时、回复字数或失败原因。 |
| `wiki/normalize.py` | `cluster(..., progress=None)`：每批回调进度（可选参数，旧调用方不受影响）。 |
| `wiki/build.py` | 归一、定义、关系、冲突四个步骤的进度与逐项结果。 |
| `writing/runner.py` | 简报、大纲、各节、评审轮次与全文检查的日志。 |
| `research/runner.py` | 查询与候选网址数；逐个网址的抓取进度与结果。 |
| `tests/test_step_logging.py` | 新增 4 项测试。 |
