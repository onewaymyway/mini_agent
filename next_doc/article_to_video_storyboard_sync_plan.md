# article_to_video 分镜同步与丰富性改进方案（待确认）

> 状态：**方案草案（2026-11-20），未实施**。请先确认第 6 节的待定问题，再按期推进；每期结束更新文档、测试并打包 diff zip。
> 范围：只聚焦分镜生成（`visual/`）与其在渲染中的呈现，不改动大纲、口播稿、配音与导出流程。

## 1. 需求

1. **画面与字幕、语音协调**：现在画面里的内容与当时说的话经常对不上。
2. **结构化画面整体显示**：表格、流程图等不要一部分一部分地出现，应一次全部显示。
3. **画面丰富性**：画面要更有内容，不能只是一串文字卡片。

## 2. 现状（已读代码，关键位置）

### 2.1 时间轴：只能精确到句

- 配音只返回每句的时长（`audio/synth.py`、`audio/timeline.py`），没有字或词级时间戳。
- 分镜的每个状态通过 `reveal[i].at_sentence` 绑定到句序号；渲染端 `compose/part.py` 用句起点换算成时间。
- 结论：**同一句内部无法精确对齐**。一句超过 60 字的长句，画面在句首就切换，而讲解仍在句中。

### 2.2 结构化画面的出现时机是按算术分配的（不对齐内容）

- `visual/director.py::_build_beat`：流程图（diagram）、表格（table）、公式（formula）、列表（list）、年代线（timeline）只设定 `items`，没有 `reveal`。
- 随后 `director.py:165-166` 调用 `uniform_reveal`，把各状态按 `i * 句数 / 状态数` 均匀分布到句子上。
- 结果：第 2 行表格何时出现，只取决于它是第几行，与哪一句提到它无关。这是“对不上”的主要来源之一，也是“一部分一部分出现”的直接原因。
- 对照：LLM 版（`director_llm.py` 经 `shots.py::scene_reveal`）已经用 `mention()` / `first_mention()` 把条目对到提到它的句子，但没有命中时仍回退为均匀分布；规则版没有使用这套逻辑。

### 2.3 插图的内容与时段对不上

- 规则版插图（`director.py:154-162`）：一个 beat 只选一个主题，`subject = emphasis[0]`（句中的强调词），不随句子变化。
- `shots_per_image` 决定一张图覆盖几个镜头；图在整段期间不变，而口播已经换到别的内容。
- 插图提示词（`visual/prompting.py`）只看主体、场景、构图与风格锚，不看它要配的句子；构图也没有检查（方案第 277 行已记为偏差）。

### 2.4 校验不检查语义

- `validators/visual.py` 检查字段、数量、范围与分配，不检查“画面里的元素是否在它对应的句子里出现过”。
- 因此错位的分镜可以通过校验，直到人工看视频才发现。

### 2.5 丰富性不足

- 规则版的 beat 大多落为 `keypoint`（逐条出现的文字卡），插图只占少数 beat（由预算决定）。
- 原文里的数字、对比、流程虽然已有结构块（`source/blocks.json`），但只用于 diagram、table 等少数类型；带数字的句子没有对应的“数据卡”。

## 3. 设计方向

### 方向 A：结构化画面整体显示，并高亮当前讲到的元素（解决第 1、2 点）

- 流程图、表格、列表、年代线、公式的**全部内容一次显示**（状态数固定为 1，即整体出现）。
- 在整体显示的基础上，用**高亮**表示“此刻讲到哪个元素”：每个元素的高亮时刻 = 它第一次被提到的句子（沿用 `first_mention()`，规则版与 LLM 版共用一套逻辑）。
- 高亮是对同一画面的覆盖层（不改变布局），因此不会让画面“一块一块地冒出来”，同时仍然能和语音同步。
- 未被任何句子提到的元素，高亮不出现，但元素仍整体可见（不隐藏）。
- 对公式保留“先显示公式，再逐条解释”的顺序（见待定问题 Q1）。

### 方向 B：画面按句子切分，插图主体跟随当前句（解决第 1、3 点）

- 规则版插图改为按“视觉变化点”切镜：镜头边界落在句子边界上，每个镜头的主体取该镜头内句子的核心名词（而不是整段的第一个强调词）。
- 一张插图只覆盖主体不变的连续句子；主体变化即换镜。
- 对齐检查：镜头的主体词必须至少在其覆盖的一句中出现（归一化后），否则判为错位，交给人工或重新生成该镜头。
- 不改变 `shots_per_image` 的预算语义，只改变切分位置。

### 方向 C：对齐校验（解决第 1 点的回归保护）

- 新增一条校验：对每个场景，其 `items`、`formula` 或 `image.subject` 中的关键词，应在它覆盖的句子中找到（允许归一化与同义简单变体）。
- 覆盖率低于阈值时给出警告（不阻断），并在分镜编辑界面标出对应句子。
- 这是纯规则检查，不调用模型，成本低，可以作为所有引擎的兜底。

### 方向 D：丰富画面类型（解决第 3 点）

按现有数据增加几种**不新增模型调用**的画面：

1. **数据卡**：句中出现数字（如“增长了 35%”）时，用大号数字加该句的说明作画面。数字与说明都来自原句，不编造（沿用 `_TOKEN` 的不编造检查）。
2. **对比卡**：两句或一段中出现“A 与 B”“相比”等对比结构，左右两栏对照显示。
3. **步骤卡**：有序的步骤（“第一…第二…”）整体显示，并按第 A 点高亮当前步骤。
4. **金句卡**：沿用现有 `quote`。

插图的使用仍由预算决定；上述卡片不占生图预算，因此可以显著增加画面变化。

## 4. 分期

| 期 | 内容 | 验收 |
|---|---|---|
| 一期 | 结构化画面整体显示（方向 A 的“整体显示”部分，状态数固定为 1）；规则版改用 `first_mention()` 决定高亮时刻 | 表格、流程图、列表、年代线一次全部可见；高亮在被提到的句子上切换；测试覆盖两种引擎 |
| 二期 | 对齐校验（方向 C）：覆盖率警告，编辑界面标出错位句子 | 人为构造错位分镜时产生警告；正常分镜无误报；警告不阻断导出 |
| 三期 | 插图按句切镜与主体跟随（方向 B） | 镜头边界落在句子边界；每个镜头主体词在其句子中出现 |
| 四期 | 丰富画面类型（方向 D：数据卡、对比卡、步骤卡） | 含数字的句子生成数据卡；数字全部来自原句（不编造检查通过）；生图预算不变 |

每期都需要：更新 `PROJECT.md`、外部总规划第 N 节、本方案的实施记录；全量测试通过；打包 diff zip。

## 5. 风险与取舍

- **句内同步是近似的**：TTS 只给句时长，没有字级时间戳。句内的高亮只能精确到句。若要做到句内同步，需要 TTS 引擎提供时间戳（部分引擎支持），这属于后续可选项，不在本方案的前四期内。
- **整体显示会让画面更满**：一次全部显示时，表格行数或流程节点过多会挤在一起。需要沿用现有的 `MAX_TABLE_ROWS`、`MAX_DIAGRAM_NODES` 限制，超出部分分到下一镜。
- **高亮依赖关键词命中**：`first_mention()` 是字面匹配，同义表述（如“营收”与“收入”）会漏掉。漏掉的元素仍会整体显示，只是没有高亮，不影响正确性。
- **LLM 版与规则版的分歧**：两者共用高亮与对齐逻辑，避免各写一套。
- **现有分镜的兼容性**：已确认的分镜（`storyboard.json`）结构变化后会被判为过期（`input_sha` 包含导演版本号），需要重新生成。这一点要在界面上提示。
- **不改动**：大纲、口播、配音、导出、预算账本；生图提示词结构保持不变（方向 B 只改变切分位置）。

## 6. 待定问题（请确认）

- **Q1**：公式场景是否也要整体显示？当前设计是“先显示公式，再逐条解释”。建议保留逐条解释（它本身是讲解顺序），但公式本体始终可见。你的意思是只针对表格、流程图，还是也包括公式和列表？
- **Q2**：高亮是否可接受？它让整体显示与语音同步，但会增加画面的视觉层次。若你希望完全静态（不高亮），一期只做整体显示即可，高亮作为可关闭的选项。
- **Q3**：对齐检查的警告是否只提示、不阻断？建议只提示，由人判断。
- **Q4**：丰富性（方向 D）是否要纳入本轮？它与前三期互不依赖，可以放在最后。
- **Q5**：一期是否同时改动 LLM 版？建议一期只改规则版（它的问题最明显，改动也最小），LLM 版在二期统一接入同一套高亮与校验逻辑。
