# article_garden 每日调用上限提示修复记录

- **触发**：用户在「设置 → 本库」把每日上限改为 100000，运行时仍报“全局今日 LLM 调用已达上限 500”。

## 1. 根因（已核实，不是保存失败）

- 设置有两个不同的上限：**本库**（每个文章库，可在「设置 → 本库」修改）与**全局**（所有文章库合计，只能在「设置 → 全局默认」修改，默认 500）。
- 本次报错的是**全局**上限。它统计所有文章库当日的总调用，并不受本库设置影响。
- 全局设置保存与读取都正常（已测试：保存 100000 后有效值即为 100000）。
- 本库设置页不显示全局上限，所以很容易以为只要改本库就够了。
- 全局上限达到 500，说明今天所有文章库合计已调用 500 次。摘要的修复循环、评审等都会计入，调用量很快达到上限。

## 2. 修改

| 位置 | 修改 |
|---|---|
| `budget.py` | 超限提示写明：已用 / 上限、该上限在哪里修改（本库 → 「设置 → 本库」；全局 → 「设置 → 全局默认」及保存文件路径）。 |
| `ui/settings_page.py` | 本库设置页的“预算”分组下，显示全局上限的当前值（只读），并注明修改位置与保存路径。 |

## 3. 验证

- 新增 3 项测试：全局提示含已用/上限、设置位置与文件路径；本库提示含本库设置位置；本库设置页显示全局上限。
- 全套 **215 项通过**，pyflakes 无告警。

## 4. 操作建议

- 要提高全局上限，请在「设置 → 全局默认」中修改，修改后下一次模型调用即生效（无需重启）。
- 如果经常达到上限，说明调用量偏高，可在首页查看“今日 LLM 调用”的用量，并考虑降低“每篇最多修复轮数”。
