# article_garden 摘要 YAML 错误定位与引文格式修复记录

- **触发**：运行日志反复出现“不是合法的 YAML（while parsing a block mapping）”，既不说明位置，也不说明哪篇文章的哪个文件，修复 10 次仍失败。

## 1. 根因

模型输出的 `quote` 值有时是原文中以 `> **` 开头的句子，例如：`quote: > **AI 经济…`。YAML 会把开头的 `>` 当作块标量指示符，于是解析失败。修复时模型又会重复同样的写法，所以循环不止。

## 2. 修改

| 位置 | 修改 |
|---|---|
| `digest/llm_io.py` `describe_yaml_error()` | YAML 错误现在给出行号、列号、出错的那一行原文，以及常见原因（以 `> * & ! # % @` 开头，或含未括起的 `: `），并提示用英文双引号括起来。 |
| `digest/summarize.py` 系统指令 | 明确要求 `quote` 的值用英文双引号括起来（内部双引号改用单引号）。 |
| `digest/validate.py` `clean_edges()` | 存储的引文去掉句首的引用/加粗标记和句末的加粗标记。只删除两端，结果仍是原文子串。 |
| `digest/runner.py` | 每条运行日志都注明文章编号、标题和**来源文件名**。 |

## 3. 验证

- 新增 4 项测试：YAML 错误含行号与原文；系统指令含双引号要求；运行日志含来源文件名；存储的引文去掉标记后仍为原文子串（并更新已有测试的期望值）。
- 把行号与列号的说明去掉后，测试失败。
- 全套 **212 项通过**，pyflakes 无告警。

## 4. 过程中的一次误改（已修正）

修改提示词时，正则替换误用在了系统指令上，测试也查错了位置。已确认 `_FIELDS` 提示词文本与上一版完全一致，只有系统指令受到预期内的改动，并把测试改为检查系统指令。

## 5. 未验证

- 真实模型是否会遵守“双引号”要求，需要在你的文章上确认。
- 如果模型仍反复输出无法解析的 YAML，修复循环会在预算内结束，并在日志中显示具体行号，便于进一步处理。
