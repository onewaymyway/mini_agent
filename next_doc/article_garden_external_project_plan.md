## 1. 结论（一页纸）

**一句话**：给定一个领域和一批已有文章，先把文章库整理成一棵「有结构、有关系、可追溯」的知识树（wiki），再让系统围绕这棵树**持续发现缺口 → 规划新主题 → 自动收集资料 → 写成新文章 → 新文章回灌知识树**，形成闭环。

**四个核心决定**

1. **以「知识树 + 断言账本」为中枢，而不是以文章列表为中枢。** 文章 → 概念/实体/断言 → 关系图 → 分类树。所有"缺什么、写什么"的判断都从这棵树上算出来，不靠 LLM 凭感觉想点子。
2. **选题 = 缺口检测（规则为主）+ LLM 命题（为辅）+ 去重打分。** 缺口有 6 类（§6），每个候选主题都带"为什么值得写"的结构化理由，可审计。
3. **成文 = 证据先行。** 先建「证据包」（来源卡），文中每个事实性断言必须绑定证据 id，由代码校验；校验失败把具体问题喂回 LLM 自动修复并持续重试（沿用你的 pipeline 约定），而不是停下。
4. **默认保守，逐级放权。** 默认 G0（全手动），选题/成文/发布各有独立开关与预算上限；生成文章默认只进 `draft`，经审核才 `published`，且标记 `origin=generated`，不会被当成"原始证据"反复自我引用。

**与 mini_agent 的关系**：作为外部项目接入。LLM 用 mini_agent 的 `LLMHelper`（与 article_to_video / info_hub 同一套 provider 配置），搜索用 `mini_agent.web_search`（duckduckgo 默认，无需 key）；**不 import** `src/mini_agent/wiki`——那套 wiki 服务于 agent 自身记忆，生命周期、页面类型和领域文章库语义不同，强耦合会两边都难演进。只借鉴它被验证过的设计：规则打分 + LLM 确认的判重（不用 embedding）、知识生命周期状态机、gap_scanner、三段式检索。

## 2. 目标与非目标

**目标**
- 导入一个领域的现有文章库（Markdown 为主），产出：每篇文章的结构化摘要、领域概念/实体表、概念间关系图、分类知识树、覆盖度地图。
- 在知识树基础上持续生成**候选选题**（带理由与优先级），可人工审核或自动放行。
- 对选题自动搜集资料、整理为来源卡，写成符合领域规范的新文章，并回灌知识树。
- 全程落盘、可断点续跑、可人工编辑、可定向重跑；产物是人类可读的纯文本（Markdown/YAML）。
- 一个项目可管理多个领域（每个领域一个独立目录）。

**非目标（本方案不做）**
- 不做自动发布到外部平台（知乎/公众号等）——只产出本地 Markdown 与静态 wiki 导出；发布接入留作后续。
- 不抓取需登录/付费内容，不绕过反爬；不整段复制来源原文（只摘取事实 + 短引用，见 §8.3）。
- 不做多语言翻译；中文优先，结构上不阻止扩展。
- 不做向量库/embedding（与 mini_agent 现有判重路线一致；规模到几千篇之前不需要）。
- 不改动 mini_agent 主体及其它外部项目的任何代码。

## 3. 总体架构

```
                       ┌────────────── 领域章程 charter.yaml ──────────────┐
                       │ 范围/读者/文风/术语/来源偏好/禁区（所有环节的"宪法"）│
                       └───────────────────────────────────────────────────┘
  已有文章库 ──► A 导入与摘要 ──► B 概念归一与关系 ──► C 知识树与覆盖度
 (library/)      digest             concepts+edges        tree + coverage
     ▲                                                          │
     │                                                          ▼
     │                                              D 缺口检测与选题规划
     │                                             gaps → topic backlog（去重/打分）
     │                                                          │
     │                              （挡位/预算/人工审核闸门）   ▼
     │                                               E 资料收集（搜索+抓取+来源卡）
     │                                                          │
     │                                                          ▼
     └──────── 回灌（走同一条 A→B→C）◄──────── F 成文（简报→大纲→初稿→校验→修复→入库）
```

**闭环的关键**：F 产出的新文章与原有文章走**完全相同**的 A→B→C 管线入树，下一轮缺口检测基于更新后的树，所以树越长越准。

**一轮 `cycle` 的固定顺序**：扫描库变更 → 增量摘要 → 概念归一/关系 → 树增量挂载 → 覆盖度重算 → 缺口检测 → 选题（按预算）→ 对已放行的选题：调研 → 成文 → 校验 → 入库 → 回灌 → 出本轮报告。每一步独立入口、可单独运行、可重入。

## 4. 数据模型与目录

### 4.1 工作目录（每个领域一个，默认 `data/domains/<domain_id>/`）

```
<domain_id>/
├── charter.yaml            领域章程（人写，系统只读；见 4.2）
├── library/                文章库（Markdown + YAML front matter）
│   ├── imported/           用户导入的原始文章（只读；记录 content_hash）
│   └── generated/          系统生成的文章（origin=generated）
├── wiki/
│   ├── digests/<article_id>.yaml    A：单篇结构化摘要
│   ├── concepts/<concept_id>.md     B：概念页（定义/别名/关系/出处文章/断言列表）
│   ├── edges.jsonl                  B：关系边
│   ├── claims.jsonl                 B：断言账本（断言→出处）
│   ├── tree.yaml                    C：分类知识树（稳定 id，含 pin/重命名）
│   ├── coverage.json                C：每个树节点的覆盖度
│   └── index.sqlite                 可重建的检索索引（FTS5，不是事实源）
├── plan/
│   ├── gaps.jsonl          D：缺口（含类型/证据/分数）
│   └── topics.jsonl        D：选题队列（状态机见 §6.4）
├── research/
│   ├── cache/              搜索/抓取缓存（带抓取时间，可过期）
│   └── packs/<topic_id>/   E：证据包（来源卡 sources/*.yaml + pack.yaml）
├── drafts/<topic_id>/      F：brief.yaml / outline.yaml / draft.md / checks.json / revisions/
└── runs/                   每轮 cycle 的日志、预算消耗、报告
```

事实源只有 `library/`、`wiki/*.md|yaml|jsonl`、`plan/`、`research/packs/`；`index.sqlite` 和缓存都可以删掉重建。

### 4.2 领域章程 `charter.yaml`（所有环节共同遵守）

```yaml
domain: 个人理财            # 领域名
scope:
  in:  [资产配置, 基金投资, 保险规划, 税务基础]
  out: [个股推荐, 加密货币投机]      # 越界的主题在选题阶段直接剔除
audience: {primary: 刚入门的上班族, levels: [入门, 进阶, 专题]}
style:   {tone: 平实克制, length: [1500, 3500], must_have: [摘要, 小结, 延伸阅读]}
terms:   {基金定投: [定投, 定期定额]}   # 术语与别名，保证全库用词一致
sources: {prefer: [官方文档, 教材, 论文], avoid: [营销号], min_credibility: B}
risk:    {disclaimer: "仅供学习参考，不构成投资建议", forbidden_claims: [保本, 稳赚]}
```

章程缺失字段取保守默认；看板「设置页」可视化编辑。

### 4.3 文章文件格式（front matter）

```yaml
---
id: a-0042            # 稳定 id，不随改名变化
title: ...
origin: imported | generated
status: draft | reviewed | published | archived   # 生成文章走 draft→reviewed→published
kind: 概念讲解 | 对比 | 教程 | 综述 | FAQ | 案例   # 文章类型
level: 入门 | 进阶 | 专题
tree_node: n-0013     # 挂载的知识树节点（B/C 阶段回填）
concepts: [c-007, c-019]
derived_from: topic-0031   # 仅 generated
evidence: [src-0101, src-0102]   # 仅 generated
content_hash: ...
---
```

### 4.4 知识三层

| 层 | 对象 | 说明 |
|---|---|---|
| L1 文章摘要 | `digests/*.yaml` | 主题、核心论点、涉及概念（原文用词）、断言列表（每条带原文位置）、读者层级、文章类型、质量自评、悬空概念（提到但未讲清的） |
| L2 概念图 | `concepts/*.md`、`edges.jsonl`、`claims.jsonl` | 概念归一后的定义页；边类型 `is_a / part_of / prerequisite / related / contrasts / causes / example_of`；断言账本记录"谁说的、哪篇文章、哪条证据" |
| L3 知识树 | `tree.yaml` | `领域 → 方向 → 主题 → 概念`，文章挂在节点上；节点 id 稳定，支持 pin / 改名 / 移动 |

## 5. 阶段 A–C：整理文章库、构建 wiki 知识树

### 5.1 A 导入与单篇摘要（`digest`）
- 导入：扫描指定目录/zip，解析 Markdown + front matter，生成 `article_id` 与 `content_hash`；重复文件（hash 相同）跳过；**原文只读**。
- 单篇摘要：一次 LLM 调用输出结构化 YAML（字段见 4.4）。长文（> 阈值）按小节 map 再 reduce（做法同 article_to_video 的 S1/S2）。
- **增量**：只有新文章/hash 变化的文章才重做；失败的单篇按"具体问题回喂 LLM → 重试"自动修复，不阻塞其它文章；每篇结果即时落盘。
- 校验（代码）：断言必须附原文位置且位置在文中存在；概念名必须出现在原文；YAML 字段完整。

### 5.2 B 概念归一与关系
- **候选合并**：先规则打分（名称归一/别名表/编辑距离/共现），高分直接合并、中间分带入 LLM 小批量确认、低分不合并（与 mini_agent wiki 判重同一思路，无 embedding）。章程 `terms` 里的别名优先。
- **概念页**：LLM 基于出处文章摘要写 100–300 字定义页；每条定义性断言必须挂 claim → 文章出处。
- **关系抽取**：先用文章内共现 + 摘要里的显式关系，LLM 只做"类型判定与方向确认"，输出边并要求给出一句依据与出处；无依据的边丢弃。
- **冲突**：同一概念出现互相矛盾的断言时，不覆盖，写入 `conflicts`（保留各自出处），在看板上显示，也是 §6 的一类缺口。

### 5.3 C 知识树与覆盖度
- **首次构建（自底向上）**：概念按关系/语义聚成主题，主题再聚成方向，**每层单批 ≤ N 个节点**，避免一次塞太多；根据章程 `scope.in` 做顶层骨架，防止树长歪。
- **增量挂载**：新概念优先挂到已有节点（LLM 在候选节点中选），只有确实放不下才建议新节点；**不重建整树**，节点 id 稳定。
- **人工控制**：节点 `pin`（锁定不被自动改）、改名、移动、合并；所有自动结构变更先出 **diff 清单，勾选确认后才应用**（沿用你在能力学习大纲修订里的做法）。
- **覆盖度**（纯代码计算，不调 LLM）：每个节点的 文章数 / 平均深度（字数、断言数）/ 读者层级分布 / 证据强度（有来源断言占比）/ 新鲜度（最新文章时间）/ 悬空概念数。输出 `coverage.json` 与看板热力图。

**阶段 A–C 的验收**：对现有文章库跑完后，可以在看板上看到树、每个节点挂的文章、概念页与关系图、覆盖度；重复跑一次（无变更）零 LLM 调用。

## 6. 阶段 D：缺口检测与选题规划

### 6.1 缺口类型（规则为主，可审计）

| 类型 | 判定 | 典型产出 |
|---|---|---|
| G1 结构空洞 | 章程 `scope.in` 内的树节点文章数为 0 或只有"浅文" | 补该节点的入门/概览文 |
| G2 悬空概念 | 多篇文章提到概念 X，但无 X 的概念讲解文（概念页仅有定义无专文） | X 概念讲解文 |
| G3 前置缺失 | 文章 A 依赖概念 P（prerequisite 边），库里无 P 的入门内容 | P 入门文 |
| G4 对比空缺 | 两概念 `related/contrasts` 且高共现，无对比文 | X vs Y 对比文 |
| G5 层级断档 | 某主题有进阶/专题文但无入门文（或反之） | 补对应层级 |
| G6 聚合/新鲜度 | 某节点已有 ≥k 篇零散文章 → 综述/FAQ/路线图；或外部有新进展（可接 info_hub 信号，后续）→ 更新型文章 | 综述/FAQ/更新文 |

### 6.2 选题生成
- 每个缺口按模板转成**候选选题**（标题草案、文章类型、层级、目标树节点、必须覆盖的概念、与哪些已有文章互链）。LLM 只用于润色标题与角度，**不负责发现缺口**。
- 另提供一条"LLM 开放命题"（默认关闭）：把树的结构摘要给 LLM，请它在 `scope.in` 内提 N 个缺口规则没覆盖到的主题，仍须通过同一套去重与越界校验。

### 6.3 去重与打分
- **去重**：与已有文章标题/概念集/摘要做规则相似度（概念集 Jaccard + 标题 n-gram + 同节点同类型同层级加罚）；高于阈值直接丢弃，中间区间交 LLM 小批量判"是否实质重复/能否换角度"。同时与**队列中和近期被拒的选题**去重（被拒原因入库，避免反复提议）。
- **打分**：`价值 = 缺口严重度 × 节点重要度（树深度/被引用次数/章程权重）× 可取证度（预估可得来源数）− 重叠度`；分数与各项明细落盘。
- **越界**：不在 `scope.in` 或命中 `scope.out` 的直接剔除。

### 6.4 选题状态机

`proposed → approved → researching → researched → drafting → drafted → reviewed → published`，旁支 `rejected(原因) / dropped(预算/证据不足) / failed`。G0/G1 下 `proposed→approved` 需人工；G2/G3 可按开关自动放行，仍受预算限制。

## 7. 阶段 E：自动收集资料

1. **查询生成**：由选题的"必须覆盖概念 + 角度"生成 3–8 条搜索查询（LLM 生成，规则去重/限长）。
2. **站内优先**：先从本领域 wiki 检索（三段式：FTS 召回 → 概念/关系扩展 → 摘要精排），已有知识不重复搜索，并明确标出"库内已有、可引用/互链"。
3. **站外搜索**：`mini_agent.web_search`（duckduckgo 默认；可配 brave/serper/tavily）。
4. **抓取与正文提取**：`requests`（可配代理）+ 正文提取（readability 类，库待定，见 Q8）；遵守 robots 与节流；失败/超时记录并跳过；浏览器渲染默认不用。
5. **来源卡 `src-xxxx.yaml`**：`url / 标题 / 抓取时间 / 来源类型 / 可信度分级 A–D（规则：官方/教材/论文 > 权威媒体 > 个人博客 > 营销内容，章程 `sources` 可调）/ 与选题相关的摘录（≤ 字数上限）/ 提取出的候选事实`。
6. **证据包 `pack.yaml`**：把来源卡按"要覆盖的要点"归类；**证据不足（A/B 级来源数或要点覆盖率低于阈值）则选题转 `dropped`/回 `proposed` 并记录原因，不硬写**。
7. 所有抓取内容带缓存与过期时间；同一 URL 不重复抓。

## 8. 阶段 F：自动整理成文章

### 8.1 流水线

`brief → outline → draft → 校验 → 自动修复循环 → 独立 critic → 入库(draft) → 回灌`

1. **brief（选题简报）**：目标读者/层级、角度、必须覆盖要点、**必须互链的已有文章与概念**、**不得重复的内容（已有文章摘要）**、证据包清单、章程文风与禁区。落盘，可人工改。
2. **outline**：节点式大纲（章节 + 每节要点 + 每节引用的证据 id）；代码校验：要点全覆盖、每节有证据、字数预算合理。
3. **draft**：**逐节生成**（不是一次性整篇），每节只拿到本节要点 + 对应证据 + 前文小结，降低漂移与幻觉；事实性句子行内标 `[^src-xxxx]` 证据标记。
4. **代码校验（不依赖 LLM 自觉）**
   - 证据完整：事实性断言必有证据标记；标记指向的来源卡存在；
   - 越界/禁区：命中 `forbidden_claims`、`scope.out`、缺少免责声明（若章程要求）；
   - 重复度：与库内文章的段落级相似度低于上限（防同质化/抄自己）；
   - 来源复制：与来源摘录的连续重合长度低于上限（防整段照抄）；
   - 结构：必备小节、字数区间、标题层级、内部链接有效；术语/别名按章程统一；
   - 可读性：句长、重复句、空话占比（轻量规则）。
5. **自动修复循环**：校验不通过 → 把**具体问题清单**喂回 LLM 仅修改相关段落 → 重新校验，**持续重试直到通过或触及预算/次数硬上限**（上限到达则标 `failed` 并保留全部中间产物，附原因，供人工或下一轮处理，不丢失）。
6. **独立 critic**：另起一次调用，不看生成过程，只看成稿 + 证据包，输出"无证据支持 / 与证据矛盾 / 与库内文章冲突"的清单；有问题同样回喂修复。
7. **入库**：写入 `library/generated/`，`status=draft`、`origin=generated`；走 A→B→C 回灌（生成文章对 claims 的证据权重低于导入文章与 A/B 级来源，**不能成为某断言的唯一出处**，避免自我引用放大错误）。
8. **审核**：看板内联审阅（diff 视图、来源卡并排、一键 采纳/修改/退回重写），通过后 `reviewed → published`（导出站点时只含 published）。

### 8.2 文章类型模板
概念讲解 / 对比 / 教程 / 综述 / FAQ / 案例 各自一份 outline 模板与校验差异（如对比文必须有对比维度表、教程必须有前置知识与步骤、综述必须链到所有被综述文章）。模板是纯配置，新增类型不改代码。

### 8.3 版权与来源
只摘取事实与短引用（有字数上限），不复制整段；每个事实可追溯到来源卡；文末自动生成"参考资料"；生成文章可按章程加 AI 生成声明（默认开）。

## 9. 自动化、挡位与预算

| 挡位 | 行为 |
|---|---|
| **G0（默认）** | 全手动：每一步由人在看板/CLI 触发；选题、成文、发布都需人工 |
| G1 | 自动：扫描/摘要/建树/缺口/选题；**选题需人工放行**，成文后需人工审核 |
| G2 | 自动：选题放行 + 调研 + 成文 + 校验；**发布前需人工审核** |
| G3 | 全自动到 `reviewed`（仍不自动 published，除非单独打开 `auto_publish`） |

- 每个能力**独立开关，默认全关**（保守 opt-in）：开放命题、自动放行、自动调研、自动成文、自动发布、定时 cycle。
- **预算（硬上限，超限即停并记录）**：每轮最多选题数、每轮最多成文数、每日 LLM 调用数/估算 token、每选题最多抓取页数、每篇最多修复轮数、`per-step` 超时（默认 40 分钟，可配，与 novel_writer 一致）。
- **定时**：`project.yaml` 默认**不声明 schedule**（同 info_hub 的保守做法），需要时按注释打开；看板自带"开始/暂停自动 cycle"。
- **失败策略**：单个选题失败不影响其它；失败原因与中间产物保留；下一轮可定向重跑（`--topic-id`）。

## 15. 成本估算（粗略，供设预算参考）

以文章库 200 篇、每篇 ~3000 字为例：
- 首次整理：digest ≈ 200 次调用；概念归一/关系/定义页 ≈ 100–200 次小批量；建树 ≈ 20–30 次。**一次性成本**，之后全是增量。
- 每个新选题：选题润色 ≈ 1，查询生成 ≈ 1，调研摘取 ≈ 5–10，brief+outline ≈ 2，逐节初稿 ≈ 5–8，修复 ≈ 0–6，critic ≈ 1，回灌 digest/归一 ≈ 3–5，合计约 **20–35 次调用/篇**。
- 因此预算开关与"每轮最多成文数"是必需项，不是可选项。

## 16. 风险与对策

| 风险 | 对策 |
|---|---|
| 幻觉/无据断言 | 证据标记 + 代码校验 + 独立 critic；证据不足不写 |
| 同质化、自我复制 | 重复度上限；brief 里显式列出"不得重复的已有内容"；每个选题必须有明确角度 |
| 自我污染（生成文章被当证据反复放大） | `origin=generated` 标记；权重低；不得为唯一出处 |
| 树漂移/结构混乱 | 增量挂载 + 稳定 id + pin + 变更 diff 确认；顶层骨架来自章程 |
| 领域漂移（越写越偏） | `scope.in/out` 在选题与成文两处校验；覆盖度对照章程 |
| 成本失控 | 多层预算硬上限；默认全关；每轮报告展示消耗 |
| 版权与来源质量 | 只摘事实+短引用；来源分级；可信度不足不用 |
| 搜索/抓取不稳定（代理、反爬） | 缓存、重试退避、失败跳过并记录；站内知识优先；允许用户手动提供资料入证据包 |
| 规则阈值难调 | 阈值全进设置页；首版用示例库做校准与回归测试 |

## 19. 界面与用户交互方案（v0.2 新增）

### 19.1 交互设计原则（贯穿所有页面）

1. **先预览、后应用**：任何会改动知识树、概念、文章、章程的自动操作，一律先生成「变更清单（diff）」，勾选确认后才落盘；可整体撤销到上一版本（每次应用前自动备份）。
2. **一个入口看全部待办**：所有需要人工介入的事项（审选题、审草稿、确认树变更、处理冲突、处理失败项）汇总到首页的「待办收件箱」，不用在各页面里找。
3. **长任务一律后台运行**：点击后立即返回，页面显示进度与实时日志；可随时停止；刷新页面/切页面不丢任务（做法同 article_to_video 的 jobs + joblog）。
4. **处处可追溯**：任何断言、概念、边、文章段落都能一键跳到出处（原文位置 / 来源卡 / 文章）。
5. **就地编辑、局部刷新**：表格/卡片直接改，用 `st.fragment` 只刷新局部，不整页重跑；编辑立即落盘并记录"人工修改"标记，自动流程不会覆盖被人工改过的内容。
6. **成本可见**：触发会调用 LLM 的按钮旁显示预估调用数；顶部常驻本日预算条。
7. **空状态即引导**：每个页面在没有数据时直接给出「下一步该点哪个按钮」，不显示空表格。

### 19.3 各页面设计

**🏠 首页（工作台）**
- 左：**待办收件箱**——按优先级排列的卡片，每张卡片有"一键处理"：`3 个选题待放行`、`2 篇草稿待审`、`知识树有 4 项变更待确认`、`1 个概念冲突`、`1 个选题失败(原因…)`。
- 右：**流水线状态条**——导入 → 摘要 → 概念 → 知识树 → 缺口 → 选题 → 调研 → 成文，每段显示 完成/进行中/有待办，点击跳转对应页。
- 下：**下一步建议**（规则生成，不调 LLM）：如"23 篇文章中 5 篇未摘要 → [开始摘要]"；"知识树已就绪，尚未做缺口检测 → [检测缺口]"。
- 底：最近一次 cycle 报告（新增文章、消耗、失败项）。
- 一个醒目的 **[运行一轮]** 按钮（受当前挡位/预算约束；G0 下按钮会逐步确认每一阶段）。

**🌳 知识树**
- 左侧树（嵌套可折叠，节点旁显示 文章数 + 覆盖度色块：红=空洞 / 黄=偏浅 / 绿=充足；已 pin 的带 📌）。
- 右侧节点详情：挂载文章列表、关联概念、覆盖度各项指标、该节点的缺口与相关选题。
- 节点操作：改名、移动（下拉选新父节点，前端排除自身子孙）、合并、pin、新建子节点、「让系统重新审视这个节点」。
- **[重新整理知识树]** → 生成变更清单：`+ 新节点 / ~ 改名 / → 移动 / ⊕ 合并`，逐项勾选，预览"应用后"的树，确认后应用。
- 视图切换：树视图 / 覆盖热力表（节点 × 指标，可排序）。

**📚 文章库**
- 表格（`st.data_editor`，只读列 + 可编辑列）：标题、来源（导入/生成）、状态、类型、层级、所属节点、字数、概念数、摘要状态。可按 状态/节点/类型/来源 过滤、全文搜索。
- 点行 → 右侧抽屉：Markdown 预览 / 摘要 / 概念与断言（点击跳转出处）/ 互链 / 前置后继文章。
- 操作：导入（上传 md 文件或 zip、或指定目录）→ **导入预览**（新增/重复/将跳过）→ 确认；批量改状态；对单篇「重新摘要」。
- 生成文章与导入文章用不同图标区分；未审核的生成文章灰显。

**🕸 概念图**
- 左：概念列表（搜索、按节点过滤、显示 出处数/是否有专文/是否有冲突）。
- 中：以当前概念为中心的关系图（`st.graphviz_chart`，不引新依赖；边按类型着色，点击列表项切换中心）。
- 右：概念页（定义、别名、断言列表，每条带出处；可编辑定义、增删别名、手动加/删边）。
- **冲突**页签：并排显示互相矛盾的断言与各自出处，操作：`采纳 A / 采纳 B / 两者并存(标注语境) / 忽略`。
- 概念合并建议：列出"疑似同一概念"的对，`合并 / 不是同一个`，选择会被记住，不再重复提示。

**💡 选题队列**
- 看板式三列：`待审(proposed)` / `已放行(approved)` / `进行中与已完成`，另有 `已拒绝/放弃` 折叠区。
- 每张选题卡：标题（可就地改）、类型/层级/目标节点、**为什么值得写**（缺口类型 + 一句理由 + 证据，如"概念『RAG』被 6 篇文章提及，但无专文"）、分数明细（展开）、互链计划、预估成本（约 N 次调用）。
- 操作：`放行 / 拒绝(必须选原因，进入去重黑名单) / 改标题或角度 / 合并选题 / 手动新建选题`。批量放行。
- 顶部 **[检测缺口并生成选题]**；设置页可开"开放命题"（默认关）。
- 手动新建选题：只需填标题和一句话角度，其余（类型、节点、互链）系统补全并给出确认。

**🔎 调研**
- 左选题 → 右证据包：按"要覆盖的要点"分组展示来源卡（标题、域名、可信度徽章 A–D、摘录、抓取时间），可 `剔除 / 提升可信度 / 手动补充链接或粘贴文本`。
- 顶部覆盖进度：`要点 5/7 已有 B 级以上证据`；不足时提示"补充资料 / 放弃选题 / 降低要求"。
- 手动补充资料入口：粘贴 URL（系统抓取）或粘贴文本（直接成来源卡），弥补搜索不稳定。

**✍ 审阅**
- 左：待审草稿列表（含校验状态灯：🟢全过 / 🟡有警告 / 🔴失败）。
- 中：成稿，事实句行内证据标记可悬停看来源摘录；右：来源卡并排 + 校验与 critic 结果清单。
- 操作：`通过(reviewed)` / `直接编辑后通过`（编辑用 `st.text_area` + 实时校验）/ **`退回重写并附意见`**（意见作为"具体问题"喂回修复循环，持续重试）/ `放弃`。
- 对比视图：本版与上一版的 diff（difflib 渲染）。
- `reviewed → published` 单独一步，需明确点击（或在设置里打开自动发布）。

**▶ 运行日志**
- 当前/历史任务列表，点击展开：**步骤时间表**（各步起止/耗时/状态）+ **实时日志**（自动滚动，可过滤 错误/警告）+ 预算消耗。
- 所有页面触发的后台任务都在此可见；失败任务有 `重试 / 从失败步骤续跑` 按钮。

**⚙ 设置**
- 两层：「全局默认」与「本文章库覆盖」（覆盖项高亮显示，可一键恢复继承）。
- 分组：**章程**（范围、读者、文风、术语表、来源偏好、禁区——表单化编辑，术语表用 data_editor）· **自动化**（挡位、各开关、预算）· **模型与搜索**（LLM 就绪检查、搜索后端、代理策略）· **校验阈值**（重复度、复制长度、证据要求…）· **危险操作**（重置派生数据 / 归档文章库）。
- 每项有说明文字与"保守默认"标记；修改前后有简短 diff 提示；保存即落盘。

### 19.4 关键用户流程

**流程 A：首次使用（向导）**
`新建文章库(命名+选模板) → 导入文章(预览确认) → 系统读 20 篇文章生成「章程草稿」(范围/读者/文风/术语) → 你在表单里改并确认 → [一键整理文章库] (摘要→概念→知识树，后台运行) → 看到知识树与覆盖度 → 引导到「检测缺口」`。每一步都可跳过、可回退。

**流程 B：日常使用（G0/G1）**
`打开首页 → 看收件箱 → 放行选题 → (后台)调研与成文 → 收到"草稿待审" → 审阅通过 → 自动回灌 → 首页看到树与覆盖度变化`。

**流程 C：失败与纠错**
任何失败都以卡片形式出现在收件箱，附原因与操作：`补充资料 / 调整选题 / 重试 / 放弃`。自动修复循环到达上限的草稿保留全部中间产物，可在审阅页手改后直接通过。

**流程 D：人工改动保护**
人工改过的概念定义、节点名、边、章程项会带 `human_edited` 标记；自动重建/再摘要遇到该标记的内容，只在变更清单里给出"建议"，不覆盖。

### 19.5 Streamlit 实现要点

- 多页面：`st.navigation` / `st.Page`；页面文件在 `ui/`，每页只做展示与调用 `article_garden` 的纯函数，业务逻辑不写进页面（便于测试）。
- 当前文章库：`session_state` + URL 查询参数；所有读写都经 `DomainContext(domain_id)`，**页面代码拿不到别的库的路径**，从结构上避免串库。
- 后台任务：沿用 article_to_video 的做法（子进程/线程 + `joblog` + 取消标志），页面用 `st.fragment(run_every=2)` 轮询日志，任务完成后才触发相关区块刷新。
- 树：嵌套 `st.expander` + 按钮，不引入第三方树组件；关系图：`st.graphviz_chart`；diff：`difflib.HtmlDiff` / 自绘着色；表格：`st.data_editor`。**首版不新增前端依赖**（想要更好看的树/图可后续作为可选增强）。
- 性能：库小（几十~几百篇）时直接读文件；大量时读 `index.sqlite`；页面级缓存 `st.cache_data` 以文件 mtime 为 key。
- 端口 8508；`project.yaml` 的 `web_app` 块声明，可在 mini_agent 看板「外部项目」里启动。
- 全部界面文案、帮助提示为中文。

### 19.6 CLI 与看板对等

每个看板动作都有对应 entrypoint（§12），均接受 `--domain <id>`；看板按钮只是调用同一入口，保证脱离看板（OS cron / 脚本 / daemon）也能完整运行。

## 20. 多文章库（多领域）方案（v0.2 新增）

### 20.1 模型
- **文章库 = 领域 = 一个完全独立的工作空间**：`data/domains/<domain_id>/` 下自有章程、文章、wiki、选题、调研、草稿、运行记录（§4.1），**互不共享数据**。
- 根目录有轻量注册表 `data/domains.json`：`{id, 名称, 创建时间, 状态(active/archived), 模板, 最近活动}`。
- 设置分两层：**全局默认**（模型、搜索、代理、阈值、预算）+ **文章库覆盖**（章程与所有自动化开关天然是库级）。新建库时自动化开关一律取保守默认（全关、G0），**不继承其它库的放权状态**。

### 20.2 创建与管理
- **新建向导**：名称 → `domain_id`（英文短名，校验唯一）→ 选模板：`空白` / `通用技术` / `人工智能（预置 scope 骨架）` / `复制另一库的章程（仅章程，不含文章）` → 创建目录与默认章程。
- **切换**：侧边栏下拉；URL 参数保存；上次所选记入本地偏好（浏览器 localStorage 仅作便利，失败不影响功能）。
- **归档/恢复**：归档只改状态（从切换器隐藏、不参与定时 cycle），**不删除数据**；彻底删除需在设置页「危险操作」中输入库名确认，且先导出 zip 备份。
- **重命名**：只改显示名，`domain_id` 不变。

### 20.3 隔离与安全
- 所有路径只能经 `DomainContext` 获得，校验在该库根目录之内（防 `..` 越界）；单元测试覆盖"两个库同名文章/概念/选题互不可见"。
- 后台任务、日志、预算按库统计；**每个库独立预算**，另有全局日日预算总闸（防多库同时跑放大成本）。
- 定时 cycle 默认只对"显式开启自动化的库"运行；多个库的 cycle 串行执行，不并发抢资源。

### 20.4 跨库（首版边界）
- 首版**不做跨库链接与跨库检索**，避免概念串味。
- 首页提供「所有文章库」总览页：每库一张卡（文章数、覆盖度、待办数、最近活动），点击进入。
- 预留：后续可选"跨库互链建议"（只读、需人工确认）。

## 21. 小规模冷启动设计：人工智能领域、20 余篇中文 Markdown（v0.2 新增）

20 篇规模意味着：整理成本很低（一次性约 20 次摘要 + 少量归一/建树调用），但**数据量不足以让"从文章归纳树"自行收敛**，且 AI 领域变化快，所以对设计做以下针对性调整：

1. **章程草稿由文章反推**：导入后用全部摘要生成章程草稿（范围/读者/文风/术语/关键概念），你确认后才作为宪法。AI 领域 `scope.in` 预置骨架供选择（如：基础概念与机器学习 / 大语言模型 / 提示词与上下文工程 / Agent / RAG 与知识库 / 训练与微调 / 评测 / 工程落地 / 安全与治理 / 行业应用），你勾选并改名，不满意可全部自定义。
2. **树由「章程骨架 + 文章」共同决定**：20 篇时先用章程骨架作顶层，文章挂载其下，文章不足的骨架节点自然显示为空洞（即第一批选题来源）；篇数多起来后再允许自底向上聚类调整。
3. **阈值随规模缩放**：覆盖度的"偏浅/充足"、悬空概念的"被提及次数 ≥ k"、综述触发的"≥ k 篇"等阈值，按库规模取分档默认值（<50 篇一档），避免 20 篇时规则几乎全不触发或全触发。
4. **新鲜度（G6）权重更高**：AI 领域时效性强，成文选题里"更新型/动态型"文章比重较大，并要求来源带发布日期；证据包按日期排序，过期来源（如超过设定月数）自动降级可信度，文章中涉及版本/数据的断言必须标注来源日期。
5. **术语表更重要**：中文 AI 术语多种译法（如 智能体/Agent、检索增强生成/RAG、微调/fine-tuning）。章程 `terms` 在首次整理时由系统从文章中抽取候选别名供你确认，之后成文校验按术语表统一用词。
6. **规模小，可以全量人工过目**：首批摘要、概念归一、树变更均默认走"变更清单确认"，不开自动应用；等你对质量放心后再逐项放权。
7. **去重阈值首版用这 20 篇校准**：先跑一遍统计库内相似度分布，据此定默认阈值并写入回归测试。
