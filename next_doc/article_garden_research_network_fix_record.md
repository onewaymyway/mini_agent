# article_garden 调研网络与循环失败原因修复记录

- **触发**：一轮闭环中，8 个网址全部“robots.txt 无法读取（HTTP 网络错误）”；PDF 网址下载 80 秒后才被拒绝；循环失败行只写“失败”，看不出是哪一步。
- **完成日期**：2026-11-23

## 1. 根因

| 现象 | 根因 |
|---|---|
| 全部网站“网络错误” | 调研抓取不使用系统代理（大模型有代理设置，调研没有）。若本机访问外网需要代理，所有请求都会失败。 |
| 断网结论持续七天 | 网络错误（状态 0）被当作 robots.txt 的结果写入缓存，缓存有效期七天。即使网络恢复，旧记录仍会阻止抓取。 |
| PDF 耗时很长 | 先下载内容，再判断“不是网页”。 |
| 循环失败无原因 | 循环结束时只写“失败”，没有列出失败的步骤与原因。 |
| 个别模型调用“未命名步骤” | 循环的各步骤没有设置步骤名。 |

## 2. 修改

| 文件 | 修改 |
|---|---|
| `settings.py` / `ui/settings_page.py` | 新增「调研（网站抓取）→ 调研抓取使用系统代理」，默认关闭，与大模型的代理设置相互独立。 |
| `research/fetch.py` | 代理开关生效；网络错误不写入 robots 缓存；读取缓存时忽略旧版本留下的网络错误记录；网络错误说明写入原因；PDF 等二进制网址在发出任何请求之前就跳过。 |
| `cycle.py` | 每个步骤都设置步骤名（模型调用可归属）；循环失败时，日志行列出失败的步骤与原因。 |
| `tests/test_research_network.py` | 新增 5 项测试：网络错误不缓存且之后可成功；二进制网址不发出请求；代理开关存在且默认关闭；旧的网络错误缓存被忽略；循环失败行格式。 |

## 3. 用户需要做的事

1. 如果本机访问外网网站需要代理：在「设置 → 调研（网站抓取）」打开「调研抓取使用系统代理」。
2. 旧版本留下的 robots 缓存已不再生效，无需手动删除；如需清理，可删除 `research/cache/robots/` 目录。

## 4. 验证

- 全套 **228 项通过**，pyflakes 无告警。
- 变异验证：恢复“缓存网络错误”后，对应测试失败。
- 未在你的网络环境中实际访问网站；代理是否需要、需要哪种代理，请以你的网络为准。

## 5. 追加修复：设置页看不到「调研抓取使用系统代理」

- **原因**：设置页的标签页是固定写死的，「模型、搜索与调研」页与「全局默认」页都没有渲染新增的调研分组。设置项本身存在，但页面上没有入口。
- **修复**：两个标签页都加入调研分组。
- **测试**：新增页面测试，要求该开关同时出现在「本库」与「全局默认」两处；去掉「本库」那一处后测试失败。
