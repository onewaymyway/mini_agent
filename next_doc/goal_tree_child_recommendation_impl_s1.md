# 目标树子目标推荐 — S1 实施记录：候选的采纳 / 忽略

> 状态：S1 已实施。S2–S4 未开始，等待确认后再做。

## 1. 已确认的设计决定

| 事项 | 决定 |
|---|---|
| 子目标推荐 | 由分解器生成候选，**用户确认**后才落地为子节点 |
| 子目标自动落地 | 只在 **Autonomous 档位**启用；其它档位只推荐，确认后才开始执行 |
| 项目创建 | **自动**：在执行目标的过程中自动创建，不需要单独确认 |
| 护栏 | 不设固定上限，按实际情况决定创建多少 |

## 2. 阶段划分

| 阶段 | 内容 | 状态 |
|---|---|---|
| **S1** | 看板上采纳 / 忽略推荐的子目标；修正采纳节点的来源标记 | ✅ 已实施 |
| S2 | Autonomous 档位下子目标自动落地；其它档位保持推荐 + 确认 | 未开始 |
| S3 | 执行目标时自动创建项目并关联（build 角色） | 未开始 |
| S4 | 驱动执行与进展回写到目标节点 | 未开始 |

## 3. 现状核实

- 后端的采纳（`GoalBacklog.accept_candidate`）、忽略（`GoalTreeDecomposer.reject_candidate`）、对应的 HTTP 路由，以及看板父节点下方的候选卡片，在 S1 之前就已存在。
- 但有两个问题：
  1. **采纳后的子节点被标成 `source="agent_derived"`**。这导致用户自己采纳的目标会出现在「📥 主动建议」的软目标待处理列表中，也会占用 SoftGoalDeriver 的配额。
  2. **候选只能在父节点展开后才能看到**。全树有几个待确认的推荐，用户很难发现。
