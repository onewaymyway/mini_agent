## 3. 关键实现与决定
| 事项 | 做法 | 理由 |
|---|---|---|
| 骨架 | 章程 `scope.in` 中没有对应方向的，生成 `add_node`（origin=skeleton）；无范围时用「未分类」 | §21-2：20 篇时由章程骨架做顶层 |
| 挂载范围 | 只送出**未挂载**的概念 | 增量的核心；已挂载的不被重新安排，保证 id 与位置稳定 |
| 模型输出 | 每个概念恰好一次：挂入已有主题（id），或新建主题（名称 + 方向 id） | 可被代码校验；新主题名与同方向已有主题重名则拒绝，要求改用 id |
| 锁定 | 锁定的主题不出现在候选中，模型选中也会被校验拒绝 | §19.1 原则：自动流程不覆盖人工控制的内容 |
| 提案 | 记录 `base_version`；应用时版本不符则拒绝 | 防止基于旧树的操作误写入 |
| 解除挂载 | 概念页被删除后，生成 `detach` 操作（需确认） | 树不残留已不存在的概念 |
| 人工操作 | 立即生效，每次保存前备份旧树为 `tree.prev.yaml` | §19.1：先预览、后应用；可回退一版 |
| 覆盖度 | 纯代码；红=0 篇，黄=篇数或字数不足，绿=充足；小库阈值 2 篇 / 1500 字 | §5.3 指标 + §21-3 分档 |
| 无变化 | 无未挂载概念且骨架无变化 → 不调用模型、不生成提案、不改版本 | §5.3 验收 |

## 5. 与方案的偏差 / 未做
- **未做自底向上聚类**：方案 §5.3 的首次构建是自底向上聚类；首版改为章程骨架 + 模型逐批挂载。§21-2 对 20 篇规模允许这种做法，文章库变大后再评估聚类。
- **文章未回填 `tree_node`**：方案 §4.3 要求回填文章 front matter；首版由概念推导文章所在节点，未写回文章文件（避免改动导入副本）。
- **提案预览**：方案 §19.3 要求“应用后的树”预览图；首版只显示操作清单。
- **覆盖度指标的替代**：“证据强度”取有依据定义的概念占比（方案为有来源断言占比）；“新鲜度”仅取导入时间。
- **方向不会自动删除**：章程删除某个范围后，已有方向保留（保证 id 稳定），需人工合并或改名。
- **方向不可锁定的语义**：锁定只对主题生效（自动挂载只挂主题）。
- **批大小 20**：固定值，未放入设置页。
- 冲突、合并建议等 P2 遗留的看板操作仍未实现（同 P2 记录）。
