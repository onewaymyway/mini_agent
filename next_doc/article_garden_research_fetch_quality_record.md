- **触发**：日志显示多数网页“与选题要点无关”，部分 HTTP 521，部分 robots.txt 禁止，以及用户建议用 CDP 浏览器抓取。

## 1. 日志中各类情况的处理

| 日志现象 | 原因 | 处理 |
|---|---|---|
| 页面与选题要点无关（页面已抓到） | 要点要求逐字出现，忽略了标点差异与同义词 | 已修复：匹配忽略标点、引号、全半角与大小写，并接受章程术语中的别名 |
| 页面内容很少（脚本加载） | 普通抓取只拿到空壳页面 | 新增可选的浏览器渲染（见下） |
| HTTP 521 | 站点服务器暂时不可用（Cloudflare 显示源站故障） | 浏览器也无法解决，保持跳过；稍后重新调研即可 |
| robots.txt 禁止抓取 | 站点明确不允许抓取 | 不使用浏览器，包括浏览器渲染在内都遵守 robots.txt |
| HTTP 403 / 401 | 站点拒绝访问或要求人工验证 | 不使用浏览器绕过，直接跳过并说明原因 |

## 2. 浏览器渲染（可选，默认关闭）

- 设置 → 调研（网站抓取）：
  - 「普通抓取失败时改用浏览器（备用）」：打开后启用；
  - 「浏览器远程调试端口」：默认 9222。
- 使用方法：
  1. `pip install playwright`
  2. 以远程调试端口启动 Chrome，例如 `chrome --remote-debugging-port=9222`
  3. 在设置中打开开关。
- 使用时机：仅在普通抓取返回空壳页面，或服务器出错（非 401/403、非 robots 禁止）时使用。
- 使用的是 Playwright 的 `connect_over_cdp`，只关闭自己打开的标签页，不关闭你的浏览器。

## 5. 注意

- 浏览器渲染会明显变慢（每页约数秒），每题仍受“最多抓取页数”限制。
- 521 这类站点故障不会因浏览器而消失，请稍后重试。

## 6. 追加修改：开启浏览器后，普通抓取的任何失败都改用浏览器

- **改为**：开启「普通抓取失败时改用浏览器」后，以下情况都会改用浏览器：超时、网络错误、404、500 等服务器错误、521、非网页内容，以及页面内容很少。只要浏览器拿到页面内容就使用；是否与选题相关，由摘录步骤判断。
- **仍然不用浏览器的两类情况**：
  1. robots.txt 禁止抓取，或 robots.txt 无法读取。站点已明确不允许，换用浏览器也不改变这一点。
  2. HTTP 401 / 403（需要登录或人工验证）。这类情况下用浏览器通过，等于绕过站点的访问控制。替代做法：在自己的浏览器中打开该页面，再用「抓取网址并加入」添加为手动来源。
- **测试**：新增 3 项（各类普通失败都会改用浏览器；浏览器结果即使较短也会使用；robots 禁止和 401 不会调用浏览器）。去掉"较短结果也使用"的修改后，测试失败。

## 7. 追加修改：调试浏览器未开启时自动启动

- **自动启动**：开启浏览器备用后，若调试端口未就绪，程序会在本机查找 Chrome、Chromium 或 Edge，以远程调试端口和独立的用户目录（`data/browser_profile`）启动，等待端口就绪后再连接。独立的用户目录是 Chrome 对远程调试的要求，也不会影响你日常使用的浏览器资料。
- **找不到浏览器**：日志明确写出"未找到 Chrome 或 Chromium，请先安装，或手动以调试端口启动浏览器"。
- **浏览器被关闭**：每次渲染前都会重新检查端口，必要时再次启动。
- **普通抓取的任何失败**：（超时、网络错误、404、5xx、521、非网页、页面内容很少、浏览器自身失败）都会改用浏览器再试一次。
- **仍然不用浏览器的两类情况**（未改变）：
  1. robots.txt 禁止抓取，或 robots.txt 无法读取；
  2. HTTP 401 / 403（需要登录或人工验证）。
  原因：这两类是站点明确的访问限制，浏览器通过它们等于绕过站点的规则。替代做法：在自己的浏览器中打开页面，再用「抓取网址并加入」添加为手动来源。
- **测试**：新增 4 项（端口已开启时不重复启动；找不到浏览器时给出明确提示；启动参数正确；普通抓取失败后自动启动并重试）。禁用自动启动后测试失败。
