# 灵感构思「一句话起稿」实施计划（待确认）

> 状态：**方案已确认（落点=独立草稿层+采用转提议；粒度=整稿+分部分；范围=命题+走向+世界观+角色+剧情+待定问题）**。按 S0→S4 分期，一期一期做，每期更新文档并打包 diff zip。
> 前提阅读：`external_projects/novel_writer/docs/brainstorm_studio.md`、`next_doc/novel_brainstorm_studio_design.md`。

## 1. 现状与缺口

构思工作室已有：题材卡 / 灵感池 / 发散 / 对话（AI 只出提议，确认后落卡）/ 整理对话 / 世界观·角色·剧情编辑 / 备选方案 / 质检 / 交接到新小说。

缺的是一条**从零起步的主线**：用户只有一个简单想法时，现在要靠对话一条条攒提议，没有「一次出整体雏形，再整稿反复修」的入口。

## 2. 目标流程

1. 用户输入一句话想法（可选：题材、篇幅倾向、必须保留/避免的元素）。
2. 系统**一次**生成「构思稿」：核心命题、故事走向（一句话主线 + 起承转合）、世界观大致（规则 / 地点 / 势力 / 禁忌）、主要角色（3–6 个）、核心剧情（分幕转折点、反转、结局候选）、尚未决定的问题。
3. 用户阅读后反馈：**整稿反馈**（「更黑暗一点」）或**针对某一部分**（「世界观改成架空近未来」）。系统据此生成新版本。
4. 版本可对比、可回退；满意后**采用**到构思卡片，进入现有的对话 / 质检 / 交接流程。

## 3. 关键设计

- **草稿层独立**：构思稿存放在 `_studio/seed_draft/`（`v001.json`…，只增不删，含原因与时间），**不直接写卡片**。这与工作室「确认之前不落卡」的原则一致。
- **结构化**：构思稿字段与现有卡片模块对齐（premise / world / cast / plot / open_questions，另加 `storyline` 故事走向），采用时可直接映射，复用 `cards` 的校验。
- **反馈修订的范围控制**：针对某部分的反馈只重写该部分，其余部分原样保留（程序层比对，被改动的其它部分直接丢弃并警告），避免「改世界观顺带改了主角」。整稿反馈允许全部改，但在界面标出各部分是否变化。
- **采用 = 生成一批提议**：构思稿按模块转成提议（进入现有「待确认的提议」列表），作者逐项勾选采纳；卡片已有内容的模块标为冲突并显示差异，不覆盖。这样复用已有的校验、冲突处理与撤销路径。
- **默认保守 opt-in**：新增独立标签「🌱 起稿」，全部手动触发，不改变现有任何标签与行为；无新开关需要打开。
- **LLM 调用**：旁路单轮、无工具，走 `LLMHelper`（与「生成设定文档」「整理对话」一致）；提示词放 `prompts` 管理方式沿用 brainstorm 现有做法。输出 JSON，经 `json_repair` 修复，校验失败带错误重试一次，仍失败则不写任何版本。
- **过程日志**：后台线程运行 + 实时日志（复用 `distill` 的 start_run / run_state 模式）。

## 4. 分期

| 期 | 内容 | 是否调 LLM |
|---|---|---|
| S0 | 构思稿数据结构与校验、版本存取（新增/列表/读取/回退）、与卡片模块的映射函数、差异函数 | 否 |
| S1 | 一句话起稿：提示词、解析与校验、重试、后台运行与日志、接口 `seed_start/seed_state` | 是 |
| S2 | 反馈修订：整稿 / 分部分，范围守卫（越界改动丢弃并警告），新版本落盘；`seed_revise` | 是 |
| S3 | 采用：构思稿 → 提议批次（含冲突标记），可选择部分模块；接口 `seed_adopt` | 否 |
| S4 | 界面「🌱 起稿」标签（输入、阅读视图、反馈框、版本对比与回退、采用面板）+ 文档 | 否 |

每期的测试：S0 校验正反例/版本只增/回退；S1 桩生成器（解析、重试、失败不落盘）；S2 越界改动被丢弃；S3 卡片已有内容时标冲突且确认前卡片哈希不变；S4 静态检查 + 页面冒烟（本环境无 streamlit，需本机验证）。

## 5. 风险与边界

- 一次生成整份构思稿，篇幅大，模型可能截断或字段缺失：靠校验 + 重试；仍失败则明确报错、不落半成品。
- 分部分反馈依赖「只改指定部分」的程序守卫，不依赖模型自觉。
- 真实模型下的质量、截断情况无法在本环境验证（与其它 brainstorm 功能相同），首次使用请留意。
- 不做：多个并行起稿分支（已有「备选方案」覆盖走向分歧）；起稿后与卡片的自动同步。

**S0 实施说明**：①构思稿六部分必须齐全且各自合法（复用 `cards.validate_module`，另要求命题非空、至少一个角色、至少一幕）；②模型常见的松散写法自动规范化（角色列表 → id 字典 c1…；待定问题文字 → q1…；世界观 rules/locations/factions 文字 → `{text}`）；③`storyline`（起承转合）没有对应卡片模块，S3 采用时计划存为一条 AI 灵感（标签「故事走向」），避免丢失。

**S1 实施说明**：①直接调用 `LLMHelper`（`spark.helper_generator`），与「整理对话」同一模式；②题材卡已填的字段会作为必须遵守的上下文放进提示词；③想法上限 2000 字（起稿只需一个简单想法）；④同一时间只允许一个起稿任务（避免并发写版本）；⑤校验失败重试一次并把错误写进下一次提示词，仍失败则不写任何版本、原始输出存档到 `_studio/seed_draft/raw_*.txt`；⑥后台运行日志在 `_studio/seed_runs/`。

**S2 实施说明**：①范围守卫在程序层：最终稿 = 原稿 + 仅选中部分的新内容，模型对范围之外部分的任何输出都被丢弃（与原稿不同时记警告）；②模型可附 `_affects`（范围外、可能需跟着改的部分），只作提示返回；③无实际改动不写版本；校验失败带错误重试一次，仍失败不写版本；④可基于任意旧版本修订（新版本追加，不覆盖）；⑤修订与起稿共用后台任务机制，同一时间只允许一个；⑥角色以带 id 的列表呈现给模型以保持 id 稳定。
