## 背景

目标树可能有 4 层（`ultimate → domain → stage → goal → objective`），
节点一多，纯递归平铺展示会让用户要滚动很久才能看到自己关心的分支，
也容易在长列表里迷失当前在看哪一层。之前完全没有折叠能力——所有
节点、无论深度，永远全部展开渲染。

## 设计要点

- **状态放在哪**：`st.session_state["_gt_collapsed_ids"]`，一个
  node_id 集合。不用 URL query params（这次特意避开，理由见
  `kanban_auth_cookie_migration_plan.md`——但这里跟安全无关，纯粹是
  "折叠状态不需要能分享链接/多标签页独立"，放 session_state 最简单）；
  也不需要持久化到后端，因为这是"我这次打开看板想先看哪部分"的临时
  浏览偏好，不是团队共享的树结构信息。
- **只给"有子节点"的节点箭头**：叶子节点（`objective`，通常没有子
  Objective）如果也放一个占位箭头会造成"点了没反应"的困惑，所以
  用 `bool(children)` 直接判断要不要渲染箭头，不额外维护一份"哪些
  level 是叶子"的清单（`children` 为空这个事实本身已经足够）。
- **收起后要留痕迹**：如果收起后这一行看起来和"本来就没有子节点"
  完全一样，用户会忘记这里其实还有内容。所以收起状态下会渲染一行
  `st.caption` 提示具体收起了几个直接子节点（只统计直接子节点数量，
  不递归统计全部子孙——这是"这一层收起了多少"的直观数字，统计子孙
  总数反而会跟"点开之后会看到几层"预期不符）。
- **"全部展开/收起"为什么不做成"记住上次状态"**：`_gt_collapsed_ids`
  存的是 session_state，标签页关闭即重置，这是有意的——目标树的
  节点会随时间新增/删除，跨会话保留折叠状态容易出现"记住的是已经
  不存在的节点 id，新节点反而意外全部收起"这类陈旧状态问题，简单
  地"每次打开都是全展开"更符合直觉，也不需要额外的失效清理逻辑。
