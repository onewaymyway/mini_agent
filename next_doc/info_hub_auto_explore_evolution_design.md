## 1. 现状与边界（已核对代码）

| 能力 | 现状 |
|---|---|
| 站点来源 | 种子目录（静态）+ 最近三天条目的外部站点首页 |
| 探索深度 | 只看站点首页，不跟随任何链接 |
| 结构识别 | 重复容器（`explore_html`）或 JSON 形态；没有 RSS/Atom 自动发现 |
| 草稿生成 | 必须调用 LLM；没有模型时整轮不做任何事 |
| 质量门槛 | 条目数 ≥ 3、字段完整度 ≥ 80%、与已有源不相似 |
| 相关性 | 预览条目未与画像比对，只要结构合格即可入箱 |
| 合规 | robots.txt（404 允许，其它错误保守不允许）；无 crawl-delay；无站点级请求预算 |
| 反馈闭环 | 被忽略的候选只记为“已知”，不影响之后的探索策略 |
| 可观测性 | 本轮跳过原因计数；没有探索漏斗视图；没有已入箱源的健康复查 |

已确认不存在：HTML `<link rel="alternate">` 的订阅发现、sitemap、站内搜索表单识别、crawl-delay、基于忽略原因的学习。（`adapters/rss.py` 只在解析已知 RSS 时读取 alternate，不用于发现。）

## 2. 主要问题

1. **强依赖 LLM**：没有模型就完全不工作；有模型时，每个站点都要消耗一次生成调用，即使该站点只有标准 RSS。
2. **探索面窄**：只看首页，且种子固定。很多优质内容入口在分类页、订阅页或站内搜索里。
3. **相关性缺失**：结构合格但与用户兴趣无关的源也会入箱，增加收件箱负担。
4. **不从拒绝中学习**：用户忽略候选后，同类站点（同一平台、同一模板）仍会被再次提议。
5. **已接受的源没有复查**：源失效只会被健康机制降频/暂停，不会尝试替代入口。
6. **合规粒度不足**：只有 robots 的允许/不允许，没有站点级的请求频率与预算控制。

## 3. 演进方向

### 3.1 确定性优先的结构发现（降低 LLM 依赖）

探索顺序改为：**确定性规则 → LLM（仅当规则无法判定）**。

1. 订阅发现：读取首页 `<link rel="alternate" type="application/rss+xml|atom+xml|feed+json">`；若存在，直接生成 `rss` 或 `json_api` 草稿，不调用模型。
2. Sitemap 发现：读取 `robots.txt` 中声明的 sitemap 与常见路径；从 sitemap 的近期 URL 推断文章路径形态（如 `/p/<id>`），生成 `html_list` 的候选选择器（仍需预览验证）。
3. 结构规则：沿用 `explore_html` 的重复容器识别，但在没有模型时也能输出“候选选择器 + 预览结果”，由用户决定是否采纳。
4. LLM 仅用于：规则无法给出可用选择器、且用户开启了模型时。

收益：无模型也能发现大部分 RSS 型站点；LLM 调用量下降，预算更可控。

### 3.2 相关性与新颖性门槛

在现有质量门槛之后增加两项：

- **相关性**：用 `profile.score_item` 对预览的前 N 条打分；若平均分低于阈值，或与画像毫无重合，则标记为“与兴趣无关”，不入箱（可在日志中保留原因）。
- **新颖性**：预览条目与已启用源的标题二元组相似度（复用 `feed.bigrams`/`jaccard`）过高时，说明该站只是转载，标记为“重复内容”。

阈值写入 `config/discovery.yaml` 的 `autoexplore` 段，默认宽松，避免误杀。

### 3.3 两跳探索（受预算限制）

从**已接受且健康**的自动源页面出发，允许跟随一级站内链接（同域、路径为分类或订阅页），作为新的种子。约束：

- 只跟随同域链接；每个来源页最多跟随 N 个链接（默认 5）；总深度为 2。
- 被跟随的链接同样经过全部门槛，不因“来自已接受源”而降低标准。

### 3.4 站内搜索探索（可选，默认关闭）

识别站点首页的搜索表单（`<form action>` + `input[name]`），用画像的高权重关键词构造查询，取前 N 条结果作为预览。

- 每个站点的查询次数受预算限制，每个关键词只查一次。
- 仅使用公开搜索页；遇到需要登录或验证码的站点立即放弃。
- 默认关闭，理由：搜索查询会对站点产生额外请求，需要用户在看板明确开启。

### 3.5 从拒绝中学习

- 候选被忽略时记录原因（可选的快捷标签：“内容与兴趣无关 / 质量低 / 重复 / 其它”）。
- 同一模板类型（如同一平台的 RSS 模式）被连续忽略达到阈值，则降低该类型的探索优先级，并在收件箱显示说明。
- 沿用已有的 `evaluation.paused_templates` 思路：采纳率低于阈值时暂停该类型探索，暂停原因在“推荐效果评估”中展示。

### 3.6 已接受源的复查与修复

- 健康机制判定“连续失败”后，若该源来自自动探索，自动尝试：同站点的替代订阅入口（3.1）→ 同站点近期 sitemap 路径；找到可用替代则生成候选，由用户确认替换，不自动替换。
- 复查频率：每个已接受源每 30 天最多一次，避免频繁访问。

### 3.7 合规与请求预算

- 遵守 `Crawl-delay`（若 robots.txt 声明），否则使用默认最小间隔。
- 站点级日请求上限（独立于每日探索站点数上限），覆盖探索、复查与草稿生成的全部访问。
- 每个站点的探索记录中保留 robots.txt 的读取时间与结论，便于审计。
- 站点可在看板“屏蔽站点”，屏蔽后不再探索，也不再从外链线索中提取。

### 3.8 可观测性：探索漏斗

看板新增“探索漏斗”视图，展示最近 7 天：

`检查站点 → 通过 robots → 通过拦截检测 → 结构可用 → 草稿生成 → 通过质量 → 通过相关性 → 入箱 → 采纳 / 忽略`

每一步给出数量与主要跳过原因；点击可查看样例站点（仅站点域名与结论，不保存页面内容）。

## 4. 优先级与分期建议

| 阶段 | 内容 | 价值 | 风险 | 估计 |
|---|---|---|---|---|
| P14 | 3.1 确定性优先结构发现 + 3.8 漏斗视图 | 高（减少对模型的依赖；能看到瓶颈） | 低 | 1.5 天 |
| P15 | 3.2 相关性与新颖性门槛 + 3.5 从拒绝中学习 | 高（减少噪声） | 中（阈值需调） | 1.5 天 |
| P16 | 3.7 合规与请求预算 + 3.6 已接受源复查 | 中（稳定性与合规） | 中 | 1.5 天 |
| P17 | 3.3 两跳探索 | 中（覆盖面） | 中（请求量增加） | 1 天 |
| P18 | 3.4 站内搜索探索（默认关闭） | 中（覆盖面大，但站点压力大） | 高 | 2 天 |

**建议顺序**：P14 → P15 → P16，先把现有探索做得更省、更准、更可控；P17、P18 放在后面，只在前三步的数据显示覆盖不足时再做。

## 5. 不做的事

- 不做大规模爬取：每个站点的访问量保持很低，全局有上限。
- 不绕过验证码、登录或访问限制；遇到即放弃。
- 不保存站点页面的完整内容，只保存结构摘要与预览条目的标题和链接。
- 不自动启用任何新源；所有候选仍需用户确认。
- 不把用户画像发送到外部服务。
