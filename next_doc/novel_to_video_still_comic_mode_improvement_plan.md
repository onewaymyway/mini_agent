# novel_to_video 动态漫模式（still 渲染）改进计划

> 状态：**方案已确认（2026-11-15）；S1–S9 已完成。本计划全部阶段已实施，待本机真实 API 冒烟与人工验收**。按第 8 节分期实施，每期更新文档并打包改动文件（保持目录结构）。
> 关联文档：`next_doc/novel_to_video_external_project_plan.md`（总体设计）、`next_doc/novel_to_video_location_spots_plan.md`（地点细化）。
> 项目路径：`external_projects/novel_to_video/`。

## 1. 背景与目标

现在项目把小说转换为竖屏短剧视频：每个镜头由「参考图 + 配音」经视频模型生成一段小场景视频（C-8），再拼接为章节（C-9）、全书（F 系列）。

新增一种**动态漫模式**（`still`）：成品仍是视频，但每个镜头的画面是一张场景图，配合该镜头的配音与字幕，通过 ffmpeg 合成为带镜头运动和转场的视频。全程**不调用视频生成接口**。

目标：
- 同一项目可选择两种渲染方式之一，默认仍为真实视频模式（`video`），现有项目行为不变；
- 动态漫模式下，镜头画面的运动方式（镜内动效）与镜头之间的切换方式（镜间转场）均可在界面配置，默认带动效；
- 动态漫的产物与视频模式的产物格式一致（720×1280、24fps、H.264 + AAC、字幕烧录），全书合成与成片校验沿用现有逻辑。

## 2. 已确认的决策

| 项 | 决定 |
|---|---|
| 落点 | 在现有项目内增加渲染方式，不新建项目 |
| 渲染方式 | 项目创建时确定 `render_mode: video \| still`，默认 `video`；同一项目不混用 |
| 场景图模型 | `agnes-image-2.5-flash`（现有配置已是该模型），输出 `size: "1K"` + `ratio: "9:16"`，再缩放到 720×1280 |
| 参考图上限 | **每个镜头最多 3 张**（沿用现有 `_reference_images` 的规则：角色最多 2 张、地点 1 张，有余量才加道具） |
| 镜内动效 | 界面可配置，**默认开启**，默认为「推近与拉远交替」，提供多种效果可选（见第 5 节） |
| 镜头时长 | **不设上下限**，镜头时长即其配音时长（加余量），不做裁剪 |
| 镜间转场 | 界面可配置，默认淡化；叠化放在第二批实现 |

## 3. 非目标

- 不做角色口型、表情或肢体动画，动效只作用于整张场景图（推拉、平移、晃动）。
- 不做漫画分格版式（多格拼图页）。本期每个镜头一张全幅场景图。
- 不改变视频模式的任何行为，包括 C-8 的提示词、参考图、片段缓存键与审核流程。
- 不做同一章内两种模式混用。
- 不做模型生成的运动（图生视频），动态漫模式严格不调用视频接口。

| 静帧推近 | `media/ffmpeg.py` 的 `still_clip` 已用于视频桩（StubVideoProvider）的静帧推近 | 作为动效实现的起点，扩展为多种效果 |

| 审核 | `shot_review.py` 以镜头视频为审核对象 | still 模式改为审核场景图 |
| 挡位与预算 | `gates.py`、`batch.py` 的预算按视频与图像调用计数 | still 模式只统计图像调用 |

## 5. 功能设计

### 5.1 渲染方式

- 项目选项 `render_mode`，创建后不可修改（界面显示为只读）。
- 流水线阶段随模式变化：
  - `video`：`script → shots → assets → audio → prompts → clips（视频）→ compose`，与现在完全一致；
  - `still`：`script → shots → assets → audio → prompts → stills（场景图）→ segments（动效片段）→ compose`。
- `clips` 与 `segments` 都输出到章节的 `clips/` 目录，文件名 `<镜头id>.mp4`，因此 C-9 章节合成的代码路径两种模式共用。

### 5.2 场景图（still 模式 C-8a）

- 提示词沿用 C-7 的拼装方式，并追加参考图说明（例如「图 1 为角色甲的定妆图，图 2 为地点的参考图」）。参考图顺序固定：角色按镜头出场顺序，地点在最后。
- 参考图处理：
  - 每张参考图先缩放到长边不超过 1024 像素，再编码为 `data:image/png;base64,...`，控制请求体大小；
  - 超过 3 张时由 `_reference_images` 截断，并在日志中记录被丢弃的图片。
- 输出：`chapters/<章>/stills/<镜头id>_v<N>.png`，版本化，不覆盖旧图。
- 审核：镜头审核的对象是场景图；通过、驳回重生成、编辑提示词的操作与视频模式相同。

### 5.3 动效片段（still 模式 C-8b）

- 对每个已通过审核的场景图，结合该镜头的配音生成一段 mp4：
  - 时长 = 配音时长 + 0.4 秒余量；**不设上下限**，镜头可以很长，画面随配音持续；
  - 无配音的镜头（纯画面）没有时长来源，使用项目配置的默认时长（默认 3 秒，可在挡位页修改）；
  - 音轨为配音，无配音则为静音。
- 动效由界面选择，参数写入项目配置，修改后只需重新生成片段（场景图不变）。
- 片段文件由 `media/ffmpeg.py` 生成，先把图放大到约 2 倍再做运动，减少抖动。

### 5.4 动效种类（镜内）

| 取值 | 效果 | 说明 |
|---|---|---|
| `auto_alternate`（默认） | 按镜头序号交替：推近、拉远 | 同一章内节奏有变化，不单调 |
| `push_in` | 缓慢推近 | 适合情绪递进 |
| `pull_out` | 缓慢拉远 | 适合收束或揭示 |
| `pan_left` / `pan_right` | 水平平移 | 适合横向场景、多人对话 |
| `pan_up` / `pan_down` | 垂直平移 | 适合高耸建筑、竖向空间 |
| `drift` | 轻微晃动（幅度很小的随机位移） | 适合紧张或不安的情绪 |
| `none` | 静止 | 保留纯静态漫画感 |

动效强度可选 `slow`（默认）、`medium`，对应缩放与位移的总幅度。

### 5.5 镜间转场

| 取值 | 效果 | 说明 |
|---|---|---|
| `fade`（默认） | 淡入淡出（0.4 秒） | 镜头之间经过黑场过渡 |
| `dissolve` | 叠化（0.4 秒） | 相邻镜头画面叠合 |
| `cut` | 硬切 | 与视频模式一致 |

叠化需要两个镜头在时间上重叠，实现方式见 7.3。

### 5.6 界面

- 项目创建页：选择渲染方式（默认 `video`），说明创建后不可更改。
- 挡位页或项目设置：动态漫模式专用的「镜内动效」「动效强度」「镜间转场」「转场时长」选择项。
- 「预览动效」按钮放在**挡位页**：对选中的一张已审核场景图，用所选动效与转场生成 3 秒的预览，便于在批量生成前确认效果。
- 修改动效或转场后，章节的动效片段标记为过期（不影响场景图与配音），界面提示「需重新合成动效片段」。

## 7. 技术方案要点

### 7.1 图像接口（`providers/image.py`）

- `ImageProvider.generate` 增加可选参数 `reference_images: list[Path] | None = None`。
- 有参考图时，请求体为 `extra_body: {"response_format": "b64_json", "image": [data_uri, ...]}`。
- 无参考图时请求体与现在逐字节一致（测试锁定）。
- `StubImageProvider` 记录收到的参考图列表，供测试断言。
- 超时保持 300 秒（文档建议 60–360 秒范围内）。

### 7.2 动效实现（`media/motion.py`，新文件）

- 输入：场景图、时长、动效名称、强度；输出：mp4 片段（无音轨），音轨由 `mux_clip` 合入。
- 用 ffmpeg `zoompan` 实现缩放与平移，输入先放大到 2 倍。
- 每种动效的 filter 字符串由纯函数生成，测试用字符串比对（golden test），避免改动后效果悄悄变化。
- `StubVideoProvider` 现有的 `still_clip` 保留，视频模式不受影响。

### 7.3 镜间转场与音频重叠

- 叠化与淡化依赖 `xfade`，它会缩短总时长（每个转场重叠 `transition_sec`）。
- 方案：每个镜头的配音时间轴保持不变，转场时长计入镜头的余量：镜头片段总时长 = 配音时长 + 0.4 秒 + 转场时长的一半（首尾镜头不加）。
- 字幕时间轴按「镜头起点 = 前面镜头起点之和 − 转场重叠」计算，与 `subtitles.build_cues` 的 `clip_seconds` 输入一致，但需要在测试中断言字幕起点与配音起点之差不超过 1 帧。
- 「淡化」（fade）可以先用逐段淡入淡出实现，不需要重叠，作为第一版；「叠化」在第二批实现，依赖 7.3 的时长补偿。

### 7.4 挡位与预算

- still 模式的 G3 预算只统计图像调用（场景图生成）；视频调用上限对该模式无意义，界面隐藏该项。
- 其余挡位规则（G0–G5）与视频模式相同。

### 7.5 修改回退

四级回退语义保持不变，在 still 模式下对应：

| 级别 | 视频模式 | 动态漫模式 |
|---|---|---|
| clip_only | 重生视频 | 重生场景图，并重建该镜头片段 |
| prompt | 改提示词后重生 | 改提示词后重生场景图 |
| dialogue | 改台词，重做配音与后续 | 同左 |
| shot_plan | 改分镜，截断之后的镜头 | 同左 |

章节与全书成片仍标记为过期，不删除旧文件。

## 9. 测试计划

- 单元测试：参考图截断与顺序；data URI 编码与缩放；请求体有无参考图的差异；动效 filter 字符串（golden）；转场时长计算；片段时长规则；render_mode 创建后只读。
- 集成测试（离线桩）：still 模式完整章节流程（场景图桩 + 静音配音桩），断言阶段顺序、产物文件、成片时长、字幕时间轴。
- 回归测试：video 模式的全部现有测试保持通过；C-8 视频路径的请求体不变。
- 界面测试：AppTest 检查渲染方式选择、动效与转场选项、预览按钮、过期提示。
- 真实环境：本机用真实生图接口与 ffmpeg 跑一章冒烟，人工检查角色一致性与动效观感。

## 10. 风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| 角色一致性 | 参考图能提供一定的一致性，但不保证每张图完全一致 | 参考图数量上限 3；审核环节允许驳回重生成；真实冒烟时人工评估 |
| 请求体过大 | 三张参考图编码后可能数 MB | 参考图长边缩放到 1024 像素；必要时降为 2 张 |
| `zoompan` 性能 | 镜头没有时长上限，长配音的镜头帧数多，耗时明显 | 输入已放大；按镜头并行渲染片段；预览与批量渲染分开计时并记录耗时 |
| 叠化时长补偿 | 转场重叠会导致字幕与配音错位 | 7.3 的补偿方案与 1 帧误差的测试 |
| 成本 | 参考图超过 3 张后按量计费（刊例价 $0.003/张，目前免费） | 上限 3 张写死；日志记录每镜头参考图数量 |
| 观感预期 | 动态漫不等于视频，观众可能期待口型与动作 | 文档与界面说明动态漫的效果范围；非目标明确 |

## 11. 已确认的问题（2026-11-15）

1. 镜头时长不设下限与上限，跟随配音长度（见 5.3）。
2. 默认动效为「推近与拉远交替」（`auto_alternate`，见 5.4）。
3. 叠化放在第二批（S7）实现，第一批提供淡化（`fade`）与硬切（见 5.5、第 8 节）。
4. 「预览动效」按钮放在挡位页（见 5.6）。

实施从 S1 开始，按第 8 节分期进行。

- **S7 叠化（dissolve）：完成（2026-11-15）**
  - 与计划 7.3 的差异：计划设想把每个片段加长 T/2 再重叠。实际实现不改动片段，而是利用每个镜头配音后已有的 0.4 秒静音余量：相邻镜头的画面重叠 T 秒，前一镜头的音频尾部裁掉 T 秒（正好是静音）。这样配音起点仍与画面起点一致，且无需重新渲染片段。代价是 `transition_sec` 的上限为 0.4 秒（余量长度），超过会切到台词，因此设置校验直接拒绝。
