# novel_writer「大纲先行」模式实施计划

> 状态：设计已确认，待按期实施。每期完成后更新本文件与 `external_projects/novel_writer/docs/`，并打包。

## 0. 已确认的决策

| 问题 | 决定 |
|---|---|
| 简述粒度 | 每章 300–600 字的场景段落式（不用要点列表） |
| 写作能否偏离简述 | 关键内容锁定，不允许偏离；非关键内容可以发挥，但必须回写简述并记录原因 |
| 模式选择位置 | 每本书在向导里单独选择，默认「直写」（现有流程） |
| 修改简述后的已写章节 | 默认由作者决定是否重写；可切换为「自动重写」档位（每本书可配置） |

## 1. 关键内容与非关键内容

每章简述分两部分，写在同一个文件里：

- **叙述段落**（300–600 字）：场景顺序、人物行动、对话要点的散文描述。这是写作的主要依据，允许写作时润色、扩写。
- **关键内容**（结构化，写作时必须保留）：
  - `must_events`：必须发生的事件；
  - `must_states`：人物状态的变化（如“李凌云得知师父已死”）；
  - `must_foreshadow`：伏笔动作（埋设 / 回收 / 推进，引用伏笔编号）；
  - `must_hook`：章末钩子。

偏离规则：
- 关键内容的偏离会被写作后的校验拦下，章节不通过；必须先修改简述，再重写本章。
- 非关键内容的偏离允许，但写作完成后要在简述里追加一条“偏离记录”（原文、改动、原因），避免简述与正文脱节。

## 2. 配置项（每本书，存于 `项目状态/workspace_config.json`）

| 键 | 取值 | 默认 | 含义 |
|---|---|---|---|
| `writing_mode` | `direct` / `outline_first` | `direct` | 写作模式 |
| `brief_change_policy` | `ask` / `auto_rewrite` | `ask` | 简述修改后，已写章节的处理策略 |

向导在选择模式时展示两者的差异；`direct` 下完全不产生简述相关步骤。

## 3. 分期

**O0 模式开关与流水线接入（不调用 LLM）**
- `workspace_config` 增加两个键，向导增加模式选择，默认 `direct`。
- `pipeline.build_plan`：仅当 `outline_first` 时，在 `blueprint_split` 之后插入 `brief_draft:*` 与 `brief_review`；`chapter_steps` 的首个写作步骤依赖 `brief_confirmed`。`direct` 下计划与现在逐项相同（有测试对比）。
- 测试：两种模式的计划步骤集合；`direct` 与改动前一致。

**O1 简述生成（调用 LLM）**
- 步骤 `brief_draft:N`：按幕分批（沿用 `plan_act` 的分幕模式，避免单次输出过长被截断），每幕生成本幕各章简述，写到 `大纲规划/章节简述/第NNN章.md`，并生成 `_index.md`。
- 确定性校验：章号完整；人物名存在于人物档案；伏笔编号存在于伏笔账本；叙述段落 300–600 字；关键内容四类都非空（`must_hook` 可以为“无”，但字段不能缺）。校验失败的章节带着错误重试一次。
- 测试：校验规则的正反例；分幕生成的章号覆盖；字数越界被拦下。

**O2 简述确认检查点（人工审批）**
- 新增 `brief_review`，闸门强制为 review（同 `ideation_review`，不受挡位与自动通过影响）。
- 界面「章节简述」页：逐章显示叙述段落与关键内容，可直接编辑；对单章写反馈 → LLM 改写该章（沿用 `revision_flow` 的分诊思路，判断是否影响相邻章，并把相邻章列出来让作者确认）；可整幕重排。
- 每次修改保存简述版本（复用 `revision_flow/versions` 的快照与差异思想，简述目录独立成版本库）。
- 确认后写入 `brief_confirmed` 与内容哈希，简述冻结。
- 测试：编辑后哈希变化；确认前写作步骤不可运行；回退到旧版本后内容一致。

**O3 写作接入与关键内容校验**
- `chapter-writer` 的输入改为：该章已确认的简述（唯一结构依据），蓝图职能字段仅作辅助。
- 写作完成后，新增校验步骤 `brief_check:N`：逐条核对 `must_events / must_states / must_foreshadow / must_hook` 是否在正文中实现。未实现的关键内容 → 章节不通过，回到写作步骤重写（最多两次），仍不通过则停在等待作者确认。
- 非关键偏离：校验步骤产出“偏离记录”，自动追加到简述文件的“偏离记录”小节，标明章号、原文、改动、原因。
- 测试：关键内容缺失被拦下；非关键偏离写入记录；偏离记录格式稳定。

**O4 简述修改后的已写章节**
- 每章简述记录其内容哈希与该章正文写作时所用的哈希。简述变更后，依赖它的已写章节被标记为“简述已变更”。
- `brief_change_policy = ask`（默认）：在「章节简述」页列出受影响章节，每章提供「重写 / 保留 / 忽略此次变更」三个操作，由作者决定。
- `brief_change_policy = auto_rewrite`：对受影响章节自动生成重写任务，复用 `revision_flow` 的执行器（滚动改写、单章校验、失败隔离、可停止、可续跑），并记入操作日志。
- 测试：哈希变化能标记到正确章节；`ask` 下不自动执行；`auto_rewrite` 下生成的任务覆盖全部受影响章节。

**O5 界面与文档收尾**
- 向导模式选择、章节简述页、写作页的“简述”查看入口。
- `docs/outline_first.md` 说明模式、配置、校验规则与偏离规则；更新 `PROJECT.md` 变更记录与 `docs/README.md` 索引。
- 打包本期新增与修改的文件（保留目录结构）。

## 4. 风险与边界

- **流水线复杂度**：`pipeline.build_plan` 与 `chapter_steps` 的依赖改动会影响所有书。O0 用“计划步骤集合对比”测试守住 `direct` 模式不变。
- **关键内容校验的准确性**：正文是否实现了某个事件，靠 LLM 判断，可能误判。误判时会要求重写，最多两次后交给作者，不会静默放行。
- **简述与蓝图的一致性**：简述由蓝图生成，蓝图若改动，需要重新生成受影响的简述；这一点在 O4 的哈希链中一并处理。
- **成本**：大纲先行会增加一轮完整生成（简述）和每章一次关键内容校验，LLM 调用量明显增加。
