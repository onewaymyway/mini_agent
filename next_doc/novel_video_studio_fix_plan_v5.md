# novel-video-studio 改进方案 v5：引入"剧本化"中间层 + 大场景时长弹性化

## 背景 / 问题

当前 `.claude/skills/novel-video-studio` 的阶段2（大场景切分）、阶段3（单
大场景详细规划）都是**直接在小说原文（自然语言、夹叙夹议、引号嵌套动作
描写）上做切分**，实际使用中反复出现"拆分出的大场景/小场景不合适"的
问题，根因可以归纳为两类：

1. **对话抽取依赖"现场抠引号+启发式识别动作描写"**：阶段3 Step 3 要求
   Agent 在原文里实时判断哪句在引号内、哪句是"她一边擦着桌子一边说"这
   类夹在对话中间的动作/神态描写，再手动拆成 `dialogue`/`narration`。
   这是让 Agent 在非结构化文本上做解析，一致性差——中文引号/直引号混用、
   引号被动作打断、直接引语 vs 间接转述的边界，全靠当场判断，
   `03_scene_detail_planning.md` 里专门列了错误示例和大段自查清单，
   `check_scene_detail.py` 也只能做启发式关键词提示，说明这个问题本身
   在当前架构下没有稳定的解法。
2. **剧情切分单位和时长约束耦合在一次判断里**：阶段2 Step 2 要求候选
   大场景同时满足"原文字数 ≤1000字"和"预估时长 ≤120秒"两条硬性上限，
   超限就必须在内部继续找次级转折点强行二次细分——这会把本该保持完整
   的连续戏剧张力（例如样例小说第二幕苏晴大段独白揭示真相）硬切断，
   属于"为了凑时长约束而牺牲剧情合理性"。

## 改进方案

### 核心思路：插入"小说→剧本"转换与校验环节，下游全部基于剧本而非原文

新的整体流程：

```
阶段0（新）小说→剧本转换
  → 阶段0.5（新）剧本校验：剧情/对话完整性核查（Agent 语义核查 + 脚本机械把关）
  → 阶段1 角色/地点抽取（原有，输入源改为剧本）
  → 阶段2 大场景切分（原有，切分依据改为剧本场次，时长约束改为弹性）
  → 阶段3 单大场景详细规划（原有，content_blocks 拆分改为直接映射剧本结构）
  → 阶段4 素材与配音（不变）
  → 阶段5 小场景视频生成与一致性核查（不变）
  → 阶段6 最终拼接（不变）
```

### 阶段0：小说→剧本转换

产物：`script.md`（自然语言剧本，非 JSON/YAML，人可读、Agent 写起来
也自然）。格式示例：

```
### 场次 1｜林远家客厅/门口·夜（内景）
旁白：2038年冬天，雪下得很大，林远四年没见过这么大的雪了。他裹着毛毯坐在沙发上，手里攥着一张泛黄的照片。
旁白：门铃响了。林远起身，透过猫眼看到一个穿白色大衣的女人站在雪地里，面容模糊。他打开门。
苏晴：林远，你还记得我吗？
旁白：那个女人抬起头，雪片落在她的睫毛上，她的眼睛是苏晴的眼睛。林远的血液在这一刻凝固了。
林远：晴？
苏晴：是我。
```

要点：
- 每个"场次"对应后续 `macro_scene` 的候选切分单元，场次头统一标注
  **地点+时间+内外景**，供后续 `visual_hint`/定妆图使用；
- **对话行固定格式 `角色名：台词`**，一行一句，说话人显式化，从源头
  消除"引号里混入动作描写"的问题——转换这一步就已把动作/神态描写单独
  放进旁白行；
- 旁白允许适度转述改写（更适合口播的表达），但**剧情事实必须准确对应
  原文，不能新增没有依据的情节**；对话台词要求贴近原文原意（不要求逐字，
  因为已经过滤掉了夹杂的动作描写，但核心内容/语气不能被篡改或代写）。

### 阶段0.5：剧本校验

核查维度（Agent 语义核查为主，脚本只做机械把关）：
1. 剧情覆盖：原文关键情节点（事件、转折）是否都在剧本里体现，无遗漏/无新增；
2. 对话覆盖与准确性：原文直接引语是否都能在剧本对应场次找到台词行，且
   内容/语气未被曲解；
3. 说话人归属：每句台词的角色名是否符合原文语境；
4. 无臆造：剧本不能出现原文没有依据的情节或台词。

产出结构化核查报告（沿用阶段5 `consistency_report.yaml` 的模式：Agent
逐条判断写结论，新增脚本 `check_script.py` 只检查报告覆盖完整性+全部
pass+未过期，不做语义判断）。核查不通过回阶段0修正剧本，通过后才能进入
阶段1，保证后续阶段读到的都是"确认忠实原文"的结构化文本。

### 下游阶段联动调整

- **阶段1**：输入源从小说原文改为剧本（剧本里角色名已显式标出，抽取
  更稳）；
- **阶段2**：直接以剧本"场次"为切分基本单位（已经按剧情/时间/地点分好），
  不再需要重新通读原文找转折点；`macro_scenes.yaml.raw_text` 改为存对应
  场次的剧本原文；
- **阶段3**：Step 3"区分旁白/对话"简化为"按时长把连续剧本行分组进
  micro_scene 并原样映射为 content_blocks"，不再需要抠引号/识别动作
  描写混入；`check_scene_detail.py` 的对话真实性校验比对源从小说原文
  改为剧本场次原文；
- **阶段4/5/6**：不受影响，消费的仍是 `scene_detail.yaml`，字段契约
  不变。

### 大场景时长约束弹性化

- **大场景（macro_scene）**：取消"≤1000字/≤120秒"硬上限，改为弹性
  建议值——默认目标 ≤120秒，剧情连续性强、拆分会破坏张力时允许放宽到
  ≤240秒（由 Agent 判断是否值得为凑时长而破坏节奏，而非机械触发二次
  细分）；`check_macro_scenes.py` 对应把超限从 error 降级为 warning
  （>120秒提示，>240秒才报错）；
- **小场景（micro_scene）**：**保持 4-12秒不变**——这是
  `gen_video_with_text` 视频生成接口的硬限制，不在本次调整范围内。

## 验证计划

用 `test_cases/inputs/novel_video_sample_novel_ai.txt` 实跑：
小说→剧本转换→剧本校验→大场景切分→挑一个大场景做详细规划，检查产出
是否合理、各校验脚本是否正常通过。

## 待确认问题

- 剧本转换阶段旁白是否允许"轻度转述改写"（更适合口播的表达），还是
  要求旁白也尽量逐句贴原文、只是重新分行——这会影响阶段0.5校验的严格
  程度。当前方案默认允许轻度转述改写，但剧情事实必须准确对应原文。
